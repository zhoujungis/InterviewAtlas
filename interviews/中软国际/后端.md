 3. OSI 四层网络模型中，各层如何解封装？跨网段通信时哪些头部会变化？ 

 答案： 

 工程中常用 TCP/IP 四层模型：应用层、传输层、网络层和网络接口层。发送数据时逐层添加协议头，接收时根据 EtherType、IP Protocol 和传输层端口逐层解析。 

 主机跨网段发送报文时，IP 层的源、目的地址通常仍是通信双方地址，但二层目的 MAC 是下一跳网关的 MAC，而不是远端主机的 MAC。路由器转发时会去掉旧二层头，再根据出接口重新封装新的二层头。 

 每经过一台三层设备，IPv4 的 TTL 减一，头部校验和也要更新。若没有 NAT，源、目的 IP 和 TCP/UDP 端口通常保持不变；经过 NAT 后，其中部分字段会被修改，传输层校验和也必须同步调整。 

 二层交换机通常只转发以太网帧，不减少 IP TTL。三层路由器根据路由表选择下一跳，并为新的二层链路重新封装帧头。 

 4. TCP 三次握手为什么不能改成两次？SYN 和数据同时到达时协议栈如何处理？ 

 答案： 

 三次握手不仅是确认双方收发能力，还要同步双方的初始序列号，并确认对方已经接收到自己的初始序列号。 

 如果只有两次握手，服务端发送 SYN-ACK 后就认为连接建立，那么网络中的历史 SYN 报文可能使服务端创建一个无效连接。客户端收到服务端回应后发送第三次 ACK，服务端才能确认客户端确实接收到了服务端的初始序列号。 

 TCP 允许 SYN 携带数据，但传统 TCP 中这部分数据通常要等握手完成后才能交给应用。TCP Fast Open 可以通过 Cookie 让已验证客户端在 SYN 中携带应用数据，降低一个 RTT，但服务端必须考虑 SYN 或响应重传导致的数据重复执行。因此，携带的请求必须具备幂等性，或在应用层提供去重机制。 

 握手成功不代表应用已经调用 accept 。连接可以先进入内核的已完成连接队列，等待应用取出。 

 5. TCP 四次挥手中，为什么主动关闭方需要进入 TIME_WAIT？ 

 答案： 

 TCP 是全双工协议，两个方向需要独立关闭。一端收到 FIN 只表示对端不再发送数据，本端仍然可以继续发送，所以 ACK 和本端 FIN 通常不能直接合并，最终表现为四次挥手。在本端恰好也没有数据发送时，ACK 和 FIN 可以合并。 

 主动关闭方在发送最后一个 ACK 后进入 TIME_WAIT，主要有两个原因。 

 第一个原因是保证最后一个 ACK 丢失时，能够重新响应对端重传的 FIN。第二个原因是让旧连接中的延迟报文在网络中自然消失，防止相同四元组被快速复用后，旧报文被误认为新连接的数据。 

 TIME_WAIT 通常持续 2MSL 。大量短连接会产生很多 TIME_WAIT，但不能因此随意跳过协议要求。常见优化方式是连接复用、长连接、负载均衡、扩大临时端口范围，以及让更适合承担 TIME_WAIT 的一方主动关闭连接。 

 SO_REUSEADDR 也不等于可以无条件复用任意处于 TIME_WAIT 的四元组，它主要影响本地地址绑定规则。 

 6. VLAN Tag 的结构是什么？Access、Trunk 和 QinQ 分别如何处理报文？ 

 答案： 

 802.1Q VLAN Tag 插入在源 MAC 和原 EtherType 之间，占 4 字节，包括 TPID 和 TCI。TCI 中包含 3 位 PCP、1 位 DEI 和 12 位 VLAN ID，因此可用 VLAN ID 范围并不是完整的 0 到 4095。 

 Access 端口通常属于单个 VLAN。接收无标签帧时，将其归入该端口的 PVID；向终端发送时，通常移除 VLAN Tag。 

 Trunk 端口可以承载多个 VLAN，交换机通常保留标签转发。Native VLAN 或 PVID 的具体处理与设备配置有关，如果链路两端 Native VLAN 不一致，可能产生 VLAN 泄漏或流量进入错误广播域的问题。

 7. DHCP 客户端没有 IP 地址时，如何完成地址申请？Relay Agent 解决了什么问题？ 

 答案： 

 客户端初次接入时通常执行 DORA 流程，即 Discover、Offer、Request 和 ACK。客户端没有可用 IP，也不知道 DHCP 服务器地址，因此最初通常以 0.0.0.0 为源地址、 255.255.255.255 为目的地址发送广播报文。 

 服务器返回 Offer，客户端通过 Request 表明选择的服务器和地址，服务器最终使用 ACK 确认租约。客户端获得的不只是 IP，还可能包括子网掩码、默认网关、DNS、租约时间等选项。 

 路由器默认不会转发二层广播。如果 DHCP 服务器与客户端不在同一广播域，需要部署 DHCP Relay。Relay 接收客户端广播后转为单播发给服务器，并通过 giaddr 或 Option 82 携带客户端所在网段、端口等信息，服务器据此选择正确的地址池。 

 如果攻击者伪造 DHCP 服务器，可能向客户端下发恶意网关和 DNS。交换机可以使用 DHCP Snooping，把可信服务器响应限制在指定端口，并建立 IP、MAC、VLAN 和端口之间的绑定关系。 

 8. ARP 缓存更新时如何防止欺骗？动态 ARP 检测依赖哪些信息？ 

 答案： 

 ARP 用于把同一二层广播域中的 IPv4 地址解析为 MAC 地址。主机发送 ARP Request 询问目标 IP，目标主机返回 ARP Reply。ARP 协议本身缺少身份认证，因此攻击者可以发送伪造 ARP Reply，把网关 IP 映射到攻击者 MAC。 

 交换机上的动态 ARP 检测可以根据 DHCP Snooping 形成的绑定表，校验 ARP 报文中的源 IP、源 MAC、VLAN 和入端口是否匹配。对于使用静态地址的服务器，还需要配置静态绑定或额外的验证规则。 

 免费 ARP 本身不一定是攻击。主机可以通过 Gratuitous ARP 检测地址冲突、更新交换机或邻居缓存，也可以在高可用主备切换后声明虚拟 IP 对应的新 MAC。 

 仅通过限制 ARP Reply 数量不能可靠阻止攻击，因为合法的高可用切换也可能集中更新缓存。防护需要结合端口信任、地址绑定、速率限制和异常告警。 

 9. ICMP 差错报文如何参与路径 MTU 发现？黑洞问题是怎样形成的？ 

 答案： 

 IPv4 发送端可以设置 DF 标志，禁止路由器对报文分片。如果中间链路 MTU 小于报文长度，路由器丢弃报文并返回 ICMP Destination Unreachable，具体为 Fragmentation Needed，同时告知可接受的 MTU。发送端据此降低报文大小。 

 IPv6 路由器不负责分片，发送端需要根据 ICMPv6 Packet Too Big 调整报文大小。因此，随意屏蔽所有 ICMP 或 ICMPv6 会破坏路径 MTU 发现。 

 如果中间设备丢弃超大报文，同时防火墙又过滤相关 ICMP 差错报文，发送端无法获知 MTU 限制。小报文可以正常传输，大报文却不断重传，这就是 PMTU 黑洞。 

 TCP 可以通过 MSS 限制单个 TCP 段的数据大小，网关也可以执行 MSS Clamping。但 MSS 只解决 TCP 场景，不能替代完整的路径 MTU 发现。现代协议栈还可以使用 Packetization Layer PMTUD，通过传输层探测不同报文大小，降低对 ICMP 的依赖。

## 我人生中的第一场Java面试

来源：牛客网 ｜ 类型：面经 ｜ 发布：2019-05-25 ｜ [原文链接](https://www.nowcoder.com/discuss/353147081667846144)

1、说起我的第一次Java面试，我不禁回想起我大学时参加校园招聘的那段日子，那时候我还是本科生，由于不是科班出身，只学过一点点Java皮毛，所以那时候对于找Java工作并没有什么概念，只是以为上过Java的课程就可以找到一份Java工作了，于是就兴高采烈地参加了一些公司的面试。 

 2、不过那个时候我还在复习考研，所以也没时间好好准备，于是拼凑出一份Java简历就想去面试。当时投递了几个省内还不错的公司，结果都是音讯全无，我当时还挺费解的，我不是学过Java吗，为什么连面试机会都不给我呢。当然那时候也没时间纳闷了，复习考研才是第一要务。 

 3、于是时间一晃到了大四，考研结束，春招到来，当时想找一份实习工作先做着，积累一些开发经验，于是就想去投几家招Java实习生的公司，当时来我们学校的公司都是一些小企业，我心想着要求应该也不会多高吧，于是“海投”了一波，送出十几份简历，结果给我面试机会的公司一家都没有，有一家公司干脆直接让我去上班，当时我一听工作内容好像和开发没有什么关系，貌似就是it维护的职位，一天给50块钱，还离学校很远，可以说是非常尴尬了。 

 4、就算当时我已经考上了研究生，但是对Java基本上还是入门水平，于是我不得不降低要求，直接到网上的招聘网站上投简历，什么智联、猎聘、51job，就算是在这种我现在嗤之以鼻的招聘网站，当时也找不到几个能投递的岗位，随便投了几个之后，终于有人来约面试了。 

 5、一开始给我电话的是中软国际，我当时还不知道这就是家外包公司，但是一看招聘要求，居然要先交钱才能上班，后来才知道这是打着招聘旗号做培训的机构，真的非常恶心。。。后来，终于又有一家小公司来联系我，让我去现场面试，公司就在本地，我打了个车过去，开始我人生中第一次真正意义上的面试。到了那个地方之后，才发现就是一间小小的办公室，有个自称面试官的人看了我的简历，然后给了我一套Java测试卷让我做，半个小时后，我把一份完成度百分之50左右的卷子交上去了，本以为挂定了，没想到这个面试官居然对我褒奖有佳，并且和我大谈人生理想，吹牛逼谁还不会啊，聊呗。 

 6、面试算是告一段落，面试官表示他的领导要来见见我，确认面试结果，结果那个领导一来，问了我的情况，才知道我只是来实习的，我刚说完我是想来实习的，领导脸色一沉，马上很抱歉地和我说，打扰了，你走吧！（大概就是这个意思）于是我人生第一场面试就这么折戟了。
