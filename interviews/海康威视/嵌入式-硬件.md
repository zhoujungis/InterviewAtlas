## 嵌入式面试经验总结 100+大厂面试总结的经验

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-22 ｜ [原文链接](https://www.nowcoder.com/discuss/942708292382384128)

简历上写“熟悉 FreeRTOS”“做过通信模块”“了解 Bootloader”，面试官点头，下一秒就开始往下挖。

 挖到第二层你还能答，第三层开始飘，第四层直接空。这类情况，在大厂嵌软面里太常见了。

 我把消费电子、安防通信、工控自动化、车企/Tier1、视觉影像这类方向的 100+ 场面经和追问路径放在一起看，发现一件很清楚的事：

 大厂嵌软考的不是知识点清单，而是你能不能把一条链路讲到边界。

 先说结论

 100+ 场面试里，反复出现的筛选标准就四条：

 C / 内存 / 中断底板扎实不扎实 

 你是不是真碰过板子、总线、RTOS 或 Linux 

 项目能不能讲成：问题 → 方案 → 验证 → 失败路径 

 出故障时，你有没有自己的排查顺序 

 所以同样一道“I2C 和 SPI 区别”：

 只会答线数和速率，属于热身合格；

 能接到上拉、时钟拉伸、挂死恢复、项目里超时重试，才算真正开始拉开分差。

 再压缩成一句话：

 会背定义，过第一轮热身；能讲机制和坑，算进门；能结合项目讲设计取舍和异常定位，才接近大厂要的“能扛模块”。 

 大厂面试官通常怎么拆一个人

 最常见的开场，不是直接甩难题，而是从你简历里最硬的那一行开始。

 你写熟悉 C，他就从指针、对齐、 volatile 、位操作切进去，看你是不是只会调库。

 你写熟悉 RTOS，他就从优先级、同步原语、ISR 边界、优先级反转切进去，看你是不是只会 xTaskCreate 。

 你写熟悉 Linux / 驱动，他就从用户态内核态、设备树、 probe 、中断下半部切进去，看你是不是只编译通过过模块。

 你写做过通信，他就从时序、波形、超时、异常恢复切进去，看你是不是只会 HAL 收发。

 你写做过 Bootloader / OTA，他就从分区、校验、掉电、回滚一路往下问，看你是不是只跑通过升级 demo。

 真正决定去留的，往往不是第一题，而是第二、第三轮追问：

 掉电怎么办？

 并发冲突怎么办？

 现场偶现复现不了怎么办？

 你怎么证明系统满足实时或可靠性约束？

 什么叫“熟悉”，什么叫“写了但经不起问”

 算熟悉

 能一句话说清这个机制解决什么问题、不解决什么问题

 能画出你项目里的数据流 / 任务流 / 启动流

 能讲至少一个真实坑：现象、定位手段、根因、改法、验证

 能回答“如果重做，哪里会改”

 不算熟悉

 只会背定义，举不出项目场景

 项目只能演示 happy path，说不清失败路径

 简历写“负责整体”，细节全是队友做的

 通信只会调通，不会抓波形、不会分析挂死

 OTA 只会下载写入，不会讲校验、断电、回滚

 一句话： 熟悉不是知识面更宽，而是项目表达更完整。 

 100+ 场面下来，高频考点其实就六条线

 1. C 语言与内存：刷人最多的底板

 重点不是语法，是指针、数组退化、结构体对齐、大小端、位域、宏副作用、 const/static/volatile 、堆栈、 .text/.data/.bss 。

 高频追问方向：

 volatile 能解决可见性，不能解决原子性和内存序

 对齐为什么影响通信协议和 Flash 映射

 MCU 上栈溢出通常怎么表现、怎么定位

 手写环形缓冲 / memcpy 重叠处理时边界怎么守

 2. 中断、并发与 RTOS：实时功底分水岭

 重点是 ISR 和任务边界、临界区、调度、同步原语、延迟来源、优先级设计。

 高频追问方向：

 为什么 ISR 里不能阻塞、不能乱拿互斥锁

 关中断、关调度、互斥锁分别适合什么场景

 队列 / 信号量 / 互斥锁怎么按语义选型

 优先级反转是什么、怎么解

 哪些 API 必须用 FromISR 版本

 3. 总线、外设与联调：硬件协同能力

 UART / SPI / I2C / CAN / DMA / ADC，表面是接口题，实际考排障。

 高频追问方向：

 你怎么确认是软件超时还是硬件无应答

 I2C NACK、总线挂死怎么恢复

 DMA 和 Cache 一致性什么时候必须考虑

 CAN 仲裁、终端电阻、异常帧你怎么查

 4. 启动、Bootloader、OTA：工程闭环感最强

 从复位到跑起来，从分区到升级回滚，这一块最能看出你是不是只在应用层调 API。

 高频追问方向：

 上电到 main() / 到 APP 跑起来经过哪些关键步骤

 APP 跳转要注意向量表、栈指针、中断哪些点

 A/B 分区解决什么问题

 升级中断电、校验失败、版本回滚怎么设计

 5. Linux / 驱动：不是所有岗都要，但一要就是门槛

 偏 BSP、平台、安防、部分手机底层，Linux 不是加分项。

 高频追问方向：

 用户态 / 内核态、进程线程、系统调用

 字符设备框架和 file_operations 

 设备树到 probe 成功的路径

 中断上下半部、会不会睡眠决定用什么锁

 摄像头岗还会挖 V4L2、不出图排查、MIPI/I2C 链路

 6. 项目深挖：真正拉开上限的地方

 八股答得一般，项目讲得深，仍有机会救；

 项目一问就空，八股背再熟也很难翻盘。

 每个主力项目至少准备：

 3 分钟介绍版

 10 分钟深挖版

 1 个最难 Bug 的完整定位链

 1 条失败路径：超时、重试、降级、安全态、日志

 不同公司味道不一样，别一份简历海投同一套话术

 消费电子（OPPO / vivo / 小米等）

 更看功耗、稳定性、内存、多任务协作、异常收敛。

 常问：你怎么平衡响应速度和功耗？共享数据怎么保护？一次卡死怎么定位？

 安防 / 通信（海康、大华、中兴等）

 Linux 味道更重，进程线程、IPC、网络、性能排障更常见。

 常问：为什么选进程/线程？丢数据怎么查？CPU 占用高怎么定位？

 强实时 / 飞控影像类（大疆等）

 更抠周期、抖动、DMA、队列满、中断预算。

 常问：控制任务周期怎么保证？采集和处理怎么解耦？你怎么证明满足实时约束？

 工控 / 自动化

 更吃通信可靠性、长时间跑机、异常恢复、日志和版本。

 常问：Modbus/CAN 超时重传怎么做？掉电参数怎么保？看门狗怎么喂才有意义？

 车载（车企 / Tier1）

 通信 + 可靠性 + 升级几乎必问，AUTOSAR / 功能安全能了解更好，没有也可诚实说边界。

 常问：CAN/CAN FD、诊断概念、Boot/OTA 回滚、ECU 复位恢复、长时间测试指标。

 摄像头 / 视觉相关

 会从“模组能不能出图”挖到整条链路。

 常问：sensor 是不是你点亮的？I2C 初始化、MIPI、DMA、丢帧、花屏、不出图怎么分层排查？

 项目怎么准备，才像能逆风翻盘的那种

 不够用的项目

 点灯、流水灯、循迹小车、纯例程改参

 只有功能演示，没有架构和排障

 简历写“精通”，细节经不起第二问

 更有杀伤力的项目特征

 至少满足 4 条：

 有闭环 ：采集 / 通信 / 存储 / 显示 / 升级 / 异常处理，至少覆盖 2～3 项

 有分层 ：APP / 协议 / 中间件 / 驱动 / BSP 边界清楚

 有真实问题 ：偶现 bug、总线冲突、升级变砖风险、内存踩踏等

 有可靠性 ：看门狗、掉电保存、校验回滚、日志、降级策略至少占一两项

 结合近年高频方向，这几类更容易打：

 工控：RTOS 多任务 + 总线协议 + HMI + 日志/报警

 车载：CAN 通信 + 状态机 + 诊断/可靠性 + Boot/OTA

 摄像头：采集显示链路打通 + 丢帧/不出图排查 + 简单算法或 ISP 相关

 系统工程：Bootloader + 双分区 OTA + 版本管理 + 掉电恢复

 高分回答通常长什么样

 别再只背第一节。高分口述更接近这个结构：

 结论一句 → 机制两句 → 我项目里怎么用 → 出问题怎么查 → 边界是什么 

 举例：被问“为什么 ISR 里不做耗时操作”。

 低分答：因为中断要快。

 高分答：ISR 打断正常调度，耗时长会抬高中断延迟、影响同优先级和更低优先级任务；我项目里中断只做置标志/投递队列，协议解析放到高优先级任务；曾经把日志打进 ISR，导致偶发丢帧，后来用逻辑分析仪和任务水位才定位到。

 面试官要的是机制 + 现场，不是标准答案复印件。

 嵌入式大厂高频题单

 C / 内存 / 启动

 volatile 能解决什么，不能解决什么？

 static / const 在嵌入式里各举一个真实场景

 指针和数组的本质区别， sizeof 为什么不同？

 结构体内存对齐规则是什么，协议场景有什么坑？

 大小端怎么判断，什么时候必须显式转换？

 栈溢出常见表现有哪些，如何定位？

 .text/.data/.bss 各放什么，上电后谁负责初始化？

 链接脚本在 MCU 工程里解决什么问题？

 中断 / RTOS

 中断上下文和任务上下文有什么区别？

 为什么 ISR 里一般不做耗时操作？

 临界区是什么？关中断、关调度、互斥锁如何选型？

 任务切换的本质是什么？

 什么是优先级反转，常见怎么解决？

 队列、信号量、互斥锁分别适合什么场景？

 哪些 RTOS API 能在中断里调用？调错会怎样？

 任务栈怎么估算，水位怎么看？

 总线 / DMA / 排障

 UART / SPI / I2C 核心区别和选型依据？

 I2C 出现 NACK 或总线挂死，你怎么处理？

 DMA 相对中断传输的优缺点是什么？

 什么时候必须考虑 Cache 一致性？

 CAN 为什么适合车载，终端电阻起什么作用？

 一次“通信偶发失败”，你的标准排查顺序是什么？

 Bootloader / OTA / 可靠性

 MCU 从上电复位到 APP 运行，关键阶段有哪些？

 Bootloader 跳转 APP 要注意哪些点？

 Flash 分区一般怎么划分？

 OTA 过程断电怎么办？

 A/B 分区和单分区回滚各解决什么问题？

 看门狗怎么设计才算“健康才喂”？

 参数区掉电保护你怎么做？

 Linux / 驱动 / 视觉

 用户态和内核态的核心区别是什么？

 字符设备驱动基本框架是什么？

 设备树解决了什么问题，如何对应到 probe ？

 中断上半部和下半部如何分工？

 摄像头不出图，你从哪一层开始查？

 V4L2 取流链路大致怎么走？

 项目与综合

 介绍你最有含金量的项目，并说明你个人职责边界

 项目里最难的一个 bug，完整讲定位链

 为什么这里用消息队列而不是全局变量？

 如果系统要保证 10ms 周期任务，你会如何设计和验证？

 如果重新做这个模块，你会改哪三处？

 使用建议：每题按“结论 → 原理 → 项目场景 → 坑点”口述；卡壳的标红，优先补，不要平均刷。

 最后把经验收成可执行清单

 准备大厂嵌软，别再把时间耗在“再背 50 个名词”上。更有效的顺序是：

 先定岗位主线：MCU/RTOS、Linux/BSP、车载、工控、视觉，别混着浅准备

 简历每个关键词都准备一条追问链，不会的词删掉

 主力项目按架构、难点、失败路径、数据/指标重讲一遍

 八股按模块攻坚，优先 C、中断/RTOS、通信排障、Boot/OTA

 按目标公司补味道：消费电子补稳定性与功耗，车载工控补可靠性，Linux 岗补驱动链路

 100+ 场面试看下来，真正稳定拿结果的人，很少是“题库背得最全”的人；

 更多是： 简历经得起挖，项目讲得成闭环，出问题知道从哪查。

 销售工程师工作体验，总结累但成长很多。 

 1.大家最先关注的就是HIK的工作压力，只能说体面厂没有辜负盛名！名不虚传！我来这边是销售岗，基本上每天都要差不多11点下班。因为销售不仅需要对接客户需求，同时需要完成下单、相关产品配型也会有产品知识的学习。这一整套下来感觉对销售的综合素养要求是相对较高的。（所以我感觉为什么这个岗位叫销售工程师）感觉在这边很充实，可以学到很多东西，对个人的成长非常有帮助，对自己未来期待较高的友友可以直接入手！
2.工作氛围很不错，领导和同事都很好相处。领导没有什么架子，大家风评一致很好。新人来了也会有大展身手的机会（我还没满一个月就已经开始接待客户了），但是有一说一产品知识有点点多，得尽快跟上啊！
3.怕没客户？作为销售大家一般都比较担心找不到客户的问题，海康给了我们这份自信！因为产品和技术的竞争力，相比于大部分销售行业来看，公司有一部分固定的客户来源，前期可以先协助对接原有客户，并在销售的过程中完成客户积累，所以不要太慌没有客户。
4.福利总体感觉也还行。来了刚好赶上公司搬家，蹭上一大堆好吃的！而且公司定期也会有团建，算是忙里偷闲的快乐。哦对，还混上了纪念T恤 哈哈哈哈！感觉穿着也不错。公司对于大家都很支持，刚来的新人，领了工牌（可惜照片给我拉瘪了）也印了名片（小卡拉米工程师）。

技术二面，题目一般不会像一面那样密集考 C 语言概念，而是更喜欢顺着项目往下挖：这个模块是不是你自己做的？为什么这么设计？异常情况怎么处理？如果放到真实产品里，能不能稳定运行？

 海康这类偏工程落地的嵌入式岗位，二面会更关注产品化思维。

 一面问你会不会指针、RTOS、通信协议；二面更可能问你：项目怎么量产？设备死机怎么定位？协议升级怎么兼容？日志怎么设计？客户现场偶发问题怎么复现？

 所以二面不能只准备八股，最好把自己的项目重新拆一遍，按“需求背景、模块职责、数据流、任务划分、异常处理、调试过程、优化结果”去讲。

 二面题目：

 选一个你最熟悉的嵌入式项目，完整讲一下背景、架构、你负责的模块和最终效果。

 你在项目里最有技术含量的部分是什么？为什么不是简单调用库函数？

 如果项目重新做一遍，你会在哪些地方重新设计？

 你负责的模块输入和输出分别是什么？和其他模块如何解耦？

 项目里有没有遇到过偶发 bug？你是怎么复现、定位和解决的？

 如果设备在客户现场运行几天后死机，但无法接 J-Link，你会提前设计哪些日志和异常记录？

 RTOS 任务是怎么划分的？优先级设置依据是什么？有没有出现过任务阻塞或饿死？

 通信协议如果要支持后续版本升级，你会如何设计帧格式和兼容机制？

 UART / CAN / TCP 通信偶发丢包时，你会从哪些层面判断是硬件问题、驱动问题还是协议问题？

 片内 Flash 保存配置参数时，如何防止掉电导致参数损坏？

 Bootloader 升级失败时如何回滚？如何判断 App 固件是否完整可运行？

 如果系统内存占用越来越高，你会如何排查栈、堆、全局变量和内存泄漏？

 如果某个传感器采集数据偶尔异常，你会如何从硬件、时序、驱动、滤波和任务调度角度分析？

 项目中有没有用过看门狗？喂狗策略怎么设计，如何避免程序卡死但仍然一直喂狗？

 如果让你负责一个新硬件模块 bring-up，你会如何看原理图、芯片手册、驱动代码和调试波形？

 嵌入式大厂面试题，基础八股文资料合集整理：

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 海康二面准备，建议重点放在这几块：

 第一块是项目复盘。

 项目一定要能讲细，不要只说“我做了某某功能”。要讲清楚模块边界、数据流、任务调度、异常恢复、调试方法，以及最后怎么验证稳定性。二面很容易围绕项目连续追问，如果项目不是自己真正做过，很容易露馅。

 第二块是工程稳定性。

 海康偏产品落地，面试官会关心设备能不能稳定运行。比如死机、复位、丢包、掉电、Flash 写坏、任务卡死、内存不够，这些都要准备排查思路。

 第三块是 RTOS 和通信协议。

 如果简历写了 FreeRTOS、UART、CAN、TCP、SPI、I2C，就要能结合项目讲任务怎么分、队列怎么用、缓冲区怎么设计、异常怎么恢复、协议怎么校验。

 第四块是调试能力。

 二面很喜欢问“如果现场出问题怎么办”。回答时不要只说打断点，要体现嵌入式调试体系：串口日志、复位原因寄存器、HardFault 信息、任务栈水位、示波器、逻辑分析仪、版本回溯、最小复现。

 第五块是职业和团队匹配。

 如果二面偏综合面，可能会问为什么选海康、为什么做嵌入式、能不能接受杭州/加班/业务方向、未来想做驱动还是应用。这个也要提前准备，不要只准备技术题。

 结尾

 海康威视嵌入式二面不一定比一面题目更多，但更容易看出项目是不是真的做过。

 一面考基础，二面考你能不能把基础放进真实项目里。

 准备时不要只背“RTOS 是什么”“信号量和互斥锁区别”这种概念，而是要能讲：我在项目里为什么用它、解决了什么问题、有没有副作用、出了问题怎么查。

 嵌入式二面真正想确认的是：你不是只会跑 Demo，而是有能力把一个模块做稳定、做清楚、做可维护。

 1.7.3 面试真题 

 

 技术工程师 

 

 1、怎么去处理的网络故障，详细说一下 

 【解题思路】 

 
 当处理网络故障时，我通常采用以下步骤： 

 确认故障现象：首先需要和用户或者相关人员确认故障现象，了解具体出现的问题，比如网络连不上，网速慢等等。 

 确认故障范围：需要了解故障是否是局部还是整个网络的问题，确定哪些设备、哪些用户受到影响。 

 分析可能原因：根据故障现象和故障范围，分析可能出现故障的原因，比如网络设备故障、网络配置错误等等。 

 初步解决方案：针对分析出的可能原因，给出初步的解决方案，比如重启网络设备、修改网络配置等等。 

 实施解决方案：根据初步解决方案进行实施，检查故障是否得到了解决。 

 验证解决效果：确认故障是否已经解决，如果没有解决需要进行进一步分析和解决。 

 总结和记录：在故障解决后，需要总结原因和解决方案，并记录下来，以备日后参考。 

 以上步骤可以帮助我更加有效地处理网络故障，提高故障处理效率。 

 
 

 2、实习和兼职经历 

 【解题思路】 

 
 好的，我可以分享一下我的实习和兼职经历。 

 在大学期间，我曾经做过一份实习，我在一家IT公司的技术支持部门工作。我的主要工作职责是为客户提供技术支持和故障排除。在这个过程中，我学会了如何与客户进行有效的沟通，并通过问问题和分析问题的方式快速定位问题并提供解决方案。 

 除了实习，我还有过一些兼职工作经验。例如，我在学校的图书馆工作过一段时间，负责维护和管理图书馆系统。我还在一家公司做过临时工，负责协助处理一些文件和数据的整理和归档。 

 这些实习和兼职经历让我获得了实际的工作经验，也让我更加了解了职场中的工作规则和工作环境。我相信这些经验对我未来的职业发展会有所帮助。 

 
 

 3、对这个岗位的理解和后续发展情况的理解，是否考虑过考研考公 

 【解题思路】 

 
 我理解这个岗位的主要职责是为客户提供高效、优质的技术支持和解决技术问题。具体来说，可能需要对客户提出的问题进行分析和诊断，并给出有效的解决方案和建议，有时还需要对客户进行技术培训和指导。 

 关于后续发展情况的理解，我认为这个岗位的发展空间是非常广阔的。随着技术的不断进步和客户需求的变化，技术支持岗位也需要不断更新自己的知识和技能，例如掌握新的技术和产品知识，了解市场趋势和客户需求等。通过不断地学习和提升自己的技能，我相信这个岗位可以有很好的发展前景。 

 至于是否考虑过考研考公，我认为这是个人职业发展规划的一部分。考研和考公有助于提高自身的知识水平和综合素质，但也需要考虑到个人的兴趣和职业规划等方面的因素。作为一名技术支持岗位的面试者，我认为我目前的职业规划是专注于技术领域的发展和提升，如果有机会继续深造和学习相关领域的知识，我会积极考虑。 

 
 

 4、自己的优点和缺点，在哪些地方可以体现出来 

 【解题思路】 

 
 谢谢面试官的提问，我的优点是： 

 态度认真负责，对待工作始终保持高度的热情和积极性； 

 具有很强的学习能力和自我提升的意识，能够快速适应新环境和新技术； 

 团队合作意识强，善于沟通和协调，能够与同事、领导和客户保持良好的关系； 

 细心周到，能够仔细聆听客户问题并及时解决问题。 

 我的缺点是： 

 在一些工作中有时会过于追求完美，容易陷入细节中； 

 有时候缺乏自信，需要在自我认识和自我提高方面多加努力； 

 缺乏一些领导经验，在团队管理和领导方面有待提高。 

 我的优点可以在日常工作中得到体现，例如对待客户时始终保持耐心和热情，细心聆听客户问题并及时解决问题，保证客户满意度；在团队协作中，积极与同事、领导和客户沟通，发挥个人特长，为团队达成目标作出贡献。我的缺点可以通过不断的努力进行提高，例如在工作中寻求领导的指导和建议，学习领导经验，增强自信心，同时也可以在自我管理和个人成长方面加强培养。 

 
 

 5、为什么不去选研发 

 【解题思路】 

 
 
 技术支持岗位对我而言更符合我的技能和兴趣，我喜欢帮助客户解决他们在使用产品或服务中遇到的问题，并且我觉得这是一种有意义的工作。 

 虽然研发岗位可能会有更高的薪资和一些其他的福利，但我认为在技术支持岗位工作会使我更加全面地了解产品和服务，从而更好

## 杰理科技数字IC设计工程师面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-12-26 ｜ [原文链接](https://www.nowcoder.com/discuss/436931902084308992)

两轮面试现场笔试，第一轮技术面先笔试题，做完了现场检查题目确认笔试过了，根据题目问一些问题，然后问了自己的项目，协议解析，FPGA验证，ASIC流程这些，你对来贵公司有什么想法，就过了。HR人也挺好没怎么为难我（就是想给我开白菜价而已），我请求加一轮面试，不然这个offer我可能不会接，然后我就往返飞了一趟珠海。第二轮面试是boss和三个技术主管，没有问基础知识，现场介绍自己的项目并在黑板上画出来解释，当时的我哪见过这样的阵仗，如同雏鸡一样瑟瑟发抖，面试表现自然是一般般，幸好遇到我师兄也在这家公司给我壮胆，简直是他乡遇故知太开心勒。事后一起吃了个饭带我开车沿着海岸线兜风，第一次见到大海的我挺激动的，我也想买车沿着海兜风了。

 我的面试感受：杰理是一家挺棒的公司，做无线蓝牙芯片这块的，我去公司也能直观的感受到氛围挺不错的，开的待遇也是在二线城市中的超级棒（给我连调了两次薪），而且包吃包住真的是怕麻烦理工男的心头好。新盖了两栋大楼，一栋办公一栋住宿，Offer时间给了三个月的考虑期。HR人挺好的，保持联系有机会也是很不错的。缺点：产品是快消芯片，技术领域并不深，市场领域已经是红海，短周期低价格的产品才能杀出重围，宿舍挨着办公楼（9xx6福报你们懂的）。而且这家公司和海康威视、紫光同芯在一周内搞完的，当时真的是累死我了。

## 海康威视-硬件开发工程师-面试经验

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-11-23 ｜ [原文链接](https://www.nowcoder.com/discuss/425064426786578432)

在笔试通过之后，首先是电话面，让你首先进行自我介绍，如何选择自己的一个项目进行介绍，介绍完之后问你如果改用这样的方法该怎么去实现。

 如何电话面通过之后，发邮件让通过面试的任参加复试，通视频进行面试，也就是第二轮专业面。

 视频面试除了让你自我介绍和相应的项目情况，还问你关于示波器的使用情况，以及FPGA资源的问题，

 1、你为什么选择这款FPGA芯片，占用了多少IO资源，为什么不用更简单的FPGA芯片。

 2、实验室示波器的带宽是多少，如何测量纹波最后就是问你有没有什么问他的。

 专业面过之后就是HR面，HR面是线下面，问你有关个人情况、性格、薪资期望的问题。

## 2021秋招，硬件工程师面经（台达、海康、汇川、宁德时代）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-10-08 ｜ [原文链接](https://www.nowcoder.com/discuss/353158680747122688)

一、台达（已拿offer），提前批总共两面，无笔试。 

 形式：腾讯会议 

 一面主要面式内容：自我介绍、然后直接聊项目，会追问项目细节，例如功率器件选型，驱动设计等细节问题。主要看你是否认真参与了项目，难度不大，但会压力逼问到你无法回答。 

 二面HR面：主要是聊薪资了，感觉有点水，很容易就招人了，而且给的岗位是资深研发工程师，但....好像全部人都是这个岗位，薪资却和这个高大尚的名称不对等。 

 
 

 二、海康威视（已过技术面），后面还有素质面试和主管面式。 

 笔试：难度不大，牛客网上有类似题目。 

 面式形式：腾讯会议 

 技术面：自我介绍，紧接着会问项目，面试官很和蔼，会引导你说出他想知道的内容， 

 1、会详细问项目中出现的电路拓扑结构，让你描述具体原理以及为什么采用这种结构。 

 2、问到具体硬件选型指标。 

 3、面试官还会问你做项目中遇到什么难题，如何解决。 

 4、你所做的项目相比于同类型的项目有何优势。 

 5、你平时是通过什么方式去学习新知识的。 我回答：我比较注重用实践去带动自己的学习积极性，会去翻阅行业内大厂提供的技术手册， 

 例如TI公司官网上会提供整个项目的设计书、英飞凌公司的IGBT选型与驱动设计手册等。拿到这些项目案例去学习，甚至动手去搭硬件复现， 

 遇到不懂的理论知识再去查阅教程，平时翻阅更多的是国外的教程，例如电力电子著名教材fundamental of power eletronics、 

 半导体器件教材 Fundamentals of Power Semiconductor Devices、 开关电源教材swiching power supplies A to Z等等。 

 6、你有什么兴趣爱好吗。 这个就比较随意了，我回答是篮球，还吹牛b说啥crossover、山姆高德、变向误导这些技术动作都会，人称xx大学小欧文，把面试官整乐了，说有机会切磋一下。 

 7、反问环节，我就问一下岗位需求技能啥的，听完面试官介绍完，我就分析了一波我自身条件与技能确实挺符合这个岗位的，让面试官知道你的诚意。 

 专业面后第二天就通知说过了，等待素质面式通知。 

 
 

 三、汇川（惨遭pass） 

 形式：网页视频，只能视频，没办法共享屏幕，没办法展示ppt 

 技术面：面试官全程黑着脸，表现不耐烦状态，估计是我表现不太好，问了几个我没怎么准备的问题，发现我搞的项目都是跟控制器相关的，dsp、fpga啥的，他不是很感兴趣， 

 然后问我拓扑结构、器件选型，采样调理电路设计等问题。只有我在侃侃而谈，面试官没有很多反馈，全程无表情。这是一次体验感比较差的面式了，自己也没有发挥到应有的水平。 

 
 

 四、宁德时代（已过专业面式） 

 笔试：在专业面试通过后，有一个测试，考数学理解（也就是那些图表题，简单计算）、语文理解。 

 面式形式：腾讯会议 

 技术面：面试官很nice，时不时微笑，搞得我有点尴尬，但氛围十分好，面式时间只有20分钟不到。开场先自我介绍。 

 1、详细聊一个你熟悉的项目，他会就硬件方面进行提问，也是分析拓扑啥的。 

 因为我其实也在做硬件编程（dsp、fpga），整套控制器架构、原理图、PCB都做了，他问我如何对待硬件工程师需不需要会编程这件事。这其实是送分了。 

 2、你觉得你项目中的创新点是什么。 

 3、项目中遇到最大的技术困难，如何克服。 

 4、反问环节，按老套路问面试官就行，让他有东西能说一下，然后自己在结合他说的，做一些反馈。 

 
 

 ps：本人是硕士学渣，暑假时在各种大厂的提前批中都当了炮灰，请大家轻喷。其实私企我准备不多，放弃了一些机会，也在试试看国企。希望能找到一个满意的工作~大家也一样~ 😁

## 2022联发科硬件工程师提前批面经(已意向)

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-08-30 ｜ [原文链接](https://www.nowcoder.com/discuss/353158373908619264)

#一面2021/08/02： 

 

 持续22分钟，面试给人的感觉不错，首先上来打招呼，进行自我介绍，自我介绍部分最后只是简要介绍了一下我自己做过的三个项目，然后主动询问了一下面试官是否需要详细对项目内容进行一下介绍，面试官一般都不会拒绝的，最好准备一个ppt，然后就一个一个介绍自己的项目。
 第一个项目是电池管理系统，他并没有问与通信相关的东西，问了一下电池主要测量什么信息，测量这些信息的精度有多高，然后就是问怎么证明你这些指标真的达到了。
 第二个项目也是简要介绍，巴拉巴拉一大堆，然后面试官问了我其中用到的zigbee主要实现了什么功能，怎么测试这些功能的，我简要提了一下zigbee需要上传什么信息，然后介绍了一下过程中解决的一个问题，以及解决的手段。
 第三个项目我上来就说这个是正在进行的，其实不应该这么说，因为说是正在进行的就会给人一种没搞完的感觉，感觉水分很大。
 谈完项目之后，面试官问我对工作地点的要求，我说都可以，又问了有没有女朋友，额，，没有，然后又问我投了哪家公司，这是第一场面试吗？我也不确定背后是什么意思，就是如实回答的，最后面试官问我有什么想问的，然后就结束了。
 
 总结，一轮是技术面，因为面试官是做射频的缘故，所以关于项目问问题的点可能和我想得不太一致，不过整体感觉还好(因为之前自学过射频基础)。
 
 这次的优点：
 1.针对性强，我本来是做电池管理系统相关的，几个项目中用到了通信技术，因为职位要求中写了与通信相关的，所以我项目资料介绍是侧重有线无线通信方向写的。
 2.思维还算清晰，口齿还算利索。
 3.态度上算是做到了不卑不亢。
 
 总结起来缺点：
 1.项目介绍部分逻辑性太差，表现在我向面试官介绍完一遍我的项目之后，面试官一没明白我做的系统的功能，二没有全面清晰了解到系统的构成，这一点在后续一定要重点加强，项目介绍一定要针对不同的工作岗位要求有不同的侧重点，这样才会在最短时间内勾起面试官对你项目的兴趣。
 2.说话要适当慢一点点，出口前想一想，别着急 😂 。 

 
 

 

 #二面2021/08/03： 

 

 二面持续40分钟左右，这一轮是主管面试，因为是第一家进入主管面试阶段的公司，还需要时间来切换表达叙述的方式，一面的时候叙述方式就是“自我介绍+获奖荣誉+项目经历”，二面本来一开始还想按照这个步骤来，可是对面面试官全程没开摄像头，直接就问我有什么问题想要问他，？？？是的，上来就是问问题，所以就问了一下关于部门岗位负责什么具体方向之类的东西，因为太突然，虽然之前也查阅了联发科相关的岗位信息，但是这里还是问的不太顺，说话逻辑性属实需要加强，然后主管向我说了联发科大致的新人培养方法，关于工作方向主管说进来之后会按照个人特质进行分配安排的，等等。然后主管问了一下本科的关键课程的成绩，模电数电一类的，之后又问了我身边的人都投了哪些公司，我说海康、大疆、华为...没提紫光一类的，然后问了我工作的意向城市，我说这个问题不大，因为现在读书的地方本来离家也很远，都一样的，问了我父母对我找工作的要求看法，我一五一十叙述了一下就结束了。
 然后主管就又回到了前边的问题，接着向下提问，他说我列举的这几家公司都是偏向做终端产品的，是偏向商业化的，但是联发科则是偏向公版原型机研发与支持的，还要负责对客户进行技术支持，也就是说，经过几年业务熟悉之后，你的水平必须要比客户更高，因为客户都是一些做终端的厂商，他们的水平肯定不错，你要比他们还强，对于这样的差异，你有什么看法？
 我说我是倾向于芯片原厂的，而且自己感觉自己的沟通能力算不上顶尖，但是也还好，做技术支持相关的业务也不排斥，芯片原厂是可以学习到更多更广泛的东西的，所以芯片原厂是我优先考虑的(大意)。
 之后问了学习能力这怎么样，我举了一个跟项目相关的例子，说明了学习能力。
 最后就是问了我感觉项目中遇到的一个问题，举例说明，刚开始我没太理解面试官的意图，以为就宽泛的说一下就好了，就简单提了项目中关于ESD静电防护的问题，后来面试官跟我强调要讲出你的解决问题的逻辑，我把解决问题的思维过程和技术实施细节都讲了一下就结束了。
 最后面试官问了一下意向薪资，我说能给个范围参考吗？(其实就是客套一下)，然后面试官说我们这是没有参考范围的，然后我说我先期做过一些调查，说了一下意向的薪资，然后就结束了。
 整体感觉还可以，可能面试官是主管的原因吧，压迫感是有的，主管面切记不要说太多虚的、概念化的东西，要仔细理解面试官的问题，直接了当、简短准确的回答，不能泛泛而谈那样想混过去，说话要有逻辑性。(我就是说话逻辑性有些欠缺，需要不停练习去完善)
 要对自己未来的规划，对找工作近期的规划以及对公司选择有一定的认识和准备。
 也的确像之前查到的主管面试的特征，核心就是主管想招一个他想要的、满足他部门需求的人，所以他问的问题会更综合一些，目的是全面考察你这个人。
 补充一点：问问题最好不要问跟岗位主要职责相关的，即使官网上招聘要求没有明说，也最好不要问，不然会让面试官觉得你没好好读官网岗位要求，虽然确实有的岗位需求写的太空泛。

 二、秋招面向对象及日程 

 秋招其实是“秋季校园招聘”的简称，一般只针对当年的应届生，比如2021年就是针对22届毕业生。因此，今年的秋招会被称作2022届秋招，这里的2022指的是2022届而不是2022年噢~ 

 
 

 在这里顺便提一句，相信大家还听过一个名词叫做“春招”，类比于秋招，很容易理解“春招”就是“春季校园招聘”的简称。但是春招一般来说是对秋招的一个补充，招聘人数和需求都会比秋招的时候要少很多。 

 
 

 去年，硬件行业提前批招聘消息从6月底就开始陆陆续续放出来了。 

 

 
 在这里说一下提前批的好处： 

 大部分公司提前批是免笔试的，而且提前批和秋招互不影响，比如 汇顶科技 、 OPPO 、 中兴 等，个人感觉某些公司的笔试还是具有一定难度的，免去笔试可以节省不少的时间和心力； 其次，提前批的竞争压力比正式秋招小很多，一方面提前批会卡学校筛选，另一方面，秋招的时候，大家都开始发力了，竞争实在大； 再者，如果公司在提前批招满了人，秋招可能就没有对应的岗位了。所以有能力参加提前批的话一定要报提前批，如若拿到了offer后面会舒服不少，就算没拿到也可以积累不少的面试经验。 

 

 
 

 

 按照往年秋招的趋势，如果要考虑提前批的话，今年6月份开始，你就需要开始留意企业的提前批招聘信息了，建议大家尽量不要赶在网申快要截止时再去投递。 

 
 

 三、校招求职准备规划 

 1、自我认知和职业规划 

 在选择公司、岗位的时候，需要问自己几个问题，并得到真实的答案，如下：
 Q1：我是否想从事本专业研发工作？是否想转行？ Q2：我能够接受的最远工作地是哪里？是否愿意出省或可能长期出差？ Q3：如果公司需要加班，我是否接受996，甚至9117？我是否必须得955？ Q4：我对目标企业的偏向，是体制内工作，还是外企，还是没有限制？ Q5：我有没有特别想去工作的企业？ 回答完上述问题，可以确定自己偏向的几家公司以及要从事的岗位。 

 那么，职业规划有三条路： 

 一、纯技术路线，成为一个“技术大牛”； 二、技术转管理，懂得技术，带领团队，完成公司项目； 三、技术兼职管理，这样混合的成长路线，不是每一个公司都能提供的，管理岗需要拉通资源、对齐需求，相较单职业路线，需要更多的精力和能力。 2、时间节点参考 

 1～3月份，准备好简历，确保简历没问题； 3～5月份，一边投递实习一边强化理论知识； 5～7月份，有实习的可以去实习积累实习经历，没有实习的可以继续笔试+面试能力； 7～9月份，正式拉开秋招帷幕，投简历、笔试、面试； 9～11月份，基本敲定工作。

 五、关于投递渠道 

 1、网申 

 网申是最常见也最常规的校招投递渠道，基本上每家互联网 公司招聘官网 都有网申渠道，需要应聘者自行填写基本信息，上传简历。 

 
 

 由于不受时间和空间的限制，头部大厂网申渠道一旦开启，往往就会收到全国各地同学的简历。在网申候选人很多的情况下，公司会设置关键词机选，来筛除一大部分简历，而毕业学校确实会成为公司筛选简历的重要指标之一。 

 
 

 因为机器筛选标准是固定的，所以如果有些同学毕业学校不太好，但实习经历特别丰富，那其实在网申上往往是会很吃亏的。在认清优劣势之后，这时就会比较推荐同学们去校园宣讲会现场投递或者走内部推荐渠道。 

 2、校园宣讲会 

 有些头部大厂每年都会在全国各大高校准备校园宣讲会，建议大家多关注留意一下自己心仪企业的宣讲会行程，特别需要留意的是有些公司会在宣讲会上当场收简历，结束后安排现场笔试面试。 

 
 

 所以，如果可以 现场投递简历 ，那通过的概率肯定是要比网申大很多。 

 
 

 另外，在宣讲会上，企业会介绍自己公司的企业文化，工作内容，工作环境，晋升渠道，薪资福利等等，这也不失为进一步了解企业的好机会。 

 3、内部推荐 

 区别于网申，内部推荐需要同学们找到 目标公司的在职员工 内推上传个人简历，内推成功后，有些公司可能会发邮件要求候选人再去官网补充简历。 

 
 

 内推的一大好处 就是，你的简历会优先被用人部门看到，如果有用人部门看中了你的简历，就可以直接发起面试。另外同学们也可以通过内推人了解一些公司内部情况和岗位要求，面试过程中出现问题也方便及时沟通。 

 
 

 但这里需要提醒大家的就是，因为公司招聘系统是同一个，所以无法重复投递，已网申过的就无法再内推了。 

 
 

 所以我强烈建议22届秋招的同学 能走内推尽量走内推 ，但前提是要找个 靠谱的内推人 。找个靠谱的内推人是很关键的，一方面，很多公司内推机会只有一次，别人帮你内推过就不能再内推了；另一方面，同学们如果不能与内推人直接建立联系，就无法知道内推进度如何，最终是否内推成功，很容易简历就沉在池子里，捞不出来，而在这种情况下一个靠谱又能直接联系的内推人是可以救你一命的。

 六、准备简历 

 （1）个人免冠照片 

 建议不要使用白色为底色的照片； 

 （ 2 ）个人信息部分： 

 交代个人姓名、出生年月、籍贯、毕业院校、专业、学历，民族和政治面貌是可选项； 

 【 Tips 】 

 籍贯与企业所在地的距离较远可能会使得HR有应聘者是否愿意背井离乡来到企业工作的担忧； 给出自己的毕业院校，如果是985、211或者属于微电子领域的国家示范性院校，则是一个加分项； 给出自己的专业、学历，如果与微电子相关，上述三点可以大大增加简历初筛的可能性。 对于有国有资产性质的企业，如国企、央企、研究院等，党员是一个很好的加分项，投递对应企业时，可以注明。 

 （ 3 ）求职意向 

 写出自己想要投递的工作岗位，使得HR可以一目了然； 

 （ 4 ）联系方式【重中之重！！！】 

 一般通过简历筛选后，后续的笔试、面试通知将会通过电话或邮件的方式进行通知或沟通，务必需要保证上述两个信息是可以在工作时间联系得到的； 

 （5 ）教育背景 

 给出自己的本（硕博）学校、专业、主修课程的信息，说明应聘者和数字芯片设计的专业相关性； 如果是相关性较弱的专业转行，则需要在【主要技能】和【工程项目经历】等方面补充说明自己的优势； （6 ）项目经历【重中之重！！！】 

 

 说明应聘者的实际工程项目能力，必须和岗位要求高度相关 项目一般写2~3个，2个为宜，实在没有项目就把自己学校做的课题拿出来 写清楚参与项目时间、项目名称以及你在项目中承担的身份。
 写清楚【项目简介】和【主要工作】。【项目简介】帮助企业快速了解该项目的应用领域和作用，而【主要工作】更为关键，是应聘者具体能力的反映，让企业判断应聘者是否符合企业需求，是否比其他应聘者更具有优势。 举例而言，可以写出自己在一个项目中承担的哪些模块的代码设计，或者验证了哪些模块的功能，或者与组内同学、同事怎样进行协同工作，完成设计任务；
 

 （7 ）论文、专利 

 反映应聘者的学术能力和科研成果的转化能力，对于发表的论文应当给出期刊的等级，对于申请的专利最好能够给出专利号或受理号； （8 ）专业技能 

 简要叙述自己的专业技能，如能够使用哪些编程或硬件描述语言，能够使用哪些测试设备，能够使用哪些开发软件等，并举例说明能够使用的关键技术 专业技能必须和求职岗位高度匹配，如果不知道怎么写可以去岗位的招聘页面查看招聘要求，再结合自己的实际情况写上。 

 

 （9 ）获奖情况 

 成绩的奖项一定要写上，比如校级奖学金之类的越多越好； 和专业相关的比赛奖项一定要写，因此在校期间一定要多参与这类比赛，例如“电子设计大赛”在电子类的岗位照频中就很吃香，华为的硬件工程师招聘要求中就有一条： 在各类电子竞赛中获得过奖项,将会被优先考虑。 与岗位关联性较低、分量不足的奖项不必写上，以免占据太多简历篇幅；

 七、准备笔试 

 笔试一般包括两种：性格测试+技术笔试(技术类岗位独有)。 

 所谓性格测试就是通过一系列的主观题来对你的性格进行评估，确认你是否积极乐观，能够胜任岗位；技术笔试涵盖的范围则比较广，它主要考察你所投递的岗位所需要具备的理论知识。 

 

 

 
 1、笔试形式 

 线上一般以浏览器为主，一般会摄像头录像加上电脑录屏监考，在给定时间完成题目，需要网络情况较好，如果中途因为网络原因掉线会被后台记录。 

 线下考试以校内考场为主，现场监考、纸质作答。 

 2、笔试题型 

 常见题型有：单选题、不定项选择题、填空题、判断题、简答题、计算题、作图题等。 

 部分企业会在技术笔试中夹杂综合测评类题目，如智力题、心理测试题等。 

 

 

 3、各大厂题型举例 

 某H厂：以单选题+多选题的组合，近几年一般是40单选+5多选或者40单选+10多选。 

 笔试难度4颗星，考察深度正常，考察范围非常广，会涉及材料、网络、机械等专业外知识。 

 某广州C厂：以不定项选择题+简答题、计算题、作图题的组合，近几年一般是20~24道不定项选择题加上4道左右的大题（简答、计算、作图）。 

 笔试难度3颗星，考察深度正常，一般只考察模电数电电源以及一些常识性题目。 

 某T姓外企：以单选题+不定项选择题的组合。题目数量较多、涉及知识面很广、难度很高。 

 笔试难度5颗星，对模电数电的考察非常深入，超过大学教材的范围。 

 某杭州大厂：以单选题+多选题+简答题的组合，题量有点忘了，应该是20道以内，时间够用。 

 笔试难度4颗星，考察模电数电电源基础，加上一些专业常识。 

 某广州电源厂：以单选题+多选题+填空题+计算题的组合，题量20道左右。 

 笔试难度3颗星，考察模电数电电源基础，电源偏多，加上一些专业常识。 

 4、专业知识准备 

 硬件行业技术笔试涵盖的范围则比较广，它主要考察你所投递的岗位所需要具备的理论知识。 我们可以通过目标企业在官网上放出的招聘信息了解岗位的具体要求，并对症下药，是使得招聘事半功倍的方案。 以华为单板硬件开发工程师为例 ，其技术笔试内容涵盖了数字电路、模拟电路、信号与系统、通信原理、信号完整性、PCB设计等一系列知识，主要考察你专业理论基础的掌握程度。 

 5、答题技巧 

 选择题：单选题以排除法为主；多选题一般是少选多选选错都没分，因此选择上要更加谨慎，同时尽量找出选项之间的联系，有助于增加不懂时蒙对的几率。 填空题：一般考察基础为主，对模电数电的相关基础概念熟悉之后，拿满分问题不大。 简答题：如果考察到知识空白区，要尽量联想到自己熟悉的部分，不要留空，增大切到给分点的几率。 作图题：注意作图规范、刻度清晰、注释明显。 

 6、刷企业真题 

 企业真题的话，牛客网这边有提供很多名企笔试真题练习，还可以根据公司、职位、年份轻松一键筛选： 名企笔试真题练习 ： https://www.nowcoder.com/contestRoom 

 
 

 八、准备面试 

 面试形式通常上来说分为技术面试+HR面试。
 其中技术面试根据公司的不同面试轮数也不同，大多数公司技术面试一般为两轮，HR面试多为一轮，因此面试一般为三轮~五轮左右。 

 1、各公司面试流程 

 （1）华为海思：总共“两轮技术面+一轮主管面”。 

 都是进入华为校招的官网上线上面试，每轮面试平均1个小时，其中两轮技术面会现场做一到两道笔试题。一轮面试完成后等候几分钟后现场通知是否通过面试，如果挂掉了就不会进入下一轮面试。主管面试完后就进入“池塘”，被捞起来后HR会直接和你谈薪资，没有HR面； 

 （2）大疆创新：“两轮技术面+一轮主管/HR面” 

 笔试通过后，第一轮技术面试是电话面试，约定一个固定时间会有面试官准时打过来。一面通过后，第二轮就是通过腾讯会议线上面试。二面通过后，终面就是一个HR和一个主管一起面试，然后等消息（友情提醒：Dji发了感谢信后可能还会捞人的，别问我是怎么知道的，反正当时很难受就对了）； 

 （3）阿里平头哥：也是“两轮技术+一轮HR面”。 

 都是通过阿里会议进行线上面试。第一轮面试好像就是部门的老大，聊了5分钟后，老大就问我还有什么问题吗，好家伙这也太快了吧，我人当时都懵了1分钟，以为人没了，结果过了一个月后收到二面通知。二面的面试官好像又是另外一个老大，貌似人还在美国，在AMD，苹果，华为都工作过，很有亲和力的一位老大。之后HR面，然后过一段时间HR发offer并找你谈薪资。 

 （4）芯原：包括“三轮技术面+HR面+口语测试+总裁面试”， 

 第一个面试官是负责上海后端部门的老大，很年轻也很有亲和力，第二三轮就都是成都这边的老大和工程师了。英语面试，小姐姐就问一个日常简单的问题，比如“如何看待压力”，然后简单从正反两个方面回答就好。终面是总裁面，总裁就问一个问题“为什么我们只做产品”，答案会在宣讲会的时候提及的。 

 （5）AMD，Cadence等外企： 

 因为外企的面试比较特别，就直接归为一类说吧。外企主要是技术面，根据你的笔试成绩和简历情况，会有不同的部门来分别面试你，比如面AMD的时候，就有GPU部门负责综合的团队和专门负责APR的团队分别面试。通过的话HR直接发offer，没有HR面试。 2、准备内容 

 面试前的准备工作，其实是对自己简历的复盘和预演。
 
 面试官对应聘者的考察是基于公司、所在部门和应聘者简历做出的。
 
 这句话的详细阐述是，面试官会根据公司的招聘要求考察应聘者的基本能力，根据招聘进的部门需要的具体技术要求详细考察应聘者是否满足要求，根据应聘者提供的简历核实应聘者是否具有简历上所写的能力，并考察简历上的内容是否有夸大的可能性。对于考察简历上的内容是否有夸大的可能性，一般采用的方式是深挖简历中提出能力或项目经历的细节，从具体技术要点的问答过程中了解应聘者的掌握程度。
 
 了解了面试考察的目的和内容，我们就应该从自己的简历出发，对于简历中展示的主要技能、主修课程、项目经历、论文与专利、竞赛奖项、实习经历等可能被询问深挖的内容做充分的准备。 

 

 3、面试技巧 

 

 （1）如果是线下面试，有的面试官会把你做的笔试题拿出来问你，特别是问没有做对的题，所以强烈建议大家面试前把自己做错的笔试题好好查一下，如果能在面试的时候改对会给面试官一个很好的印象！ （2）和技术官打交道的时候，被问到自己很熟的知识点就多说一点，让自己锋芒毕露。而被问到不熟悉的点就不要强行装下去了，先跟面试官提前认个怂实话实说，可以先表示个歉意然后说自己确实没有接触过，或者只接触了一点点，面试官都会表示理解的。和这种技术大牛打交道一定要真诚！ 

 （3）如果面试官问你愿不愿意调岗，愿不愿意去xx城市，这个时候要好好考虑了，因为你说愿意的话能提高你拿offer概率，但是一定要问清楚调到什么岗位和城市，再结合自己能否接受再回答； 

 （4）面试官会问你还有什么问题要问的时候，一定要抓住这个机会去和他深入交流，一般问1到2个就差不多了，问多了耽误他后面面试其他同学的时间。问题的大致方向可以是： 

 a. 公司的环境和氛围，岗位所负责的方向，是否加班等这些你所关心的问题； b. 面试的时候被问到的没有回答上的问题，可以请面试官告诉你答案。一方面表示你对他问的问题很上心，另一方面可以省去自己去找答案所花费的精力时间； c. 可以和他讨论岗位的职业前景以及未来的规划和发展，这也是我最喜欢问这些大牛的问题了，每个人都有每个人的思考和看法，可以对这个行业有更深刻的认识； 

 4、多看面经、多复盘 

 因为各家公司的面试风格不一样，不同岗位的侧重点也不一样，所以很难有一个统一的总结。 因此看各家各岗位的面经是 最方便大家了解自己心仪岗位的考察要点的。 

 讨论区每天都会有非常多大佬发布新鲜出炉的面经，除此之外，我们还为大家开辟了 找面经专栏 ，大家可以轻松针对公司和岗位找到面经合集。 

 牛客网讨论区 ： https://www.nowcoder.com/discuss 面经合集 ： https://www.nowcoder.com/discuss/experience/index 除了看面经，还有就是多累积面试经验。面试得多了、总结得多了，自然也就有感觉了。 

 每场面试下来一定要 注意总结自己在这场面试中遇到了哪些问题，面试官问的问题哪些是我不会的、答得不好的；哪些是我做得好的，应该继续保持下去。
