## 米哈游日语本地化笔试未通过

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-19 ｜ [原文链接](https://www.nowcoder.com/feed/main/detail/7c35b2f383db45f5b498af676074f2cd)

【先说结论】本地化岗位的笔试环节大概率不全看笔试完成度，有较强的随机性。
本来想写面经的，结果面试都没推进到，烂完了。
我很多年前就有高分N1，之后去日本留学，语言学校+本科+硕士一共七年时间，口语和语感都练到了母语级。再叠加我多年的字幕组校对经验和对AI辅助翻译工作的研究，自认为推进到一面还是没问题的，结果折戟笔试。
这笔试题有一定难度，但主要难在考察得很综合，面面俱到有点难。就我个人而言，除了个别特别难的题之外，其实基本都在我的舒适区内。我的笔试分数往低了估也在85-90分这个区间。所以我直接开始准备面试的内容了，没想到等了两周以后居然是这样的结果，很让人不解。
后来我偶然得知一位字幕组的旧友在若干年前也投递了这个岗位，他是日语专业+日语翻译硕士背景，CATTI二级，一样是笔试感觉没什么问题的情况下被刷。他后来进入了另一互联网公司做翻译，水平值得信赖。
这么一看大致就能得出结论了：所谓笔试环节中笔试本身的占比很可能并不高，这轮的本质是综合性的二次筛选，主要看的是你在过了初筛的这个池子里竞争力如何。如果岗位少+同批竞争对手过强很有可能莫名其妙就飞了。
总之就是这么个情况，想劝大家（也是劝我自己）不要过分自省，真实世界里不可控的变量真的很多，牛角尖钻不得。

13.如果猫鼠双方的速度都提升20%的话会对猫鼠双方哪方更有利呢
14.原神每日委托设计测试用例
15.原神要出一个新角色，针对这个角色列出测试点
16.哪些场景适合做自动化测试
17.对于手机游戏来说，哪些问题是兼容性的问题，画面渲染会有什么样的问题
18.自己玩的过程中有遇到过什么比较严重的bug吗
19.比如说煎蛋回血这个问题，本次修复后，你要怎么在后续的版本规避这个问题呢，可能会有牛排回血等类似问题，要怎么避免呢

 3. http1.1 和 http2

 
 头信息压缩： HTTP/2 实现了头信息压缩，由于 HTTP 1.1 协议不带状态，每次请求都必须附上所有信息。所以，请求的很多字段都是重复的，比如 Cookie 和 User Agent ，一模一样的内容，每次请求都必须附带，这会浪费很多带宽，也影响速度。HTTP/2 对这一点做了优化，引入了头信息压缩机制。一方面，头信息使用 gzip 或 compress 压缩后再发送；另一方面，客户端和服务器同时维护一张头信息表「HPACK 算法」，所有字段都会存入这个表，生成一个索引号，以后就不发送同样字段了，只发送索引号，这样就能提高速度了。

 

 
 HPACK 算法的优势

 

 
 首先是在服务器和客户端之间建立哈希表，将用到的字段存放在这张表中，那么在传输的时候对于之前出现过的值，只需要把 索引 (比如0，1，2，...)传给对方即可，对方拿到索引查表就行了。这种 传索引 的方式，可以说让请求头字段得到极大程度的精简和复用。
 
 其次是对于整数和字符串进行 哈夫曼编码 ，哈夫曼编码的原理就是先将所有出现的字符建立一张索引表，然后让出现次数多的字符对应的索引尽可能短，传输的时候也是传输这样的 索引序列 ，可以达到非常高的压缩率。

 

 
 

 
 二进制协议 ：HTTP/2 是一个二进制协议。在 HTTP/1.1 版中， 报文的头信息必须是文本（ASCII 编码）{这个问题被字节一面面试官问过，还答错了，和数据体搞混了。} ，数据体可以是文本，也可以是二进制。HTTP/2 则是一个彻底的二进制协议，头信息和数据体都是二进制，并且统称为"帧"，可以分为头信息帧和数据帧。 帧的概念是它实现多路复用的基础。

 多路复用： 多路复用产生的原因是「HTTP队头阻塞」，而队头阻塞又由「HTTP请求-应答」模式所造成（在同一个 TCP 长连接中，前面的请求没有得到响应，后面的请求就会被阻塞。），后面我们使用了 并发连接 和 域名分片 去解决这个问题，但这并没有真正从 HTTP 本身的层面解决问题，只是增加了 TCP 连接，分摊风险而已。而且这么做也有弊端，多条 TCP 连接会竞争 有限的带宽 ，让真正优先级高的请求不能优先处理。原来Headers + Body的报文格式如今被拆分成了一个个二进制的帧，用 Headers帧 存放头部字段， Data帧 存放请求体数据。分帧之后，服务器看到的不再是一个个完整的 HTTP 请求报文，而是一堆乱序的二进制帧。这些二进制帧不存在先后关系，因此也就不会排队等待，也就没有了 HTTP 的队头阻塞问题。通信双方都可以给对方发送二进制帧，这种二进制帧的 双向传输的序列 ，也叫做流(Stream)。HTTP/2 用流来在一个 TCP 连接上来进行多个数据帧的通信，这就是 多路复用 的概念。

 
 所谓的乱序，指的是不同 ID 的 Stream 是乱序的，但同一个 Stream ID 的帧一定是按顺序传输的。二进制帧到达后对方会将 Stream ID 相同的二进制帧组装成完整的 请求报文 和 响应报文 。当然，在二进制帧当中还有其他的一些字段，实现了 优先级 和 流量控制 等功能

 
 服务器推送： HTTP/2 允许服务器未经请求，主动向客户端发送资源，这叫做服务器推送。在 HTTP/2 当中，服务器已经不再是完全被动地接收请求，响应请求，它也能新建 stream 来给客户端发送消息，当 TCP 连接建立之后，比如浏览器请求一个 HTML 文件，服务器就可以在返回 HTML 的基础上，将 HTML 中引用到的其他资源文件一起返回给客户端，减少客户端的等待。

 
 4. 说说 Vue2 中 computed 的原理

 响应式基础：

 vue是采用 数据劫持结合观察者模式 的方式，通过defineProperty()/Proxy来劫持各个属性的setter，getter，在数据变动时发布消息给订阅者，触发相应的监听回调来渲染视图。

 在Vue中，Dep是一个订阅器，它的作用是收集依赖（watcher）并在数据变化时通知它们进行更新。Dep中的subs存储的是所有依赖该Dep的watcher实例。Watcher是一个观察者，它的作用是当数据变化时，执行相应的回调函数。Watcher中的deps存储的是该watcher实例所依赖的所有Dep实例。Dep.target是一个静态属性，它的值为当前正在计算的watcher实例，该值是在watcher实例计算之前被赋值的。

 回答：

 
 依赖追踪 ：当 computed 属性被访问时，Vue 会记录所有依赖于该 computed 属性的观察者（ Watcher ）。

 缓存策略 ： computed 属性会缓存其计算结果。只有当依赖的数据发生变化时，才会重新计算。这是通过 Watcher 实例的 dirty 属性来控制的。只有当 dirty 为 true 时，才会调用 evaluate 方法进行计算。

 惰性求值 ： computed 属性在首次访问时才会进行计算，之后会根据依赖数据的变化情况决定是否重新计算。

 
 Detail:

 
 使用 Object.defineProperty 劫持数据，使其变为响应式数据。

 创建 Watcher 实例，用于依赖收集和更新通知。

 通过 Dep 实现依赖收集，当依赖数据变化时，触发 computed 属性的重新计算。

## 米哈游 市场境外岗位 面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-08-23 ｜ [原文链接](https://www.nowcoder.com/discuss/391620261110460416)

更新一下面试中的一个重要准备部分：对于海外市场，用户和游戏的了解 

 

 毕竟是应聘境外岗，对于海外的情况一定要有一些了解，我大致准备了以下几个方面： 

 
 

 

 1．明确自己比较了解的海外市场：米哈游的游戏在很多国家和地区皆有发行，比如欧美，日本韩国，东南亚，俄罗斯等。选一到两个自己较为熟悉或者感兴趣的市场进行了解。 

 

 2．准备具体的海外游戏案例：根据自己应聘的岗位，找几款海外游戏，总结一下他们的运营方法等。 

 

 3．准备关于海外用户的资料：根据自己选的海外区域，了解那个区域游戏用户的特征，最好能进行一下用户分析。 

 以上这些准备都是为了能在面试中更好地展示自己的职位匹配度。准备阶段可能还是比较辛苦的，但是值得！

 这部分其实难度不大，而且春招的笔试和秋招的笔试模式不太一样。秋招的时候是发一套很长的试卷让你几天填完，秋招就是限时三小时笔试了，其实个人而言更喜欢第一种，突然换成第二种还感觉怪怪的呢！春招的笔试感觉难度不大，几道非常经典的概率题加简答题。不过看样子笔试环节难度不大，我在很明显有一道概率题做烂了的情况下还能过，大家稳住心态好好写就可以了！

## 米哈游文案策划面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2020-04-21 ｜ [原文链接](https://www.nowcoder.com/discuss/353156351666888704)

面试的是米哈游的乙女组，我非常喜欢未定这个项目但因为时间问题只能放弃offer。 

 米哈游的面试让我受益匪浅，又想来米哈游牛客面经较少，特此写下面经回馈大众。 

 ========面试体验与反馈======= 

 非常好，面试官会全程引导你。 

 说话时会认真的倾听，面试官会对你的回答做出反馈，是我面过的公司里体验相当好的。 

 面试结束大约半小时收到结果。 

 =======面试全程50分钟============ 

 1.如何写一段200行的剧本，而且能一直吸引玩家的兴趣。
 2.你作品中的主要矛盾是什么？有哪些次要矛盾，如何发起，如何解决。解释一下。
 3.刚才说到起承转合，你解释一下。
 4.对游戏配置有没有了解。
 5.你作品中的一处，你是如何安排画面的。
 6.如何创造吸引人的人设。
 7.实习中主要学到了什么。
 8.你是如何掌握你作品的节奏感。
 9.你遇到的重大挫折
 ==================================
 

 有许多小问题已经无法记忆，只把记得的记录下来。 

 一面结束hr联系说可以发短期实习offer了。但如果长期（可转正）则需要加面一次，因为导师实在不允许，遂只能放弃。 

 =========所需技能=========== 

 总所周知，米哈游的系统策划需要懂得编程等技能。 

 与此相对的，除去文笔外，文案策划也需要又足够懂美术，同时能够懂得游戏配置。 

 米哈游很注重策划的“实践性”，问题会问的很细，而不是大而空的道理。 

 最好是有过相关且成绩不错的游戏作品，且拥有能让面试官瞩目的经验是十分重要的，机会永远是留给有准备的人。 
 

 
 

 米哈游是我非常喜欢和想去的厂，希望秋招能够再次相遇。[比心]
