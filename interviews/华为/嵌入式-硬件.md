一、流程

 
 投递简历 

 机考 （上机编程，约 120 分钟）

 综合测评 （性格测试，无技术难度）

 技术一面 （约 50分钟）

 技术二面 （约 50 分钟）

 主管面 / HR 面 （约 20分钟）

 保温电话 → 报批 → Offer

 
 二、机考：和通用软件岗同一题库

 经验：

 
 输入可能只测部分情况， 提交前一定要过边界 （全 0、超长、重复值）。

 先做简单题快速拿分，把时间留给最后一题。

 题库不算太大， 多刷相似题型 ；不少人前两题就是"刷到过类似的"。

 平时太依赖 IDE 补全的同学要小心：机考时连一个长度判断都要来回改， 练无补全手写 。

 
 三、综合测评：

 性格测评没有技术难度，注意要 保持前后一致 。选项贴近"积极向上、情绪稳定、能完成任务、重视团队协作"。真实作答，别前后矛盾。

 四、技术一面：项目深挖是主战场

 典型流程： 自我介绍 → 简历挖项目 → 基础八股 → 手撕代码 。八股反而问得很基础，真正的时间和分数都在项目上。

 
 栈 vs 堆的区别；内存泄漏如何避免

 const int *p 与 int * const p 的区别

 C 与 C++ 的区别，C++11 用得多吗

 TCP / UDP 区别， 粘包拆包 怎么理解

 用过什么数据结构；哈希表键值冲突怎么处理

 树的 BFS 和 DFS

 手撕：快速选择排序、移除元素、无重复子串

 
 一个项目深挖 （串口用 DMA 接收、降低 CPU 占用）：

 
 为什么用 DMA？不用串口中断行不行？

 DMA 接收不定长数据，怎么判断一帧结束？

 空闲中断触发时，DMA 还在继续搬数据吗？

 读取接收长度时新数据又进来了，怎么办？

 如果连续来了两帧，上一帧还没处理完，会不会覆盖？

 环形缓冲区由中断写、任务读，怎么保证并发安全？

 
 五、技术二面：启动流程、RTOS、总线

 二面继续深挖项目，同时压更底层的技术点。

 ① 启动流程 / 链接脚本 

 
 .data 为什么要从 Flash 复制到 RAM？

 .bss 为什么只需清零、不用存初始值？

 启动文件里的中断向量表放在哪里？

 程序能不能直接在 RAM 里运行？

 改了链接脚本，最容易出什么问题？

 
 ② RTOS（FreeRTOS 方向） 

 
 互斥量和二值信号量有什么区别？为什么互斥量一般有优先级继承、信号量没有？

 优先级反转是怎么发生的？

 中断里为什么不能直接调用普通队列发送函数？

 任务栈溢出有哪些表现？怎么定位？

 一个高优先级任务不阻塞，会发生什么？

 
 ③ 总线协议 

 
 I2C 为什么要用开漏输出 + 上拉电阻？总线上两设备同时发不同电平会怎样？

 SDA 被从机一直拉低，主机怎么恢复？

 SPI 和 I2C 的对比与适用场景

 I2C 通信画图：先传什么、为什么这样设计、应答位作用

 I2C 死锁问题；Linux 下接入十几个传感器怎么处理（设备树角度）

 flash / ROM / RAM / EEPROM 的区别与应用

 
 手撕 ：快速选择排序

 二面经验 ：提前准备 1–2 个能深入讲的技术难点案例；遇到不会的先说思路、再补细节，比硬编更保命。

 六、主管面 / HR 面：看的是"能不能融进来"

 
 聊职业规划、城市意向、团队合作。

 了解华为的文化吗？能接受高强度加班吗？

 项目/实习里最难的问题是什么，怎么解决的？

 最大的一次挫折是什么，怎么调整的？

 和团队有分歧怎么办？你的想法被别人否定过吗？

 为什么想进华为？为什么选这个城市（东莞/珠三角等）？

## 嵌入式手撕必考20题汇总（建议收藏）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-13 ｜ [原文链接](https://www.nowcoder.com/discuss/928680586456100864)

先聊聊：手撕代码到底有多重要？

 很多同学以为嵌入式面试就是背八股：背背volatile、背背中断流程、背背通信协议就完事了。 大错特错。 

 现在的嵌入式大厂面试（华为、字节、大疆、宁德、比亚迪、小米、海康、TP-Link等等），几乎无一例外都会安排 手撕代码环节 。有的公司甚至手撕挂了，八股答得再漂亮也不要。原因很简单：

 八股可以背，代码骗不了人 。手撕环节考的是你真实的编码功底、思路清晰度和工程习惯，这是装不出来的。

 嵌入式岗位对代码严谨性要求极高 。一个位操作写错、一个空指针没判，在真实产品里可能就是设备死机、批量返工。面试官通过手撕，一眼就能看出你有没有“产品级”的编码意识。

 手撕是分层最明显的环节 。八股大家分数都差不多，真正拉开差距、决定你是SP还是普通offer的，往往就是手撕这一关。

 而且嵌入式手撕有自己的鲜明特点： 不太考复杂算法 ，重点考察C语言基本功、位运算、内存操作、字符串处理和链表能力，题目经典、重复率极高。也就是说， 这是最容易通过提前准备拿满分的环节 。

 下面这20道题，是我结合各大厂嵌入式面经整理的高频必考题。建议每道题都 亲手写一遍、能白板/腾讯会议共享屏幕下一遍写对 ，不要只看。

 嵌入式大厂面经总结基础八股文专栏：（支持简历辅导，答疑）300K+同学学习，2300+人订阅，包括常考八股文以及大厂面经

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 必考20题清单

 【位运算类】——嵌入式特色，出场率最高 

 判断一个整数是2的整数次幂

 统计一个整数的二进制表示中1的个数

 置位、清零、翻转、判断某一位（寄存器位操作四件套）

 求两个整数的平均值（要求不溢出）

 不用临时变量交换两个整数

 求一个数的绝对值（不允许分支判断）

 【字符串/内存类】——基本功照妖镜 

 手写strlen（考虑const、返回size_t、边界处理）

 手写strcpy / memcpy（重点：内存重叠问题，memmove的实现）

 手写strcmp / strstr

 字符串转整数atoi（处理正负号、非法输入、溢出）

 手写内存置零memset

 判断字符串是否为回文

 【C语言关键字/语法类】——结合八股一起考 

 用宏定义求结构体成员的偏移量（offsetof）和容器首地址（container_of）

 定义一个宏，求两个数的最大值/最小值，并说明宏的坑（副作用、括号）

 用宏实现位域操作：将指定位置1/清0的带参宏

 函数指针的声明与应用：用函数指针实现一个简单的回调机制

 【数据结构类】——链表是重灾区 

 单链表的反转（手撕率第一名级别）

 判断链表是否有环（快慢指针）

 找到两个单链表的相交节点

 链表的中间节点 / 删除链表倒数第N个节点

## 嵌入式大厂招聘到底要什么？别再用“会点灯、做过小车”去投华为大疆了

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-31 ｜ [原文链接](https://www.nowcoder.com/discuss/923841950229241856)

简历写得很满——C 语言、STM32、FreeRTOS、Linux 驱动、UART/SPI/I2C、做过智能小车、参加过电赛。

 结果一面过了，二面被问：

 “你这个项目，数据从串口进来，到任务处理，再到掉电保存，整条链路怎么走？”

 当场卡住。

 说实话，这不是个例。 大厂嵌入式招聘的要求，早就不是“你会不会用 HAL 库”，而是你能不能证明自己具备工程化交付能力。 

 下面这篇，我把近几年公开岗位描述、牛客面经、提前批准备帖里反复出现的共性要求，整理成一套 能直接对照简历和复习计划的标准 。

 先说结论：大厂要的不是“会嵌入式”，而是这 5 件事

 如果你现在只有 30 秒，记住下面这张表：

 C/C++ 功底 

 会写 if/for

 能讲清内存、指针、并发边界

 系统能力 

 跑通过 FreeRTOS

 能设计任务、处理同步、解释实时性

 硬件协同 

 会调 UART/SPI

 能解释中断、DMA、时序、总线故障

 项目深度 

 功能能演示

 能讲架构、排障、量产、可靠性

 岗位匹配 

 一份简历海投

 MCU 岗、Linux 驱动岗、车载岗要求完全不同

 一句话：大厂嵌入式招聘，筛的是“你能不能独立扛模块 + 能不能讲清整条链路 + 出了问题会不会查”。

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 

 

 

 

 一、岗位先分清楚：同样是“嵌入式”，要求差很多

 很多人投岗最大的误区，是把所有嵌入式岗位当成一类。

 实际上，大厂至少分 3 条主线：

 1. MCU / RTOS 产品岗（最常见）

 典型公司/方向： 华为嵌入式软件、海康/大华固件、大疆部分底层岗、汇川、安克、拓竹、影石等。

 核心要求： 

 C 语言必须扎实

 STM32/ARM MCU 外设机制清楚

 FreeRTOS / RT-Thread 等 RTOS 能讲调度与同步

 通信协议不是“会调库”，而是能排障

 项目要有完整闭环：采集、通信、显示、存储、升级、看门狗

 简历上写什么算数： 

 Bootloader + OTA + 掉电恢复

 Modbus/CAN/以太网通信

 多任务架构 + 日志 + 异常定位

 低功耗、量产、可靠性设计

 写什么基本不够： 

 只会点灯、循迹小车、超声波避障

 只会改例程，讲不清为什么这样设计

 项目只有功能，没有架构和排障故事

 2. Linux 驱动 / BSP 岗

 典型公司/方向： 华为 BSP、小米 Linux、龙旗、诺瓦星云、部分手机厂商底层团队。

 核心要求： 

 C 功底 + 一定 Linux 用户态/内核态认知

 设备树、platform 驱动、字符设备框架

 中断上下半部、阻塞 IO、mmap

 probe 失败、oops、死锁、性能问题的排查思路

 Bootloader → kernel → dtb → rootfs 启动链路

 简历上写什么算数： 

 写过或改过字符设备驱动

 能讲设备从 DTS 到 probe 成功的路径

 做过内核/用户态通信（ioctl、设备节点、select/epoll）

 有实际 bring-up 或板级适配经验

 写什么不够： 

 只会装 Ubuntu、跑过几个命令

 只会编译别人的驱动模块

 简历写“熟悉 Linux”，但说不清进程线程区别

 3. 车载 / 智驾 / 工业控制岗

 典型公司/方向： 比亚迪、极氪、特斯拉相关供应链、汇川、中兴通信底层、部分机器人公司。

 核心要求： 

 C/C++ 都可能考，C++ 岗会更看重 OOP、智能指针、线程安全

 CAN/CAN FD、UDS 诊断、通信可靠性

 功能安全、诊断、冗余、异常恢复概念

 实时性、稳定性、长期运行能力

 项目要能讲系统级设计，不是单个模块 demo

 二、硬技能要求：大厂嵌入式校招/社招的“通用底盘”

 不管你去哪家，下面这几块基本是 底线 ，不是加分项。

 1. C 语言：不是会写，而是能扛追问

 大厂一面几乎必问：

 指针和数组区别

 const / volatile / static 的真实场景

 栈、堆、全局区、内存对齐

 大小端、位操作、结构体对齐

 函数指针、回调、状态机实现

 到什么程度算够： 

 能把一段嵌入式代码里的内存行为讲清楚

 能解释为什么 ISR 里不能做的事

 能根据场景判断用栈还是堆

 到什么程度不够： 

 只会背八股定义

 看到指针题就慌

 项目里全是 HAL 封装，说不清底层发生了什么

 2. MCU 外设：不是“点亮”，而是“理解机制”

 STM32 方向高频考点：

 启动流程：上电 → 时钟 → VTOR → main

 GPIO、EXTI、NVIC 优先级

 UART/SPI/I2C 轮询、中断、DMA 的差异

 DMA + Cache 一致性问题（H7 尤其爱问）

 看门狗、HardFault、复位原因分析

 面试官真正想问的是： 

 你为什么这里用中断，不用轮询？

 你为什么这里用 DMA？

 如果通信偶发错包，你怎么查？

 3. RTOS：应届生的重要分水岭

 近几年牛客讨论里一个很一致的判断：

 不懂 RTOS ：岗位选择明显受限

 只会创建任务 ：刚及格

 能讲清调度、同步、栈、优先级反转 ：有培养价值

 必须掌握：

 任务、优先级、时间片

 信号量、互斥量、队列、事件组

 临界区、关中断、FromISR API 边界

 栈溢出、死锁、优先级反转、饥饿

 典型追问： 

 为什么这里用队列，不用全局变量？

 两个任务抢 I2C 总线，你怎么设计？

 OTA 擦 Flash 时，别的任务怎么不被拖死？

 4. 通信协议：会调接口不够，要能排障

 大厂不会满足于“我会用 Modbus/UART/SPI/I2C/CAN”。

 他们更关心：

 帧格式、超时、重试、校验

 粘包、半包、错包怎么处理

 总线被拉死怎么恢复

 多设备组网时的冲突和终端电阻

 从物理层到协议层到应用层的完整链路

 这正好对应很多同学的短板： 会通信，但不会查“为什么偶发”。

 5. Linux：不是所有岗都要，但会是明显分水岭

 如果你目标是华为 BSP、小米底层、驱动相关岗位，Linux 不是“加分”，是“门槛”。

 至少要会：

 进程/线程/内存基本概念

 文件系统、设备节点、驱动框架

 设备树、platform driver、probe 流程

 用户态和内核态怎么交互

 日志、strace、/proc、/sys 的基本使用

 三、项目要求：这才是大厂真正用来筛人的

 很多 985/211 同学挂掉，不是学校不好，是 项目太像课程作业 。

 什么叫“不够用的项目”

 智能小车循迹避障

 单纯点灯、温湿度显示

 跟完例程改两行参数

 功能能跑，但说不清架构

 简历写“负责整体开发”，一问细节全是队友做的

 这些不是没价值，而是 在 2025–2026 年的大厂校招里，竞争力已经明显偏弱 。

 什么叫“能打动面试官的项目”

 至少满足 4 条：

 有完整闭环不是只有采集，还有通信、存储、显示、升级、异常处理中的至少 2–3 项。

 有架构分层能讲清 APP / 协议层 / BSP / 驱动 / 公共模块怎么分。

 有工程问题你遇到过真实 bug，并且讲得出定位过程。

 有可靠性设计看门狗、掉电保存、OTA 回滚、日志、异常恢复，至少占一两项。

 举例（比智能小车更能打）： 

 STM32H7 双核 + Bootloader + 双分区 OTA + EEPROM 元数据

 Modbus 从站 + 参数掉电保存 + 以太网远程升级

 FreeRTOS 多任务采集/通信/显示 + 总线冲突排查

 Linux 字符设备驱动 + 用户态测试程序 + probe 排障

 技术栈是否和岗位匹配

 精通 C、精通 Linux、精通 RTOS

 项目描述只有功能列表，没有个人贡献

 2. 笔试关

 C 语言基础题

 数据结构/simple coding（链表、字符串、排序）

 部分公司有专业卷：驱动、RTOS、硬件基础

 准备建议： 

 不要只刷 LeetCode 难题，嵌入式笔试很多是“中等题 + 基础题”

 2. 项目描述用“四句话模板”

 每个项目建议写成：

## 22届北邮通信本华为OD三年嵌入式，想转AI Infra网络HPC方向可行吗？

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-26 ｜ [原文链接](https://www.nowcoder.com/discuss/922140694838251520)

网友提问： 

 YT你好，我是22届北邮通信工程本科，毕业后在家考研失败后进入了华为od，薪资年包23左右，到现在总共工作三年，主要是做大型linux嵌入式的通信设备，计算机功底还算扎实，相关性高的岗位的技术面基本都能过。（涨幅大概在30%左右的offer还是能拿到一些的，再高就拿不到了）

 我现在想咨询一下我现在的学历和经历能否符合AI infra的硬性要求？市场行情是否刚需硕士或者要有论文之类的，自学做项目可行吗？

 我想朝ai infra的网络或者hpc方向转，因为我感觉这个方向一方面是薪资水平比较高，一方面是比较有前景，而且技术相对通用，做老本行通信设备，基本就只有那几家厂商在做，闭门造车的东西还是有点多

 Yt回复： 

 一、你的背景：北邮通信本 + 华为OD三年，面试机会不会少 

 22届北邮通信工程本科，毕业后考研二战失败，进入华为OD，做大型Linux通信设备开发，三年工作经验。

 首先，你这个背景投递出去，肯定有知名企业面试机会——不管是校招还是社招。北邮在通信/网络领域的认可度很高，加上华为三年的实战经验，你的简历不会缺面试。

 华为OD年包23万左右，三年后跳槽涨幅30%，总包到30万。这个涨幅是正常的业界水平（20%-30%是合理区间），30万的总包也不低。

 你现在的核心问题是：想从通信设备转向AI Infra，学历够不够？项目怎么做？

 二、AI Infra的硬性要求是什么？ 

 AI Infra不是一个“统一的岗位”，它是很多细分方向的集合。

 AI Infra的几大方向包括：

 网络侧：RDMA、DPDK、eBPF、XDP、高性能网络协议

 存储侧：SPDK、分布式文件系统、高性能存储

 计算侧：CUDA、GPU调度、异构计算

 你问“学历和经历是否符合硬性要求”，我直接回答：没有统一的硬性要求。

 不同的AI Infra团队，要求不一样。有些团队确实偏爱硕士/博士，但也有一些团队更看重实战经验和网络功底。你的北邮通信本 + 华为三年通信设备开发经验，在“网络侧”的AI Infra方向是有竞争力的。

 三、你的优势在哪？ 

 你在华为OD做的是大型Linux通信设备开发，计算机功底扎实。

 通信设备和AI Infra的网络侧是高度相关的：

 你懂的TCP/IP协议栈、网络编程、高性能网络

 你熟悉Linux内核网络子系统的部分逻辑

 你对高并发、低延迟有实际工程经验

 这些东西，跟你去搞AI Infra的网络优化方向，是相通的。AI大模型的训练和推理，对网络带宽和延迟要求极高。处理过大型通信设备网络问题的人，去搞AI集群的网络调优，其实底子很接近。

 四、你需要补的技术栈 

 方向大于努力，你先选定方向，再针对性地补充知识。

 你目前做通信设备，对网络开发感兴趣，但通信设备本身的市场确实比较窄（主要是华为、新华三、中兴等少数几家）。如果你想往AI Infra方向走，建议你了解以下四个方向：

 DPDK：高性能数据包处理，绕过内核协议栈，直接操作网卡

 RDMA：远程直接内存访问，AI集群中用于GPU之间的高速通信

 XDP/eBPF：Linux内核的高性能网络包处理和可编程能力

 把这些技术中的一个或多个落地到项目中（比如用DPDK做一个高性能转发程序，或用eBPF做网络监控工具），写进简历，你面试时的广度会完全不同。

 五、关于HPC和薪资 

 你提到HPC（高性能计算）一方面薪资高、一方面有前景，而且技术相通。

 HPC确实薪资不错，但它更像一个技术手段，而不是一个产品方向。HPC通常是为某个具体项目服务的，比如气象模拟、基因测序、AI训练……它不会像路由器、防火墙那样作为单独的产品卖。HPC不一定是你简历里最直接的落脚点。

 相比之下，网络侧的东西更具体——DPDK、RDMA、eBPF、XDP……这些技术是你能实际落地、能演示、能写进简历的。你现在要做的，是在简历里体现出你懂这些方向、做过相关实践。你的通信背景+网络技术知识，是AI Infra团队很需要的组合。

 六、总结 

 北邮通信本 + 华为OD三年，你的面试机会不会少。

 AI Infra没有统一的学历门槛。网络侧的AI Infra方向，你的背景是匹配的。

 通信设备和AI Infra网络侧是相通的，你的经验不是白费。

 补DPDK、RDMA、XDP、eBPF，做一两个相关项目，是你的切入点。

 不要等“完全准备好”再投。先学起来，边学边投，你的底子已经够了。

## 嵌入式实习，一定要进大厂吗？

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-05-29 ｜ [原文链接](https://www.nowcoder.com/discuss/889802938934173696)

简历上写着「暑期实习」，评论区却清一色在问：没进华为、大疆、蔚来，这段经历算不算废了？更狠一点的说法是——嵌入式不进大厂，秋招基本没戏。

 这话听着吓人，但经不起拆开看。真正该问的不是「公司大不大」，而是：这段实习，能不能让你在面试里讲清楚自己做过什么。

 先给结论

 嵌入式实习不必进大厂，但实习不能空。

 大厂实习是加分项，不是入场券。一份能独立负责模块、能讲清技术细节、能对应岗位方向的小厂实习，永远比大厂边缘打杂、面试一问三不知要强。反过来，大厂核心业务岗、带教规范、能接触量产链路和主流技术栈，对秋招背书确实更硬。

 没有绝对的去或不去，只有：你的背景、可选 offer、秋招目标，和岗位含金量是否匹配。

 为什么大家会迷信「大厂实习」

 嵌入式和纯互联网后端不太一样：岗位分散在车、机器人、工控、安防、芯片平台、消费电子里，JD 名字也不统一——固件、BSP、驱动、车载软件、终端软件，搜「嵌入式工程师」往往漏掉一半机会。

 在这种环境下，大厂标签确实省事：

 流程规范：代码评审、测试设备、文档体系，能建立工程化习惯

 技术栈主流：常见 SoC、RTOS、Linux 驱动、通信协议，和校招考点更接近

 简历过筛：HR 和面试官都认识名字，背书成本低

 视野：参与过完整产品链路，知道「量产」意味着什么，而不只是点亮 LED

 如果你目标是三年后做架构师、技术专家，或者秋招就想锁死头部平台，有核心业务的大厂实习，优先级通常更高。

 但「大厂」三个字，掩盖不了很多坑。

 嵌入式大厂面试题，基础八股文资料合集整理：

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 （20+大厂嵌入式经典面试八股文资料）

 大厂实习，不等于好实习

 嵌入式在大厂里经常是这样分工的：

 你只改某条驱动的某个分支，导师不让碰上下游

 岗位名义是嵌入式，实际做脚本、测试工具、文档整理

 部门边缘，接触不到板子、协议、调试、量产问题

 秋招面试时，面试官问的不是「你在哪实习」，而是：

 你负责哪一块？边界在哪？

 出了问题怎么定位？用过哪些工具？

 和中断、DMA、内存、调度、协议栈相关的细节，你能讲到哪一层？

 大厂边缘打杂 + 讲不清技术细节，不如小厂核心项目 + 能复盘一条完整链路。

 行业里反复出现的判断标准就这几条，和公司规模无关：

 正规实习协议、实习证明、合理薪资和离职流程

 有 mentor，有学习计划，不是扔个任务就不管

 能碰真实业务，能独立负责模块，不是长期拧螺丝

 技术栈和你秋招方向一致（MCU/RTOS、Linux 驱动、BSP、车载、工控等）

 公司业务稳定，不是随时停摆的空壳

 满足这些，小厂照样能写出硬核简历；一条都不占，大厂 title 也救不了。

 小厂实习，什么时候反而更值

 嵌入式在小公司有个很现实的优点：活多、链短、责任大。

 半年里你可能同时碰到：Bootloader、外设驱动、RTOS 任务划分、联调通信、配合硬件改板、写测试报告。没人替你兜底时，Google + 数据手册 + 示波器/逻辑分析仪，会变成真本事。

 这类经历特别适合：

 学校项目偏 demo，缺「从 0 到能跑、能测、能讲」的完整故事

 你想走「全栈嵌入式」路线，软硬件都要能聊

 大厂只给到边缘岗，而小厂能让你扛主模块

 很多面试官心里清楚：大公司看深度，小公司看广度，最后能成事的是能把深度和广度接上的人。 先在小厂把一条产品线走通，再跳大厂补规范和平台视野，是常见且有效的路径。

 但要注意：不是「小厂」两个字就有含金量。无意义拧螺丝的小厂，不如在家沉下心做两个能讲透的项目，冲秋招。

 按阶段怎么选，比纠结「大厂」更实用

 如果你基础还薄（C 指针、内存布局、中断/DMA、常见协议都说不利索）

 

 优先保证：能进正规公司、有人带、能碰板子和真实问题。大厂核心业务当然好；若只有边缘岗，别为了 title 浪费一个暑假。

 如果你已有 1～2 个完整项目，差的是背书和规范

 

 可以花 1～2 个月主攻大厂暑期；末期仍 0 offer，再选优质小厂保底，比空白强太多。

 如果你秋招目标就是某几家头部

 

 大厂核心业务实习的加成最大；但入职前若大厂 offer 是打杂、小厂 offer 是核心模块，不要为了「大厂」毁了一段能写进简历的故事——已签小厂未报到、大厂发来核心业务 offer，再去大厂，这很合理。

 如果你更想去工控、安防、机器人、汽车供应链等垂直赛道

 

 「大厂」定义要变：汇川、海康、大华、速腾聚创、地平线……在各自赛道里就是「大厂」。投岗时别只搜「嵌入式工程师」，要加上固件、BSP、驱动、车载软件、设备软件等关键词。

 比公司规模更重要的三件事

 第一，岗位是不是「真嵌入式」。

 

 校招越来越看重工程型能力：Linux 驱动、RTOS、BSP、启动流程、协议栈、量产调试。纯 CRUD、纯测试脚本、长期远离硬件的岗位，对嵌入式秋招帮助有限。

 第二，实习结束你能留下什么。

 

 理想状态是：能画一张你负责模块的架构图；能讲 2～3 个你亲自解决的 bug；能说明你的代码如何进版本、如何测试、如何交付。这些比 logo 更能打。

 第三，实习是为秋招服务的，不是为虚荣心服务的。

 

 实习是跳板：转正 HC、mentor 评价、项目深度、技术栈匹配度，都比「朋友圈晒工牌」实在。

 常见误区，顺手拆一下

 没大厂实习，秋招没戏

 没硬核经历才没戏；小厂核心实习 + 能讲透，照样能打

 大厂 title 等于技术强

 边缘岗 + 说不出细节，面试官会快速降档

 小厂=乱、学不到东西

 业务核心的小厂，成长速度可以非常快

 实习只为刷简历一行字

 一行字撑不过三轮技术面的追问

 嵌入式只有互联网大厂才算大厂

 车、机器人、工控、安防、芯片生态里都有头部平台

 最后一句实话

 嵌入式实习不必迷信大厂，但不能没有质量。

 大厂给的是规范、资源和背书；小厂给的是责任、广度和完整项目经验。你真正要攒的是：能在面试里站得住脚的技术故事。

 若你手里是大厂核心业务 offer，去，别犹豫。若只有大厂边缘岗，而另一边能让你独立扛模块、技术栈又对口——选能让你秋招时讲得下去的那一段。

 公司大小是标签，你做过什么、学到什么、能证明什么，才是嵌入式这条路上最硬的通行证。

个人情况：23年末9软工毕业，排名80%~90%，当初毕业连点击就送的迪子都进不去。22年11月开始在现在的公司实习，毕业当月转正，主要做车载功放MCU侧的嵌入式开发。在职期间主要跟了两个项目，最近第二个项目开始收尾，老板对我的下一步安排有点离谱，再加上公司一直在走下坡，遂开始找下家

 

 备战心得：

 联系hr之后会给牛客的刷题链接，牛客的稍微过一遍就行，大部分都是字符串处理相关的问题。主要还是得去看真题，某“专业开发者社区”上有几个人的付费专栏给按ABC卷分好的，具体就不多说了，避免打广告，看别的面经里有提到有的hr会免费给类似的原题。面试算法题要比机试简单，甚至达不到机试100分题的难度（应该还是取决于面试官对面试者能力的界定吧，我看有的人的面试算法题不简单）。另外，找个靠谱的HR真的很重要，我运气挺好，在BOSS直聘里跟我打招呼的几十个HR里随便选了一个就非常靠谱，整个过程一直在鼓励我，给的各种建议起了很大作用，各种流程也是跟的非常紧，往往在出正式反馈前就已经通知我结果了。我的HR在牛客好像没有号，就不@出来夸了。相比于我，我的一个二战失败同学找的HR就没那么靠谱，机试安排好了又说推迟，之后就没信了，就挺离谱。

 

 面试过程：

 4.8 周一收到机考链接

 机考链接一周内有效，4月14号开始机考，C卷里的三道题，具体哪三道忘了，就记得前两道没考到啥具体的算法，主要看能不能理解题目并且抓住问题点，更像是脑筋急转弯一点；第三道运气比较好，看到原题了，图像物体边界(好像叫这个标题)，用到并查集合并。最终得分400。

 

 4.15 性格测试

 有一说一，这个性格测试有的题还挺恶心的，有时候三个选项都是正向的，非得选个最不符合的，还得注意跟之前选的不能矛盾，看别的面经提到还真在这一关挂人。

 

 4.16 HR帮选部门

 这个部门我没自己选，就说了城市首先考虑北京，其他城市可接受。主要原因是HR了解我现在的薪资(7.5k)后觉得正常情况下我要求的最低薪资(13k)通不过审批，因为卡涨幅30%，只能走可以特批薪资的部门，最终匹配到2012实验室下某部门，具体工作与操作系统相关。

 

 4.17 资格面试+业务交流；

 HR面就正常问了问为什么要换工作，为什么薪资要这个数，反问了下部门。

 这个业务交流一般情况下是没有的，当时问HR，HR也说不知道是干什么的，反正就是业务专家想提前聊聊。当时想着反正也就聊聊，什么也没准备就进会议了，进去之后业务专家就简历里写的项目简单问了问，由于我在项目中提到有用DMA优化数据存取，就这个点专门问了下，问是否熟悉IOMMU(应该是这个缩写)，我说没接触过，然后专家又说MMU应该知道吧，当时没反应过来，回答“概念有点模糊了”，之后业务专家开始介绍IOMMU，提到与DMA安全有关，这时候我才反应过来MMU是指什么，原来在问操作系统的东西。介绍完之后让反问，于是又反问了下部门具体工作，总之内容和HR面没太大区别。

 4.19晚 技术1面

 1面的面试官态度挺好，上来先是简单介绍了下自己，然后开始正式面试。首先自我介绍，然后介绍下项目经历，之后就项目经历提问，又问到了DMA，因为这算是我项目里少数能跟操作系统有关系的地方。没有八股环节，直接开始手撕代码，题目非常简单，将100个64bit数按位依次生成800个8bit数，其实就是把数组a[100][64]中的数据按要求转到b[800][8]中，就是普通的数组操作，双重循环解决。不过当时太紧张，设置的变量累加时机总是不太对，最后差不多40min才写出来。

 

 4.20上午 技术2面

 2面的面试官也挺不错，前面的流程还是自我介绍、项目经历、就项目经历提问。二面的面试官应该就不是所面部门的员工了，问的问题比较宽泛，类似于“你在项目里遇到过什么困难”、“你觉得解决这些困难之后对你接下来要参与的工作有什么积极影响”。二面有八股环节，问的是C++内存管理方面的内容。这里我确实比较菜，直接背的牛客面试宝典(内容有误，面试宝典评论区有指出，但我当时没看，复盘的时候才看到)，然后回答完之后面试官一脸玩味的看着我，说看来你对C++不太熟啊，那我们写道代码题吧，就这么稀里糊涂地进入手撕代码环节。代码题目是力扣原题 面试题 17.14. 最小K个数 ，难度也比较低，还没毕业的时候我还刷到过，不过当时就想着会暴力得了，堆就不看了，反正平时工作用不到，没想到在这碰见了，所以说平时题解还是得好好看看。当时我一看这么简单，直接sort()拿下，面试官一看我要用sort直接叫停，让讲下思路，然后我说准备直接排序解决，面试官直接就提出玩意给的数据很多怎么办，你再优化下，之后几分钟想了下实在不会，只能坦白刷到过，知道要用堆，但不会。后面面试官自己想了下，提示可以用一种插入时就排序的数据结构，回答用map，之后让我给出思路，确认思路正确之后由于时间不够，面试官让写了一个简化版代码，相当于把题目简化成一个数只会出现一次，不用再考虑map的value了。写完之后进入反问环节，啥也没问，直接结束。

 

 4.22 

 HR通知一面通过，二面结果说不准(这里感觉是HR顾及我心态没明说，说的是可能挂了，也可能是一二面结果不一样，不过我觉得二面表现不太像能过的样子)，需要加面。

 联发科是我投的第一家，应该算是提前批，笔试是选择和编程，编程限制c语言，是一道链表题，具体忘记了，因为我平时用c++刷题，所以编程题没有写出来，但是收到面试通知，面试时候其余都好，手撕代码时候出现问题，面试官要求用c写，前面也说了，我是用c++刷题，所以那一道手撕寄了，后来也没收到二面通知，但是无所谓，本来也不打算去合肥，拿来试手的。

 所得到的收获

 这次面试收获挺多的，c语言不太熟练是我的锅，既然选择了嵌入式方向，因为大部分的公司嵌入式都是偏向底层开发，c语言必须熟练， 像常见的字符串和链表题，必须要用c语言熟练的手撕出来 ，所以在后面一段时间，我又开始练c语言。

 英伟达和英特尔

 这两家公司在笔试是就放弃了，英伟达的笔试是全英文，题目确实挺新颖的，第一次笔试没过，后面收到了第二次笔试，但是看到群里那么多大佬和那么少的hc，所以就放弃了，英特尔的笔试，看到卷子后面两三道编程题都是限制c语言和python，就交白卷放弃了，当时c语言还是不熟练，这里我想吐槽一下，为何允许python，就不能用c++。

 紫光展锐和小米

 这次秋招， 体验最差 的两家公司。
 先说紫光展锐 ，我投的比较晚，笔试特别简单，我做完后，估计90分没有问题，后面一直没收到通知，过了一个月给我发了感谢信，最后问了才知道，南京嵌入式没有hc了，tmd，没有hc你发什么笔试，浪费时间。
 再说小米 ，小米今年秋招真的是乱，我在提前批时候就投了小米， 岗位是相机底层驱动开发工程师 ，但是一直没有收到面试，我想这也正常，可能达不到提前批的资格，于是等到秋招，我收到笔试链接，小米的笔试真的简单，提前40分钟交卷的，也是唯一一场，我的编程全ac的，但是就是没有收到面试通知，当时我是用内推码(内推码真的没有用)，我的那个内推人推了很多，单单是我这个小众岗位就有18个人，他那边有个网页可以查看每个岗位所有内推人员的进度，直到10月份，投递 相机底层驱动开发工程师 的所有人包括提前批的进度最快在一面，当时其他部门正式批都基本面完了，国庆节后打电话通知我面试，拒了面试。

 所得到的收获

 最好准备一个PPT，有时面试准备一个PPT介绍你的项目，是个加分项，同时PPT可以防止你由于面试紧张导致的忘记项目细节。
多练习输入输出，不要让他影响你的做题时间。

思来想去，还是想写一篇帖子，给自己的秋招做一个总结。

 因为自己本科通信专业，研究生也一直做通信相关的项目，也写过一些FGPA、ARM等硬件开发，因此把意向职位锁定在了嵌入式开发和通信算法/通信软件两类岗位。 

 
 

 一开始非常不顺，经历了各种简历挂，以及提前批面试十连挂，后来面通信相关的岗位才逐渐顺了一点，拿了几个offer，可见岗位匹配多重要。

 最应该感谢的还是华为，当时没报太大希望投的，想着进不去这个部门我就不去华为了，没想到就进来了，满意的平台和满意的薪资，也算给秋招画上了完美的句号。 

 
 

 这一路走来说不上多辛苦，庆幸心里很清楚，是因为还有那么一点在乎，才执着这段旅途。在大概一年半之前就在担忧和规划毕业后的打算了，看着好多师兄都转码去了bat大厂，男朋友也一直劝我去银行，当时有认真的考虑转学计算机还是坚持通信，但从始至终我就好喜欢通信，傅里叶变换、OFDM、polar码，我觉得都好美妙。因此我坚持了自己的初心，事实证明我也赌对了，通信岗的薪资也可以不输互联网。 

 
 

 前几天看到华为、5G、polar码的B站视频有点热血沸腾，希望未来也能继续努力，为无线通信贡献自己的一点绵薄之力。

## 华为优招 消费者BG终端芯片-嵌入式面经

二、技术面
一面：
线上面试，面试官人很好，气氛比较轻松。先是介绍自己的项目。面试官会根据你的项目问一些针对性的问题。我是做光纤激光器和硅片的。就问了我项目里一些功能是怎么实现的，为什么要这么做。然后问了我这个激光器的转换效率，被什么限制了。因为我的激光器功率不高，面试官就问我觉得搭建高功率激光器系统的话，需要注意什么。反正就是针对你的项目展开话题，因为我项目介绍的还算详细，所以不难。过程中还给我介绍了岗位情况。

二面：

全程40分钟左右。结束后几分钟通知过了，等待主管面。

三、主管面

## 华为海思数字芯片实习面经分享

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-05-18 ｜ [原文链接](https://www.nowcoder.com/discuss/353157944680325120)

海思数字IC实习面筋

 0.概况

 个人情况

 本科专业偏电气强电，研究生电子通信，非微电子科班。项目：一个FPGA项目，主要包括SPI、I2C驱动芯片，还有fifo、UDP通信。

 海思实习主要流程是笔试、在线测评（心理测试）、技术面、综合面试，相比秋招少了一轮技术面。从3.18官网投递，到5.18拿到实习offer历时两个月。因为是第一批笔试面试的要等后面的，所以时间拉的比较长，其实华为的效率很高，面试反馈很快。隔得最长的就是面试通过到offer完成审核的阶段了。开放日时候有人问这个问题，答复是10-20工作日，确实也做到了。

 1.笔试

 海思的笔试考纲是公开的，不过只有书名，比如数字IC就是：

 数字集成电路--系统与设计 System Verilog 验证-测试平台编写指南 Verilog-2001 半导体制造技术 高级ASIC芯片综合 复杂SOC设计 其他岗位的可以在海思招聘官方公众号找到。

 客观题，60分及格。题目都是偏基础的，但是范围很广，海思数字IC岗不区分设计、验证，所以都会考！甚至还会设计一些后端的、物理的问题，上面的书都要看，重要的是理解，很多题目是结合Verilog代码的例子考察基本概念。

 笔试非常关键，千万千万不要轻视！因为题量不是特别大所以容错率不高，我就差点栽在笔试。我自认对FPGA、verilog、综合这些都比较熟，第一次就直接裸考了，结果挂了……不过比较幸运申请到补考机会。然后第一次考也发现了自己的问题，就是systemVerilog、验证、还有计组相关很薄弱，就恶补了下，还好第二次过了。

 2.在线测评

 没啥好说的，根据直觉选，别猜测答案。

 3.技术面

 先是自我介绍、介绍项目，然后回根据项目问面试官感兴趣的问题。比如：画项目的系统框图，解释某一部分是怎么工作的，然后层层递进，看你对项目的理解和对知识的掌握。

 我面试的问题基本是基于项目，从系统框图到某个模块的电路图、时序图，还有基于电路图算STA。中间我也算了不少bug，因为手算STA真没准备过。不过在面试官的提示下基本能修改回来。我认为这个过程不完全是考察知识掌握程度，也会是学习能力的考察，遇到不会的不熟的不要慌，跟面试官交流你的想法，在他的提示下做好也是ok的。

 4.综合面

 比较轻松愉快，跟业务主管聊天，互相了解。也可以提一些感兴趣的问题。

## 还愿，认真的一篇面经，希望能给大家帮助。

来源：牛客网 ｜ 类型：面经 ｜ 发布：2019-10-10 ｜ [原文链接](https://www.nowcoder.com/discuss/353155669480120320)

前几天在牛客许愿华为，昨天终于收到签约短信了。沈阳站，硬件研发。

面经

浪潮

基本没啥好说的，自我介绍完，也不知道两位面试官听没有，随便问了我几个问题。其中有一个印象很深刻，也是唯一一个有一点点专业性的问题，问我LDO是啥？？我当时就震惊了，然后回答了一下，然后就在说，我这个实习学到了很多东西啊，然后就我问他们问题了。两位面试官离我比较远，全程就和电话面差不多，没办法画图讲解之类的，都是说个大概，很水。然后没笔试，一面后就通知签约。

上海微电子

技术一面：问了实习的一个项目的原理框图，挑其中的一部分，手撕电路，问了元器件型号，adc精度，运放之类的。然后问fpga，非阻塞和阻塞赋值区别，hold time ，set time，另外好评是给我详细讲了很多很多fpga我不知道的东西，三段式，开发流程，整整一张纸，把我的简历背面写满了，超级感谢，临走我还特地把他给我讲的东西拍了照呢。大概半个小时往上。

技术二面：讲了项目的原理，构成，没有详细的画出来。同样问了项目中关键元器件型号，问了adc精度，adc时钟提供者，并给项目提出了建议。另外挑一个模块，也是手撕掉路，问了滑变的精度。

华为

技术一面：讲了实习参与得一个项目，同样画原理框图，面试官根据我画的框图，提问，都是很细节的问题，然后我回答，另外就是项目中遇到了哪些困难，怎么解决，阻值为什么选xxΩ。另外就是我开始随便讲了，想到啥讲啥，发散性思维，全程就当作给同学讲题吧。很轻松，也很有趣，最后还推荐他看看我实习公司的产品呢。

技术二面：问了我一面讲了啥，然后他就没再问实习的，挑简历上没问的问我，现场出了三道题，面试官边出题边问我这个会不会？用没用过？这时候一定要诚实回答，因为他是根据你的项目和你的回答出题的，不会的一定要说不会，不熟悉的也不建议说会。我的三道题：①挑了一个项目，让我手撕电路，讲原理。②51单片机初始化，端口。③ fpga根据电路功能写verilog。面试官主要考察的是解决问题的能力，另外，说一个小技巧，如果题目答的不太好，可以发散性的讲一些和题目相关的，能体现出知识面的广度。做完三道题后，提问面试官，闲聊，然后面试结束。感觉也很好，很开心。

技术主管面：①一定注意第一印象，面试官从你走进教室，还没和他交流这中间，会观察你，所以，一定要注意自己的一言一行。这段时间他会初步判断你是一个怎样的人！很重要。②你的优点是什么？你的缺点是什么？你有男朋友吗？没有的话，你觉得你什么问题导致你没找到对象？别人有指出你的缺点吗？你最遗憾的事情，最愧疚的事情，最近哪些挫折？为啥不考研？总体就是考察你的回答的严密性，逻辑性，千万不要前后矛盾，不然会被怼的很惨，建议：他问你的时候，就当成讲故事吧。😁

大疆

电话一面，很凉凉，没啥好说的，我实在不适合电话面。

秋招就这四家吧，很多面试撞车了，只能选一家。

总体建议

①简历很重要，笔试和简历没有必然联系，发笔试不代表你简历过了，笔试答的很好或者很不好，不代表可以进面试或者淘汰，面试官更多根据简历决定要不要面试，笔试只是一个参考。但是，笔试仍要认真对待，因为流程走完了，录用排序应该会参考笔试成绩。

②本科生而言，技术深度是弱一点的，建议准备面试，用思维导图，发散性思维，由一个知识点联想到另一个，构建自己的知识体系，然后面试就有的聊了，面试官也会觉得，你怎么懂得这么多。

③笔试不太好的话，建议每次笔试完，整理笔试题，就像考试一样准备。这个不单单是对笔试有用，在第二点面试的时候，就可以发散了，讲到之前的笔试题。

④没事少刷牛客，少和同学讨论谁拿了offer，谁签约了，多去操场转转，不然会很焦虑的。

⑤招聘的每一步都要稳稳的，稳扎稳打，这样出现流程走完没收到签约通知的概率会小很多。不要抱着侥幸心理，也不要相信运气。

祝大家顺利哦！！加油[比心]
