## 嵌入式面试经验总结 100+大厂面试总结的经验

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-22 ｜ [原文链接](https://www.nowcoder.com/discuss/942708292382384128)

简历上写“熟悉 FreeRTOS”“做过通信模块”“了解 Bootloader”，面试官点头，下一秒就开始往下挖。

 挖到第二层你还能答，第三层开始飘，第四层直接空。这类情况，在大厂嵌软面里太常见了。

 我把消费电子、安防通信、工控自动化、车企/Tier1、视觉影像这类方向的 100+ 场面经和追问路径放在一起看，发现一件很清楚的事：

 大厂嵌软考的不是知识点清单，而是你能不能把一条链路讲到边界。 

 嵌入式八股文专栏：（附嵌入式各家大厂面经资料整理 100+嵌入式大厂面经以及全套基础八股文） 

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 先说结论

 100+ 场面试里，反复出现的筛选标准就四条：

 C / 内存 / 中断底板扎实不扎实 

 你是不是真碰过板子、总线、RTOS 或 Linux 

 项目能不能讲成：问题 → 方案 → 验证 → 失败路径 

 出故障时，你有没有自己的排查顺序 

 所以同样一道“I2C 和 SPI 区别”：

 只会答线数和速率，属于热身合格；

 能接到上拉、时钟拉伸、挂死恢复、项目里超时重试，才算真正开始拉开分差。

 再压缩成一句话：

 会背定义，过第一轮热身；能讲机制和坑，算进门；能结合项目讲设计取舍和异常定位，才接近大厂要的“能扛模块”。 

 大厂面试官通常怎么拆一个人

 最常见的开场，不是直接甩难题，而是从你简历里最硬的那一行开始。

 你写熟悉 C，他就从指针、对齐、 volatile 、位操作切进去，看你是不是只会调库。

 你写熟悉 RTOS，他就从优先级、同步原语、ISR 边界、优先级反转切进去，看你是不是只会 xTaskCreate 。

 你写熟悉 Linux / 驱动，他就从用户态内核态、设备树、 probe 、中断下半部切进去，看你是不是只编译通过过模块。

 你写做过通信，他就从时序、波形、超时、异常恢复切进去，看你是不是只会 HAL 收发。

 你写做过 Bootloader / OTA，他就从分区、校验、掉电、回滚一路往下问，看你是不是只跑通过升级 demo。

 真正决定去留的，往往不是第一题，而是第二、第三轮追问：

 掉电怎么办？

 并发冲突怎么办？

 现场偶现复现不了怎么办？

 你怎么证明系统满足实时或可靠性约束？

 什么叫“熟悉”，什么叫“写了但经不起问”

 算熟悉

 能一句话说清这个机制解决什么问题、不解决什么问题

 能画出你项目里的数据流 / 任务流 / 启动流

 能讲至少一个真实坑：现象、定位手段、根因、改法、验证

 能回答“如果重做，哪里会改”

 不算熟悉

 只会背定义，举不出项目场景

 项目只能演示 happy path，说不清失败路径

 简历写“负责整体”，细节全是队友做的

 通信只会调通，不会抓波形、不会分析挂死

 OTA 只会下载写入，不会讲校验、断电、回滚

 一句话： 熟悉不是知识面更宽，而是项目表达更完整。 

 100+ 场面下来，高频考点其实就六条线

 1. C 语言与内存：刷人最多的底板

 重点不是语法，是指针、数组退化、结构体对齐、大小端、位域、宏副作用、 const/static/volatile 、堆栈、 .text/.data/.bss 。

 高频追问方向：

 volatile 能解决可见性，不能解决原子性和内存序

 对齐为什么影响通信协议和 Flash 映射

 MCU 上栈溢出通常怎么表现、怎么定位

 手写环形缓冲 / memcpy 重叠处理时边界怎么守

 2. 中断、并发与 RTOS：实时功底分水岭

 重点是 ISR 和任务边界、临界区、调度、同步原语、延迟来源、优先级设计。

 高频追问方向：

 为什么 ISR 里不能阻塞、不能乱拿互斥锁

 关中断、关调度、互斥锁分别适合什么场景

 队列 / 信号量 / 互斥锁怎么按语义选型

 优先级反转是什么、怎么解

 哪些 API 必须用 FromISR 版本

 3. 总线、外设与联调：硬件协同能力

 UART / SPI / I2C / CAN / DMA / ADC，表面是接口题，实际考排障。

 高频追问方向：

 你怎么确认是软件超时还是硬件无应答

 I2C NACK、总线挂死怎么恢复

 DMA 和 Cache 一致性什么时候必须考虑

 CAN 仲裁、终端电阻、异常帧你怎么查

 4. 启动、Bootloader、OTA：工程闭环感最强

 从复位到跑起来，从分区到升级回滚，这一块最能看出你是不是只在应用层调 API。

 高频追问方向：

 上电到 main() / 到 APP 跑起来经过哪些关键步骤

 APP 跳转要注意向量表、栈指针、中断哪些点

 A/B 分区解决什么问题

 升级中断电、校验失败、版本回滚怎么设计

 5. Linux / 驱动：不是所有岗都要，但一要就是门槛

 偏 BSP、平台、安防、部分手机底层，Linux 不是加分项。

 高频追问方向：

 用户态 / 内核态、进程线程、系统调用

 字符设备框架和 file_operations 

 设备树到 probe 成功的路径

 中断上下半部、会不会睡眠决定用什么锁

 摄像头岗还会挖 V4L2、不出图排查、MIPI/I2C 链路

 6. 项目深挖：真正拉开上限的地方

 八股答得一般，项目讲得深，仍有机会救；

 项目一问就空，八股背再熟也很难翻盘。

 每个主力项目至少准备：

 3 分钟介绍版

 10 分钟深挖版

 1 个最难 Bug 的完整定位链

 1 条失败路径：超时、重试、降级、安全态、日志

 不同公司味道不一样，别一份简历海投同一套话术

 消费电子（OPPO / vivo / 小米等）

 更看功耗、稳定性、内存、多任务协作、异常收敛。

 常问：你怎么平衡响应速度和功耗？共享数据怎么保护？一次卡死怎么定位？

 安防 / 通信（海康、大华、中兴等）

 Linux 味道更重，进程线程、IPC、网络、性能排障更常见。

 常问：为什么选进程/线程？丢数据怎么查？CPU 占用高怎么定位？

 强实时 / 飞控影像类（大疆等）

 更抠周期、抖动、DMA、队列满、中断预算。

 常问：控制任务周期怎么保证？采集和处理怎么解耦？你怎么证明满足实时约束？

 工控 / 自动化

 更吃通信可靠性、长时间跑机、异常恢复、日志和版本。

 常问：Modbus/CAN 超时重传怎么做？掉电参数怎么保？看门狗怎么喂才有意义？

 车载（车企 / Tier1）

 通信 + 可靠性 + 升级几乎必问，AUTOSAR / 功能安全能了解更好，没有也可诚实说边界。

 常问：CAN/CAN FD、诊断概念、Boot/OTA 回滚、ECU 复位恢复、长时间测试指标。

 摄像头 / 视觉相关

 会从“模组能不能出图”挖到整条链路。

 常问：sensor 是不是你点亮的？I2C 初始化、MIPI、DMA、丢帧、花屏、不出图怎么分层排查？

 项目怎么准备，才像能逆风翻盘的那种

 不够用的项目

 点灯、流水灯、循迹小车、纯例程改参

 只有功能演示，没有架构和排障

 简历写“精通”，细节经不起第二问

 更有杀伤力的项目特征

 至少满足 4 条：

 有闭环 ：采集 / 通信 / 存储 / 显示 / 升级 / 异常处理，至少覆盖 2～3 项

 有分层 ：APP / 协议 / 中间件 / 驱动 / BSP 边界清楚

 有真实问题 ：偶现 bug、总线冲突、升级变砖风险、内存踩踏等

 有可靠性 ：看门狗、掉电保存、校验回滚、日志、降级策略至少占一两项

 结合近年高频方向，这几类更容易打：

 工控：RTOS 多任务 + 总线协议 + HMI + 日志/报警

 车载：CAN 通信 + 状态机 + 诊断/可靠性 + Boot/OTA

 摄像头：采集显示链路打通 + 丢帧/不出图排查 + 简单算法或 ISP 相关

 系统工程：Bootloader + 双分区 OTA + 版本管理 + 掉电恢复

 高分回答通常长什么样

 别再只背第一节。高分口述更接近这个结构：

 结论一句 → 机制两句 → 我项目里怎么用 → 出问题怎么查 → 边界是什么 

 举例：被问“为什么 ISR 里不做耗时操作”。

 低分答：因为中断要快。

 高分答：ISR 打断正常调度，耗时长会抬高中断延迟、影响同优先级和更低优先级任务；我项目里中断只做置标志/投递队列，协议解析放到高优先级任务；曾经把日志打进 ISR，导致偶发丢帧，后来用逻辑分析仪和任务水位才定位到。

 面试官要的是机制 + 现场，不是标准答案复印件。

## 大华嵌入式软件二面 面经总结

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-07-09 ｜ [原文链接](https://www.nowcoder.com/discuss/904635172467863552)

面向大华这类安防/IPC/NVR 业务，二面会更看重： Linux 驱动与系统、音视频链路、网络协议、多线程并发、RTOS 实时任务、项目排障能力 。下面 13 题全部换新，每题附参考答案。

 1. Linux 用户态和内核态的区别？为什么驱动必须跑在内核态？

 参考答案： 

 用户态程序运行在进程地址空间，权限受限，不能直接访问硬件寄存器、不能随意操作中断和 MMU；内核态拥有完整硬件访问权限，负责进程调度、内存管理、驱动、文件系统、网络协议栈等。

 驱动需要直接操作硬件（寄存器读写、DMA、中断处理），必须与内核统一管理资源，否则会出现权限冲突、内存越界、中断响应不及时等问题。所以字符设备驱动、平台驱动、V4L2 驱动等通常以内核模块或内置驱动形式存在。

 大华 IPC 场景里，Sensor、ISP、编码器、网卡、GPIO 复位、看门狗等都要靠驱动层打通，用户态应用通过 /dev/video0 、 ioctl 、 mmap 等接口访问。

 2. 进程和线程的区别？大华 IPC 里为什么常用多线程而不是多进程？

 参考答案： 

 
 
 
 
 
 
 
 
 资源

 
 独立地址空间

 
 共享进程地址空间

 
 
 
 切换开销

 
 大

 
 相对小

 
 
 
 通信

 
 IPC（管道、共享内存等）

 
 直接共享全局变量/堆，需同步

 
 
 
 崩溃影响

 
 一般只影响本进程

 
 可能影响整个进程

 
 
 
 
 IPC 产品里，一个主进程通常拆成多个线程：采集线程、编码线程、网络推流线程、存储线程、告警处理线程。它们要共享帧缓冲、编码队列、配置参数，用多线程更高效；但必须用互斥锁、条件变量、无锁队列做好同步，避免花屏、死锁、丢帧。

 3. 互斥锁、信号量、条件变量的区别？各适合什么场景？

 参考答案： 

 
 互斥锁（mutex） ：同一时刻只允许一个线程进入临界区，保护共享资源，如编码器上下文、配置结构体。

 信号量（semaphore） ：计数型同步，可允许多个生产者/消费者，如缓冲池有 N 个空闲帧。

 条件变量（condition variable） ：配合锁使用，等待某个条件成立，如“队列非空再取帧”“编码完成再发送”。

 
 典型 IPC 模型：

 采集线程 --[帧队列]--> 编码线程 --[码流队列]--> 网络线程

 
 空队列时编码线程 pthread_cond_wait() ，采集线程入队后 pthread_cond_signal() 唤醒。

 4. volatile 关键字的作用？和中断、多线程有什么关系？

 参考答案： 

 volatile 告诉编译器：该变量可能被编译器看不到的方式改变，禁止把读写字段优化掉。

 常见场景：

 
 寄存器映射地址 ： volatile uint32_t *REG = (uint32_t *)0x40021000; 

 中断与主程序共享标志位 ：中断置位，主循环读取

 RTOS 任务间简单标志 （更推荐原子变量或关中断保护）

 
 注意： volatile 不能保证原子性，也不能替代锁 。多线程下修改共享数据仍要 mutex；RTOS 下还要考虑任务切换和中断抢占。

 5. 什么是中断？中断服务程序（ISR）有哪些注意事项？

 参考答案： 

 中断是硬件/外设打断 CPU 当前执行流，要求 CPU 优先处理紧急事件的机制。

 ISR 注意事项：

 
 尽量短 ：只做清中断标志、读少量数据、发信号，复杂逻辑放到下半部/任务

 不能阻塞 ：不能 sleep 、不能长时间持锁、不能调用可能阻塞的 API

 Linux 内核 ：中断上下文不能睡眠；可用 tasklet 、 workqueue 、 threaded IRQ 延后处理

 RTOS ：ISR 里通常用 FromISR 版本 API 唤醒任务，如 xSemaphoreGiveFromISR() 

 共享数据要保护 ：防止 ISR 与任务/主循环竞态

 注意重入 ：同一中断连续触发时的处理

 
 大华设备里，按键告警、Sensor 帧完成、网卡收包、GPIO 触发都会走中断链路。

 6. Linux 字符设备和块设备的区别？摄像头、SD 卡分别属于哪类？

 参考答案： 

 
 
 
 
 
 
 
 
 字符设备

 
 按字节流顺序访问

 
 UART、I2C、SPI、按键、部分传感器

 
 
 
 块设备

 
 按固定大小块随机访问，有缓存

 
 eMMC、SD、SSD、硬盘

 
 
 
 
 摄像头在 Linux 下通常走 V4L2 框架 ，本质是视频采集设备，可理解为字符设备接口模型；SD 卡属于块设备，文件系统挂载在 /dev/mmcblk0p1 这类块设备上。

 2. 你简历里的项目属于 Linux 应用开发还是 MCU/RTOS 开发？你在其中具体负责哪些模块？ 

 
 如果项目是 MCU/RTOS：属于 MCU + FreeRTOS 裸机/RTOS 开发 ，主要做底层驱动、任务调度、中断处理和协议通信。

 回答要点：明确项目平台 + 自己负责的具体模块 + 实际贡献，不要只说“参与”。

 
 3. const 和 volatile 关键字分别是什么作用？在中断服务函数或寄存器访问场景下为什么要用 volatile ？ 

 
 const ：表示只读，防止变量被意外修改；常用来定义常量、只读参数、Flash 中的配置数据。

 volatile ：告诉编译器该变量值可能随时变化，禁止优化，每次都必须从内存/寄存器真实读取。

 寄存器访问必须用 volatile ，否则编译器可能缓存旧值，导致读不到硬件状态。

 中断中修改的标志位、主循环读取的全局变量，必须加 volatile ，否则主程序可能永远看不到中断更新的值。

 注意： volatile 只保证可见性，不保证原子性；多任务下还要配合临界区、互斥量或原子操作。

 
 4. 请说明进程和线程的区别。嵌入式 Linux 开发里为什么更常使用多线程而不是多进程？ 

 
 进程：资源分配的基本单位，有独立地址空间，切换开销大，相互隔离性强。

 线程：CPU 调度的基本单位，同一进程内共享地址空间和资源，切换开销小。

 进程间通信复杂（管道、消息队列、共享内存等）；线程间可直接共享全局变量、堆内存，但要做好同步。

 嵌入式 Linux 更常用多线程，因为设备资源有限，需要多个模块并发运行，如采集、编码、网络传输、日志管理。

 多线程共享内存更高效，适合 IPC、NVR 这类业务模块紧密协作的场景；多进程更适合强隔离需求，但在嵌入式里成本更高。

 
 5. FreeRTOS 中信号量、互斥量、队列三者有什么区别？分别适合什么场景？ 

 
 信号量 ：用于同步或资源计数，不传递数据。二值信号量适合“事件发生通知”，计数信号量适合“资源个数管理”。

 互斥量 ：用于互斥访问共享资源，同一时刻只允许一个任务进入，支持优先级继承，适合保护共享变量、外设、缓冲区。

 队列 ：用于任务间传递数据，FIFO，支持阻塞等待，适合采集→处理、中断→任务传数据。

 选型：只通知事件用信号量；保护共享资源用互斥量；传数据用队列。

 
 6. 什么是优先级反转？FreeRTOS 里通常如何缓解这个问题？ 

 
 优先级反转：低优先级任务持有资源，高优先级任务等待该资源，中优先级任务反而先运行，导致高优先级任务被间接阻塞。

 典型场景：低优先级任务拿到互斥量，高优先级任务等待互斥量，中优先级

 FPGA资源包括什么

 逻辑资源：FPGA包含大量的逻辑门，如AND门、OR门、NOT门等。这些逻辑门可以配置为执行特定的计算任务或实现特定的逻辑功能。

 存储资源：FPGA具有不同类型的存储资源。其中包括：

 寄存器：用于存储中间结果、状态变量和控制信号。

 块RAM（BRAM）：用于存储数据或查找表等小规模数据存储。

 分布式RAM：存在于逻辑单元中的小型存储单元，用于快速存储和访问数据。

 DSP资源：FPGA通常包含专用的数字信号处理（DSP）模块，用于高性能数字信号处理任务，如乘法、累加和滤波等。

 I/O资源：FPGA上的输入/输出资源用于与外部世界进行通信。这些资源可能包括GPIO（通用输入/输出）、UART（通用异步收发传输）、Ethernet、PCIe等接口。

 PLL（锁相环）：锁相环用于产生和控制FPGA内部的时钟信号，使其能够适应不同的时钟频率和时序要求。

 时钟网络：FPGA内部有一个复杂的时钟网络，用于分配时钟信号到各个逻辑区块和存储单元。

 运算单元：一些FPGA架构还可能包含特定的硬件运算单元，如乘法器、除法器等。

 通信接口：一些FPGA可能还包含通信接口，如高速串行通信接口（如Gigabit Ethernet、PCIe等）。

 

 ram的资源有哪几类？：

 块RAM（Block RAM，BRAM）：块RAM是FPGA内部的一种专用存储器资源，通常用于存储大量数据和查找表。BRAM具有较高的存储密度和快速的访问速度，因此在许多应用中被广泛使用。它适合存储中间结果、缓冲区和数据表等。

 分布式RAM（Distributed RAM）：分布式RAM存在于FPGA的逻辑单元中，每个逻辑单元都包含一小段存储器。它可以通过在Verilog或VHDL代码中定义信号来创建。分布式RAM通常用于存储较小的数据集或中间变量，它们在时钟周期内能够提供更快的访问速度，但存储容量较块RAM较小。

 线路缓冲RAM（LUTRAM）：线路缓冲RAM也是分布式RAM的一种形式，但是它用于存储LUT（查找表）数据。在某些FPGA架构中，LUT可以用作RAM来实现较小的存储需求。

 1. C++ 什么情况下必须用初始化列表

 成员类型是 没有默认构造函数的类 。若没有提供显示初始化式，则编译器隐式使用成员类型的默认构造函数，若类没有默认构造函数，则编译器尝试使用默认构造函数将会失败。

 const 成员 或 引用类型 的成员。因为 const 对象或引用类型只能初始化，不能对他们赋值。

 对于普通数据成员而言，其值的设定可以放在 初始化阶段或者普通计算阶段完成。对于 const类型和&引用类型数据成员，其初始化必须在初始化阶段完成。若通过普通计算阶段来初始化该值， 编译器会报错：该变量未初始化 。

 
 2. 面向对象的三大特点

 C++为了更好的实现面向对象的编程思想，于是引入了新的数据类型—— 类 。由此衍生出三大特性：（1）封装。（2）继承。（3）多态。

 封装 

 C++类将类中成员分为三种属性：private、protected、public

 （1） 私有成员 （变量和函数）只限于类成员访问，由 private 限定；

 （2） 公有成员 （变量和函数）允许类成员和类外的任何访问，由 public 限定；

 （3） 受保护成员 （变量和函数）允许类成员和派生类成员访问，不允许类外的任何访问。所以 protected 对外封闭，对派生类开放。

 C++这样做都是有道理的，实现了很好的封装，这就是C++的第一个重要特性： 封装 。

 继承

 面向对象程序设计中最重要的一个概念是 继承 。继承允许我们依据另一个类来定义一个类，这使得创建和维护一个应用程序变得更容易。这样做，也达到了 重用 代码功能和提高执行效率的效果。

 当创建一个类时，不需要重新编写新的数据成员和成员函数，只需指定新建的类继承了一个已有的类的成员即可。这个已有的类称为 基类 ，新建的类称为 派生类 。

 多态

 基类指针可以按照基类的方式来做事，也可以按照派生类的方式来做事，它有 多种形态 ，或者说有多种表现方式，我们将这种现象称为 多态（Polymorphism） 。多态的实现机制为 虚函数 。

 虚函数的作用是允许在派生类中重新定义与基类同名的函数，并且可以通过基类指针或引用来访问基类和派生类的同名函数 。

 方法是在基类中为同名函数添加关键字 virtual

 静态多态（编译器多态）：重载

 动态多态（运行时多态）：多态

 5. list和vector的应用场景？

 频繁访问的场景下，可以使用数组。

 6. 构造函数可以为虚函数吗？父类的析构函数为什么是虚函数？

 构造函数不能为虚函数 ，当申明一个函数为虚函数时，会创建虚函数表，那么这个函数的调用方式是 通过虚函数表来调用 。若构造函数为虚函数，说明调用方式是通过虚函数表调用，需要借助虚表指针，但是 没构造对象，哪里来的虚表指针？但是没有虚表指针，怎么访问虚函数表从而调用构造函数呢 ？这就成了一个先有鸡还是先有蛋的问题。

 若存在继承关系时，析构函数必须申明为虚函数，这样父类指针指向子类对象，释放基类指针时才会调用子类的析构函数释放资源，否则 内存泄漏 。

 9. 你了解的锁机制？

 （1） 互斥锁 ：mutex，保证在任何时刻，都只有一个线程访问该资源，当获取锁操作失败时，线程进入阻塞，等待锁释放。

 （2） 读写锁 ：rwlock，分为读锁和写锁，处于读操作时，可以运行多个线程同时读。但写时同一时刻只能有一个线程获得写锁。

 互斥锁和读写锁的区别：

 （a）读写锁区分读锁和写锁，而互斥锁不区分

 （b）互斥锁同一时间只允许一个线程访问，无论读写；读写锁同一时间只允许一个线程写，但可以多个线程同时读。

 （3） 自旋锁 ：spinlock，在任何时刻只能有一个线程访问资源。但获取锁操作失败时，不会进入睡眠，而是原地自旋，直到锁被释放。 这样节省了线程从睡眠到被唤醒的时间消耗，提高效率。 

 （4） 条件锁 ：就是所谓的 条件变量 ，某一个线程因为某个条件未满足时可以使用条件变量使该程序处于阻塞状态。一旦条件满足了，即可唤醒该线程(常和互斥锁配合使用)

 （5） 信号量 。

## 大华海康硬件工程师三面（已offer）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2019-11-26 ｜ [原文链接](https://www.nowcoder.com/discuss/353155936145580032)

前言： 牛客网上 硬件工程师 的文章向来的很少的，而且比较久远，本来是签完三方就想要整理下自己的面试经历，但是毕业的事情搞得焦头烂额的就忘记了，现在终于抽出来点时间，写一下自己的面试经历，也为后面的学生朋友提供些帮助。 

 ps：楼主双非渣硕（手动狗头），研究方向就是硬件设计， 纯硬件工程师培养方案（项目培养） ，项目做得还是比较丰富的，没有大厂实习经历（因为不让实习，能干活啊） 

 
 

 1、面试公司和面试情况。 

 因为本着贵精不贵多的原则，没有海投和海面（懒[害羞]），而且以杭州为主，上海为辅进行投递。按照顺序和结果如下 

 兆易创新（拿到意向书，后面签了就婉拒了） 

 TI（1面过了，后来没联系了，比较卡学历） 

 大疆（过了笔试和1面，第二面技术面挂了） 

 聚光（过了1面技术面，面试感觉不错，后面2面邀请婉拒了） 

 舜宇（2面，面试体验很差，后面没联系我，估计相互看不上） 

 大华（拿到offer，婉拒了） 

 海康（拿到offer，工资待遇挺好的，但是因个人原因毁约了） 

 华为（拿到offer，签了） 

 还有新华三、宇视、汇顶科技等等，没有去面试，因为手头上有了offer还有就是懒…… 懒不是主要原因 ，别胡说，我不是，我没有！ 

 
 

 2、大华面试 

 大华是来我们学校面试的，挺给我们学校面子的，毕竟都是杭州的。 

 面试很严谨，一共是3面，2面技术，1面HR。 

 一面： 

 1、先自我介绍下吧 

 巴拉巴拉巴拉 

 2、针对这个项目流程图画下吧 

 画画画画，边画边讲 

 3、下面是项目相关的问题： 

 MIPI有几对差分线；传输速度怎么样？还有就是USB传输速度？总线传输速度计算方法是什么？
 

 4、遇到过哪些问题，怎么解决的 

 5、优点和缺点个人 

 二面： 

 1、画下框图（和1面项目不一样） 

 2、JTAG信号有哪些；双运放某个电路改成单运放怎么改；三极管和MOS管搭建与或非电路；运放中失调电压，失调电流是什么，是否注意？ 

 3、FIR滤波器和II2滤波器 

 三面： 

 1、手头有offer吗 

 2、期望薪资 

 3、对大华看法，还有一些其他的 

 
 

 总结： 大华挺不错的，面试很严谨，有些问题真的没考虑到，也没复习到，当时还没怎么系统的面试过，着实锻炼了自己的面试能力。 

 个人觉得面试表现一般，这个offer收到的都挺晚的，当时已经拿到海康的双方了，工资待遇都好一大截，所以婉拒了。 

 
 

 3、海康面试 

 海康是去总部面试的，真的很气派，那三幢大楼贼霸气。但是感觉不是很好，等了好久好久，估计是面试人太多了，差不多平均延后面试时间3~4个小时。 

 等着面试，叫到后去面试，一般都是两面（感觉减小流程了），本人面了3面（别问我，我也不知道），一面技术面，一面HR，一面主管。面试感觉挺好的 

 一面： 

 介绍项目，针对项目上问题去问你，所以对自己做过写在简历上的项目必须非常熟悉，ok 

 （他们有记录表格，会记录面试表现吧） 

 这块问题其实不具有普及型，所以就不放了。 

 二面： 

 针对工作地点，女朋友，薪资状况，有无offer等情况进行了解 

 三面： 主管针对我简历上项目去了解我个人擅长，因为说了我就是纯硬件的，所以能聊的蛮多的。 

 比如：聊聊硬件包含的领域有哪些？你认为你做项目最难的点在哪里？怎么解决遇到的问题？如何和同事进行项目沟通？等等吧，都是一些你项目做过都会遇到的问题，聊得范围挺广的。 

 
 

 总结： 整体来说可能是因为人太多了，导致主要是进行项目沟通比较多，时间比较短，但是还是能够比较充分判断一个人的能力的，毕竟都是经验丰富的面试官。 

 ps： 海康待遇是真的不错，给了小sp，当然比不上牛客大佬们各种高水平薪资，人贵有自知之明，签了双方。 

 但是由于有颗沸腾的心，还有想追求进一步技术的提升以及去上海看看，所以楼主最后签了华为。因为是个人原因，秉承契约精神，所以愿意承担相应海康违约金（9000大洋），虽然很肉痛。 

 
 

 4、总结 

 

 手好酸，先这样吧，其他的有感兴趣的在下面留言，我有时间会补上其他的面试经历和回答大家问题。还有就是薪资要保密的，所以有想了解具体公司的私聊我，不公开说，其实你们可以offershow查的，上面是匿名的。 

 华为的面经很多了，楼主还要入职，就不写了，哈哈。 

 其实大华和海康对于我们硬件来说都很好，特别是在杭州，安防第一和第二不是开玩笑的，主要是我的个人意愿占主导，论待遇和薪资华为和海康给的五五开（海康加班少很多），奥利给！
