 Maven作为一个开发工具，具体有什么用途

 Maven 是一个用于构建和管理 Java 项目的工具，广泛应用于 Java 开发中。它的主要用途可以概括为以下几点：

 1. 构建自动化： 

 Maven 自动化了项目的构建过程，包括编译源代码、打包 JAR/WAR 文件、执行单元测试、生成文档等。通过简单的命令，开发者可以轻松地构建和部署项目。

 • 编译和打包 ：Maven 能根据项目配置文件（pom.xml）自动进行编译、打包操作。

 • 生命周期管理 ：Maven 提供了预定义的构建生命周期（如 clean, compile, test, install 和 deploy 等），确保每个阶段都能按顺序执行。

 2. 依赖管理： 

 Maven 使用中央仓库（Central Repository）来自动下载和管理项目所依赖的库文件和插件。

 • 依赖声明 ：开发者只需在 pom.xml 文件中声明项目的依赖（如第三方库），Maven 会自动下载并包含这些依赖。

 • 版本管理 ：Maven 支持自动管理不同版本的依赖，避免了版本冲突和手动下载的麻烦。

 3. 项目管理： 

 Maven 的 pom.xml 文件不仅用于描述项目的依赖关系，还包含了项目的元数据、构建配置、插件配置等，帮助开发者在不同环境中快速启动并管理项目。

 • 模块化 ：Maven 支持多模块项目（Multi-module Project），方便大型项目的管理。

 • 构建配置管理 ：可以通过继承父 POM 文件，统一管理多个项目的构建设置。

 4. 持续集成和部署： 

 Maven 可以与持续集成（CI）工具如 Jenkins、GitLab CI 等结合使用，自动执行构建、测试和部署等操作。

 5. 插件支持： 

 Maven 提供了丰富的插件，帮助开发者在构建过程中执行各种任务，如代码检查、文档生成、部署操作等。

 • 常用插件 ：maven-compiler-plugin（编译源代码），maven-surefire-plugin（运行单元测试），maven-jar-plugin（创建 JAR 文件），maven-deploy-plugin（将构建结果部署到远程仓库）等。

 6. 文档生成： 

 Maven 可以自动生成项目文档，包括 Javadoc、依赖树、构建报告等，帮助团队管理和维护项目。

 7. 可扩展性： 

 Maven 的架构支持插件和扩展，可以根据项目需求进行定制化，适应不同的开发需求。

 8. 跨平台： 

 Maven 是基于 Java 的工具，可以在任何支持 Java 的平台上运行，提供了一种跨平台一致的构建和管理方式。

 典型的 Maven 使用流程： 

 
 
 创建项目 ：开发者通过 Maven 命令或 IDE 创建一个新的 Maven 项目。

 
 定义依赖 ：在 pom.xml 中添加项目所需的第三方库、插件和其他模块。

 
 构建项目 ：运行 mvn clean install 来编译、测试、打包项目并将构建结果安装到本地仓库。

 
 发布和部署 ：使用 mvn deploy 将项目发布到远程仓库或者进行部署。

 
 Maven常用指令

 1. mvn clean 
• 作用 ：清理项目，删除 target 目录下的所有文件。常用于在重新构建项目之前清理上次构建留下的文件。
• 使用场景 ：在构建过程中遇到问题时，清理掉旧的编译结果，再次进行构建。

 2. mvn compile 
• 作用 ：编译项目的源代码。它会根据 src/main/java 目录中的 Java 源代码进行编译，生成 target/classes 目录中的 .class 文件。
• 使用场景 ：当你只想编译代码而不进行打包或测试时使用。

 3. mvn test 
• 作用 ：运行项目中的单元测试。它会编译源代码并执行测试（通常是在 src/test/java 中的测试类）。
• 使用场景 ：确保项目的单元测试在构建过程中成功通过。

 4. mvn package 
• 作用 ：编译源代码并打包成 JAR/WAR 文件，通常会将打包结果放在 target/ 目录下。
• 使用场景 ：完成项目的构建并生成可分发的文件。

 5. mvn install 
• 作用 ：构建项目并将构建结果（如 JAR/WAR 文件）安装到本地 Maven 仓库（~/.m2/repository）。
• 使用场景 ：在本地仓库中安装构建的项目，以便其他项目能够引用它作为依赖。

 6. mvn deploy 
• 作用 ：构建项目并将构建结果部署到远程 Maven 仓库（例如 Nexus 或 Artifactory）。
• 使用场景 ：当需要将构建好的项目发布到共享的远程仓库时使用。

 7. mvn clean install 
• 作用 ：先执行 clean 清理操作，然后执行 install 安装过程。通常用于确保在新一轮构建时，不会有旧的文件干扰。
• 使用场景 ：常用于完整的构建流程，在从头开始构建时确保不会留下遗留文件。

 8. mvn validate 
• 作用 ：验证项目是否正确，检查 pom.xml 文件中的配置是否正确并且依赖是否存在。
• 使用场景 ：在构建之前验证项目的配置是否正确。

 9. mvn site 
• 作用 ：生成项目的站点文档。Maven 可以生成一些标准的项目报告（例如：测试报告、依赖报告、插件报告等）。
• 使用场景 ：生成项目的文档，便于团队协作和后续维护。

 10. mvn dependency:tree 
• 作用 ：显示当前项目的依赖树，帮助开发者理解项目依赖关系。
• 使用场景 ：调试依赖问题，查看依赖的版本和层级。

 11. mvn clean verify 
• 作用 ：先清理项目（clean），然后执行验证步骤（verify），以确保项目符合特定的质量标准。
• 使用场景 ：进行完整的项目验证，确保一切都正常。

 12. mvn spring-boot:run 
• 作用 ：启动一个 Spring Boot 项目（如果项目是 Spring Boot 项目）。
• 使用场景 ：在开发过程中直接启动 Spring Boot 应用进行调试。

 13. mvn dependency:analyze 
• 作用 ：分析项目中的依赖，检查是否有多余的依赖或遗漏的依赖。
• 使用场景 ：帮助清理项目的冗余依赖，优化项目配置。

 常用的参数： 
• -D ：用来传递系统属性，例如：

 mvn clean install -DskipTests
 
 这将跳过测试执行。
• -U ：强制更新本地仓库中的依赖，检查远程仓库是否有更新的版本。

 mvn clean install -U
 
 validate和verify的区别是

 1. mvn validate 
• 作用 ：验证项目的配置是否正确。主要是检查 pom.xml 配置文件中的内容是否符合 Maven 的标准和规则。
• 具体操作 ：
• 检查 pom.xml 是否存在，格式是否正确。
• 验证项目的依赖是否有效，是否能够从配置的仓库中找到。
• 确保 Maven 配置中没有错误或遗漏。
• 使用场景 ：通常在构建之前运行，确保项目的配置没有问题。它并不会进行代码的编译或测试，也不会执行任何构建的后续操作。主要是用于验证项目环境的完整性。
• 生命周期中的位置 ：位于构建生命周期的开始阶段。

 2. mvn verify 
• 作用 ：验证项目的构建是否成功，通常是执行测试、检查生成的构件（如 JAR/WAR 文件）是否符合质量标准。
• 具体操作 ：
• 在项目编译和测试之后，执行所有的测试（如单元测试、集成测试等）。
• 验证项目是否符合预期的质量标准（如运行测试、检查代码质量、检查构建的有效性等）。
• 使用场景 ：通常在构建和测试阶段之后运行，确保构建成功并且通过了所有的测试。verify 阶段通常用于执行质量保证任务，例如运行集成测试、检查代码质量等。
• 生命周期中的位置 ：位于构建生命周期的后期阶段，通常在 install 之前执行

 快排

 
 选择一个基准元素（pivot）。

 将数组按照基准元素分成两个部分，左边部分小于基准，右边部分大于基准。

 对左边和右边的部分递归地进行排序。

 最终所有的子数组都被排序后，整个数组即完成排序。
O(nlogn)

 
 冒泡排序

 
 从数组的第一个元素开始，依次比较相邻的两个元素。

 如果前一个元素比后一个元素大，则交换它们的位置。

 每一趟遍历后，最大的元素会“冒泡”到数组的末尾。

 重复步骤 1-3，直到数组完全排序。
O(n^2)

 Mysql 索引失效的场景

 当我们使用左或者左右模糊匹配的时候，也就是 like %xx 或者like %xx%这两种方式都会造成索引失效；

 当我们在查询条件中对索引列使用函数，就会导致索引失效。

 当我们在查询条件中对索引列进行表达式计算，也是无法走索引的。

 MySQL 在遇到字符串和数字比较的时候，会自动把字符串转数字，然后再进行比较。如果字符串是索引列，而条件语句中的输入参数是数字的话，那么索引列会发生隐式类型转换，由于隐式类型转换是通过 CAST 函数实现的，等同于对索引列使用了函数，所以就会导致索引失效。

 联合索引要能正确使用需要遵循最左匹配原则，也就是按照最左优先的方式进行索引的匹配，否则就会导致索引失效。

 在 WHERE 子句中，如果在 OR 前的条件列是索引列，而在 OR后的条件列不是索引列，那么索引会失效。

 为什么MySQL 采用 B+ 树作为索引

 B+树的非叶子节点不存放实际的记录数据，仅存放索引，因此数据量相同的情况下，相比存储即存索引又存记录的B树，B+树的非叶子节点可以存放更多的索引，因此B+树可以比B树更「矮胖」，查询底层节点的磁盘1/0次数会更少。

 B+树有大量的冗余节点（所有非叶子节点都是冗余索引），这些冗余索引让B+树在插入、删除的效率都更高，比如删除根节点的时候，不会像 B树那样会发生复杂的树的变化；

 B+ 树叶子节点之间用链表连接了起来，有利于范围查询，而B树要实现范围查询，因此只能通过树的遍历来完成范围查询，这会涉及多个节点的磁盘！/O 操作，范围查询效率不如 B+树

 1, B+Tree vs B Tree

 B+Tree 只在叶子节点存储数据，而B树的非叶子节点也要存储数据，所以B+Tree 的单个节点的数据量更小，在相同的磁盘1/0次数下，就能查询更多的节点。

 另外，B+Tree 叶子节点采用的是双链表连接，适合 MySQL 中常见的基于范围的顺序查找，而B树无法做到这一点。

 2、B+Tree vs 二叉树

 对于有 N 个叶子节点的B+Tree，其搜索复杂度为 0（1ogdN），其中d表示节点允许的最大子节点个数为d个。

 在实际的应用当中，d值是大于100的，这样就保证了，即使数据达到千万级别时，B+Tree 的高度依然维持在3~4 层左右，也就是说一次数据查询操作只需要做3~4次的磁盘1/0 操作就能查询到目标数据。

 而二叉树的每个父节点的儿子节点个数只能是2个，意味着其搜索复杂度为 0（1ogN），这已经比

 B+Tree 高出不少，因此二叉树检索到目标数据所经历的磁盘1/0次数要更多。

 3、B+Tree vs Hash

 Hash 在做等值查询的时候效率贼快，搜索复杂度为 0（1）。

 但是 Hash 表不适合做范围查询，它更适合做等值的查询，这也是 B+Tree 索引要比 Hash 表索引有着更广泛的适用场景的原因。

 redis上分布式锁和数据库锁的区别

 1. 锁的粒度和作用范围 

 • 数据库锁 ：

 • 数据库锁通常是 在单一数据库实例 或数据库内部进行的锁，主要针对同一数据库的多个并发操作进行控制。

 • 数据库锁通常是应用于数据库表中的行级（行锁）或表级（表锁）锁。

 • 数据库锁的作用范围限于一个数据库实例内，无法跨数据库或跨服务器。

 • Redis 分布式锁 ：

 • Redis 分布式锁是 跨多个应用实例 和 跨多个机器 的分布式锁，通常用于需要跨多个服务实例共享的资源控制。

 • Redis 锁使用 Redis 提供的 SETNX 或者 Redisson 等工具来实现，可以有效地在多个系统节点间同步锁状态。

 2. 实现方式 

 • 数据库锁 ：

 • 数据库锁通常使用数据库管理系统（如 MySQL、PostgreSQL）的锁机制，常见的方式有：

 • 行锁（Row Locking） ：通过 SELECT FOR UPDATE 语句或 UPDATE 操作，锁住特定行，防止其他事务修改该行数据。

 • 表锁（Table Locking） ：通过 LOCK TABLES 语句，可以锁住整张表，防止其他操作对表进行修改。

 • 数据库锁会阻塞其他请求，直到锁被释放，通常适合在单个数据库实例内部进行数据同步。

 • Redis 分布式锁 ：

 • Redis 分布式锁的实现一般基于 SETNX （SET if Not eXists）命令或使用专门的 Redis 分布式锁工具库（如 Redisson）。

 • SETNX 是 Redis 提供的一个命令，如果指定的 key 不存在，就会设置该 key 的值并返回 OK，否则返回 0。利用这一特性可以实现基本的锁机制。

 • Redis 分布式锁还可以使用 超时机制 ，如使用 EXPIRE 设置锁的过期时间，防止因程序异常未能释放锁而导致的死锁。

首先介绍一下自己，本人双非，我知道以我的学历来说自己确实进入不了银行，当然这也是经历完春招后才明白的，写这个贴子就当作一个记录，给以后的自己看看，同时如果能给别人提供参考也挺好 

 

 首先，我是大概在二月底左右投的兴业银行，在三月中旬左右，接到的电话，然后先是一个电话的面试吧，我是这样的，问的我为什么想要投上海，我说经济发展地，互联网聚集地，发展速度比较快，能够积累学习到东西 ；然后问我为什么投银行，我说目前银行数字化发展是一个大趋势，数字化的发展对计算机和软件方面的需求量是比较大的，同时我也对金融方面比较感兴趣，说是感兴趣，其实就买过几个基金，玩的比较稳吧赚了一小点；其次会问到自己未来的一个职业规划。然后结束，后面发短信问我约面试时间，然后我很好奇那直接约面试不就行，为什么还要问问题 

 

 后面一面，两个面试官，基本只有一个在问问题， 一面准备一下身份证，好像每个银行都要这样，验证一下身份，后面一面问了，栈和队列区别；在使用数据库的时候需要用到哪些字段，范式，事务；然后聊到自己比较喜欢的一门计算机课，我说的操作系统，自己说了哪门课最好自己熟悉的，问了我 LRU 
 算法，然后又问了自己的职业规划，一面结束 

 

 期间发了一次笔试题，笔试题还好，行测加技术，最后一道编程题，银行大多都是这样，有时是1 -2 道编程题，刷一下力扣，基本都能过。笔试结束，后面发来总行面试通知，总行面就比较快，就简单问了一下，自己 做过最好的项目，有校园实习经历的会问你在社团或者班里举办过最好的一个活动，然后技术方面就问了一个现在流行的最新的一个框架，结束 

 

 都说兴业银行面完需要等很久，说有得等了一个月，我就等了，等了大概2 0 天吧，我就觉得我应该是凉了，然后我就去投其他的去了。春招投了很多，也面了很多，如果想走技术路线的，一定要在笔试面试前准备好，不然有很多机会容易错失。我是考研失利，感情失利，参加春招那段时间一直很难受，没有认真的去准备，所以各位，加油吧！

 二面：一对多，每个人10分钟左右。先做自我介绍，然后行长拿着你的简历随机提问，每个人几乎都会问到：你的性格弱点，我为什么选你。有时候是你说到什么行长就接你的话问你。比如，你说到专业能力很强，他可能问你：那你说说银行的理财产品有哪些。若你说到学习能力还不错，他可能说他觉得学习成绩好并不等于学习能力强，学习能力是一种应用能力，那你就得举个证明你学习能力的例子。

## 2022届我的秋招总结（互联网+银行面经）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-01-24 ｜ [原文链接](https://www.nowcoder.com/discuss/353159124454154240)

秋招结束了有一段时间了，正好过年回家有时间写一写我的秋招经历，不能说非常丰富，但也经历过不少，希望对大家找工作有些帮助！ 

 另我秋招遇到的互联网面试真题已经总结完成了： 

 2022届校招我的互联网面经（回馈牛客！） 

 另以下是我总结的一些自己在银行面试中的答题技巧，如果你也需要准备无领导小组讨论、半结构化面试的话，这篇文章或许能帮到你（已更新无领导、半结构真题）： 

 获取文章请+卫星：nulinulizainuli5216

 一、前言 

 我本硕就读于某985计算机类专业，7、8月份的工作目标设定为 互联网大厂 ，但之后由于户口、稳定等原因将主要精力转为 银行 。 

 二、offer情况： 

 （1）互联网： 

 百度、字节、小米、京东 

 （2）银行： 

 农行总行、邮储总行网络金融部、中行软件中心、农行数据中心、农行研发中心、农行北京分行、工行软件开发中心、北京银行信息科技岗、兴业银行总行管培。 

 三、求职准备 

 首先就是要把自己的简历准备的精彩一点，可以说你这次求职能否成功简历就决定了一半。简历可以从网上下载一个模板，但我个人建议是尽量简洁，突出重点。一定一定把自己的实习经历、项目经历、获得荣誉写清楚，这三块是你的加分项，如果你的学校不够好，这些往往能拯救你。（但一定一定要注意，你写在简历上的任何东西都有可能被问到，没有的项目经历、荣誉千万不要写！！！万一被问出来可能被认定为是诚信问题）。 

 简历准备好之后还有一个重点就是准备自我介绍，自我介绍需要注意以下几点： 

 毕业院校（本科学校一般的话可以不说） 

 成绩与所获奖励（这一块如果不够突出也可以少说） 

 实习经历（必须要说！加分项！） 

 项目经历（如果你有很多，就说最符合该岗位要求的项目经历） 

 自我介绍需要准备一分钟的、两分钟的和一个英文的，这三个自我介绍要做到倒背如流！万一哪个面试忽然让你英文自我介绍要能张口就来。 

 下面分别说一下我的互联网、银行的求职准备： 

 （1）互联网： 

 互联网我的思路是首先一定一定要多刷题，建议把力扣的热题100、剑指offer、前100道题都刷一遍，时间允许的话多刷几遍。刷题目的不仅是见识更多题型，更重要的是保持手感，因此在找工作期间一定要坚持每天刷几道，不要想着我都刷了一两百道了，肯定没问题了，但到了面试场上可能大脑一片空白，一定要保持手感。 

 再有的话就是一定要多看面经，多逛逛牛客，最好能找到某某公司、某某部门的面经，很可能碰到原题，另外也可以拓宽知识面，光看教材是远远不够的，看面经还是很有必要的。而看面经一般只有问题没有答案，这就需要自己去查阅资料，更要做到理解，相关的题也都要会。 

 再有互联网面试一般两三轮技术面，每次面试完一定要记录下自己的面经，因为很可能这次面试就会问到你上次面试答得不好的地方在哪里，再重新回答一下（亲身经历）。 

 （2）银行 

 银行属于国企，国企对学历、实习经历甚至身高、性别、长相都有所要求，因此不要认为求职银行比互联网容易，同样需要好好准备。 

 -a:针对笔试 

 各家银行笔试基本都包括行测（数量关系、言语理解、逻辑判断等）、英语、该银行基本情况等，题型基本为单选和多选。国开行、农发行会另考申论，进出口行会另考大量英文相关题目（翻译、写作等等）。笔试还是建议买中公的那个一本通（从淘宝搜银行考试资料出来的第一个就是），里面还包含了几套练习卷，个人认为至少要知道可能考到的题型都有什么，可以记下一些简单的做题技巧。笔试最重要的就是要注意做题速度，因为一般银行给的题量都是做不完的，看到不会的直接跳过，先做会的，最后把没做的蒙一下，英语阅读在考前也要读两篇找找题感。 

 -b:针对面试 

 由于近两年疫情的影响，大量面试改为线上，22届秋招据我了解仍为线下面试的有：农行数据中心、工行总行管培、北京银行总行管培、国开行总行、农发行总行等。无论线上还是线下，面试形式一般为半结构（多对多、多对一）+无领导小组讨论的形式。在着装上一定一定要 准备一套得体的正装 ，每次都要穿，别因为穿着给面试官留下不好的印象。 

 另外在面试时，一定要准备好自己的 中文一分钟、两分钟、英文自我介绍 ，面试官一般会依据你的自我介绍和简历来问接下来的问题，因此你的简历和自我介绍必须足够出彩，面试官才会来问你，如果一次多对多的面试下来面试官没问你几个问题，而对其他人一直追着问的话，你也就基本凉了。另外答题时会就是会，不会就是不会，现场编的话往往不如诚实点好（亲身经历）。 

 四、投递情况（2022届秋招） 

 （1）互联网 

 由于互联网面试时间参考价值不大，秋招的时候每个人的面试时间都是HR打电话来跟你一次一次确定的，因此仅列举我参加部分面试的时间。 

 百度：提前批：7.21一面+7.23二面+7.25三面 

 京东：提前批：7.22一面+7.26二面 

 字节：提前批：7.26一面+7.27二面+7.28三面 

 阿里：高德：8.2一面+8.3二面 

 小米：智慧场景部：9.13一面+9.15二面 

 （2）银行 

 银行考试时间线整体都比较晚，以下主要列出国有行及政策行的笔面试时间及考试形式，另外还有一些股份制银行的面试时间没有记录。 

 农行总行（9.9笔试+9.18线上无领导、线上半结构） 

 农行数据中心（9.17笔试+9.25线下半结构+9.30体检） 

 农行研发中心（9.6笔试+9.14线上双机位面试+10.8体检） 

 中行软件中心（10.24笔试+11.18线上面试） 

 工行总行（简历挂） 

 工行研发中心（10.23笔试+11.12半结构线上面试+11.22体检） 

 建行总行（10.24笔试+12.07面试） 

 国开行（11.07笔试+12.05线下面试（半结构+无领导）） 

 进出口行（11.10笔试） 

 农发行（10.17笔试+11.21面试（半结构+无领导）） 

 邮储总行（10.25笔试+11.27邮储线上一面+12.3邮储线上二面） 

 五、写在最后 

 （1）个人认为找工作的时候一定要多投递一些，不要害怕在这方面当“海王”，多投互联网可以积攒技术类面试经验，多投银行可以练习无领导小组讨论与半结构上的表达能力，当你手上拿到多个offer的时候再去选，这样找工作会比较有底气。 

 （2）要明确自己的求职目标，无论是想去互联网、银行、券商还是其他国企，一定要早做准备，因为现在无论是互联网还是银行，秋招都在逐渐提前。比如我是2022届毕业生，那么我在2021年3月就开始找实习了，6月左右秋招提前批就已经开始了，因此一定要明确目标后早准备。 

 （3）简单来讲，互联网的好处是高薪、成长空间大，国企的好处是稳定、在北京有户口，建议都多尝试，综合比较找到最适合自己的。 

 找工作确实很累，大家也要注意休息，祝大家找到满意的工作！

本文章将收录在专栏《手把手带你破解银行科技岗面试》，大家可以 点击这里 查看专栏介绍。
如果你对银行科技岗（研发中心、数据中心、软开中心、金融科技岗、科技人才岗）感兴趣，欢迎订阅专栏。本专栏将手把手带你破解银行科技岗面试，学习本专栏至少可以让你知道：

 1. 前言

 我之前已经把我的互联网求职经历写了一篇长文发了出来，如果有感兴趣的话可以点进我的主页看一看。本篇文章是记录我求职金融行业（主要是银行）的经历，以及会 推荐牛客上几篇优秀的银行求职的帖子 给大家，属于“入门帖”，求职银行必看！
按照惯例先提一嘴背景：我是2019级的硕士，本硕都就读于在京某985的计算机类的专业，求职方向原来是互联网大厂的Java后端，后来改为了 银行的科技岗（包括总分行科技岗和科技直属中心） ，目标城市北京。拿到银行科技岗的offer情况如下：

 农行数据中心

 工行软开

 招总FinTech管培

 交总FinTech管培进入体检流程放弃

 
 我转战银行科技岗的心路历程（牛客真的不止能查互联网面经）

 其实最开始我求职的目标是 互联网大厂的Java后端 ，但后来在某厂实习了一段时间之后，又觉得自己更适合去国企。所以经过询问师兄师姐，就把目光锁定在了银行的科技岗这块儿。

 其实大家一开始都是小白，根本不知道目前我国有什么银行、银行的架构是个什么样的情况、银行里我们能去什么单位什么岗、以及如何报名、考什么、面什么。

 当初也是在各大平台各种找资料，但找到的都是一些非常零星的资料，要么是只介绍了银行的架构，要么都是一些 经济金融类 的求职银行的经验，很少有科技岗的笔面经验，直到我在 牛客 上看了一篇相见恨晚的帖子：

 
 拿了6家银行信息岗offer的一些经验

 除此之外，我在上面不仅找到了银行的面经，还找到了和一些产品、运营相关的群面面经都可以复用到银行求职上，非常的nice，所以这篇帖子就主要和大家分享一下我是如何充分用好牛客这个大资源平台，找到真正对求职银行有用的信息的。并且也会推荐一些我认为对求职银行有帮助的帖子，希望大家能多多点赞收藏支持一波。

 银行笔试其实没什么好说的，除了农业银行和交通银行，别的银行我没见过有考编程的。

 5. 求职银行面试要准备什么？

 感谢牛客平台，我是搜刮了进两年几乎所有和牛客平台相关的银行面经和总结，大致总结出了这么三种面试形式，现在分享给大家。

 
 群面 ：以交行北分的优才项目为例

 半结构化面试 ：说白了就是情商题目，类似你的优缺点是什么，你为什么想来我行工作，你和同事有矛盾怎么办等等这类问题。这个半结构化有可能是单面也有可能是群面，性质一样。

 银行技术面 ：其实就是一个技术要求较低的互联网面试，无手撕代码，只有基础知识 + 聊项目，并且时间很短，以农行数据中心为例。这个技术面也有可能是单面也有可能是群面，性质一样。

 
 5.1 关于群面

 群面对于我们理工科的同学来说，可以说是比较棘手的一种面试形式，所以需要重点补一补，这里就又需要把牛客大大拉出来了，牛客上有不少比较优质的群面技巧总结帖：

 
 亲身经历几十场面试的面试经验&技巧总结（群面&业务面） 

 【腾讯上岸还愿】校招复盘 | 我是怎么混过产品岗群面的？

 5.2 关于半结构化

 建议大家提前收集收集这方面的问题，把问题的答案都 沉淀成自己的 ，想想怎么答这个问题是面试官最想听到的。

 这里限于篇幅就暂时不对每一类问题展开讲，如何把自己的优点和特点在短短十几分钟的时间内展现给面试官也是一门学问，这每一类问题展开讲都能写篇两千字的技巧文章，由于时间精力的限制我会在过年前这一段时间慢慢把回答半结构化问题的经验写出来。

 5.3 关于银行技术面

 银行技术面实在不用担心，因为银行的秋招求职时间特别晚，所以我建议大家有意向求职银行科技岗的都去面一下互联网，只要能面过互联网大厂，那么银行技术岗可以说一点点问题都没有。

 实在没时间准备互联网面试的，可以只准备八股文和剑指offer和lc100题，把项目和实习经历搞透，这样应付银行技术面真的完全足够了。

## 兴业数金C语言笔经面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-04-14 ｜ [原文链接](https://www.nowcoder.com/discuss/353157813079842816)

本人福州某211本科，考研失败春招找工作。福州本地好像挺缺人的，之前面试的时候也在牛客之类的地方搜了很多资料，在这里结合自己的经验分享给大家。 

 流程是笔试，一面，二面 内审，体检然后拿offer 

 笔试单选多选加起来80分，还有一题编程20分，c这边主要考数构计算机知识之类的，c考的比例不高（牛客多刷题就可以过） 

 编程题可以用任意语言写，如果没过后面会补考 

 一面技术面，我是两个面试官，一个问你基本情况，另一位考技术知识，问的挺多的，sql和网络知识比重很大，面试没考c，面试官态度都还可以，速度也挺快，应该是前两年给骂惨了今年有所改进。 

 ps：用的腾讯会议，提前给的会议号码得在里面一直等到他叫你，没有办法主动联系 

 二面综合面，我这边是一个很慈祥的阿姨，基本上就自我介绍问了一下基本情况，没有技术方面的事情。用小鱼易联开始前十分钟会有人打电话通知。 

 内审会比较久，后面就是体检了。流程会比之前看到的帖子快挺多，态度也还可以，就是等待面试的时间确实挺长的，好好准备一般没问题。单位比较看重学历，笔试难度一般，面试技术面有些难度。就是听说是年薪制风评不怎么好 

 有其他问题的朋友可以私信我

## 兴业银行、交通银行、汇丰银行管培生校招面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2020-11-18 ｜ [原文链接](https://www.nowcoder.com/discuss/353157346463522816)

兴业银行 面试过程： 

 春招投了简历，之后收到面试通知就去了。一面是无领导小组，讨论分ab组一组12人，给一个案例，要求20分钟讨论给出选择，然后3分钟阐述。接着20分钟讨论策划一个广告，最后给3分钟表演，最后是给3分钟两组相互提问。要注意团队合作，面试官整个过程都不怎么说话，就是注意观察周边人的表现比较严肃，有一定难度群面要多练。 

 
 

 交通银行 

 面试过程： 

 一面的话是蛮多人，我们都是校招。约好的周六，先过去填表，然后排顺序，一次大约进去6个人吧。然后每个人简单的自我介绍，很简单的那种。然后面试官问了一个问题，你有什么兴趣爱好啊。我填表的时候比较晚了，所以去面试都到了中午了，面试官那时候就不让超过一分钟的自我介绍了，超过了一分钟会被打断，然后就问你有什么兴趣爱好就完了 

 
 

 汇丰银行 

 面试过程： 

 首先在大厅填写了个人简历表格，然后被带到办公室进行一对一的面试，当天的面试官是总监级别。由于不是金融专业本来有些紧张，面试官很nice，面对非专业人员逻辑清晰地介绍了工作内容和培训机制，并解答了我的一些问题。对于求职者，个人感觉主要是了解了一下有无经验，同时在谈话过程中考察一下交流能力。总体面试过程比较顺利，公司地理位置很方便，办公环境感觉不错。

## 中州期货、兴业证券、川财证券经济金融岗校招面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2020-11-03 ｜ [原文链接](https://www.nowcoder.com/discuss/353157277865680896)

中州期货 面试过程： 去面试有很多人，没有单独面试，就是一起聚在会议室听HR讲公司的一些背景信息。之后会有测试，模拟交易，用公司给的帐号和模拟软件进行测试，根据测试成绩判断。测试分2个阶段，第一阶段约2周，没有补助。通过后会有第二阶段，有补助，按交易日算。第二阶段测试时间有长有短，一般约1~2个月。主要看稳定盈利能力。 

 

 兴业证券 

 面试过程： 

 1、因为是在校园招聘会上投递的简历，学校在漳州，但是公司在泉州，所以第一轮先是人事部门人员对大家投递的简历进行筛选。 

 2、接着同学入面的同学去一间教室接受领导面试，有三个领导（不太地区分公司的负责人)对入面的同学进行群面，一次四个同学，主要是针对每个人的简历进行提问，不会很难，只要表现出自己能胜任这人工作，让领导认可你就好了 

 一些问题：问你觉得自己有哪些优势 

 
 

 川财证券 

 面试过程： 

 1、第一轮，无领导小组讨论，严格限制时间，多一秒都不行； 

 2、第二轮，面试完成之后，留下来一个一个单独与人力聊，主要是了解求职意向，岗位调整和工作地点协商，完事之后回去等通知。 

 3、最后一轮是公司领导面试，远程面。 

 面试官的问题：问针对你的实习，谈谈留下的印象最深的一件事。

## 中国华融资产管理，兴业基金财务校招面经

中国华融资产管理 

 面试过程或经历: 

 参加的是会计核算岗位的招聘，只招聘一个。无意看到HR还拿着一份更为详细的名单包括年龄，党员是否，学历等信息。 去会议室参加的面试，两位老师，主要就是自我介绍，包括他们对简历提出来的一些问题，比较看重证书，最好是有注会证书及相关有含金量的证书。 另外一方面就是问了一下，对华融的了解。第三个问题是你认为一名会计人员需要具备哪些素质。 问题不难，主要是自己的观点和看法。 

 面试官的问题： 

 问对华融的了解。 

 答四大资管公司（基本的内容官网上都介绍了）大致讲讲，华融的现有业务内容基本之一还是处理不良，之后开始市场化运作之后，也逐渐涉及信托/资产管理/资产置换/资产处置/投资等业务。 

 
 

 兴业基金 

 面试过程或经历: 

 和同事交流下来面试主要分为3-4轮，面试时间较长，普遍超过一个月，甚者有超过3个月：1、部门老总面试：由于当时比较缺人，面的时候感觉比较简单，当然主要也是因为领导人好 

 2、分管领导面:我们这个部门的分管领导是督察长，督察长面试基本属于聊天，没有问专业内容 

 3、高管面：这是董事长委托一个高管面，这个高管提了很多专业问题，由于我的经验不足，因此回答上来的不多，走的时候还怕没有被录取，因为真的面试风格非常严肃，而且问题又难 

 4、董事长面：过了高管面之后，就是董事长面，由于董事长已经委托过高管面过了，所以我仅仅是做了一下自我介绍就过了。 

 面试官的问题： 

 问金融资产的估值方法。

## 兴业数金面经总结

来源：牛客网 ｜ 类型：面经 ｜ 发布：2020-03-06 ｜ [原文链接](https://www.nowcoder.com/discuss/353156105901645824)

今天面试的，在写这个面经时，还未收到hr的面试通知，我希望自己能收到吧，但是我知道很悬。

 
 那就当成经验，平常心对待吧，从来没有写过面经，主要是这次想找这个银行的面经没找到，既然我参加了，那我随意写写吧。

 
 一面：主要是项目方面，要对自己的项目足够清楚，同时对你自己的模块，和用到的技术都要清楚。

 
 因为我是一直在写vue的，所以面试时，说到项目也是在说vue.

 
 面试官一：

1.自我介绍

2、项目简介

3、项目中我负责的那一块，项目负责的功能

4、当谈及一个模块时，数据是如何传输的

假设说的是会议这块，那基础数据有哪些

数据传输问题（说了好久），主要是自己表述不清，说到后面，面试官说没听懂我说的是哪个模块

 面试官二：

router和routers，route的区别

生命周期，生命周期每一期所干了什么事

扩展运算符...

遍历的方法：map,set,v-for,foreach,for-of

有没有做过轮播图的demo

千张图片做轮播图，会遇到什么问题，要怎么做。

我的回答是千张图片做轮播，肯定会引起性能不是很好，说看能不能按需加载，后续问了一些大神说是延迟加载。网上有例子说是会存在内存溢出的问题

 面试官三：

用了element UI的哪些组件、form表单用了什么组件，增加页面，用了什么组件，怎么绑定属性数据的。

面试总结：把项目表述清楚，项目中用到的技术相关的东西全部搞清楚

 
 二面：好像是兴业银行的面试官，说面试分两轮，第一轮结束后，半个小时内会进行第二轮，我没有等来第二轮，失望中，哎。

 
 1、ES6的兼容性问题，能不能兼容IE浏览器

 
 2、会不会react

 
 3、写过移动端和微信小程序没

 
 4、能不能接受长期出差

 
 感觉这一轮主要看你会的有哪些。

## 兴业银行研究岗面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2020-01-17 ｜ [原文链接](https://www.nowcoder.com/discuss/353156017057898496)

一面 

 面试是按照到达现场的时间排序的，所以来的越早就能越早面完。现场还会给提供一些水果饮料，来的完也不怕。 

 面试形式是单面，有两位面试官，都比较年轻。问题基本就是围绕简历展开的，问了我的专业的主修课程是什么，最喜欢的课程有哪些，你做的这个课题研究方向是什么，有什么成果；专业成绩怎么样，排名多少；有没有参加过社团活动，具体内容说一下；然后问了实习经历，简单说一下你的实习，实习期间遇到的最大困难是什么，怎么克服的。总之，面试官就是一直围绕某件事情的具体经过和结果询问，按事实回答就可以了，全程大概25分钟。 

 二面 

 二面的问题比较多，也比较散，但总体上还是和以前的各种经历相关，主要是问你对这件事情的看法，还是要对自己的简历熟悉，对上面写的各个事件进行一下复盘，多问自己是什么、为什么、怎么样。然后还问了很多专业名词的概念，如果回答的时候不知道开始乱说的时候面试官就会打断，继续提问下一个问题。然后问了为什么选择上海；有没有女朋友。 

 面完之后就去会议室等着了，然后过了几分钟，hr救过来和我说我进了终面，让我去面试。 

 终面 

 终面也是两位面试官，都是女性，看着比较严肃。问了为什么做研究；为什么选择兴业；对岗位的认识了解；学习经历，研究生期间主要研究什么内容之类的。 

 终面过了一个星期左右后收到了实习通知，实习通过后就可以签订正式合同了。
