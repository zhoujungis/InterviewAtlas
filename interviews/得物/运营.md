## AI驱动：从运营行为到自动化用例的智能化实践｜得物技术

来源：掘金 ｜ 类型：面经 ｜ 发布：2026-04-23 ｜ [原文链接](https://juejin.cn/post/7631495035478589450)

一、项目背景

 随着交易业务的快速增长，对质量保障工作提出了更高标准与全新要求。为提升研发体验和架构升级，大量后台页面经历从 Vue -> React -> 全栈的迁移过程。业务演进过程中，后台能力持续迭代与优化；团队在交付新能力的同时，同步保障存量链路的稳定与可预期行为。为进一步完善测试用例覆盖范围，高效支撑回归测试与重构验证工作，需通过技术手段升级质量保障模式，为业务与架构迭代提供更充分的质量支撑。

 E2E 测试： 即端到端测试，是一种从用户视角出发，模拟真实操作验证应用完整业务流程的自动化测试方法。 自动化生成用例： 用线上内部运营操作日志自动生成 E2E 测试用例，快速覆盖核心流程，解决用例缺失问题。 智能元素定位： 自动识别重构等场景 UI 变化并调整定位策略，实现维护流程的自动化。 平台化管理： 通过数据看板管理用例和执行结果，让 E2E 测试可追踪、可优化，提升测试效率。

 基于以上分析，我们致力于构建一套自动化 + 智能化的 E2E 测试方案，该方案旨在支撑快速迭代开发模式，有效应对用例覆盖与重构验证等场景，从而在现有资源条件下，持续为业务快速迭代和技术架构升级提供可靠的质量保障。

 二、价值收益

 提供基于线上真实运营行为的自动化 E2E 测试能力，能够实际发现页面线上/重构等场景的体验问题。在页面重构等迭代任务中，通过优化回归测试流程与资源分配，有效进一步提升测试支持效率。测试的页面代码覆盖率≥X%；无代码覆盖率场景步骤执行成功率≥X%。

 页面代码覆盖率：页面用例在测试过程中 运行的代码行数 / 该页面关联的所有代码行数 * 100%步骤执行成功率：页面用例在测试过程中 执行成功的步骤数 / 用例总步骤数 * 100%。

 三、方案选型

 传统 E2E（DOM）

 名词解释 核心差异 传统 E2E 基于 DOM 的测试方案，主要通过操作和验证浏览器中的页面元素，来模拟用户行为的测试方案。 定位方式： 依赖 XPath/CSS 选择器 。用例生成： 手动编写或录制 。维护成本： 高 （DOM 变化需手动更新用例）。 
 AI E2E

 名词解释 核心差异 AI E2E 指利用人工智能技术，增强传统 E2E 测试的智能化、自适应性和效率的测试方案。 定位方式： 视觉识别、语义化分析 （如按钮文本、图标）。用例生成： 自动生成 （基于用户行为日志或需求描述）。维护成本： 低 （AI 自动适应 UI 变化）。 
 方案对比

 传统 E2E 优势： 贴近真实用户操作：实际触发页面渲染和事件。跨页面流程验证：适合测试多步骤业务场景（如登录→下单）。 传统 E2E 劣势： 脆弱性：DOM 结构变化易导致用例失败（需频繁维护定位表达式）。执行速度慢：依赖浏览器渲染和网络请求。

 AI E2E 优势： 降低维护成本：减少因 UI 微调导致的用例失败。提升覆盖率：AI 可探索非预期路径（如异常输入）。 AI E2E 劣势： 黑盒性：AI 决策过程不透明，调试困难。高成本：需积累足够数据优化模型，复杂视觉处理需要更高性能。

 基于上述对比分析，我们选用 AI 驱动的 E2E 测试方案，能够在支持重构场景的同时，显著提升用例生成的自动化水平，从而形成高效可持续的自动化测试解决方案。

 四、AI 工具选型

 特征 Midscene 原生 JavaScript + WebExtensions API；开源 AI 驱动 UI 自动化工具； 支持 Playwright、Puppeteer 定制行为逻辑；支持 Dom 分析和视觉分析，如 Qwen-vl、Chain-vl。 browser-use Python + 大语言模型（LLM）+ 浏览器驱动；基于 Playwright；同时支持视觉和非视觉模型；同时支持 DOM 分析和视觉分析。 
 Midscene优点： 基于 JS 技术栈，前端友好，开发成本较低；支持 Playwright、Puppeteer 定制行为逻辑；公开渠道反馈与迭代节奏相对清晰；支持 DOM 与视觉多模态分析。如上优点对工程化落地更友好。 Midscene缺点： 调用视觉/大模型时存在 Token 消耗与成本。

 browser-use优点： 支持 Playwright 定制行为逻辑；支持 DOM 与视觉分析，能力面较全。 browser-use缺点： 同样存在 Token 消耗与成本；基于 Python 技术栈，有开发语言熟悉成本。

 综合评估后采用 Midscene，主要考量： 与现有技术栈匹配： 以 JavaScript 为主，便于与前端工程、现有工具链协同，降低接入与维护成本。 能力与扩展方式符合需求： 支持 DOM 与视觉等多路径信息输入，并可在需要时用 Puppeteer / Playwright 补充确定性、可编排的自动化逻辑，覆盖模型不稳定或不适用的环节。 工程化与定制空间： 定制与扩展路径清晰，便于按业务拆解控制流、做兜底与回归，贴合当前团队的交付方式。

 核心流程可以概括为：将运营真实操作记录转化为可执行的测试用例，并通过智能化的方式在测试环境中回放验证。具体实现链路分为四个阶段：

 

 阶段一：智能用例生成——从“行为记录”到“可执行脚本”

 这是整个流程的源头与起点，目标是实现测试用例的“自动化生产”。

 

 阶段二：灵活执行触发——从“静态资产”到“动态任务”

 本阶段负责调度，将静态的测试用例转化为具体的执行任务。

 

 阶段三：AI驱动执行——从“指令”到“结果”的转化

 

 阶段四：平台化数据运营——从“结果”到“决策”的质量闭环

 

 通过这四个阶段的闭环，系统实现了从真实运营行为到自动化测试用例的完整转化，并将执行结果转化为可运营的质量数据。

 之后我们将持续优化 AI 模型的准确率和稳定性，逐步实现从「用例执行」到「质量预测」的升级。同时推动平台向标准化、智能化方向发展，让质量保障真正成为业务创新的加速器而非瓶颈。

流程：1轮电话面+1轮视频面 

 电话面：了解个人信息＋约面试时间

 个人认为电话面试虽然看起来相对简单，但是对于是否能够进入后续面试起着决定性作用。

 表现出对岗位的热情和了解，以及尽量保证尽快到岗、出勤天数和实习时长，这些客观因素往往会帮助你超越一部分竞争对手。

 视频面：

 1、简单的自我介绍。

 2、讲一下你XXX活动的经历，你在其中负责了什么，取得了什么结果？

 因为是活动运营岗所以主要问了我大一在乐高的线下活动经历（真的很久远）。所以大家对于自己简历上的内容一定一定一定要烂熟于心且适当做延伸，而且面试官 prefer想听你自己负责的哪部分，这个问题主要是让面试官看到为什么“我”要选择“你”，你给我能提供什么价值，并不是打打杂那么简单。

 3、你认为线上活动和线下活动的区别是什么？

 我之前实习是偏线下，和线上还是有一定区别的。另外，我结合对抖音电商运营谈了自己对于电商活动运营的理解。这样可以让面试官觉得即使没有相关经历但你也认真了解了岗位内容。

 4、你了解潮玩吗？说出几个你知道的潮玩。（相关问题：比如为什么选择得物？为什么（从其他职业）想做电商运营？等等）

 我说了两个吧（就没了）。复盘时候个人认为准备面试时要对所在行业的线上线下市场从大盘及细分角度有所熟知，以及行业现状和前景如何，说出自己的观点。（很重要！！通用经验！）

 5、反问环节：我们的日常工作内容都有什么？

 面试官说了两大块主要工作内容，for商家＆活动（具体有点忘记），问我想做哪一块。

 总体感受：整个面试很流畅，面试官人也很好。我选择投递得物的原因之一也是它是年轻人的潮流聚集地，工作内容和理念相信也是扁平化和丰富有趣的。

## 得物数据运营面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2023-01-03 ｜ [原文链接](https://www.nowcoder.com/discuss/439776323633016832)

得物面试基本都是一面，全程差不多半个小时。结果一般一到两个工作日就会出来，所以效率还是很高的，就是喜欢这种干脆的。

 1.自我介绍：我是分以下几部分介绍的（仅供参考）

 1:学校 专业 绩点排名（不高的话可以不说）获得奖学金等。

 2:课外参加的一些竞赛获奖情况。

 3:实习经历（简单介绍即可，比如有过几段实习，分别是什么岗位。不用太详细，后面他会根据简历详细问你的）

 4:为什么投递该岗位。表达对该岗位的渴望和对公司的认可（说是得物的忠实用户会加分，所以面之前多熟悉下app）

 2.深挖简历：确保简历上的每一句话都了如指掌！多问问自己这句话后面面试官可能会问些什么，特别是实习岗位中的工作内容。我们在写工作内容的时候其实可以写得含糊点，比如：我对大促活动进行了复盘。面试官肯定会好奇你在复盘的过程中有得到什么结论以及是否有后续改进方案，这样我们就可以把面试官引向我们准备的内容中，占领主导权。（只能浅浅主导一下下[笑cry]）

 3.sql题：sql是必考的，不用部门考察方式不同。我朋友面试的时候是拉了个飞书群，在飞书群里发布题目，然后把代码发到飞书群里；我的话就是口述思路，然后每步用什么函数，mentor主要看你的思路对不对，逻辑是否清晰。

 题量一般在两到三题这样，题目类型基本都是电商类的题目，比如每周鞋类销售情况、复购率等等。这部分只能靠刷题了，多刷刷牛客网，对每种类型题目进行总结，问题不大。

 4.业务题：这部分应该是最难准备的，因为没有实际接触过业务，很难像他们考虑得那么全面。但我们在面电商类公司的时候，最基础的电商类业务题我们要好好准备，比如：GMV下降如何分析、用户质量评价、大促活动效果如何评价等等。

 我的业务题是如何衡量得物社区用户质量以及如何提升用户质量。这还算比较常规的题目，之前正好准备过类似的，所以就可以套上。

 希望这篇文章可以给各位牛友一点帮助！实习了一段时间，体感不错，学到挺多东西。

## 2022届人力资源专业秋招记录

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-10-21 ｜ [原文链接](https://www.nowcoder.com/discuss/353158775542587392)

我的秋招基本上结束啦， 发个帖子记录一下这段经历

 希望能给和我差不多情况的朋友们一些帮助~

 祝大家早日上岸心仪的公司和岗位🥰

 
 

◆自身情况：211本 人力资源专业 
 ◆实习情况：一段互联网大厂人力实习+一段老牌互联网人力实习

 ◆秋招投递岗位：主投人力资源；次投运营岗（虽然很神奇的最后上岸了运营岗）因为自身喜欢游戏动漫这些，最初投递游戏、互联网公司相对多，后来就各行各业都投了一些，投递的中小厂偏多。

 ◆局势：211本没占据竞争力，职能岗hc少，投递者多且学历高。

 ◆建议：

 （1）笔试一定要练行测题（大佬们除外！）可以下个考公刷题app突击。我最初因为笔试很差，好多公司就挂在了笔试🥺

 （2）一定要海投、多投、早点投！我大概是投了60+家企业，有很多都是9、10月份才投的，其实相对来说很晚了。最初可能不知道该投怎样的企业，我投的这些希望能给大家一些灵感。

 （3）不要好高骛远、找准自己定位投递公司，谁都想去大厂，但是也不要光投大厂，要找一些中小厂。

 （4）面试挂了也不要灰心(⁎⁍̴̛ᴗ⁍̴̛⁎) 也许根本不是我们的问题，maybe是公司没有hc了。振作起来迎接下一场，如果一直低迷真的容易找不到工作，就不能成为富婆了（bushi）😢但是要经常复盘，有很多问题是重复问到的。

 （5）面试时候不要给自己挖坑，不太了解的一定不要说，面试官很有可能会顺着问下去。也不要和面试官因为聊的很好，看到他/她笑了觉得自己稳了然后就开始说真心话，很有可能那只是假象！我们还是要保持从容的心态。

 （6）不要怯场，要自信！！即使群面时候其他同学是比我们学历高很多的，也要装作自己不紧张。

 
 

 ◆人力岗面试经常问到的问题：

 （1）简历实习经历：包括在某段经历做了什么、结果、收获、遇到的困难怎么解决的、最有成就感的事情、最失败的事情……宝洁八大问这些。人力岗对于简历挖的相对较深，一定要把自己的实习经历说的很透彻有深度，体现你的思考能力。

 （2）自身：成长过程最有成就感的、最有挫折感、遇到的困难（上面那些可以围绕学生工作、校园经历或者实习来说）；自身优点缺点、别人对你的评价和你自己对你的评价；怎样选择公司和工作地点、父母的情况；自身职业规划是怎样的，精确到3年、5年；怎么样获取知识的，有看什么书？

 （3）职业路线：对公司有怎样的了解；对人力哪个板块感兴趣，为什么；觉得自己适合哪个板块，原因；没接触过这个工作的话，认为该如何入手。
