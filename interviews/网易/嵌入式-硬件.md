 自我介绍（2‑3 分钟） 

 为什么投递网易软件开发岗位？你的背景偏向嵌入式通信，怎么看待岗位差异？ 
答：底层 C/C++、内存管理、多线程、协议处理这些技术是相通的。虽然项目偏向嵌入式，但在项目中大量使用 C++ 面向对象、RAII 资源管理，熟悉大型项目编码规范。网易在游戏、互联网服务端底层软件技术积累深厚，我希望把底层开发能力迁移到业务软件开发，持续打磨 C++、系统底层能力。

 平时玩游戏吗？对游戏开发有没有了解？ 
答：平时偶尔玩游戏作为放松，没有实际游戏项目开发经验。但是游戏开发对实时性、资源调度、内存管理的要求，和我做过的实时系统项目底层思路相通，比如低延迟调度、资源生命周期管理，这些底层能力我可以快速迁移学习。

 项目开发周期看起来偏短，你怎么看待？ 
答：部分项目集中开发阶段时间不长，但均是完整落地工程。除原型项目，也参与过长周期实验室迭代项目，完整经历需求分析、编码、静态扫描、回归压测整套流程。原型项目侧重功能验证，长周期项目打磨稳定性，两类经历互补，能够快速上手全新业务。

 项目中遇到深浅拷贝问题，请举一个实际案例？如何避免后续重复出现这类隐患？ 
答：当类内部持有动态分配的指针成员，编译器默认拷贝构造只会做浅拷贝，复制指针地址，多个对象指向同一块堆内存。对象析构时会重复释放内存，触发 double free 程序崩溃。解决遵循 RAII、三 / 五法则，手动实现拷贝构造、赋值运算符，做深拷贝；不需要拷贝的类直接 delete 拷贝函数。工程上配合静态代码扫描工具、编码规范，明确资源所有权，优先使用智能指针管理动态内存，减少裸指针传递。

 编码过程中如何落实编码规范？工具和文档分别起到什么作用？ 
答：团队会有完整 C/C++ 编码规范文档，约束指针、结构体拷贝、内存管理、分支处理。开发流程上 CI/CD 集成静态扫描工具，代码提交自动检查隐患，告警不通过无法合入主干；同时强制 code review 人工复核。文档定标准，工具拦截大部分低级隐患，人工评审兜底复杂业务逻辑问题。

 讲一个印象最深的 bug，现象、定位手段、修复方案？ 
答：项目出现内存泄漏，函数内部动态申请内存，部分异常分支直接 return 退出，没有执行释放逻辑。一开始想用 goto 统一回收资源，后续改用 unique_ptr 智能指针，依靠 RAII 对象生命周期结束自动释放内存。修复后编写对应测试用例，跑回归 FT，CI 扫描无告警，长时间压测验证不再泄漏。

 CI/CD 静态扫描工具，拿到的输出结果是什么？改完如何确认修复正确，不会引入新 bug？ 
答：工具输出告警报告，标记风险代码行、隐患类型，例如内存泄漏、空指针、未初始化变量。修复后本地编译，执行单元测试、功能测试；提交触发 CI 自动跑全套回归用例，全部 pass、无新增告警；复杂改动还要做 code review，确认分支逻辑全部覆盖，排除回归问题。

 FreeRTOS 多任务共享数据，如何保证数据一致性？互斥锁会带来什么问题？ 
答：共享结构体、传感器数据访问使用互斥锁保护，读写都要获取锁，操作完成释放锁，避免读到脏数据。互斥锁会带来优先级反转问题；FreeRTOS 互斥锁开启优先级继承缓解该问题；编码尽量缩小临界区，锁内只做数据拷贝，禁止复杂运算，降低阻塞时间。

 什么是优先级反转？除了优先级继承，还有哪些工程上规避手段？ 
答：高优先级任务等待低优先级任务持有的互斥锁，中间优先级任务抢占 CPU，导致高优先级长时间阻塞。工程手段：缩小临界区减少持锁时间；架构层面避免高优先级任务等待低优先级任务所持锁；锁获取顺序统一；设置锁等待超时；必要采用无锁队列、双缓冲方案代替锁。

 自定义通信协议帧如何设计？如何保障无线通信链路的可靠性？ 
答：帧结构包含帧头、命令字、数据长度、有效载荷、校验和。可靠性手段：CRC 校验丢弃错误帧；序列号检测丢包乱序；超时重传；心跳检测；设置失联超时阈值，触发安全保护逻辑；强干扰场景增加重传次数，必要前向纠错。

 通信连续丢包如何区分是短暂干扰还是真正失联？失联之后业务层做什么处理？ 
答：少量丢包只触发重传，不判定失联；只有连续多次心跳、报文超时，多次重传全部失败，才判定链路失联。业务层清空过期缓存指令，执行预设安全策略；链路恢复后重新握手同步状态，再恢复正常业务交互。

 C++ RAII 机制是什么？解决什么问题，举几个实际使用场景？ 
答：资源获取即初始化，构造函数获取资源，析构函数释放资源，栈对象出作用域自动释放。解决异常、提前 return 导致资源忘记释放。应用：unique_ptr/shared_ptr 管理堆内存；lock_guard 管理互斥锁；fstream 管理文件句柄。

 C++ 智能指针区别？shared_ptr 循环引用如何解决？ 
答：unique_ptr 独占所有权，移动语义，不允许拷贝；shared_ptr 引用计数实现共享；weak_ptr 不增加引用计数，用来解决 shared_ptr 循环引用。循环引用时两个对象 shared_ptr 互相持有，引用计数永远不为 0，内存泄漏，引入 weak_ptr 打破环。

 vector 底层扩容机制？扩容会发生什么问题？ 
答：vector 动态数组，容量不足开辟更大新内存，把旧元素拷贝移动过去，释放旧内存。扩容会迭代器、引用全部失效；频繁扩容带来大量内存拷贝，性能损耗；提前 reserve 预留容量可以减少扩容次数。

 select 和 epoll 的区别？epoll 水平触发和边缘触发差异？ 
答：select 文件描述符有上限，每次调用拷贝大量 fd，遍历全部描述符 O (n)；epoll 内核红黑树管理 fd，就绪链表回调，O (1) 拿到就绪事件，没有数量限制。水平触发：只要缓冲区有数据就持续通知；边缘触发只有状态变化通知一次，ET 模式必须一次性读完缓冲区全部数据，否则事件不再触发。

 大量 TIME_WAIT 是什么原因？带来什么风险？如何优化？ 
答：TIME_WAIT 是主动关闭连接一方状态，保持 2MSLS。大量 TIME_WAIT 代表大量短连接。风险占用端口，新连接无法建立；占用内核内存。优化：服务端尽量改为被动关闭；调整内核 tcp_tw_reuse 参数；业务层面长连接复用代替频繁短连接。

 线上程序偶发崩溃，core 文件栈被破坏，怎么一步步排查定位？ 
答：栈被破坏 bt 调用栈不可信，先看崩溃信号 SIGSEGV/SIGBUS，查看寄存器、崩溃地址；怀疑越界写、use‑after‑free、double free。优先 ASan/UBSan 复现；无法线上开启工具，增加对象 canary、日志；查看业务日志，定位复现场景，构造最小复现 demo，压测复现问题。
