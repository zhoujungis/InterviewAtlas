## 写给看到这篇秋招经验贴的有缘人，希望助你收割大厂~

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-09-14 ｜ [原文链接](https://www.nowcoder.com/discuss/353158506821918720)

9.1号小米二面完，9号拒了用友的高潜批群面，正式结束我的2021年秋招了。本来是想签完三方一切稳定了再分享一下我的经验，可是觉得现在互联网秋招似乎是越来越早，差不多是金八银九了，早点发出来可能就会给以后找工作的同学们更早带来帮助。
 
 先说下我的基本情况吧。计算机科班，双非本，末流985硕，本科混了两个国家级竞赛奖(然而面试从没被问过)，研二在华为实习了两个月(托导师的福)，算法很菜，题刷了300左右，简历写了两个项目，一个实验室的项目，一个自学的SpringBoot项目(跟着视频复现)，工作意向是北京的Java开发。秋招投递了34个公司，参加了12个公司的面试(有的笔试挂了有的拒了)，拿到了字节百度美团京东以及几个中小厂的意向书。下面我就结合自己的经历，从准备、投递、面试几个方面来分享一些经验，希望能够帮到大家。
 
 首先是秋招的复习准备。准备当然是越早开始越好，不过如果你开始的晚，也不必着急，只要努力，策略得当，也来得及。对于Java后端来说，面试涉及的内容主要包括：计算机网络、操作系统、Java、MySQL、Redis、SSM框架、消息队列如Kafka(非必需)、搜索引擎如ElasticSearch(非必需)以及你的项目和手撕算法。对于计算机网络和操作系统，我在复习时主要是看了小林coding的图解网络及图解系统的系列文章，深度和广度都很够，个人觉得足以应对大多数面试题。对于Java，主要涉及到Java基础、集合、并发编程、JVM四个方面。推荐B站尚硅谷宋红康老师讲的视频及书籍疯狂Java讲义、并发编程的艺术、深入理解Java虚拟机。MySQL部分，推荐先看MySQL必知必会，然后再看MySQL是怎样运行的，如果想继续提升，可以看极客的MySQL45讲(有点难)。Redis部分，必看经典的Redis设计与实现，再根据面经进行扩展，基本够用。后台框架如SSM可以看B站尚硅谷的视频，这部分的重点主要是Spring和SpringMVC，而且对于应届生，不会太深入，建议直接面向面经复习。其他非必需的技术，我没有深入的学习过，不作推荐，只是整理了相关的面试题来复习。以上的内容，我们称为基础，现在也叫八股，如果时间充足，耐心学习完上面的内容，八股自然就在心中了。如果没有足够的时间去看这么庞大的内容，可以面向面经复习。我的建议是，以JavaGuide作为大纲，作为第一轮复习基础，掌握这些后，进行广度和深度的扩展，通过相关知识点的博客及面经来形成自己的一个复习文档，当然我自己也有整理，如果你需要，可以私信我（或Q群--917205237--，笔记放在这里了，不是广告群哈，秋招相关的问题可以在群里交流，我看到也会帮忙解答的）。算法方面，我的算法真的是很辣鸡，笔试基本就是a一道两道的水平。但是面试的手撕算法我却全都做出来了，一方面是运气，一方面是我的复习策略吧。其实我很早就开始刷算法题了，20年上半年疫情在家，每天3道easy题，把力扣所有的easy题都做了一遍，可惜那时候就是按序号刷，一点规律和总结都没有，刷了几百道一点提升都没有，浪费了半年时间。后来我知道了labuladong的算法小抄和codetop，前者让我学会了一些做题的模板和套路，后者则统计了高频的算法题。后期我在做题时，发现了代码随想录，感觉他的题解质量都很高，而且他也有专门讲算法的文章，感觉也很不错，不过当时我没时间从头学了。我跟着算法小抄做了上面的题，又刷了剑指offer和力扣的Hot100，以及codetop上面的前十页高频题，这些题其实有很多重叠的，如果熟练掌握了，我觉得对开发来说，已经可以应付大多数的手撕算法了。对了，还有就是手撕SQL，我是练习了这个：50道SQL练习题及答案与详细分析，感觉也够用了。在项目上，我当初是准备了一个RPC项目和牛客论坛的项目，但是学习RPC的时间不够了，就用实验室项目代替了它。如果同学们没有项目，可以去JavaGuide的github上面找找，他有一些不错的推荐。项目不用太多，2个足够，但是要吃透，禁得起问。
 
 如果你准备充分，实际上准备到70%左右，就可以开始尝试投递了。投递前当然是要先说下简历，程序员的简历一定要简洁干净，切忌用花里胡哨的模板，简历上写的东西一定是你自己掌握很好的，如果写了不擅长的东西，那就是给自己挖坑。投递可以分为实习和秋招两个阶段。如果你复习的比较早，一定要投递各个厂的暑期实习，一是检验自己的复习成果，二是可以提前积累面试经验，最重要的是，有很多厂是有秋招直通车的，也就是即使你拿到了实习offer没去，秋招时是有直通终面的机会的！多香啊~所以，即使你的老师不让去实习，也不要放弃投递实习。但是切记，如果复习不到位，就安心复习，千万不要盲目投，因为你的实习面评可能会影响秋招，我认识好几个人就是实习面评差被锁简历了。然后就是秋招，我感觉现在的秋招简直是夏招，7月份百度字节京东就开了提前批，8月份美团腾讯阿里网易等大中厂就开了正式批。等到九月初，我认识好多人都已经拿了几个大厂offer躺平了。所以，秋招，一定要争分夺秒！早复习，早投递！无论是提前批还是正式批，越早优势越大。首先，开始的时候，简历相对较少，HC较多，流程走的也快。随着时间推移，流程会变慢，池子也越来越大，泡池子的感觉可不好受。很多同学想先投一些小厂练手，然后再冲大厂，其实有个问题就是，往往小厂的流程都比较慢，如果等小厂面完再去投大厂，可能已经比较迟了。所以我的建议还是，有条件的同学尽量早点开始准备，时间就是你最大的优势。在投递时，还要注意一下，如果你没有地点要求，尽量选HC多的base，比如我就只去北京，其实北京腾讯虾皮阿里什么的，都是没有总部HC多的，竞争还激烈， 投递总部机会会更多一些。
 
 最后一部分就是面试了，我会简单介绍我参加的12家公司的面试体验和我根据身边人了解到的相关情况，仅供参考。首先是字节，字节的流程是最快的，一共三轮技术面，我是提前批，投递完两天就约面了，HR全程跟进，体验极好。面试官都是根据项目来问一些场景和八股，众所周知字节非常看重算法，难度也很大，如果你的题刷的少，建议先别冲字节。京东是我面的第二家，我的体会是想和东哥做兄弟，运气远大于实力。京东一共两轮技术面，各个人的面试难度只能说参差不齐，有的人两轮技术加起来30分钟，有的每轮都1个小时，有top2硕大佬HR被刷，也有985硕一面就挂，如果被京东挂，只是你没有跟东哥做兄弟的命，无他。百度是我面的第三家，也是最慢的一家，从一面到OC用了50天。百度有三轮技术面，但提前批第三轮经理面有的只是聊天，不问技术。提前批三轮是分开的，但是正式批是集中面试，连续三面，不知之前是否是这样，好多公司在秋招都采用集中面试，如果当天没有走完全部面试流程，就说明你挂了。我没参加百度正式批，据我了解正式批的三面都是交叉面。美团是流程第二快的，仅次于字节，技术面有二有三，分部门。我从一面到HR完成就一个星期，又隔两天收到意向。美团是对我来说是压力最大的，三轮技术面试下来，一共是60+80+100分钟，问了很多智力题、场景题、设计题、并深挖项目。身边其他同学反馈反而不是很难，并且美团的手撕普遍很简单，基本都是easy或medium。猿辅导也是三轮技术面，都安排在周末，猿辅导的算法题很难，前两面都出了hard，还都不是高频的，在面试官引导下才勉强做出来。HR说两周内给消息，目前已经快3周还没给我意向。腾讯是我第一个挂的公司，也是我体验最差的，本来我官方流程显示初试过了已经到复试，结果又给我挂了，显示官网流程终止，我以为是bug，后来给我发的邮件还说是复试，结果面试到一半才发现是被别的部门捞起来重新面的，然后和面试官委婉提出了终止面试。腾讯多数部门是2-3轮技术面。另外，腾讯北京不是大佬建议别冲。阿里是我主动拒面的，一志愿简历挂了，然后二志愿被阿里健康捞了，当时手里有几个offer了，不想面试被pua，就拒了，阿里的技术也是2-3轮，好像是以电话为主，随时突袭。贝壳和度小满都是集中面试，难度一般，手撕都是简单题有的甚至不撕。贝壳连续两轮技术面+HR面，我挂在了HR面。度小满三轮技术，三面是技术主管，收到测评就代表面试通过了，测评后隔两天收到了意向书。手机厂面了小米和荣耀，都是两轮面试。小米两轮都是技术，难度一般，手撕简单。荣耀一面问基础，全是八股，无手撕，二面主管面，主要问校园经历+聊天，向你传输公司文化，其实就是告诉你得能加班，已拿意向书。还有个北京用友网络，投的高潜批，就一轮技术，全程八股，高潜批额外还有个高管团群面，拒了(后悔)。其他公司，虾皮简历挂，蔚来笔试挂，携程测评挂(有点sb)，网易顺丰华为新浪等其他投递的都拒了，把机会留给别人吧。面试其实就是一个和面试官互动交流的过程，不同面试官的风格也很不同，要去适应。不过整体上看，面试无非是八股+项目+场景题或设计题+算法。很多同学惧怕场景题，其实在我看来场景题也不过是八股的延伸。最简单的，比如直接问你Redis缓存雪崩缓存穿透你能背出来。那问你项目里用到redis了吗，在实际使用时有什么问题，你就得反应一下，知道有缓存雪崩、缓存击穿、缓存穿透，缓存不一致等问题。再比如不直接问你分布式锁如何实现，而是根据一个需要用分布式锁的场景，问你怎么解决，你得知道是用分布式锁，然后再说怎么用。所以本质上还是对这些基础知识的融会贯通，能够灵活运用。
 
 最后，我想说的是，找工作是需要实力+毅力+运气的。你需要有持久的毅力，不断的去学习，提升自己；你需要有绝对的实力，才能在面试时不露怯，对答如流；你需要好运气，保佑你笔试懵的都是对的，面试考的都是会的，部门HC多池子又小，如果面试屡屡受挫，千万不要质疑自己，别放弃，别气馁，做好复盘，查缺补漏，好运总会眷顾你。祝福同学们都能拿到满意的offer，如果有问题，可以留言或私信，我会尽力解答。

 MySQL的基础架构 

 

 MySQL 的基础架构可分为 Server 层和存储引擎层两部分，Server 层包含 MySQL 的大多数核心服务功能，存储引擎层负责数据的存储和提取。各模块功能如下：

 连接器：负责跟客户端建立连接。

 查询缓存：之前执行过的查询语句会以 key-value 的形式存在缓存中，MySQL 收到一条查询语句会先去查一下缓存中是否有相同的 key，如果有直接把 value 返回。但是这个功能在表更新比较频繁的场景中别用，因为每次表更新都会刷新缓存。

 分析器：会对输入的 SQL 语句进行词法分析和语法分析。

 优化器：优化器制定SQL语句的执行方案，比如会从表里的多个索引中选择一个最合适的索引，或者在一个语句有多表关联的时候，决定表的连接顺序。

 执行器：根据优化器定制的执行计划进行操作，返回结果。

 存储引擎：存储数据，提供读写接口。

## 网易Java后端开发面试心得

来源：掘金 ｜ 类型：面经 ｜ 发布：2019-01-26 ｜ [原文链接](https://juejin.cn/post/6844903768027299847)

Java后端面试标准其实不复杂：第一能干活，第二Java基础要好，第三最好熟悉些分布式框架。

 其实，很多面试者能力其实不差，但面试时没准备或不会说，这样的人可能在进团队干活后确实能达到期望，但可能就无法通过面试，但面试官总是只根据面试情况来判断。

 但现实情况是，大多数人可能面试前没准备，或准备方法不得当。要知道，我们平时干活更偏重于业务，不可能大量接触到算法，数据结构，底层代码这类面试必问的问题点，换句话说，面试准备点和平时工作要点匹配度很小。

 在本文里，将通过一些常用的问题来介绍面试的准备技巧。大家在看后一定会感叹：只要方法得当，准备面试第一不难，第二用的时间也不会太多。

 1. 框架是重点，但别让人感觉你只会山寨别人的代码 

 在面试前，面试官会阅读简历以查看面试者在框架方面的项目经验，在面试者的项目介绍的环节，面试官也会着重关注面试者最近的框架经验，目前比较热门的是SSM。

 其实我们每个人都这样过来的，但在面试时，如果你仅仅表现出这样的能力，就和大多数人的水平差不多了，在这点就没法体现出你的优势了。

 我们知道，如果单纯使用SSM框架，大多数项目都会有痛点。比如数据库性能差，或者业务模块比较复杂，并发量比较高，用Spring MVC里的Controller无法满足跳转的需求。所以面试官一般还会主动问：你除了依照现有框架写业务代码时，还做了哪些改动？

 对于这个问题，面试官不在乎听到什么回答，面试官只关心回答符不符逻辑。一般只要答对，面试官就会给出“在框架层面有自己的体会，有一定的了解”，否则，面试官就只会给出“只能在项目经理带领下编写框架代码，对框架本身了解不多”。

 其实，在准备面试时，归纳框架里的要点并不难，我就不信所有人在做项目时一点积累也没，只要你说出来，可以说，这方面你就碾压了将近7成的竞争者。

 2. 别单纯看单机版的框架，适当了解些分布式 

 此外，在描述项目里框架技术时，最好你再带些分布式的技术。

 
 
 反向代理方面，nginx的基本配置，比如如何通过lua语言设置规则，如何设置session粘滞。如果可以，再看些nginx的底层，比如协议，集群设置，失效转移等。

 
 远程调用dubbo方面，可以看下dubbo和zookeeper整合的知识点，再深一步，了解下dubbo底层的传输协议和序列化方式。

 
 消息队列方面，可以看下kafka或任意一种组件的使用方式，简单点可以看下配置，工作组的设置，再深入点，可以看下Kafka集群，持久化的方式，以及发送消息是用长连接还是短拦截。

 
 以上仅仅是用3个组件举例，大家还可以看下Redis缓存，日志框架，MyCAT分库分表等。准备的方式有两大类，第一是要会说怎么用，这比较简单，能通过配置文件搭建成一个功能模块即可，第二是可以适当读些底层代码，以此了解下协议，集群和失效转移之类的高级知识点。

 如果能在面试中侃侃而谈分布式组件的底层，那么得到的评价就会比较好了，比如“深入了解框架底层”，或“框架经验丰富”，这样就算去面试架构师也行了，更何况是高级开发。

 3. Java核心方面，围绕数据结构和性能优化准备面试题 

 Java核心这块，网上的面试题很多，不过在此之外，大家还应当着重关注集合（即数据结构）和多线程并发这两块，在此基础上，大家可以准备些设计模式和虚拟机的说辞。

 
 
 String a = "123"; String b = "123"; a==b的结果是什么？ 这包含了内存，String存储方式等诸多知识点。

 
 HashMap里的hashcode方法和equal方法什么时候需要重写？如果不重写会有什么后果？对此大家可以进一步了解HashMap（甚至ConcurrentHashMap）的底层实现。

 
 ArrayList和LinkedList底层实现有什么差别？它们各自适用于哪些场合？对此大家也可以了解下相关底层代码。

 
 volatile关键字有什么作用？由此展开，大家可以了解下线程内存和堆内存的差别。

 
 CompletableFuture，这个是JDK1.8里的新特性，通过它怎么实现多线程并发控制？

 
 JVM里，new出来的对象是在哪个区？再深入一下，问下如何查看和优化JVM虚拟机内存。

 
 Java的静态代理和动态代理有什么差别？最好结合底层代码来说。

 
 上述的问题，其实不仅仅只停留在“会用”级别，比如面试官不会问如何在ArrayList里放元素。大家可以看到，上述问题包含了“多线程并发”，“JVM优化”，“数据结构对象底层代码”等细节，大家也可以举一反三，通过看一些高级知识，多准备些其它类似面试题。

 4. 通读一段底层代码，作为加分项 

 如何证明自己对一个知识点非常了解?莫过于能通过底层代码来说明。

 
 
 ArrayList,LinkedList的底层代码里，包含着基于数组和链表的实现方式，如果大家能以此讲清楚扩容，“通过枚举器遍历“等方式，绝对能证明自己。

 
 HashMap直接对应着Hash表这个数据结构，在HashMap的底层代码里，包含着hashcode的put，get等的操作，甚至在ConcurrentHashMap里，还包含着Lock的逻辑。我相信，如果大家在面试中，看看而言ConcurrentHashMap，再结合在纸上边说边画，那一定能征服面试官。

 
 可以看下静态代理和动态代理的实现方式，再深入一下，可以看下Spring AOP里的实现代码。

 
 或许Spirng IOC和MVC的底层实现代码比较难看懂，但大家可以说些关键的类，根据关键流程说下它们的实现方式。

 
 不要小看这个，一旦你讲了，只要意思到位，那么最少能得到个“肯积极专业“的评价，如果描述很清楚，那么评价就会升级到“熟悉Java核心技能（或Spring MVC），且基本功扎实”。要知道，面试中，很少有人能讲清楚底层代码，所以你抛出了这个话题，哪怕最后没达到预期效果，面试官也不会由此对你降低评价。所以说，准备这块绝对是“有百利而无一害”的挣钱买卖。

 5. 一切的一切，把上述技能嵌入到你做过的项目里 

 你之前费了千辛万苦（其实方法方向得到，也不用费太大精力）准备的很多技能和说辞，最后应该落实到你的实际项目里。

 请记得，“实践经验”一定比“理论经验”值钱，而且大多数你知道的理论上的经验，一定在你的项目里用过。所以，如果你仅仅让面试官感觉你只有“理论经验”，那就太亏了。

 小结 

 本文给出的面试题并不多，但本文并没有打算给出太多的面试题。从本文里，大家更多看到的是面试官发现的诸多面试者的痛点。

 你的能力或许比别人出众，但如果你准备面试的方式和别人差不多，或者就拿你在项目里干的活来说事，而没有归纳出你在项目中的亮点，那么面试官还真的会看扁你。
