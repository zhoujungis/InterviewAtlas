## 某辅导教育大厂真实面试过程与经验总结

来源：掘金 ｜ 类型：面经 ｜ 发布：2025-09-19 ｜ [原文链接](https://juejin.cn/post/7551322994409783311)

面试概述

 某辅导是国内知名的在线教育平台，面试过程通常包括笔试、技术面试和系统设计面试，具体流程如下：

 

 
 笔试环节 ：主要测试基础编程能力、数据结构与算法以及一些计算机网络和操作系统的知识。

 技术面试 ：考察候选人的编程能力、系统设计能力以及对常见技术栈的掌握情况（如 MySQL、Redis、Dubbo 等）。

 系统设计面试 ：针对高并发、大规模分布式系统的设计问题进行考察，通常涉及架构、数据一致性、分布式系统等方面。

 
 在面试过程中，面试官通常会提问一些涉及到技术细节的问题，并要求结合实际项目经验进行阐述。下面是我在猿辅导教育大厂的面试过程总结。

 

 1. 一个网页从输入到获取数据的过程经历了什么 

 这个问题的目的是考察你对网页请求过程的理解。在一个标准的网页请求过程中，通常会经历以下几个步骤：

 
 DNS解析 ：浏览器首先通过域名解析（DNS）将 URL 转换为目标 IP 地址。

 TCP连接 ：浏览器和服务器通过三次握手建立 TCP 连接。

 HTTP请求 ：浏览器向服务器发送 HTTP 请求，包括请求头、请求体等内容。

 服务器处理 ：服务器接收到请求后，解析请求并处理，比如查询数据库或调用其他服务。

 返回数据 ：服务器处理完成后，返回 HTML、CSS、JavaScript 或数据（如 JSON）等响应内容。

 浏览器渲染 ：浏览器解析返回的数据，进行渲染显示。

 
 

 2. 介绍一下项目 

 在面试中，我介绍了我参与的一个 电商系统项目 。该项目是一个高并发的分布式系统，涉及到的技术栈包括 Java、Spring Boot、MySQL、Redis 和 RabbitMQ。我的主要工作是负责 订单处理模块 ，包括订单的创建、支付、库存管理等功能，并实现了高效的 异步处理和消息队列 来应对系统的高并发请求。

 3. MySQL的索引 

 MySQL 的索引是一种数据结构，主要用于加速数据的查询。常见的索引类型包括：

 
 B-Tree索引 ：最常见的索引类型，适用于范围查询、排序等操作。

 Hash索引 ：适用于等值查询，查找速度非常快，但不支持范围查询。

 全文索引 ：用于全文搜索，特别适用于查找包含特定单词的文本字段。

 联合索引 ：多个列组成一个索引，可以提高复合查询的性能。

 
 4. 慢查询优化 

 慢查询指的是执行时间较长的 SQL 查询。常见的优化方法包括：

 
 创建适当的索引 ：优化查询条件中的字段，确保查询能利用索引。

 优化查询语句 ：避免使用 SELECT * ，只查询需要的字段，避免在 WHERE 子句中使用函数。

 分解查询 ：将复杂查询拆分成多个简单的查询，减少数据库的计算压力。

 查询缓存 ：开启查询缓存，减少重复查询的次数。

 EXPLAIN分析 ：通过 EXPLAIN 命令分析 SQL 执行计划，找出瓶颈所在。

 
 5. Redis的缓存穿透和雪崩 

 
 缓存穿透 ：指请求的数据既不在缓存中，也不在数据库中。可以通过 布隆过滤器 或者将无效请求记录到缓存中来防止缓存穿透。

 缓存雪崩 ：指缓存中存储的多个数据在同一时间过期，导致大量请求直接访问数据库。解决方法包括 设置不同过期时间 ，或者使用 双重缓存 方案。

 
 6. Dubbo的负载均衡策略 

 Dubbo 提供了多种负载均衡策略，常见的有：

 
 随机策略 ：随机选择一台服务器进行请求处理。

 轮询策略 ：按照顺序选择服务器，平均分配请求。

 加权轮询 ：给不同的服务器设置不同的权重，权重大的服务器被选择的概率更高。

 最少活跃调用 ：选择当前活跃调用最少的服务器，避免某一台服务器负载过高。

 
 7. 分布式一致性哈希的原理 

 一致性哈希是一种用于解决分布式系统中节点动态增减问题的算法。它通过将每个节点和数据映射到一个环形空间上，保证节点的增减不会导致大量数据的重新分布，从而提高系统的可扩展性和稳定性。

 8. zk和redis实现分布式锁的原理 

 
 Zookeeper 分布式锁 ：Zookeeper 提供了可靠的分布式协调服务，通过在 Zookeeper 上创建临时顺序节点实现分布式锁。客户端在获取锁时，创建一个顺序节点并判断其是否为最小节点，如果是，则获取锁。

 Redis 分布式锁 ：Redis 通过 SETNX 命令实现分布式锁。如果锁不存在，客户端可以设置锁并获取。为了防止死锁，通常还会设置锁的超时时间。

 
 9. MQ的特性 

 消息队列（MQ）的主要特性包括：

 
 异步解耦 ：生产者和消费者之间解耦，生产者不需要等待消费者处理完毕。

 可伸缩性 ：可以通过增加消费者实例来扩展消费能力。

 可靠性 ：消息队列支持消息持久化和确认机制，确保消息不会丢失。

 
 10. RocketMQ事务消息的模型 

 RocketMQ 的事务消息模型支持分布式事务。分为三部分：

 
 事务消息发送 ：发送事务消息时，首先发送一个半消息到 Broker。

 事务执行 ：消息生产者执行本地事务，根据执行结果提交或回滚事务消息。

 事务状态确认 ：Broker 根据生产者的事务状态来决定是否提交或回滚消息。

 
 11. 如何维持幂等性 

 幂等性保证同一操作多次执行的结果相同。在分布式系统中，可以通过以下几种方式实现幂等性：

 
 唯一标识符 ：每次操作使用唯一标识符来标识请求，防止重复提交。

 数据库唯一约束 ：通过数据库的唯一索引来确保数据的一致性。

 
 12. final的关键字的作用 

 
 修饰变量 ：确保变量的值不可修改。

 修饰方法 ：表示方法不可重写。

 修饰类 ：表示类不能被继承。

 
 13. final关键字修饰引用类型，那么在GC有什么特点 

 final 修饰的引用类型变量，表示引用指向的对象不可修改，但对象本身的内容可以变化。GC 仍然会回收该对象，只是引用本身不能被更改。

 14. 写题：非递归的对称二叉树 

 对于二叉树的对称性检测，可以使用 非递归 的方式，利用 栈 或 队列 来模拟递归过程。

 
 public boolean isSymmetric(TreeNode root) {
 if (root == null) return true;
 Queue queue = new LinkedList<>();
 queue.offer(root.left);
 queue.offer(root.right);
 
 while (!queue.isEmpty()) {
 TreeNode left = queue.poll();
 TreeNode right = queue.poll();
 
 if (left == null && right == null) continue;
 if (left == null || right == null) return false;
 if (left.val != right.val) return false;
 
 queue.offer(left.left);
 queue.offer(right.right);
 queue.offer(left.right);
 queue.offer(right.left);
 }
 return true;
}

数据预取与本地缓存
• 提前加载数据：在应用启动或空闲时段，主动从其他集群节点预取可能会用到的数据，存储在本地缓存中。这样当需要使用这些数据时，可直接从本地缓存获取，减少对其他集群的查询请求。
• 结合本地缓存工具：利用如Ehcache、Caffeine等本地缓存工具，与Redis集群配合。对于访问频繁且不要求强实时性的数据，在从Redis获取后存入本地缓存，后续优先从本地缓存读取。
优化数据分布与查询逻辑
• 合理设计分片键：根据业务数据特点和查询模式，选择合适的分片键。让经常一起查询的数据尽量分布在同一集群节点上，减少跨节点查询。如以用户ID为分片键，将同一用户相关数据存储在同一节点。
• 批量查询：如果有多个查询请求涉及不同集群节点的数据，尽量将这些请求合并为批量查询。利用Redis集群的mget等批量操作命令，一次请求获取多个数据，减少请求次数。

## 2023届，双非本非科班转码之路，上岸大厂经验总结与分享

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-11-29 ｜ [原文链接](https://www.nowcoder.com/discuss/427138132425908224)

文头先放个秋招个人面经汇总，有需要的可以看看： 2023届秋招前端面经汇总：包含快手、字节、华为、荣耀、猿辅导等共二十余场面试 

 其实从国庆节后收到快手和猿辅导的两个意向开始，我的秋招就结束了。现在三方已经寄出，差不多可以写个总结帖来给自己的秋招画上个句号。大学经历还差五次阳光长跑和一个毕设，只能画个逗号，还画不了句号 : (

 1. 个人情况

 杭州非211双非一本 万金油工科专业 一段实习，零奖项，无出众校园经历 2. 转码历程

 跟大多数人相似，刚上大学的我没什么清晰的规划，不过总的来说还是奔着考研去的，谁还没个名校情结呢。

 因为我这个专业的原因，军训的时候就接触到了恩智浦智能车，当时觉得好厉害，于是就以这个为短期目标开始构建大学未来几年的框架。

 大一期间基本都是学C、玩单片机，自己学点嵌入式的东西。之后在大一暑假的智能车实验室集训，起初练习做的东西还蛮有意思会有点成就感，但是后期调车的阶段，确实有点没绷住，硬件的玄学问题、通宵调参负收益，引起的心态问题让我开始怀疑我是不是不适合做这行。

 集训结束回家休息那半个月，我就开始在知乎搜，在论坛找学长询问智能车这个比赛对自己技术成长的帮助。最终得到的结果让我在正式进入校实验室的两周后就离开，并试着探索其他赛道。

 当时考虑到了几个因素：首先是得避免跟硬件接触，再者尽量不要浪费之前一整年打下来的软件基础，第三最好是要自己感兴趣的方向。于是就自然而然的踏入了“互联网”这个赚血汗钱的赛道。

 这个时候开始，也开始重新思考要不要考研的问题（“你为什么不考研？”最后居然变成了我的面试被问的高频题 =n=）。考虑的因素有很多，各有权重，但最终总结起来差不多就是：学校凑合能看，我想做工程，进大厂有希望，考研只想强校且没上岸不接受二战，不考了。

 3. 开始转码

 探索踩坑

 大二一整年基本都在踩坑，虽说因为兴趣问题初步选择了前端这个方向，不过那个时候也不懂找个靠谱的学长带，更不懂牛客、知识星球、掘金这种网站可以找到相对较多的干货和学习路线。于是从三件套入门之后就开始学 jQuery，bootstrap，vue2，node，mysql....什么都学一点，但是学的也都不扎实。

 跟很多自学前端的小白一样，心里也都会有一个问题：前端的门槛和天花板会不会太低，不利于自己后续的发展（鸡、米、键盘）。于是出现中途有两个月跑去学 java和数据库的情况（现在已经忘光了）

 重学基础

 转折点是第一次面试的失败与掘金的一篇面经。

 第一次面试，那时候连“面经”是个什么东西都不知道。虽说时隔一年半，但由于尴尬和羞愧，当时的题目是什么我还能很清楚的记得。

 讲一下HTML有哪些标签 get 和 post 请求的区别 讲一下三次握手和四次挥手 从网址栏输入url到展现出页面都发生了什么 算法：括号匹配（朴实无华版） 反问 除了第一题和最后一题（反问），其他的答得都不尽如人意。

 在那之后不久，有一天在掘金上（进步很大，已经会找博客看了）看到了神三元的一篇面经，才发现原来前端要学这些东西，得学到这种程度。至此，开始下定决心打好基础重学前端，这个时候大概是大二刚结束。

 大二浪完了对我来说大学的最后一个暑假，大三一开学就开始在b站看王道考研的408，也没学多深，只是过一遍让脑子里有个印象和大致的索引。然后开始重学前端，但把重点放在了 js 和 vue 上面，求深不求广。

 实习

 过完年就开始刷面经准备找个实习，二月份赶出来了一个包装之后没什么亮点但还凑合能看的项目，不过这个时候还没刷什么算法，所以就先投了几个中小厂的实习试水，打算刷算法到三月底再开始投大厂。但最后由于简历不行，只收到了两家大厂的面试邀请（后续因为约面时间太晚以及怕脏面评的原因拒掉了）

 最后在四月选择了一家安防中厂实习，平时的工作内容挺简单的，唯一的难点可能就是在屎山里面找逻辑，一周的需求差不多两天就能做完开始摸鱼刷题。但是对应的，没有什么拿得出手的产出，也代表着到时候秋招的简历上面“项目经历”一栏没什么能写的。

 恰好这个时候，咕了我半个月的体面厂终于oc了，于是我果断结束了这个为其半个多月的第一段实习跑路去隔壁体面厂喝开水。事实证明我的运气和决策都还不错，到了康子后就得到了几乎从零开始参与做一个产品的机会，最后这个项目也成了简历上一个在面试的时候比较有讨论点的东西。

 起初的规划是实习到八月底，但春天开始的各厂裁员毁三方，提前批简历筛选比往年严格很多，今年各厂秋招要猛缩hc的消息。都让我重新开始审视自己在校招大军中的竞争点在哪，继续实习重复搬砖有没有意义。

 于是在暑期留校申请通过之后的第二天，我就跟 mt 和 ld 提了离职，两天后顺利跑路。（注：留个工卡做纪念都要赔工本费）

 4. 秋招总结与分享

 整个秋招包含提前批在内一共投了 72 个简历，共参加 28 场笔试，共进面 11 家，技术面排序被挂两家，其余都走到 hr 面或者主管面，最后拿下 4 个意向。

 下面是我个人学习的方法和经验，仅供各位参考。

 八股

 html+css 和计算机网络，这些内容我是用最暴力直接的方法，遍历一遍网上能找得到的面经，不仅限于校招生，还包括两三年经验社招的面经。遇到不会的就弄懂，深挖到禁得起两三次追问。

 JS与框架

 JavaScript 是前端的重中之重，所以在条件允许的前提下，把它挖的再深也不过分。可以自己系统性的搭好一个框架，然后根据每一块具体的内容，去查阅一些书籍和博客甚至是规范，在整理的过程中，自然就会有自己的思考和理解。

 对校招生来说，vue 和 react 选择一个专精就好。我自己最开始学的就是 vue，实习的时候用的也是vue，所以我就深挖 vue 这块内容：github 上有个 minivue 的项目，同时配合着看《vue设计与实现》这本书，我大概花了一个月的时间把 vue3 核心的源码撸了一遍，在面试的时候遇到 vue 相关的问题，基本上都能拿下。

 算法

 算法我刷的也不是特别多，力扣大概两百六十多题，不过在前端这块还算是够用。这块最好跟着别人整理的资料系统性的刷，我是跟的Carl哥的《代码随想录》，三刷随想录之后再去刷hot100，然后是剑指offer，剩下的也就是 codetop 的一些高频题了。

 这次秋招最大的体会大概是算法基本是拿来应付笔试的，面试问的题目大多是经典高频题，都能比较轻松的解决掉。

 5. 小结

 今年是真冷，就我个人来说，大厂除了个别不怎么看学历的，简历关就几乎都挂掉了。

 我是八月初开始投递的，八月投的公司大多都有笔试，不过有些笔试ak了也等不来面试。九月份投了大概三十多家，只有两家约了面，还有一个被 kpi 的。所以能早投就尽早，这个很关键。

 需要提前去做做功课，就用大白话说出来就行，别背定义

## 裸辞半个月的程序猿在干什么？

来源：掘金 ｜ 类型：面经 ｜ 发布：2022-08-16 ｜ [原文链接](https://juejin.cn/post/7132329117722083341)

裸辞一个月的程序员第二阶段总结。。。 

 裸辞程序猿面试一个月经验分享。。。 

 序

 8月1日，美好的一天，我果断裸辞，在公司1年半交接不过半天时间便匆匆结束了这在里的征程。心情由忧转喜再转忧再转喜，好比是坐山车似的 来回起伏 。

 

 为什么选择裸辞？

 

 裸辞并不是对自己的不负责任，也不是任性，对于我来说可能是一次重新的洗礼。
大家都明白现在的 互联网 形势并不是很乐观，在我裸辞的前夕 每日优鲜 又爆雷了。在如此悲凉的环境之下为什么还是要义务反顾的选择裸辞？我自己裸辞主要有4个原因：

 1.之前的工作确实让人 心累且身体累 。自己需要一段时间来恢复一下身心健康。因为身体是本钱，并不能因为自己是年轻人而肆意挥霍，提前透支。 心情精神 则更是重中之重，心情愉悦，才能百病不轻，才能有更加积极向上的态度。

 2.自己没有大多生活的负担，如家庭，车贷房贷等。这可能也是年轻人这个阶段唯一的一次特权了，因为不久之后这些东西都会接踵而至，那个时候， 裸辞 这个词也许永远不可能出现在我的字典中。这一次自己还是要好好享受这人生的最后一次特权。

 3.对于我这个阶段的程序员来说，好好规划自己的 职业生涯 显得尤为重要， 选择 远比 努力 来得重要。且这个阶段的程序员找工作我始终认为都是一个应该好好准备的过程，不仅仅是 查漏补缺 一些知识点，更是应该定下心来为 自己的将来 做一些规划。

 4.大环境的不好对于我来说可能有些许影响，但是对自己足够自信的我相信这并不是挡住我裸辞的拦路虎。也许这个思想后面会有转变，但绝对不会是现在！

 

 当然这些东西某种程度上来说也许都是借口，因为 健身学习、查漏补缺、人生规划 可以放在平时下班之后或者是双休日。并不一定需要一大段空闲时间来做这些事情。在没辞职之前我也是一直对自己这样说的，我确实也是这样做的，但是总是感觉效果不佳，或者说没有 心思 ，也许这也是我 自身意志不够 的原因吧。但我相信不少人应该也是同我一样，心理知道但是却不能高效的做到。

 裸辞真的好么？

 裸辞真的好么？掘金上也有很多针对于 年轻人裸辞好坏的讨论 ，但是对于我来说我觉得 效果是不错 的。

 裸辞之后，我为自己制定了一份所谓的 计划表 ，也确实都的做到了，因为这份计划表实在是太简单了， 除了运动就是玩 ，没有任何学习的计划，持续2周。

 1.5点半起床空腹晨跑，我坚持了一天最后被我无情删除了这个计划。（说实话真的难）最后被我改成了早晨起床后做一些室内的有氧运动。

 2.上午就是玩手机看视频。（动漫补番，玩玩手游，看看电影电视剧）

 3.下午2点-4点半健身房健身游泳。

 4.晚上7-9点看书，看完夜跑5km，11点睡觉。

 现在的我已经经过了2周的洗礼，体重减了3.4kg，整个人精神状态都好了不少，心情愉悦，一改之前的颓废。自己的改变自己才是最清楚的，文字真的很难描述清楚。有过这种感觉的人也许会明白。

 裸辞之后我做了什么

 

 上面讲到了我前2周的 玩耍健身 计划，那么后2周的 学习健身 计划也应该开始了，这篇文章就是计划的开始。运动健身看书的时间是不会做任何修改的，主要是把之前的玩乐的时间划 3分之2 给学习罢了，细节就不多说了。

 我这个人缺点很多，尤其是不能 长时间坚持 ，但是短时间的坚持我从来没有失败过。所以我给自己定制的计划时间都相对来说很短。毕竟裸辞，生活还是要继续的，再次找工作的时间区间也就1个多月时间罢了。

 尾

 裸辞 对于每个人来说意义效果都是不同的，对于我来说裸辞只是让我能够更好的开启我的下段征程。我分享自己的裸辞一是为了给自己一个 交代与监督 ，二是为jym提供一些短浅的 建议与经验 而已。

 在我 学习健身 计划结束的时候，我同样会分享一篇文章来对自己的 第二阶段 做一个总结。

 非常感谢能看到这里的jym!

1、对朴素贝叶斯的理解？（快手） 

 参考答案 

 朴素贝叶斯分类是贝叶斯分类中最简单，也是常见的一种分类方法。“朴素”是指假定给定目标值时属性之间相互条件独立。 

 答案解析 

 由于各属性之间相互独立，可以得到朴素贝叶斯计算公式为： 

 
 

 优点：朴素贝叶斯算法假设了数据集属性之间是相互独立的，因此算法的逻辑性十分简单，并且算法较为稳定，当数据呈现不同的特点时，朴素贝叶斯的分类性能不会有太大的差异。即朴素贝叶斯算法的稳定性比较好，对于不同类型的数据集不会呈现出太大的差异性。当数据集属性之间的关系相对比较独立时，朴素贝叶斯分类算***有较好的效果。 

 缺点：数据集属性的独立性在很多情况下是很难满足的，因为数据集的属性之间往往都存在着相互关联，如果在分类过程中出现这种问题，会导致分类的效果大大降低。

 挂在简历筛选的公司 只招与需求极度相符的人：b站、图森未来 要求没达到：农行(英语六级没过) 未知理由：京东(听说面试都挺迷的) 挂在机试的公司

 机试一般有性格评测和笔试两部分，性格评测主要是性格测试题+阅读理解+小学奥数+找规律+图表题，大概30min完成。 

 性格评测挂了：拼多多(忘做了)、华为实习生(挂了被捞了) 笔试挂了：(应该是和简历综合评判之后觉得不符合) 挂在面试的公司

 实习生面试挂太多了：腾讯(之前实习生面试挂了三次，估计评分很低) 只招与需求极度相符的人：shopee(后端岗疯狂问用过哪些后端框架，不问基础和C++) 面试累了，鸽了面试：快手、猿辅导 自己拒了：中电 29 所(研究方向不符) 收割 offer

 TP-Link：6 月就开始秋招提前批，公司有 985 情结，面试基本就聊天，很容易就过了，在北京工资不高，并且无加班费 字节：典型的挂了又捞，捞了有挂，经历了安全岗简历挂和一面挂，被广告部门捞起来，技术面三轮 +hr 面拿 offer 深信服：机缘巧合投的大牛批，一面很水，二面是正常技术面，三面主管面很契合项目方向，拿了 ssp 招银科技：调过电话面(摸底)，两轮技术面，问的东西都很浅，范围还比较广 国电南自：一面技术面，比较简单，三天发 offer，本科生薪资低，还需要出差 百度：无人车部门两面挂，语音识别部门三轮技术面+一轮主管面，跟字节类似，主管画技术饼 华为(待安排)：实习生过了所以免笔试，一轮技术面+主管面，基本聊天，但 offer 下发周期长 美团点评(待安排)：三轮技术面不是很难，hr面后两个月不给结果，估计是 hc 少，池子深 三、面试总结

 由于大部分公司都是投的提前批，所以很少有笔试，面试一般是 2-5 轮，摸底面+技术面+主管面+hr面，侧重点各不相同。

 摸底面

 摸底面也就是很多公司的电话面，比如招银科技、国电南自，一般时间不会很长，大概在 10-20 分钟之间，主要是自我介绍+项目经历简介，有的会有一些常见的基础题，比如 TCP 为什么三次握手这种。只要有一定的准备，电话面基本都不会挂，有的公司如果你简历 or 笔试表现好会跳过这个环节。

 技术面

 技术面是面试流程中的核心环节，主要考察我们对计算机基础知识的掌握程度，一般会涉及计网、操作系统/Linux、数据库，编程语言(c++/Java等)，部分会问到编译原理这种比较偏向计算机专业的问题。

 一般公司的技术面为 2-3 轮，主要模式都大概相似，开始自我介绍，紧接着问一些基础知识相关的问题 or 项目相关的技术问题，最后是 1-2 道现场编程题，也有的公司会先上来让你写题，后续根据你的表现来决定问什么问题。

 主管面

 并不是所有公司都有主管面，一般是部门直招 or 你前面面试表现较好，可能有 sp 的情况下才会有主管面试，一般主管的级别越高就说明你的评级越高。

 主管面并不会拘泥于具体的技术问题，在你的自我介绍后，主管喜欢针对项目进行提问，主要是考察你对自己所做项目的掌握程度，并且很多时候会问到一些与人沟通相处相关的问题，比如如果组员之间出现了意见分歧你们会怎么办，另一方面，你印象最深的一次项目经历也是常问的问题，这些都是需要提前准备好的。

 在主管面的时候我会更多的讲一些自己的学生工作，领导项目 or 组织活动的经历，当然这种经历最好是与技术挂钩的。以及与主管讨论编程规范，自动化测试、软件工程、测试驱动开发，或者项目管理等问题也是正中他们要害的，并且一定要多问，一般主管们很喜欢给新人讲这些，给他们机会，装作很感兴趣的样子。

 hr 面

 hr面一般就直接确认 offer 或者谈薪了，极少见到 hr 面还刷人的(听说京东和阿里会)，一般 hr 会问你一些基本的家庭和学习情况，以及你现在拿了哪些 offer。

 在 hr 面自己也可以问一问公司的一些情况，比如薪资结构，五险一金，加班情况，加班费计算，升职加薪的规章制度，年假安排等，这些都是需要提前了解并且纳入 offer 考虑范围的，不过薪资才是硬道理。

 四、知识点总结

 实际上在实习生阶段已经整理了很多被问到的问题以及部分问题写了一下自己的解答(还有很大一部分坑没填呢)，春招阶段感觉其实万变不离其宗，问来问去都是那么几个问题，所以就没做记录了。在此依据记忆在几个主要的方向写出几个最常见的问题吧。

## 【教育行业】21届学姐校招规划与求职准备经验分享

 一、校招简介 

 每年的校招主要由秋招和春招两部分组成，面向应届毕业生进行人才选拔，各自都有提前批、正式批以及补录的批次。 1、时间线 

 不同企业开启校招的时间节点各不相同，但大致时间线是每年7月前后开始秋招提前批、正式秋招、秋招补录，每年3月开始春招提前批、正式春招、春招补录的节奏。 2、基本流程 

 校招主要由网申-笔试-群面-单面-总监面-HR面6个环节组成，offer沟通也是一个比较重要的环节，单独提出来希望大家注意不要掉以轻心。 不同公司或者不同的项目组，具体设置情况不一样，比如我在跟谁学面试的时候是进行了三轮单面，没有群面的环节。但在参加校招前期需要对每个环节有详尽的准备，才能临危不乱，毕竟大多数人都没有办法提前预知公司当年校招设置的情况。 

 二、教育行业整体状况 

 1、行业现状 

 首先，整体行业来看，传统线下教育培训仍然是行业增长主力，受疫情影响在线教育崛起迅速，企业产品模式线上化增速稳定。但是由于教育本身面对面授课和线上学习的体验仍有差别，选择回归线下场景的教育企业比例逐渐增高。 其次，知识付费与在线教育的融合是目前的业态趋势。知识付费更多是出版行业的在线化，但由于存在学习的成分，也有大量人群将知识付费与在线教育挂钩。 

 此外，行业内的细分赛道较多，K12、素质教育、语言培训、早幼教以及职业教育是目前行业内发展较快的几个品类。 

 *关于在线教育 

 在线教育其实有两个划分维度，第一个是传统教育行业受疫情影响，利用互联网技术手段更改授课形式的产物（例如：新东方在线）；第二个是互联网行业内，由于在线教育的发展符合互联网公司的特点（前期靠融资烧钱扩张获取流量，形成规模效应，最后获得一定程度垄断并实现盈利）且拥有超大的市场规模，大量互联网企业专门推出的独立业务/品牌（例如：字节旗下的大力教育）。 2、人才偏好 

 行业整体发展迅速，市场规模超大，对于人才的需求量极大。 2020年市场规模超2000亿，预计2050年之前会超过8000亿；
 市场增速高，2020年在线教育用户规模达到3.05亿，比2019年增长17.8%，由于疫情影响，在线教育开始向三四线城市渗透；
 根据艾瑞咨询对教育行业的研究数据反映了目前教育行业尤其是在线教育，正迎来大发展趋势，诞生大量连锁教育品牌，行业整体正逐步走向成熟，对人才的需求也更大。 人才需求岗位不再集中在传统的教师岗，出现更多新选择。 在数字化经济和疫情的双重作用下，教育行业在获客方式、运营手段、授课形式等方面都进行了优化升级，特别是发展如日中天的在线教育，在人才需求上类似互联网行业。除教师岗外，教育培训类企业的人才需求集中在教研产品研发、学科运营以及渠道销售等岗位。 3、代表公司 

 教育行业的细分赛道很多，作为应届毕业生可以关注的企业数量也很客观。我只列举出一些行业内各垂直领域比较有代表性的公司供大家去关注。 培训机构类 ：新东方、好未来、樱花日语、中公教育等 早幼教/K12类 ：好未来、跟谁学（现改名为高途）、猿辅导、VIP KIDS等 门户/平台类 ：沪江网、网易云课堂、腾讯课堂、百度传课、小鹅通等 工具类 ：有道词典、作业帮、扇贝、百词斩等 三、岗位状况 

 在线教育热度从去年疫情开始就不曾降过，最明显的感受就是各大公司放出的岗位越来越多，似乎工作机会越来越多，但好的工作机会其实仍旧较少。 由于在线教育与其他互联网领域存在本质区别，岗位设置也有很大不同。我将会针对招聘需求量较大的运营类岗位进行简述，但需要注意的是，每个岗位都衍生与具体的公司与业务，即便是同岗位在不同的公司，工作内容可能差别极大，我只针对行业内的常见情况进行说明。 

 目前岗位越来越多元化和细分化，光运营岗位就分为 用户运营、产品运营、课程运营、渠道运营、学科运营、师资运营 等。有些岗位从字面上可以理解，但有的岗位就很懵。尤其是名字很像的这几个：用户增长、增长运营、增长产品、策略运营。 

 1、增长岗 

 目前大量在线教育公司在招聘用户增长，主要分布在市场或者是增长团队，部门不同决定了增长方式不同，可概括为外向式或内向式的增长。 外向式增长（市场） 岗位职责：寻找外部渠道，进行案例拆解了解新玩法，将流量从公域引到私域
 岗位关键词通常有渠道、引流、转化等 内向式增长（增长团队） 岗位职责：通过产品内部的功能优化和用户生命周期管理，实现内向式增长，比如老带新，新带新，扩科等
 岗位关键词通常有数据分析、用户精细化运营和目标拆解 2、增长产品 

 根据公司、部门和项目需求进行产品设计、功能开发，从需求调研、需求规划、产品原型、需求评审、需求排期、研发、测试、推广等全阶段为产品做增长类动作，偏向基础搭建，有些类似互联网产品经理的工作。 3、增长运营 

 根据公司、部门和项目的需求进行用户的全生命周期管理，集中在做流量和留量，目标是实现用户数增长，包括产品内部的增长策略优化和产品外部的增长，偏向用户和产品运营。 4、策略运营 

 近两年出现的新岗位，去看市面上的招聘，其实还可以细分为转化策略、销售策略和教学策略运营。这是前后端都需要的岗位，通过提供可落地的策略方案，跟进执行，利用数据做策略优化或迭代。
 策略运营的核心是数据分析和更新SOP。通过数据分析，优化业务指标相关的SOP，包括社群、课程打磨、转化等，会对具体的指标负责，要求的技能会更全面一些。 5、课程运营 

 负责课程的选题策划、内容框架搭建、讲师沟通、课程打磨、课程上线等等工作，权限较大的情况下会直接负责课程的推广运营，属于学科团队。 6、学科运营 

 负责教学产品线的课程、招生、活动等等，主要对招生人数负责。 7、社群运营 

 上手门槛较低的一个岗位，负责各种类型的社群搭建、管理，SOP和内容输出等等，前后端都有相应岗位，但具体的职能不太相同，需要看具体业务分析。某些公司也叫社群班主任或者辅导老师。 四、求职规划 

 本篇内容主要面向确定求职教育行业的同学，那么我们重点就围绕在教育行业中如何选择岗位以及做针对性的求职计划。大致可分为自我分析、岗位研究、确定职业规划并制定可落地的求职计划这几步。 1、自我分析 

 自我分析，就是通过对个人情况的梳理，从过去经历中提取出自己的性格特质、优缺点以及职业偏好等建立自我认知。主要目的就是去明确自己的求职方向，做出职业预期，帮助筛选意向企业和岗位，面试中也能从容应对关于自我认知、职业诉求类的问题，帮助我们提升求职成功率。 （1）现状梳理 

 客观条件 （也可以说是简历的要素） 

 教育背景：学校、专业、年级 经历：实习、校园经历（各类学团组织）、项目（各类比赛、科研项目、创业项目） 附加：荣誉/获奖情况（考虑含金量） 技能项：技能及掌握程度如何 通过梳理个人情况，可以了解到自己当下实际状况，也能与同龄人比较自己的竞争力，但关键是自我定位，梳理出与目标企业、岗位之间的差距。 

 内在特质 

 兴趣：自发喜欢愿意付出努力，如果有做出结果产出更好，比如语言类的考级证书、教师资格证等等 擅长：梳理出自己擅长的事情 性格特质：主要反映在行为偏好上，比如性格外向的话，一份需要与人沟通的工作会更适合 内在特更多体现在人岗匹配的程度，直接影响到工作过程中个人的舒适度，也要提醒同学们注意综合考量。 

 （2）不知道喜欢什么，该怎么办？ 

 多尝试和总结 不尝试，永远不知道自己究竟喜不喜欢，擅不擅长。 多问自己深层的问题 比如教育行业中经常被人认为辅导老师有销售性质，很多同学就很抗拒。不喜欢销售性质的岗位，就要问自己为什么不喜欢，是不喜欢销售的哪个方面？是不喜欢销售的产品还是不喜欢工作应酬？不喜欢销售过程接触的客户还是不喜欢这个行业？ *教育行业的关键环节是获客和转化，核心量化评价指标是转化率，大部分运营岗甚至教学教研岗都需要对转化率负责，也造成很多同学会认为教育行业的岗位有销售性质，关键是理解行业特点和业务造就的，希望大家可以正确理解 

 借助性格/职业测评 通过借助专业的测评工具来帮我们分析出自己的性格特质和职业方向也是不错的一个选择，在实际的校招笔试环节，性格测试也是一个考察部分，衡量你是否与投递岗位相匹配。 常用的性格/职业测评工具：MBTI（不同题数的版本很多，可自主选择）、DISC等 

 （3）如何做职业预期 

 职业预期简单来说就是找工作，你对工作环境、团队氛围、工作地点、时间、薪资福利等有怎样的一个期待。
 常见的一些考量维度也给大家梳理出如下的一些维度可供参考。 工作环境 工作地点 工作氛围 薪资福利 职业预期的判断因人而异，需要各位同学结合实际情况进行提炼在意和不在意的点，但是一定要有理可循。 

 说我个人的例子，对于工作的思考维度主要是 在工作内容、工作氛围以及成长空间 这三个维度。 

 关于 工作内容 ，我曾经有过一段教育行业内的实习经历和创业经历，了解到业务链条中的核心是获客和转化，所以在工作内容上，希望是与获客或者转化直接相关的工作，争取核心岗位。 工作氛围 ，是直接影响到我的工作状态，希望工作氛围轻松外向，同事之间能够高效沟通，协同解决问题。教育行业的从业者大多是能言善道，沟通表达能力较强的，而且组织架构比较扁平化，工作氛围比较轻松。 我认为职场小白最重要的是 快速成长 ，需要快速学习和掌握各种技能，同时leader能够给到试错的机会和时间，指引我提升。在线教育作为在快速发展中的行业，会给到新人大量的机会锻炼和提升，是个不错的选择。 2、求职目标 

 对未来的工作有了基本的预期后需要确定求职目标，而求职目标主要是岗位的选择。
 面对庞大的细分岗位类目，很多同学会不知道该如何进行岗位的选择。了解和认识一个岗位，通常可以从 工作内容、量化评价指标、团队定位 三个维度进行衡量。 工作内容 ：通过了解岗位的实际工作内容，可以初步判断对该岗位是否感兴趣，并通过工作内容来挖掘该岗位所需的技能，判断自己掌握技能和岗位技能要求的匹配度，并针对性提升自己。 量化评价指标 ：岗位背负的指标是否清晰明确，是影响职业晋升/涨薪和职业成长的重要因素。有清晰的量化评价指标，能使得员工依靠专业能力获得晋升，职场环境较为公平。作为新人，也能够在职业初期明确自己的工作侧重点和努力方向，实现快速成长。 团队定位 ：岗位在团队内的定位以及与其他团队跨部门协作的关系，能反应出该岗位在公司/部门的重要性。可以结合公司的组织架构来推断该岗位的天花板，对于新人来说能较为清晰的建立起职场发展的方向，比如转岗、跳槽等。 3、制定求职计划 

 （1）确定自己是哪一类求职人群 

 根据目前的学年、过去经历等情况，做一个定位。 比如，一个准大四、准备参加秋招、没有实习经历、学校/专业较为普通的学生A，一个考公/考研失败、没秋招也没实习的应届生B，或者是一个选择回国求职的海归C，这三种人群的求职计划就会完全不同，主要差别是准备时间的充足与否。 

 （2）根据定位制定求职计划 

 A同学 

 针对目标岗位的知识技能要求分析，输出知识或技能短板；
 根据目标公司的往年校招流程，输出自己的薄弱环节。
 比如：校招流程通常不可避免的有简历、笔试和面试的环节，这一类同学可先了解简历的撰写逻辑、笔试方面注意行测题的练习以及主观题的解题方法，另外面试方面可以多看面经，了解真实面试场景针对做准备；
 根据目前自己所处的时间节点，合理制定个时间节点的计划即可。 B同学 

 这类人群通常是应届毕业生只剩最后一学期的时间，错过秋招只能参加春招的人群，时间上相对紧迫，选择也较为有限，整体的求职节奏会比较紧凑
 具体来说，有以下几种选择： 1.面对现实适当的降低期望值 
 综合考虑时间少、机会少、试错成本高的情况，对于职业选择的几个标准适当的妥协，再根据短板进行补短； 

 2.坚持寻找理想工作 
 本科的同学，可以照常进行原计划参与校招，如果情况不理想还能考研提升学历再去给自己一段时间去准备求职； 

 研究生学历的同学，其实为了求职，没有必要再往上提升学历，压力会有些大，集中精力做最后冲刺即可，第一份工作不顺心没关系之后再跳； 

 3.寻找含金量高的实习 
 一些公司部门或者项目组独立招的短期实习生，可能没有转正机会，但是可以学到公司的业务模式和做事方式，也可以积累人脉。教育行业的公司数量多，并非都严格卡毕业时间或者应届生身份，特别是在拥有业内大公司实习经历，公司会优先考量。 

 C同学 

 留学生的毕业时间是公司HR比较头疼的问题，关乎到应届生身份，入职时间等等。
 我自己是留学生，比较了解留学生求职归国的迷思。建议大家尽早制定求职计划 申请留学前：需要特别注意毕业时间，界定自己参加哪一年的校招，确定准备时间
 接受入学offer，在出国前的时间：找实习或者做项目
 出国后：找远程/线上实习，关注面向留学生的独立招聘，比如：猿辅导的海外招聘、高途课堂的A++计划等，这些独立招聘的开启时间会区别于国内校招的统一开放时间 

 （3）备战内容 

 在了解整体求职时间后，需要理清准备内容，我按照时间顺序进行了简单梳理。 过去经历梳理 确认意向岗位和方向 简历制作 作品集准备：包括产品分析报告、活动策划案等（根据岗位不同可省略） 笔试练习：行测、专业专题（多看多练） 面试练习：群面、单面（预设问题进行演练） 关注行业动态：各类行研报告、知识社区，提升行业融入感；时刻关注校招的动向和时间节点 不断总结复盘 五、求职准备 

 1、岗位必备技能 

 运营岗本身作为教育行业中的核心岗位之一，划分方向很多，覆盖业务的所有环节，发挥的空间很大。每年企业会花大量的成本开启校招选拔合适的同学，但应届生短期内其实无法有输出，企业对校招生的能力要求更多在软实力，而非业务能力或专业知识。 在能力方面对于运营岗的要求可以概括为以下五个方面。 

 （1）理解认知能力 

 理解认知能力具体指对运营岗位和教育行业本身的理解和认知。对于自己即将从事的岗位和行业有清晰的认知体现了个人独立思考和判断能力，同时也反映出候选人对于自己的职业发展是有明确的规划的。面试中也比较常出现考察这点的问题，比如：说说你对在线教育的看法？你对课程运营岗的工作是如何理解的？等等 （2）执行力 

 作为职场小白，缺乏相关专业能力和实践经验，无法承担决策者的角色，更多会参与到执行的工作中。执行力具体表现为团队当中分配给你的任务，是否能够正确理解并输出符合预期或者超出预期的结果。执行力也是很多大企业对于校招生必备能力的要求。一个好的执行者，能更轻易的获得他人的信任，认为你是一个靠谱的人，会不断地给予你挑战和成长的机会。运营岗位本身比较类似多面手的角色，会有大量机会进行跨部门沟通合作，抓住每一次的工作任务，保质保量的输出结果，也是未来获得团队内部和外部支持的重要因素。 （3）学习能力 

 学习能力并不是只是根据GPA或在校成绩做评判。在职场中，工作模式和思考方式与校园中有很大差异，企业并不会过多在意在校成绩的好坏。需要注意的是，教师岗这类教学教研相关的岗位对学科功底的判断中学业成绩会占一定的权重。 企业对校招生学习能力的考查一般是两个方面，第一，是否有主动探索未知问题的好奇心。拿岗位本身来说，我们知道运营岗、产品岗等其实是没有完全对口的专业的，那求职过程中你是否对于该岗位有主动搜索资料去建立自己的岗位认知。 

 第二，举一反三的能力。面对一个完全超出自己认知范围的问题不能够快速给出一个专业回答的时候，是不是能够利用已有知识进行举一反三。比如：一个文科专业出身的同学，在面对一个编程赛事的活动运营case的时候，通过利用校园活动策划的经历去给出可以套用的活动策划方案，这就体现出了这位同学举一反三的能力。 

 （4）用户思维 

 所有的产品都是用户导向的，尤其运营类岗位属于前端岗，最贴近用户，是否具备用户思维是顺利开展工作的关键点。用户思维其实就是换位思考的能力。在教育行业中，运营岗的同学会接触到各种不同类型的用户，在提出方案时，需要结合对方在使用产品或服务的过程中的实际场景揣摩对方的心思，找到关键问题，提出针对性的解决方案。 （5）逻辑思维 

 逻辑思维是企业在校招中考核的核心能力。工作的技能是可以培养的，但底层的逻辑能力很难改变。特别是运营岗位是一个强目标导向型的岗位，所有的运营动作都是为了达到最终的目的，逻辑思维是工作开展的基础。
 关于逻辑思维的考核会贯穿校招全过程。在网申阶段，会考察简历内容的排版、过去经历的描述是否有行文逻辑；在笔试中，可以结合题目按照推进逻辑对试题答案进行阐述，同时善于利用各类字符突出核心信息；在面试中，我会注意回答的条理性，可以结合金字塔原理的方式去回答问题，或者是分点明确简明扼要的回答。 2、岗位发展路线 

 （1）基本发展方向 

 运营岗的事业发展路线主要是两个方向： 专业方向和管理方向。 
 专业方向 ：成为某个领域的专家，比如增长岗的同学，会深耕用户增长模块，探索企业获客新方式等 管理方向： 通常是从一个小组长开始，做到部门负责人，再做到事业部的负责人等等。 作为职场新人，在刚进公司的1-3年，暂时不需要考虑走专业还是管理。这个阶段都处在搬砖成长期，要做的是接到一个任务就做好，提升自己的执行力和思考能力，学习身边优秀的前辈的做事方式。此外，要注意提高沟通协作的效率，为未来在职场攀升打基础。 

 在飞速成长后成为熟练工，可能会迎来瓶颈，会觉得自己岗位细分方向的内容掌握的差不多了。尤其在大公司或产品成熟的项目组中，工作更多是重复性的。这个时候可以选择换个方向，又或者同方向换个公司看看他人的做事方式和思考维度。当然，有时候转岗也不错，但是希望大家都清晰地知道我为什么要换，我想获得什么。 

 经历一次变换之后，接触新任务新同事没有事飞速成长学习的阶段，此时大致有3-5年的工作经历，同样，在遇到瓶颈时，对于未来走管理方向还是专业方向就会有比较清晰的意向。 

 关于自己职业规划的问题希望大家好好思考，在面试中一些职业规划类的问题也能从容应对。 

 （2）企业职级 

 企业职级是指企业整体的职级分部情况，大公司一般都有清晰的职级和薪资水平的设定。通俗来讲就是工作多少年才能升职加薪走上人生巅峰，天花板大致在哪里。大家可以找到自己意向企业的职级分部情况进行研究。 需要注意的是，升职加薪的年限和要求并不是绝对的，会受到公司、部门情况、业务发展等主客观因素影响，甚至一些公司没有完善的职级定义和晋升路径，需要大家入职后再去了解。

4.终审：第三天就是终审了，还有一节课的废话时间，这就不用做笔记了，建议大家准备终审的续报问题。之后就按照顺序进入课堂，一对一的，没到你的时候千万别点进去，不然就凉凉了。

其实整个过程，只要你认真点通过不会有太大的问题，当时我们第一天培训完就有一部分人被淘汰了，主要是老师叫他他不在，所以大家一定要守在设备旁边哟。我们开始在群里的有50几个人，最后只有20几个人了，淘汰了一大半。总体上我认为比较简单的，大家有问题就留言吧！
