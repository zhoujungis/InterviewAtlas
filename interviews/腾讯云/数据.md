1. 如何提升 SpringBoot 项目的启动速度？
① 减少类加载与组件扫描开销：在 @SpringBootApplication 中精准指定 scanBasePackages 来限制扫描范围，并利用 exclude 属性排除掉项目中未使用的自动配置类，精简 pom.xml 中的冗余依赖。
② 默认情况下，Spring 会在启动时实例化所有单例 Bean。对于非核心或非强依赖链上的 Bean，可以使用 @Lazy 延迟初始化。
③ 优化外部资源连接：对于非关键的资源初始化，通过 @PostConstruct 将其推迟到应用启动完成后再执行。
 
2. 代码如下：
String str1 = "Hello world!";
String str2 = "world!";
str1 和 str2 指向的是内存中的同一块地方吗？
若要把 str1 指向的内存块改变（比如将"Hello world!"改为"Hello,world!"），该如何实现？
① 不是。使用双引号声明的字符串字面量会被存放在方法区的字符串常量池中，str1 和 str2 指向的是常量池中两块不同的内存区域。
② 在 JDK 8 及更早的版本中，String 类内部是通过一个 private final char[] value 数组来存储字符的。虽然 String 类本身是 final 的，且 value 字段也是 final 的，但仍可通过反射机制强行修改：
⚫通过 str1.getClass().getDeclaredField("value") 获取到 value 字段。
⚫调用 field.setAccessible(true) 绕过 Java 的访问权限检查。
⚫利用 Unsafe 类或者反射修改 final 修饰符（移除 final 属性）。
⚫最后通过 field.set(str1, newCharArray) 将新的字符数组塞进去。
从 JDK 9 开始，Java 引入了紧凑字符串优化。String 内部不再使用 char[]，而是改为了 byte[]，并增加了一个 coder 字段来标识编码格式。这一底层结构的改变，加上 JVM 对 String 内部字段访问权限的进一步收紧，导致过去那种通过反射直接修改 value 数组的代码在 JDK 9+ 中要么抛出异常，要么无法达到预期效果。

3. 抽象方法可以用 static 修饰吗？为什么？
不可以。
抽象方法“只定义规范，不提供实现”，核心目的就是为了被子类重写，由子类提供具体的实现逻辑。
静态方法“属于类本身，而不属于对象实例”，在类加载阶段就已经确定，且不能被重写（子类定义同名方法叫隐藏，而非多态意义上的重写）。
抽象方法的调用依赖于多态机制，在运行时，JVM 会根据实际对象的类型，去虚方法表中查找并执行子类重写后的方法。
静态方法的调用在编译期就已经确定（静态绑定），是通过“类名.方法名”直接调用的，根本不需要创建对象，也不涉及虚方法表和运行时多态。
抽象方法需要运行时的动态绑定，而静态方法只有编译期的静态绑定，两者在 JVM 的执行机制上无法兼容。

4. 反射常用的 API 有哪些？
① 获取 Class 对象：类名.class；对象.getClass()；Class.forName。
② 动态创建对象：getDeclaredConstructor(Class ... parameterTypes)；constructor.newInstance(Object... initArgs) 。
③ 动态调用方法：getDeclaredMethod(String name, Class ... parameterTypes)；invoke(Object obj, Object... args)；getReturnType()、getParameterTypes()。
④ 动态读写属性：getDeclaredField(String name) ；field.get(Object obj)；field.set(Object obj, Object value)。
权限突破：setAccessible(true)。

5. 线程池常用的任务队列有哪些？
ArrayBlockingQueue（数组阻塞队列）、LinkedBlockingQueue（链表阻塞队列）、SynchronousQueue（同步移交队列）、PriorityBlockingQueue（优先级阻塞队列）。

6. 如何优化一个接口的响应速度，讲讲你的思路？
① 链路追踪，定位耗时最长的环节。
② 数据库层优化：索引与查询优化。
③ 应用与代码层优化：引入缓存、异步化与并行处理。

8. 服务器内存资源有限，硬盘中有大量数据需要排序，如何实现？
① 数据分块；
② 数据块内部快排；
③ 创建一个最小堆，每轮循环从每个数据块中读取第一个元素放入；
④ 重复上述过程，直到最小堆为空。
