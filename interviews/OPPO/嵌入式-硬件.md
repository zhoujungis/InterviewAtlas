 4. Flash A/B 分区

 主要是为了提高 OTA 的可靠性和可回滚能力，升级过程不破坏当前运行系统，升级失败可自动回滚，避免设备变砖。

 Flash 分区布局

 Flash
┌──────────────┐
│ Bootloader │
├──────────────┤
│ Kernel_A │
├──────────────┤
│ RootFS_A │ ← 当前运行版本
├──────────────┤
│ Kernel_B │
├──────────────┤
│ RootFS_B │ ← OTA 写入新版本
├──────────────┤
│ Data 分区 │
└──────────────┘

 
 
 A 分区：当前正常运行的系统版本

 B 分区：OTA 升级包写入的备用分区

 
 正常 OTA 升级流程

 假设当前运行在 A 分区：

 A 分区正常运行
 ↓ 下载新固件
 ↓ 写入 B 分区
 ↓ 校验 B 分区固件完整性
 ↓ Bootloader 设置下一次启动分区为 B
 ↓ 系统重启
 ↓ 从 B 分区启动
 ↓ 系统自检通过
 ↓ 确认 B 分区有效，升级完成

 
 升级失败回滚机制

 如果 B 分区启动失败，触发自动回滚：

 B 分区启动失败
 ↓ 连续重启计数累加
 ↓ bootcount 超过阈值
 ↓ Bootloader 自动切回 A 分区启动
 ↓ 系统恢复到升级前的正常状态

 
 5. 数据校验。 有没有更好的方法

 需根据不同场景选择不同的数据校验方式。

 OTA 固件升级比较基础的是 CRC。

 比如固件分包传输时，每个数据包增加：

 帧头 + 数据长度 + 包序号 + 数据 + CRC

 接收端重新计算 CRC，如果不一致，就说明这一包数据在传输过程中出现了错误，可以要求重传。

 6. CPU占用，堆栈怎么分配的？

 一般从 CPU 使用率 和 任务栈使用情况 两个维度进行系统性能分析。

 ① CPU 占用率怎么看？

 FreeRTOS 中可以通过任务运行时间统计功能，查看每个任务的 CPU 占用占比。

 如果发现某个任务 CPU 占用过高，会从以下方向进一步排查：

 
 任务执行周期是否设置过短

 是否存在空转轮询逻辑

 是否包含大量数据运算处理

 是否存在频繁串口打印

 是否长时间处于运行态、从不阻塞

 是否存在高频中断持续占用 CPU

 
 优化思路

 对于不需要持续运行的任务，尽量让任务进入阻塞状态，通过事件驱动唤醒，例如使用：

 
 vTaskDelay() / vTaskDelayUntil() 

 xQueueReceive() 

 xSemaphoreTake() 

 ulTaskNotifyTake() 

 
 避免使用忙等轮询的写法：

 // 不推荐：持续轮询占用 CPU
while (1) {
 if (flag) {
 // do something
 }
}

 
 ② FreeRTOS 任务栈怎么分配？

 每个 FreeRTOS 任务都拥有独立的任务栈，创建任务时通过 xTaskCreate() 的 usStackDepth 参数指定栈大小：

 xTaskCreate(
 TaskFunction, // 任务函数
 "Task", // 任务名称
 512, // 栈深度
 NULL, // 任务参数
 3, // 任务优先级
 NULL // 任务句柄
);

 
 关键细节：栈深度的单位

 这里的 512 不代表 512 字节，而是 StackType_t 类型的个数 。例如在 StackType_t 为 4 字节的 MCU 上： 512 × 4 = 2048 Bytes 

 FreeRTOS 官方明确说明： usStackDepth 表示栈能够容纳的 字（word）数量 ，而非字节数。

 ③ 栈大小怎么确定？

 不能只根据 “任务内有多少个变量” 简单估算，实际栈使用量受多个因素影响：

 
 局部变量、局部数组的大小

 函数调用的嵌套深度

 中断嵌套的栈开销

 编译器优化等级

 printf / sprintf 等库函数的栈开销

 
 例如包含大数组、多层函数调用的任务：

 void Task(void *arg) {
 uint8_t buffer[512];
 func1();
 func2();
 func3();
}

 
 其栈需求远大于简单的状态检测任务。

 实践做法

 先根据任务复杂度给出一个合理的初始值，再通过实际运行测试栈的实际使用情况，逐步调整到合适大小。

 ④ 怎么判断栈空间够不够？

 可以使用栈高水位线函数：

 UBaseType_t watermark;
watermark = uxTaskGetStackHighWaterMark(NULL);

 
 它返回的不是 “当前剩余栈空间”，而是 任务运行以来历史最低的剩余栈空间 。

 举例：

 
 任务栈总大小：512 words

 High Water Mark：100 words

 
 说明任务运行到栈最深的时候，还剩余 100 words 的栈空间。这个值越接近 0，代表栈越接近溢出。

 栈空间优化依据

 
 栈设置过大 → High Water Mark 数值很大 → 可以适当缩小栈

 栈设置过小 → High Water Mark 数值很小 → 需要增加栈空间

 
 ⑤ 发生栈溢出怎么办？

 可以开启栈溢出检测配置：

 configCHECK_FOR_STACK_OVERFLOW

 
 并实现栈溢出钩子函数：

 void vApplicationStackOverflowHook(
 TaskHandle_t xTask,
 char *pcTaskName
) {
 // 栈溢出异常处理
}

 
 日常开发中结合 uxTaskGetStackHighWaterMark() 提前评估栈余量，提前发现栈空间不足的风险，避免运行时栈溢出。

 一、前言 

 在求职过程中，受到牛客网的帮助非常多，但是牛客网上关于硬件的内容相对还是太少了，所以萌生了发起一系列关于硬件工程师求职的讨论帖，在这个系列的讨论帖里面，希望大家都可以进来畅所欲言，给本菜鸡以及后续想要从事硬件工程师的萌新们一些求职的经验以及启发，系列内容初步构思包括简历、笔试、面试、offer选择等等方面。 

 本帖主要讨论面试高频考点和所需基本功，我先写出一些我自己参加过的面试，抛砖引玉。 

 ⭐笔试篇在此：https://www.nowcoder.com/discuss/933546?source_id=profile_create_nctrack&channel=-1

 

 二、面试形式和基本流程 

 面试形式：因为疫情的原因，现在企业基本上都采用线上面试的形式。建议面试前选取一个安静的环境，准备好耳机和摄像头，提前测试好面试环境，不要迟到。还有就是不要迟到，慎重申请调整面试时间，有的公司是统一安排的面试档期，并不一定确保能调期成功。比如我因为某些原因就错过了华星光电的面试，后续申请调期也没有成功。

 基本流程：自我介绍、面试官提问（项目介绍、深挖项目、基础知识）、反问环节。

 

 三、面试基本内容 

 1.自我介绍： 

 自我介绍是你给面试官的第一印象，所以需要好好提前准备一下，我认为包括个人信息、项目经历、比赛经历、获奖历史等等的内容，时长大概在一分钟左右，如果明确要求做一个三到五分钟的自我介绍，可以适当扩展一下项目、比赛经历和获奖的内容。

 附一个自我介绍模板：

 各位面试官你们好，我叫XXX，来自XX大学XX学院，是XX专业的一名本科生。项目经历方面，在大学期间我曾经作为项目负责人带领团队完成过一个XX项目并获得了X级结题证书，项目的题目是XXXX。还有一些课程设计项目，比如嵌入式课程的课程设计项目XXXX，平时和同学也会合作完成一些小项目，比如最近在做的一个XXXX。竞赛方面，作为小队队长参加过两次XX竞赛，分别获得XX赛区一等奖以及XX赛区二等奖。学习方面，一直保持在专业前X%的成绩，获得过两次XX大学年度X等奖学金。（自我评价抗压能力不错，融入新环境比较快，喜欢团队合作的成果。）

 虽然经历不算丰富，但是希望能够有机会加入xx公司继续学习成长。以上是我的自我介绍，谢谢。

 2.项目： 

 项目是你个人能力最好的证明，面试前需要对于自己写在简历上的项目做到了如指掌，因为面试官对于你的个人能力的评价，无非是你基于你对简历上项目的介绍、深挖项目内容、基于项目内容提问基础知识等等方面进行的。

 对于项目我分为项目介绍和项目提问两个环节，两个环节的联系在于，你介绍时候给自己挖的坑你被提问的时候需要自己一个个填上。

 挖坑这个事情有利有弊，当你毫无面试经验，复习不够，这个坑足以让你掉进万丈深渊；如果你准备充分，对于自己的项目掌握很好，那你可以有意识的引导面试官的提问方向，比如我复习了IIC和UART，但是没有复习SPI，就可以适当的扬长避短。

 （1）项目介绍：对于项目的介绍，一般你需要将简历上自己参与度最高，最满意的那个项目做一个完善的准备，比如我简历是上有一个智能家居系统，我会把这个项目的由细入微地介绍：设计目的、设计思路、实现的功能、功能如何实现、最后完成度如何、对于项目做一个简短的总结。

 （2）项目提问：项目提问都是基于你介绍时所提到的专业知识，比如我介绍智能家居系统说的电源模块用到了DCDC芯片，面试官可能就会问DCDC用的是升压还是降压→DCDC的基本拓扑→画出基本拓扑并解释原理等等；又比如我介绍传感器和MCU的通信接口用的是IIC，面试官可能就会让你介绍一下IIC协议→IIC的时序怎么定义→为什么需要接上拉电阻→上拉电阻的选择会影响到什么等等。不必过于紧张，项目深挖只是为了验证对于项目的参与程度，如果问到后面真的不会只需要诚挚的说明即可，不懂装懂不可取。

 3.基础知识 

 有的面试官还喜欢考察一些基础的知识，基本上是模电数电的一些知识，关于专业基础课有哪些、怎么复习都在笔试篇说过，此处不再叙述。

 4.反问环节 

 一般最后都会有反问环节，可以问一下你感兴趣的问题，比如入职培训、部门业务、晋升渠道、职级设置、员工福利等等。

 

 四、面试准备 

 关于面试所需的基本功，我分为项目复盘和面试八股文两个部分。

 1.硬件八股文： 

 所谓八股文就是面试出现频率极高的一些问题，比如dcdc和ldo的区别，运放的选型标准等等的问题。对于硬件面试的八股文，网上还没有人做过系统的整理，所以需要自己总结，我当时在牛客网上疯狂翻看别人的面经，不分企业只要是单板硬件的面经我都看，看了大概有上百篇篇的面经，然后总结了一个Word，记录了很多别人遇到的共性的问题，然后自己去一个个问题想清楚解决掉，然后记下来自用。

 还有就是推荐一下牛客网面试题库——硬件工程师板块，里面有很多公司面试真题，我看了基本符合我刷面经获取的信息，可以缩短八股文准备的时间，当时面试准备阶段并没有发现这个板块，不知道是还没上线还是我没看到🤣。

 2.项目复盘 

 项目复盘我是完整的思考自己的项目，从宏观到微观地去复习自己的项目，每一个项目里面用到的知识点，都当作一个单独的内容去复习，由浅入深的去复习。还是用智能家居系统举例，我供电板用到了DCDC、LDO、IIC、SPI、ZigBee、WiFi，每一个都是可以复习的点，每一个点都往硬件岗位需要的方面去复习。比如WIFI和ZigBee的内容，可能对于硬件岗需要复习的并不是协议内容，而是两者同时运行在2.4GHz频段会不会产生干扰，有没有发生过传输数据干扰或者丢失。

 项目复盘另一个重要的点，就是面试官最喜欢问的，你在项目进行过程中遇到的难题以及如何去解决的，这就需要你结合自己实际情况去准备了。

 3.以战养战，复盘面试 

 面试是一个煎熬的过程，但是也是促进你成长的过程，面试后立马做记录复盘，总结自己做得好的以及不好的地方。还记得我第一次面试的企业是一家东莞的新能源船舶企业的电控硬件岗位，当时的表现我自己评价就是稀烂，就是企业希望我可以过去实习再评估能不能发正式offer的程度。到了第二第三次面试我经过前面的复盘，面试感觉已经非常良好。然后到了vivo的面试我遇到了深挖项目的技术面，又一次遇到瓶颈，然后我复盘继续复习，到了TP-LINK的面试是两轮技术面+一轮主管面，第二轮技术面也是那种深挖项目的形式，表现相比前一次也有了提升。

 对于笔试面试，做个简单总结吧。更详细的内容，可以到github查看笔试面试的一系列内容。（ 点击阅读原文可以直达 ）

 
 
 扎实基础，准备好八股文 。面试的重点，主要是 基础知识 和 综合素质 的考察。

 
 简历重点突出 。简历上的内容，一定把你想要面试官问的内容放在一眼可以看到的地方。要对写在简历上的每一个字负责。可以适当吹牛，但是，你要保证可以自圆其说。

 
 心态 。无论是秋招，还是春招，心态一定要调整好。像我本硕都是双非的，简历投出去没消息，被刷掉很正常。被大公司刷了KPI也很正常。

 
 多投简历，充分利用等待期 ，不要在一棵树上吊死。投完简历，简历并不一定会被及时处理，中间还有很长的等待期，可以利用这段时间面试其他的公司，让自己保持在一个很好的面试状态。

 
 及时跟进，及时反馈 。一般来讲，面试结果一周内都会给到。如果在面试完一周后没有任何消息，可以尝试给负责的HR打电话询问具体情况。

 
 碎碎念

 交流群的人越来越多了，群里交流氛围也不错。最近，在群里，群友还发现了致富门路，哈哈。

## 秋招面经分享-卑微的射频工程师

来源：牛客网 ｜ 类型：面经 ｜ 发布：2019-10-31 ｜ [原文链接](https://www.nowcoder.com/discuss/353155845569585152)

白嫖了牛客三个月，看大佬们都是软件的，就发一个硬件工程师的面经吧。以下公司投递的均是射频工程师

 
 1， OPPO 

 
 第一家面试的公司，也是拿到第一个 offer 的公司，公司分成三面。一面和二面均是技术面，三面为 HR 面。整体感觉公司偏年轻化，面试过程么有遇到刁难的情况，基本技术面都是我讲完项目。项目一般说的是叫我讲现在的硕士课题，就分析了一下自己工作的指标要求，先叫他听懂，然后说一下和别人的内容有啥难点需要突破，这就告诉他了自己做的东西很有意义。然后说一下进展以及成果。面试时还讲了一个别的项目。从系统出发，画出系统框图，然后从本振 PLL 开始一步步细化，分别画了 PLL 的电路，分析其中的重难点，然后是 AGC 电路，混频器以及射频前端的 LNA 和步进衰减以及后面的中频滤波等等。就完事。剩下的就是职业发展等等一些问题。最终拿到 OPPO 的 SSP offer 。 

 
 

 
 2， VIVO 

 
 7月份的时候错过他家的提前批。后来又开了一个电子专场。因为自己在北京，就进行远程视频面试，说实话，我觉得，不是现场面试的，都不能准确把握对方的真实情况。面试分为技术面和 HR 面。没错，只有 2 轮，技术面的时候，除了我的项目介绍，面试官问了几个问题： 1 ，放大器的原理，其实是三极管放大的原理。我就说了 NPN 三极管中的电子流动的情况，其中存在一个 B 倍的电子流，每个三极管因为这个参数的不同导致其放大倍数不一样。另外我想画一下三极管的小信号等效模型，但是因为视频面试，只能作罢。其实要是画的话，也不一定记得清楚。 2 ，然后问 , 放大器的供电，所谓的直流电源。就说了一下为三极管提供合适的静态工作点，使得其在放大区工作，同时分析一下常见的电源滤波。 3, 问是否对 PA 了解。然后从效率的角度分析了一下甲乙丙类功率功率放大器的原理。随后就是问丙类功放的基本知识。大概说了一下为什么效率高，以及怎样实现的。最后问了一下导通角的定义。 4 ，问是否熟悉仪器，因为自己在爱立信实习过，所以对 VNA 等的射频常用仪器都很熟悉，故 NF,GAIN.IIP3 等等都说了一下。 HR 面，主要问的是自己的发展规划，以及实习情况，因为本人在爱立信、 ADI 、华为 2012 、清华大学创业园都实习过。最终 offer SSP 

 
 

 
 3， 大疆 

 
 大疆一直是我觉得技术很好的一家公司，但是大疆我一面挂，面试是电话面，问的很细，主要包括以下几点： 1 环路带宽的影响 2 LNA 的设计过程 -- 稳定如何判断，如何让其稳定 3 混频器的原理，乘法器如何实现（问的很细，问我乘法器的电路设计） 4 信号末端挂小于四分之一波长的微带，呈现什么特性 5 VCO 的架构（这个后面问到我内部构造的时候，没答上来，说实话，自己只知道基本的振荡电路，但是具体怎么实现的，没关注过）。 6 各种滤波器，椭圆、切比雪夫等的差别（直接放弃。说不会） 07 频谱仪相关的： RBW ，和 VBW ，各种检波方式（当时太紧张，忘了 VBW 是啥）。最后面试官小哥哥对我已经没有了兴趣。就结束了。 

 
 

 
 4，华为 

 
 华为是实习生转正，部门是在 2012 实验室。所以只有实习生面试的经历。当时觉得华为的实习生面试很水。可能也是赶在今年华为面试改革之前吧，首先，一面的时候就是项目介绍，完事，面试官说可以，就过了。二面是主管面（入职后才知道面试官是 2012 三级部门主管）。刚开始面试就感觉面试官气场很强，介绍了硕士课题，问的很刁难。问我相控阵的原理，故大概画了个示意图，写了几个基本的公式。此外随便聊了聊课题，问我实习的情况，很好奇怎么去那么多公司实习过。就给过了。进去后得知，自己是部门实习排名第一进来了，和一面面试官同一部门。导师是部门三个领域专家（部门在北研所级别最高的）。在实习期间，给我感觉就是在一个实验室里面干活，部门氛围确实很好，大家都是纯纯的理工科男生，暑期 2 个月，在北研所参观了实验室，和同事一起去打了羽毛球，也和实习小伙伴一起开技术分享会，和导师以及同事请教问题。确实学到了很多东西。不可否认，这是华为工作很淳朴的情况。 

 
 但是呢，有意思的是，自己最后实习生转正给的 13 级，心里肯定有落差，和大家情况差不多，毕竟等了那么久。且不说自己能力高低吧，这个结果我自己十分不满意，有一种被侮辱的感觉。华为的实习生一直被人诟病。既然如此，那么就拒了呗。就当是旅途中的小插曲就完事了。 

 
 最后，两点建议： 1 ，华为的氛围确实不错，对于应届生，特别是和我一样做射频的，这是一个很好的平台。 2, 不要去华为实习，千万不要去华为实习。答辩完事之后就很卑微，特别卑微。 

 
 

 
 5，爱立信 

 
 因为自己师兄在这工作，所以他们一直建议我先去别的公司锻炼几年，他们觉得外企相对太轻松。但是还是投递了爱立信成都的岗位。一共分为两面，一面技术面，聊的课题，以及一些团队合作的问题。二面的话是经理面，英文交流，因为自己英文不咋的。面的不好。更多的问题关注点在团队合作，团队问题这方面。最后没过。 

 
 

 
 6，中电 29 所 

 
 唯一一家投递的研究所，通过面试发现，研究所其实更多的关注去工作的可能性大小，然后对技术要求不是那么大。一面的时候，和技术官聊得很好。直接告诉我，正常第二天晚上就能发 offer 。二面的时候，就是一些基本问题，更多的是，会不会去那工作，当然问的很隐晦。拐弯的形式，比如叫自己对薪资，地点等进行优先级排序等等。最后面试官说我的意向不够。觉得凉了，但是最后还是给过了，感觉很奇怪。 

 
 

 
 7， TP-LINK 

 
 所谓的 C7 养老院，工资给的很高是确实。感觉 TP 的面试没啥难度，只要简历筛选过了去面试应该都能过吧，也可能是北京地区要求高。一面和二面都是简单了解情况，包括项目，个人情况。等等，问的很随意。最终给过了，不过，最后彼此互为备胎。 

 
 

 
 

 
 总结：感觉公司面试能不能拿到最终 offer ，很大程度上取决于面试，特别是综合面试给面试官表现出来的意愿，当然前提是技术面过了。只要把技术弄好，其实也就是自己的项目弄明白，基本都能走到综合面，我一般面试一家公司之前都会稍微关注一下公司最近的信息。或多或少在面试的时候说一两句还是挺有用的。起码表现出来了意愿嘛。我个人整体秋招没有投递很多公司，总共十几家吧。一共面试了上面的几家，小米、高通、思科、海康威视没有面试通知。在所有的面试中，总结一下基本都会问的问题。包括技术和非技术： 

 
 

 
 1，方案 — 超外差接收机的整体框架 

 
 2， PLL ，工作原理。细化到环路滤波器的参数设置，以及 VCO 和 PD 的工作原理 

 
 3， AGC 工作原理 

 
 4， LNA 

 
 5，基本的测试技能，包括 VNA ，频谱仪等的使用， NF,S 参数， P1dB 等 

 
 6， PA, 效率等等 

 
 7， Smith, 匹配， S 参数，阻抗等 

 
 

 
 非技术： 

 
 1，自己的职业规划（每次都问） 

 
 2，射频领域现在存在的问题与挑战，未来何去何从 

 
 3，团队关系
