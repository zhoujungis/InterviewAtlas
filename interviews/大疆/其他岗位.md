## 《地狱级面试：2025年国内最难入职的10家IT公司》

来源：掘金 ｜ 类型：面经 ｜ 发布：2026-05-29 ｜ [原文链接](https://juejin.cn/post/7644782504341159962)

在互联网红利逐渐消退、行业进入存量竞争的2025年，“进大厂”早已不是当年那般遍地 Offer 的景象。如今，真正的顶尖 IT 公司不仅考察技术能力，更在学历背景、算法硬实力、项目深度、甚至是心理抗压能力上层层加码。有些公司的面试流程之长、难度之大，让无数优秀的候选人折戟沉沙。那么，究竟哪些国内 IT 公司是公认的“入职地狱模式”？下面这份榜单，或许能让你感受到什么叫“连简历关都过不去”。

 1. 字节跳动：算法“修罗场”

 作为国内互联网的顶流，字节跳动的面试难度常年霸榜。它的“难”首先体现在算法环节——LeetCode Hard 级别的题目是家常便饭，而且面试官极其注重代码的时空复杂度优化，写出来只是第一步，能否在 follow-up 中给出更优解才是关键。其次，字节的“压力面”名声在外，面试官会不断打断、质疑你的方案，考察你在高压下的逻辑反应。很多技术大牛都在三轮技术面后倒在了 HR 面的“价值观匹配”上。

 2. 华为（尤其是“天才少年”计划）

 华为的普通校招已经难度不低，但真正让外界仰视的是它的“天才少年”计划。这个项目由任正非亲自发起，年薪可达 200 万，但面试流程堪称“轮番轰炸”：从技术笔试、性格测试、技术一面、二面、综合面，到最终的总裁面，多达 7-8 轮。每一个环节都有极高的淘汰率，候选人不仅要展示顶级的科研或工程成果，还要现场解决从未见过的前沿难题。即便不是天才少年计划，华为的“狼性”筛选也意味着你必须通过五轮以上的综合评估。

 3. 腾讯（微信事业群）

 腾讯内部的“微信事业群”被公认为最难进的部门之一。微信团队对代码质量、工程规范的要求近乎偏执。面试中除了常规算法，还特别重视操作系统、网络协议底层原理的追问。有候选人分享过这样的经历：面试官会让你现场设计一个微信抢红包系统，并反复追问在高并发下的所有边界情况。更关键的是，微信团队很少走批量校招，大部分名额由实习生转正或内部活水，社招岗位竞争比例时常超过 300:1。

 4. 拼多多：极限性价比与算法深度

 拼多多的面试风格与它的商业模式类似——极致、高效、不留情面。它的技术面试通常没有太多寒暄，上来就是三道算法题，而且要求白板手写、无 Bug 运行。面试官会严格卡时间，每道题只给 15-20 分钟。除了算法，拼多多非常看重候选人处理海量数据的能力，比如现场设计一个支持百亿级 UV 的计数系统。高强度的工作文化也反映在面试中——面试官会明确告知“11116”的工作节奏，接受不了的直接 PASS。

 5. 阿里云 / 达摩院：学术+工业的双重门槛

 如果说普通 BU 的阿里还有套路可循，那么阿里云和达摩院则完全是另一维度的竞争。这里不仅要求候选人具备扎实的工程能力，往往还附加顶级论文发表记录（尤其在 AI 方向）面试官很多是业界知名的技术专家，他们会在一个极窄的领域深挖到博士论文的深度。比如你提到做过分布式存储，对方会让你复现 Raft 协议的所有细节，甚至指出你论文里某个实验设置的缺陷。没有真材实料的“面霸”在这里几乎撑不过一面。

 6. 大疆：机器人与硬核技术崇拜

 大疆虽然常被归类为硬件公司，但其软件、算法岗位的入职难度不输任何互联网大厂。大疆的面试极其“硬核”，尤其对于机器人控制、计算机视觉、SLAM 等方向，面试题直接来自实际产品研发中的未解难题。有求职者反馈，大疆的笔试经常出现需要微积分和矩阵论推导的题目，而非调用现成库。而且大疆非常低调，招聘名额少，很多岗位甚至不对外公开，依靠员工内推和定点挖掘，普通渠道投递基本石沉大海。

 7. 深度求索（DeepSeek）与“六小虎”AI 公司

 以 DeepSeek、月之暗面、智谱华章为代表的顶尖 AI 创业公司，是 2025 年新晋的“最难入职”代表。这些公司正处于大模型军备竞赛的核心，对候选人的要求极度“精英化”：通常要求 QS 前 50 的 CS/AI 方向博士，或在顶级会议（NeurIPS、ICML、CVPR）上发表过一作论文。面试不仅是做题，更是一场学术答辩：你需要清晰地讲解自己论文的创新点，并当场复现某个模型的训练细节。由于估值高、前景好，这些公司一个算法岗的录取率常常低于 1%。

 8. 美团（自动驾驶部门）

 美团的“难”不在总部，而在其前沿的无人机和自动车配送部门。这个部门集结了来自清华、北航、MIT 的机器人人才，面试官会直接甩给你一个未解决的规划控制问题，要求两小时内写出可运行的仿真代码。由于业务直接关系到配送效率，面试中对工程落地能力要求极高——不只要理论正确，还要在有限算力下跑出实际效果。很多在其他公司拿到 SP 的候选人在这里连二面都进不去。

 9. 微软亚洲研究院（MSRA）

 虽然是外企，但 MSRA 在国内 IT 界有着“黄埔军校”的地位，也是出了名的难进。它更偏向研究型岗位，对候选人的学术背景和创造力要求极高。面试通常分四轮，每一轮都是不同方向的资深研究员。他们会围绕你的研究经历连环追问，甚至故意提出相反观点看你的反应。MSRA 的实习岗常年被清北华五的顶尖学生挤满，转正留用更是凤毛麟角。

 10. 幻方量化 / 九坤投资（量化 IT）

 严格来说这属于金融科技，但其 IT 岗位的技术难度常常被拿来与顶尖互联网公司对比。幻方、九坤等头部量化私募的算法岗，要求候选人在极短时间内解决复杂的概率、统计和编程综合题。面试中可能出现这样的问题：“在 10 秒内估算出纽约帝国大厦的重量，并写一个蒙特卡洛模拟程序验证。” 不仅智商要超高，心理素质也要极强。这些公司开出的年薪往往是互联网大厂的 2-3 倍，也因此吸引了全世界最顶尖的竞赛金牌得主。

 
 结语 

 这份名单并不是一份“劝退指南”，而是为所有立志进入顶尖 IT 领域的技术人画一张真实的地图。每一家“难进”的公司背后，都代表着一套高标准的筛选逻辑。如果你正好在这些公司的面试中受挫，不必过度怀疑自己——毕竟，能被邀请去面试，已经是一种对你能力的认可。真正重要的是，在准备的过程中，你是否变得更加坚韧、深度和全面。也许下一次，当你再次站在那间面试室里，就可以从容地说出那句：“我们开始吧。”

#非技术面试记录# 
我投的全球服务培训生。90分钟90道题，不是投完秒发。收到测评后五个自然日内完成。
看网上都说大疆测评难所以一直拖着前段时间才投，但不用太怕！！题目难度算比较大的，但没那么大，我集中精力速通完还剩半小时来研究五道不会做放一边了的题（个人感觉百度管培的比这个难🥲）。 

题型：职场性格测评➕数学题➕言语理解。体感数学部分比较侧重，言语理解部分较少。想要给数学题留足时间的话，建议不要在性格测评上花太多时间。跟其他家测评不一样的一点是：大疆是所有题型交叉混杂在一起的，意味着可能上一道题是性格测评，下一道就是数学，再下一道又是言语理解🙂不过做下来感觉影响不大！ 

小建议是碰到难题直接随便选一个放一边，在草稿纸上记录好难题题号，然后迅速前往下一题。所有做完后再看难题，这样时间也会比较充裕，心情也会比较轻松，就算做完没空看了，也避免了因小失大。

## 互联网大厂面试题解析之大疆一面

来源：掘金 ｜ 类型：面经 ｜ 发布：2024-02-29 ｜ [原文链接](https://juejin.cn/post/7340603873604190243)

统计接口请求数量，以及接口耗时如何去做。

 方案

 首先在 Java 中统计接口请求数量，可以通过以下设计方案之一实现：

 
 使用计数器变量：在代码中维护一个计数器变量，每当接口被调用时，增加计数器的值。这种方法简单直接，适用于单线程环境。

 
 public class RequestCounter {
 private int requestCount = 0 ;

 public void incrementRequestCount () {
 requestCount++;
 }

 public int getRequestCount () {
 return requestCount;
 }
}
 
 
 使用并发安全的计数器：如果在多线程环境下进行统计，可以使用 Java 中的原子变量或者使用并发集合类来保证线程安全。

 
 import java.util.concurrent.atomic.AtomicInteger;

 public class ConcurrentRequestCounter {
 private AtomicInteger requestCount = new AtomicInteger ( 0 );

 public void incrementRequestCount () {
 requestCount.incrementAndGet();
 }

 public int getRequestCount () {
 return requestCount.get();
 }
}
 
 
 使用拦截器或过滤器：在 Web 应用中，可以使用拦截器或过滤器来统计接口请求数量。每当请求进入时，拦截器或过滤器会进行统计操作。

 使用 AOP（面向切面编程）：通过 AOP 可以在方法执行前后插入统计逻辑，实现统计接口请求数量的功能，这种方法适用于更复杂的应用场景。

 当然也可以借助其它中间件来去看，比如：SpringBoot - Actuator、Prometheus、Zabbix、Garafana等等。具体看实际的业务场景。

 
 
 SpringBoot - Actuator应用监控使用详解3（metrics端点：度量指标信息展示） 

 
 www.hangge.com/blog/cache/… 

 
 
 以上是几种常见的设计方案，具体根据业务场景去选择。当然实际业务场景中也可借助一些系统已经使用的中间件，比如Redis

 需求分析

 当需要统计每个接口的访问量的话，首先，设计接口访问统计表是一个常规的任务，表的设计应包含一些常见字段。例如，统计类型可以按小时、天或月进行统计；接口访问名称和URL也是必要字段。另外，可以增加一个统计时间字段，其格式可以根据需求而定。对于时间段统计，可以设计开始时间和结束时间；而对于具体统计时间，可以从上次统计时间到当前时间进行统计。最后，接口访问量是另一个重要字段。设计非常灵活，没有固定的模式，可以根据项目的实际需求进行调整。

 实际思路方案

 
 首先，需要一个地方来存储所有需要统计的接口信息，主要包括URL和接口说明。由于接口请求的URL通常是固定的且不会频繁更改，对于少量数据，可以考虑使用枚举值进行存储或者将这些信息配置在独立的配置文件中，并在项目中加载。对于大量接口数据，如数百甚至上千条数据，枚举值可能不太适用，可以考虑创建数据表来存储接口数据。

 其次，需要实现存储每次调用接口时的访问信息。对于访问量较大且需要快速响应的接口，一个简单实用的方法是将访问信息存储在缓存中，先将数据保存，然后再进行其他处理。每次访问接口时，增加该接口的访问量计数。

 最后我们可以使用Redis进行统计操作非常方便，可以直接对Redis中存储的某个值进行加一操作。这一步操作可以通过拦截器结合异步方式来对被访问接口进行自增操作，从而加快接口的访问效率。

 
 完成前面的步骤后，最后一步涉及如何进行统计。通常的做法是启动一个定时任务，比如每半小时或每小时执行一次，统计接口的访问量，然后将统计数据永久存储到数据库中。这种方式可以避免在Redis服务异常时数据丢失的风险。具体的统计逻辑可以如下：

 
 定时任务触发统计操作。

 从Redis中获取各个接口的访问量数据。

 将这些数据汇总，并写入数据库进行永久存储。

 可以考虑保留历史统计数据，以便进行趋势分析或性能优化。

 
 这样的设计思路可以帮助您实现接口访问统计功能，并根据项目的需求灵活调整和扩展。

## 23年最后的低语 — 终入大厂

 回眸

 2023年的年底好像发生了很多东西，分手、第一次离职、肠胃炎，期末考试...，十一月到十二月，我颓废了很久，可能是我大学两三年来第一次超过一个月没碰电脑没敲代码。依稀记得当时自己晚上不睡白天不起，每天晚上都用酒精麻痹自己，身体开始暴瘦，现在想想也挺好笑的，大概这个就是20岁的愚昧吧。（我现在还是挺愚昧的）

 时间来到十二月，我开始出去好好玩，说是玩，不如说是不想一个人待在宿舍胡思乱想，见了很多老朋友，大家闲来饮茶。特别感谢我的好兄弟-阿趴（那段时间他因保研失败也郁郁不得志，怎么有点同为天涯沦落人的感觉，咳咳），这段时间开始跟他出去到处拍照，把前两年广州没去的地方都去了个遍。

【开头介绍】本次经验分享适用哪些方面
本次的面试经验分享，适合于以下对象：
 1. 投递RM专属招聘渠道的RMer，特别是机械结构工程师（深圳）岗位
 2. 正在秋招投递各大公司的工科同学

（注：本次主要以RM专属招聘渠道中的“机械结构工程师（深圳）”为主要分享目标。如果是其他理工科类的岗位，都有一定参考性）

【面试事项】DJI面试流程
 DJI的面试主要分为两大部分：线上考核与面试阶段。
 在完成了线上考核的性格测试题与笔试题目后，你即将面临的是DJI面试阶段。在面试阶段，大疆面试官也会更关心你的RM项目经历，针对于这一部分，大家都要好好准备。
 第一轮面试是问答交流，面试官主要会针对简历内他们感兴趣的“某个技术点”来进行提问，在第一轮面试只需要注意到以下几点即可：
 1. 简历真实，简历上描述与实际负责部分一致；
（第一轮面试，在你对以往项目有完整项目总结的前提下，基本上不用刻意准备，只需要坦然的面对面试官的提问即可）
 2. 技术点精炼，有项目梳理能够逻辑清晰的讲述。
（更看重的是针对面试官提出问题时的回答方式，你需要较强的逻辑性，能够从“技术点选择验证”、到“技术点实施方法”、再到“技术点复盘结果”进行完整的技术介绍；当然在这是如果有相关的总结文档，更能节省交流的时间，提高交流的效率，让面试官了解你更立体）

 第二轮面试是项目自述，面试官会在你自述时针对他们感兴趣的地方进行提问；那么第二轮面试中，我们需要做好：
 1. 清晰明了的项目资料
（PPT的形式最好、PDF＋模型 或 Word文档的形式次之，最好不要只有单独的语言描述；因为站在面试官的角度来讲，在一天的面试中信息流较多，如果纯文字理解起来较为繁琐，但是有图片、视频展示，能降低交流的成本，让你和面试官的交流更加顺畅）
（项目资料准备的形式：一、大学期间项目总览；二、项目设计依据；三、关键难点的解决方案；四、性能指标介绍；五、主要结构概述；六、工作原理及系统）
 2. 深挖技术点底层原理
（例子：选择碳纤维板的原因；强度、刚度、硬度三个参数的区别）

## 大疆群面经验贴

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-09-09 ｜ [原文链接](https://www.nowcoder.com/discuss/353158464925016064)

中午2点--2:50进行了大疆的群面，现在进行复盘。复盘的核心要点：自己语言表达能力是硬伤。

 大疆群面问题是采购出现不能按时供应问题，提出解决办法；由于题目没有难度，后面加上分析具体会是哪些原因并提出解决办法。

 题目不难，考察的是自己的逻辑分析能力，能否分析的全面并且有理有据。每个人都能想到解决办法，无非就是从供应商、公司领导协商（调换产品先后工艺顺序以及预售方案)。那么就看自己在这些点上能否想的全面，并且表达清楚了。这个时候工具辅助要点记忆就显得很重要了。

 群面形式是先读题，5分钟思考时间，每个人3分钟发言时间（包括自我介绍），15分钟讨论时间，5分钟代表总结发言时间。

 在个人介绍环节，有个人做的相当不错，大概思路是自己学历---实习经历--个人优点分析。有些人则做的相当不好，把个人介绍时间说的过长，大家都优点不耐心了，而且这过长的经历并不能引起别人的兴趣，所以，个人介绍要事先准备长、中、短三种模板，这样遇到什么情况都不会慌张了，而且要紧扣突出自己优点，那些不好的点一定不能说，一定要想方设法避免说。消极词汇是自我介绍和面试的大忌。

 个人描述环节感觉大家都说的差不多，拉不出什么差距，关键还是在集体讨论环节，这个环节我通过屏幕共享Xmind记录发言抢到了记录者和领导者的角色，而且在整场讨论环节中自己时间节点卡的非常好，几乎让大家把所有重要的环节都给讨论完成了，形成了一个清晰的解题方案。这是自己在这场群面中表现好的地方。

 自己表现不好的地方是发言逻辑混乱，重点不突出，让人听起来不知所以，自己最后虽然抢到了reporter的角色，但是发言的不好，自己感觉很糟糕，不出意外，因为最后总结环节hr会把我过滤掉。反省下自己出错的原因-----容易紧张。

 我能想到的是，自己私底下把自己的个人介绍和简历全面都写成一小段话，然后不断训练，找朋友来听，最后达到大人听了不觉烦小孩听了觉得有趣的程度，这就需要自己很多次的总结和复盘，自己可以录屏或者录音。

 以上分享给大家，给自己积攒人品也祝大家秋招顺利。

假定在待排序的记录序列中，存在多个具有相同的关键字的记录，若经过排序，这些记录的相对次序保持不变，即在原序列中，r[i]=r[j]，且r[i]在r[j]之前，而在排序后的序列中，r[i]仍在r[j]之前，则称这种排序算法是稳定的；否则称为不稳定的。
