## 大疆 AI全栈开发一面

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-11-26 ｜ [原文链接](https://www.nowcoder.com/feed/main/detail/3f358c64eb5a4daaab07071e14a91bf1)

11月24一面，主要是拷打项目，凭着记忆+AI协助整理问题
1、你这个系统是 5 个 Agent 串行协作的，为什么不用「单 Agent + 一堆工具」搞定？拆成多 Agent 的收益具体在哪，复杂度又怎么管
2、Router Agent 做意图分类，如果分错了（把该转人工的判成了自动处理），后果是什么？你怎么发现这种错误的，有没有兜底？
3、加了 rerank 和 query 改写之后，你怎么单独量化每一步的贡献？也就是说你怎么知道是召回的问题还是排序的问题？有没有做过消融？
4、LLM Provider 统一接口，降级策略是什么？触发条件、重试次数、超时阈值分别怎么定的？
5、你怎么验证降级真的生效了？降级之后答复质量掉了多少，这个影响你测过吗？
6. 答复是 SSE 流式推给前端的，如果推了一半客户端断连，LLM 已经生成的那半截结果怎么处理？用户刷新回来还能看到吗？
7、 长任务状态持久化、支持断点恢复——那进程重启时正在跑的任务怎么续上？恢复的粒度是整个会话还是单个 Agent 节点？
8、消息幂等是怎么做的？用什么 key 去重？怎么同时保证不重复回复和不漏回复？
9、这 5 个 Agent 串下来，端到端延迟大概多少？P99 呢？哪个节点最慢，优化过吗？
10、项目二的设计稿你是怎么借助 AI 实现的，完整流程说一下？
11、反问
等待二面中...有面过二面的来说下都会问啥吗 #发面经攒人品#
