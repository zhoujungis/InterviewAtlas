如果你想做一个面试复盘App，需要用到Preferences和标签分类

 
 想体验一个完整的面试复盘应用吗？打开鸿蒙应用市场，搜索「面经库」下载体验，看看面试题目记录、回答要点、反思标签这些功能实际用起来是什么感觉。体验完了再回来，咱们一起拆解它是怎么做出来的。

 
 
 写在前面

 面试复盘这件事，做过几次面试的人都明白它的重要性。面试完不总结，下次遇到同样的问题还是答不好。所以做一个面试复盘App，把每次面试的题目、你的回答、以及事后的反思都记下来，是非常有价值的。

 这篇文章我们以「面经库」这个App为例，从React的实现开始，搬到鸿蒙ArkTS上。重点聊标签系统的设计和题目分类筛选的实现。

 这篇文章聊什么

 
 标签系统设计 -- 怎么设计一个灵活的标签系统，支持多标签筛选

 题目分类筛选 -- 怎么根据标签、公司、岗位等维度筛选面试记录

 数据存储 -- 怎么用Preferences存储结构化的面试记录

 
 第一步：设计面试记录的数据结构

 一条面试记录包含：面试的基本信息（公司、岗位、日期）、题目列表（问题、回答、标签）、以及整体反思。

 enum Difficulty {

}

 // 单个面试题目的数据结构 
 interface InterviewQuestion {
 id : string ;

 myAnswer : string ; // 我的回答 
 idealAnswer : string ; // 理想回答 
 tags : string []; // 标签数组

}

 // 一条面试记录 
 interface InterviewRecord {
 id : string ;
 company : string ; // 公司名称 
 position : string ; // 岗位 
 date : string ; // 面试日期 
 round : string ; // 面试轮次

}
 
 ArkTS版本用了 enum 来定义难度等级，比字符串字面量联合类型更规范。 tags 是字符串数组，一个题目可以有多个标签，比如一道题既属于"JavaScript"又属于"手写题"。

 第二步：标签系统设计

 标签系统是这个App的核心。好的标签系统要满足：可以快速添加标签、可以按标签筛选、可以看到所有用过的标签。

 React版本

 // 获取所有唯一的标签（从所有面试记录中收集） 
 function getAllTags ( records ) {
 const tagSet = new Set ();
 records. forEach ( record => {
 record. tags . forEach ( tag => tagSet. add (tag));
 record. questions . forEach ( q => {
 q. tags . forEach ( tag => tagSet. add (tag));
 });
 });
 return Array . from (tagSet);
}

 // 按标签筛选面试记录 
 function filterByTags ( records, selectedTags ) {
 if (selectedTags. length === 0 ) return records;
 return records. filter ( record => {
 // 记录的整体标签匹配 
 const recordMatch = record. tags . some ( t => selectedTags. includes (t));
 // 题目的标签匹配 
 const questionMatch = record. questions . some ( q => 
 q. tags . some ( t => selectedTags. includes (t))
 );
 return recordMatch || questionMatch;
 });
}
 
 getAllTags 遍历所有面试记录，收集所有出现过的标签，用 Set 去重。 filterByTags 根据选中的标签筛选记录，匹配逻辑是：记录的整体标签或任何题目的标签包含选中标签就算匹配。

 ArkTS版本

 // 获取所有唯一的标签 
 function getAllTags ( records: InterviewRecord[] ): string [] {
 const tagSet : Set = new Set ();
 for ( const record of records) {
 for ( const tag of record. tags ) {
 tagSet. add (tag);
 }
 for ( const question of record. questions ) {
 for ( const tag of question. tags ) {
 tagSet. add (tag);
 }
 }
 }
 return Array . from (tagSet);
}

 // 按标签筛选面试记录 
 function filterByTags ( records: InterviewRecord[],
 selectedTags: string [] ): InterviewRecord [] {
 if (selectedTags. length === 0 ) {
 return records;
 }
 return records. filter ( ( record: InterviewRecord ) => {
 // 检查记录的整体标签 
 const recordMatch : boolean = record. tags . some (
 ( t: string ) => selectedTags. includes (t)
 );
 // 检查题目标签 
 const questionMatch : boolean = record. questions . some (
 ( q: InterviewQuestion ) => q. tags . some (
 ( t: string ) => selectedTags. includes (t)
 )
 );
 return recordMatch || questionMatch;
 });
}

 // 按公司筛选 
 function filterByCompany ( records: InterviewRecord[],
 company: string ): InterviewRecord [] {
 if (!company) return records;
 return records. filter ( ( r: InterviewRecord ) => 
 r. company . toLowerCase (). includes (company. toLowerCase ())
 );
}

 // 按难度筛选 
 function filterByDifficulty ( records: InterviewRecord[],
 difficulty: Difficulty ): InterviewRecord [] {
 return records. filter ( ( r: InterviewRecord ) => 
 r. questions . some ( ( q: InterviewQuestion ) => q. difficulty === difficulty)
 );
}
 
 ArkTS版本的筛选逻辑和React版本一样，只是加了类型注解。 filterByCompany 用 includes 做模糊匹配，这样用户输入"字节"就能匹配到"字节跳动"。 filterByDifficulty 筛选包含特定难度题目的面试记录。

 这三个筛选函数可以组合使用：先按公司筛选，再按标签筛选，最后按难度筛选。这种管道式的筛选方式很灵活，用户可以随意组合筛选条件。

 第三步：用Preferences存储面试记录

 ArkTS版本

 import { preferences } from '@kit.ArkData' ;

 // 保存面试记录 
 async function saveRecords ( context: Context, records: InterviewRecord[] ) {
 const store = await preferences. getPreferences (context, 'interview_store' );
 await store. put ( 'records_list' , JSON . stringify (records));
 await store. flush ();
}

 // 加载面试记录 
 async function loadRecords ( context: Context ): Promise {
 const store = await preferences. getPreferences (context, 'interview_store' );
 const data = await store. get ( 'records_list' , '[]' );
 return JSON . parse (data as string ) as InterviewRecord [];
}

 // 添加一条新的面试记录 
 async function addRecord ( context: Context, record: InterviewRecord ) {
 const records = await loadRecords (context);
 records. unshift (record); // 新记录放在最前面 
 await saveRecords (context, records);
}

 // 删除一条面试记录 
 async function deleteRecord ( context: Context, recordId: string ) {
 const records = await loadRecords (context);
 const index = records. findIndex ( r => r. id === recordId);
 if (index >= 0 ) {
 records. splice (index, 1 );
 await saveRecords (context, records);
 }
}
 
 unshift 把新记录插入数组最前面，这样最新的记录显示在列表顶部。删除用 findIndex 找到索引，然后 splice 移除。每次增删之后都要调用 saveRecords 持久化。

 第四步：标签云UI组件

 标签云是展示所有标签的常用方式，标签越大表示使用次数越多。

 ArkTS版本

 @Entry 
 @Component 
struct TagCloud {
 tags : string [] = [];
 selectedTags : string [] = [];
 onTagClick : ( tag: string ) => void = () => {};

 // 计算每个标签的使用次数 
 private getTagCount ( tag : string ): number {
 return this . tags . filter ( t => t === tag). length ;
 }

 build ( ) {
 Flex ({ wrap : FlexWrap . Wrap , justifyContent : FlexAlign . Start }) {
 ForEach ( this . tags , ( tag: string ) => {
 Text (tag)
 . fontSize ( 14 )
 . padding ({ left : 12 , right : 12 , top : 6 , bottom : 6 })
 . margin ( 4 )
 . borderRadius ( 16 )
 . backgroundColor (
 this . selectedTags . includes (tag) ? '#FF6B6B' : '#F5F5F5' 
 )
 . fontColor (
 this . selectedTags . includes (tag) ? '#FFFFFF' : '#333333' 
 )
 . onClick ( () => {
 this . onTagClick (tag);
 })
 }, ( tag: string ) => tag)
 }
 . padding ( 8 )
 }
}
 
 Flex 组件设置 wrap: FlexWrap.Wrap 让标签自动换行， FlexAlign.Start 让每行从左边开始排列。选中的标签背景色变成红色，文字变成白色，给用户明确的选中反馈。 borderRadius(16) 让标签变成胶囊形状，看起来更柔和。

 第五步：完整的面试记录页面

 @Entry 
 @Component 
struct InterviewListPage {
 @State records : InterviewRecord [] = [];
 @State allTags : string [] = [];
 @State selectedTags : string [] = [];
 @State searchCompany : string = '' ;
 @State filteredRecords : InterviewRecord [] = [];

 async aboutToAppear ( ) {
 this . records = await loadRecords ( getContext ( this ));
 this . allTags = getAllTags ( this . records );
 this . filteredRecords = this . records ;
 }

 // 当筛选条件变化时，重新计算筛选结果 
 applyFilters ( ) {
 let result : InterviewRecord [] = this . records ;
 result = filterByCompany (result, this . searchCompany );
 result = filterByTags (result, this . selectedTags );
 this . filteredRecords = result;
 }

 // 标签点击处理 
 onTagClick ( tag: string ) {
 const index : number = this . selectedTags . indexOf (tag);
 if (index >= 0 ) {
 // 取消选中 
 this . selectedTags . splice (index, 1 );
 } else {
 // 选中 
 this . selectedTags . push (tag);
 }
 this . selectedTags = [... this . selectedTags ];
 this . applyFilters ();
 }

 build ( ) {
 Column () {
 // 搜索栏 
 Row () {
 TextInput ({ placeholder : '搜索公司名称...' })
 . layoutWeight ( 1 )
 . onChange ( value => {
 this . searchCompany = value;
 this . applyFilters ();
 })
 }
 . padding ( 16 )

 // 标签云 
 TagCloud ({
 tags : this . allTags ,
 selectedTags : this . selectedTags ,
 onTagClick : ( tag: string ) => this . onTagClick (tag)
 })
 . padding ({ left : 16 , right : 16 })

 // 面试记录列表 
 List ({ space : 12 }) {
 ForEach ( this . filteredRecords , ( record: InterviewRecord ) => {
 ListItem () {
 Column ({ space : 8 }) {
 // 公司和岗位 
 Row () {

 Button ( '添加面试记录' )

 applyFilters 方法在筛选条件变化时被调用，它依次执行公司筛选和标签筛选，把结果赋给 filteredRecords 。UI上显示的是 filteredRecords 而不是原始的 records ，这样筛选条件变化时UI会自动更新。

 onTagClick 处理标签的选中/取消选中。如果标签已经在 selectedTags 里，就移除；如果不在，就添加。然后触发 applyFilters 重新筛选。

 总结

 这篇文章我们聊了面试复盘App的核心实现：

 
 标签系统 -- 用字符串数组表示标签，支持多标签筛选和标签云展示

 题目分类 -- 管道式筛选：先按公司，再按标签，再按难度，灵活组合

 数据存储 -- 用Preferences存储结构化的面试记录，每次增删后立即持久化

 
 核心API就是 Preferences ，用来存储和读取面试记录数据。标签系统的设计是这个App最有意思的部分，它让用户可以多维度地组织和查找自己的面试经历。如果你对完整的「面经库」App感兴趣，去鸿蒙应用市场搜索下载体验一下吧。

## iOS面试小结

来源：掘金 ｜ 类型：面经 ｜ 发布：2021-04-25 ｜ [原文链接](https://juejin.cn/post/6954907622004752391)

前言

 面试是职场中必经的一个步骤，在短短的几十分钟内去考察一个人的各项能力与综合素质，判断候选人与团队和团队匹配程度。从技术角度来看，面试更像是针对某些知识的讨论，寻求面试官和候选人的知识共通点，从而判断候选人是否满足团队需要。 一个恰当的面试不是要难倒候选人，而是要引导候选人展示长处；从候选人熟悉的内容入手，考察技术细节和背后思考。 
本文便谈一谈我对iOS面试的一些思考。

 正文

 iOS的面试大致包括三大部分： 基础知识、项目经历、代码考察 。

 基础知识 可以分为：
a.计算机基本知识：网络原理、操作系统、编译原理、数据结构、数据库等；
b.平台相关知识：OC基础、Runtime、内存管理、RunLoop、多线程、Xcode等；

 项目经历 指的是做过的项目以及特定知识的积累，包括Crash分析、性能优化、持久化、代码架构、Pod化、模块化、组件化、持续集成等。

 代码考察 是观察候选人在遇到问题如何理解题目、分析问题、实现过程，通常一些解题思路有贪心、动态规划、数据结构、递归、二分、排序等。

 一、基础知识

 1、Objective-C基础

 为了切合iOS面试的主题，面试官通常都会从这一块知识开始入手。OC的知识非常庞杂，有时候遇到熟悉的内容就很了解，如果没有接触过可能就没有印象。比如说： viewDidLoad 的触发时机是发生在什么时候？以及延伸的问题， viewDidLoad 与loadView的关系以及先后顺序。

 所以这部分知识，更合适问一些基础、共性的问题。比如说：

 
 常见的property有哪些属性？各自的属性应用场景有哪些？

 介绍KVO和KVC的区别？KVO是否会引起循环引用？如果观察对象已经释放，会导致什么现象？用NSNotification 替代KVO，观察对象已释放会如何？如何手动实现KVO？

 如何创建一个字符串常量？在.h声明并且实现会有什么问题？

 category和extension的区别？category的实现原理？extension是否可以和category写在同一个文件？

 
 2、内存管理

 ARC和MRC，iOS开发者需要对两种内存管理方式都熟悉。一个了解MRC的开发者，遇到CF开头的函数怎么办？
很常见的面试切入点是从ARC的实现原理开始，引入 __strong/__weak/__unsafe_unretained/__autoreleasing 多个关键词的区别，再联想到循环引用，block实现原理，block持有外部的局部变量，autoReleasePool的使用，autoReleasePool与MRC的autorelease区别。

 三、代码考察

 简单的以LeetCode为标准，大部分公司的要求是在easy难度，进阶要求也只到medium难度。

实际面试过程中，可能是长时间没有做面试题并且没有事先准备，也可能刚好考察到思维盲区，能顺利完成easy难度的题目都是凤毛麟角。

 做题并不是为了把题目解决，而是从做题过程去分析思考面试者遇到问题是如何思考解决，以及能否把代码用实现想法。 

 选择性针对某些考察点去用对应题目也是一种方向，比如说：
1、对于一个整数m，计算其二进制表示有多少个1，并分析其复杂度；

2、计算1~1000中，有多少个数字7；

3、有两个很大的整数是用字符串来表示，实现一个函数加法，输出这两个字符串数字相加的结果；（大数加法）

...

 分享一些做题要点：

1、快速理解题意，对于不清楚的条件及时提出疑问；

2、三思而后行，先分析题目考察点，再进行方案分析，最后做复杂度分析；

3、先讲思路，再进行coding；

 理想结果：

1、思路顺畅，实现过程简单清晰；

2、边界处理完善，考虑周全；

3、代码可读性强，具有一定的抽象和扩展；
