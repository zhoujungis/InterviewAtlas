## 寒武纪 C++ 二面面经（27届秋招）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-11-09 ｜ [原文链接](https://www.nowcoder.com/discuss/949235420494061568)

1. 你们这套 AI 编译器从 ONNX 到 NPU 指令，中间经过哪几步？你负责哪块？

 参考答案：

 
 前端：解析 ONNX 成计算图，做 shape 推导和类型检查，再转成内部 IR，我们支持约 300 个算子，不支持的走 CPU 回退。

 图优化：常量折叠、死代码消除、算子融合、layout 转换消除；ResNet-50 从 320 个节点降到 78 个，减少的主要是 BN 和 ReLU。

 后端：算子选择（按 cost model 定 tiling 和指令）、内存分配、流水编排、代码生成，最后交给运行时下发到硬件。

 
 2. 算子选择怎么做？你的 cost model 用什么指标，准不准？

 参考答案：

 
 候选集：每个算子有多个实现，direct、im2col + gemm、winograd 各有适用区间，按 shape 和 dtype 生成 3~8 个候选。

 代价模型：用片上存储占用、DMA 字节数、MAC 利用率三项加权打分；手写公式初期误差 20%，用实测数据拟合后降到 7%。

 兜底策略：模型不准时靠 autotune 实测选优，编译超过 200 ms 就回退到公式；我们保留 top-2 候选，运行时还能切换。

 
 3. 手撕：给你一张计算图，写一个拓扑排序，输出可执行的算子顺序，怎么写？

 参考答案：

 
 实现：统计入度，入度为 0 的入队，出队时把后继入度减 1，减到 0 再入队；O(V+E)，邻接表用 vector 比 unordered_map 快一倍。

 细节：队列用 vector 加 head 索引，避免 deque 的块分配；同层节点按 id 排序，保证两次编译产出完全一致的 binary。

 用途：这个序既是下发序，也是内存复用分析的基础；1 万节点的图排序耗时 1.2 ms，占编译总时间的 3%。

 
 4. 追问：图里有环怎么办？是直接报错还是尝试修？

 参考答案：

 
 检测：拓扑排序输出的节点数小于总数就说明有环；要定位环用 DFS 三色标记，遇到灰色节点时回溯栈就是环的路径。

 处理：合法 ONNX 图不该有环，遇到就报错并打印环上的节点名和 op 类型；但 Loop、If 展开后可能成环，要先做结构化。

 兜底：我们留了环检测开关，线上只报错不自动修；曾有一次 Reshape 前后共用 buffer 被误判成环，实际是别名分析没做好。

 
 5. 算子融合为什么能省时间？Conv + BN + ReLU 融合到底省了什么？

 参考答案：

 
 省访存：不融合要写 3 次中间结果、读 3 次，56×56×64 的 FP16 特征图 400 KB，三次往返就是 2.4 MB 流量；融合后只在寄存器里传递。

 省启动：每次 kernel launch 有 3~5 μs 固定开销，ReLU 这种算子本身只要 2 μs，融合后启动开销被摊掉。

 融合边界：要求 shape 和 layout 兼容，且不能跨 concat 这类多输入节点；融合后 ResNet-50 的 kernel 数从 53 降到 31。

 
 6. 手撕：实现一个 best fit 的内存池，怎么快速找到最合适的块？

 参考答案：

 
 结构：按 size 分级，16、32、64 一直到 2048，每级一条空闲链表，申请时向上取整到级，分配是 O(1)；更大的块走伙伴系统。

 最优匹配：单链表版本要遍历所有空闲块找最小满足的，O(n)；改成按大小排序的 set 或分级链表，能降到 O(log n) 甚至 O(1)。

 碎片控制：best fit 会产生大量小碎片，我们加了相邻空闲块合并和 10% 的 slack 容忍，碎片率从 23% 降到 8%。

 
 7. 追问：张量的内存复用怎么设计？两个 tensor 生命周期重叠还能复用吗？

 参考答案：

 
 前提：按拓扑序算出每个 tensor 的 [def, last_use] 区间，只有区间不重叠才能共用一块内存，这就是 liveness analysis。

 算法：维护按 size 排序的空闲块集合，每次分配找最小满足的块（best fit），生命周期结束就归还并尝试与相邻块合并。

 收益：1.2 GB 的中间激活压到 380 MB，省 68%；但复用会让调试变难，debug 版本关掉复用并给每个 tensor 单独命名。

 
 8. tiling 是为了解决什么问题？tile 大小怎么定？

 参考答案：

 
 要解决的问题：片上 SRAM 只有 2 MB，一个 256×256 的 FP16 特征图就 128 KB，加权重根本放不下，必须切块搬入。

 约束条件：tile 要满足 SR

## 寒武纪 C++ 一面面经（27届秋招）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-11-09 ｜ [原文链接](https://www.nowcoder.com/discuss/949235115660472320)

1. 一个带虚函数的类，对象内存里到底放了什么？虚表是什么时候填的？

 参考答案：

 
 对象布局：只有 vptr 占 8 字节且在偏移 0，后面才是成员变量；虚表本身在 .rodata 段，编译期由编译器生成，vptr 在构造函数里被赋值。

 虚表内容：按声明顺序存放虚函数地址，前面两个槽是 RTTI 和偏移信息；派生类覆盖就替换对应槽，多继承会有多个 vptr。

 构造期陷阱：构造和析构中调虚函数只会调到当前类的版本，因为 vptr 是分阶段更新的；我们在基类构造里调过 log()，结果一直打到基类实现。

 
 2. 为什么基类析构要写成 virtual？什么情况下可以不写？

 参考答案：

 
 未定义行为：用基类指针 delete 派生类对象，派生类析构不会执行，里面 new 的 buffer 全泄漏；标准里这是 UB，实际表现通常只是调了基类析构。

 实现代价：加一个 vptr 8 字节，析构变成间接调用；像 Vec3 这种没有虚函数的叶子类不必虚析构，我们规范要求 final 类不加。

 正确写法：基类写 virtual ~Base() = default，或者把析构设成 protected 禁止外部 delete 基类指针，两种都行但不要混用。

 
 3. unique_ptr、shared_ptr、weak_ptr 你在项目里怎么选？shared_ptr 的代价到底在哪？

 参考答案：

 
 选型：独占所有权一律 unique_ptr，大小和裸指针一样且能编译期检查；确实要共享才用 shared_ptr，只观察不拥有就用 weak_ptr 断开循环。

 代价：控制块一次堆分配加两个原子计数，make_shared 能把对象和控制块合成一次分配；引用计数增减约 10 ns，热路径每秒千万次就是 10% 的 CPU。

 踩坑：多个线程对同一个 shared_ptr 变量赋值是数据竞争，不是线程安全的；aliasing constructor 可以让 shared_ptr 指向 Tensor 的子视图而共享控制块，我们靠它管切片。

 
 4. vector、list、deque、map 你怎么选？迭代器失效的规则能说清吗？

 参考答案：

 
 复杂度：vector 随机访问 O(1)、尾部插入均摊 O(1)；list 插入 O(1) 但每个节点一次 cache miss，1 万节点遍历比 vector 慢 5~8 倍。

 失效规则：vector 扩容后全部失效，没扩容时插入点之后的失效；deque 中间插入全失效；map 和 list 只有被删的那个节点失效。

 实战：遍历中删除必须写 it = c.erase(it)，不能 it++；我们有个 bug 是范围 for 里 erase，只在特定数据量下崩，查了两周。

 
 5. vector 的扩容过程说一下，1 亿个 int 做 push_back 大概要拷贝多少次？

 参考答案：

 
 扩容流程：申请新块（通常 2 倍或 1.5 倍），把旧元素搬过去，析构旧元素，释放旧内存；libstdc++ 是 2 倍，MSVC 是 1.5 倍。

 拷贝量：倍增策略下总搬运次数约 2N，1 亿个 int 就是 2 亿次拷贝、800 MB 内存流量；提前 reserve 一次这些全免。

 优化：只有移动构造是 noexcept 才走 move_if_noexcept，否则为了强异常保证退化成拷贝；我们给 Tensor 补了 noexcept 移动，扩容快 3 倍。

 
 6. 模板你在项目里怎么用的？模板报错几百行你怎么定位？

 参考答案：

 
 常见用法：用模板参数做策略，编译期绑定后能内联，比虚调用快 3~5 倍；我们的 kernel 用 template 生成多个 tiling 版本，运行时按 shape 选。

 报错定位：从实例化栈底往上看，找第一行 "required from" 指向的用户代码；C++20 上了 concepts 之后，错误能收敛到约束不满足的那一行。

 代码膨胀：每个实参一份独立代码，10 个类型实例化一个大模板能涨 20 MB；与类型无关的逻辑抽到非模板基类，常用类型用 extern template 抑制重复生成。

 
 7. 手撕：实现一个简化版 vector，支持 push_back、size、capacity 和析构，你打算怎么写？

 参考答案：

 
 骨架：三个指针 begin、end、cap，push_back 发现 end == cap_ 就按 2 倍扩容，用 std::move 搬旧元素，全程保证异常安全。

 关键点：拷贝构造要深拷贝，移动构造要把源对象三个指针置空；operator= 用 copy-and-swap 一次解决自赋值和异常安全。

 易错点：析构要先对有效元素逐个调 destroy，再释放裸内存；new T[n] 会默认构造 n 个对象，正确做法是 ::operator new 拿内存再加 placement new。

 
 8. 追问：为什么扩容是 2 倍，不是每次多给 10 个？1.5 倍和 2 倍有什么区别？

 参考答案：

 
 摊还分析：每次固定加常数会退化成 O(n²)，1 亿次插入约 5×10^15 次拷贝；倍增的总搬运是 2N，均摊下来才是 O(1)。

 增长因子：2 倍时新块总比之前所有释放块之和还大，堆无法复用旧空间；1.5 倍增长后旧块能被后续申请复用，所以 MSVC 选 1.5。

 取舍：2 倍扩容次数少、均摊更快，但峰值内存是 3 倍（新旧同时存在）；我们推理框架的输出 buffer 改用 1
