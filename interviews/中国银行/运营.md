 真题一：讲讲你在研会经历（2022届 运维岗 春招实习单面） 

 答题方向： 归到 个人经历类 ，用 讲故事法 STAR+F。学生工作类题的考点不是"你当过什么"，而是组织、协调、推进—— 运维岗为什么问这个？ 因为值班要交接、出故障要拉人协调、半夜被叫起来还要对外解释清楚，都需要你能在人前把场面撑起来。讲的时候突出四个动作：我定了流程、我控了时间、我照顾到不说话的人、最后出了成果。 

 答题话术参考： 我在研究生会做过 XX，主要组织 XX 活动，前后办了 X 期，我负责流程这一块：提前两周定主题和人选，提前一周发通知；开场先花两分钟把议程和每段时间说清楚；中间有人超时我会提醒；最后留一段时间自由讨论，我会点名请一直没发言的同学说说看法，有几次反而是他们提的问题最有价值。办下来参与人数从二十多到四十多。我的体会是，组织讨论最难的不是自己讲得多好，而是让每个人都参与、最后能收出结论，做故障复盘会是同一种能力。

 真题一：你和你同事因为工作上事情的问题意见不一样，你的方法科学有效，你怎么劝他用你的方法？（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 人际沟通类 ，用 新人思维 ，按"先找自己原因 → 再找双方原因 → 委婉看对方 → 给可落地方案"四步。题眼在"你的方法科学有效"这个设定——它在测你会不会 居高临下压人 。运维特别在意这点：半夜出故障你要拉的是别的组的人，人家没义务听你的，靠"我是对的"压人一定失败。所以答案里要放弃"说服"，改成"对齐事实、一起验证"。 

 答题话术参考： 首先我不会一上来就说我的方法更好。作为新人，我掌握的背景信息未必全，对方坚持他的方案，很可能是他知道一些我不知道的约束，所以第一步我会请他把顾虑讲完，我也把依据摆出来，看是不是在同一个事实上讨论。如果确实是角度不同，我会建议小范围验证：挑一个影响可控的场景分别试，或者用一组数据比对效果，让结果说话，比谁口才好更有说服力，也避免谁下不来台。如果验证下来我的方案更优但对方仍有顾虑，我会把两套方案的利弊列清楚，请他一起找组长定，我不会绕过他。我的目标是问题被解决，不是我的方案被采纳。 

 真题二：最拿手的编程语言（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 个人经历类 的简历确认，用 词+事 。只报一门"最拿手"的，按"语言 → 熟练到什么程度 → 用在哪 → 边界在哪"四层说，最后那句边界很加分，因为它证明你对自己有清醒判断。 

 答题话术参考： 我最拿手的是 Java。从本科到现在一直在用，研究生阶段两个项目都是 Java 写的，Spring Boot 这一套、多线程、MySQL 和 Redis 的常规用法我都实际用过，也做过 JVM 层面的排查，比如看线程栈定位死锁、调 GC 参数。到这个程度我写代码和读别人的代码都没问题。但我也要说实话，对一些很细的东西，比如 JIT 和内存模型的边界情况，我还停留在知道原理、没实战过的阶段。如果岗位需要，我上手补起来很快，因为基础是通的。 

 真题三：用此语言做过什么有成就的项目（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 个人经历类 ，用 讲故事法 STAR+F。限定词是"有成就"，所以 R 必须给数据，并讲清"成就"是相对什么而言的（原来什么样、现在什么样）。A 要写清卡点和具体操作，这是面试官判断真伪的地方。 

 答题话术参考： 我讲的是 XX 系统，背景是业务方每天要处理大概 X 万条数据，原来靠脚本加人工，出错率不低，我们的目标是做成自动化服务。我负责 XX 模块的设计开发，技术栈是 Spring Boot 加 MySQL。最大的卡点是数据一致性，上游会重复推送，早期没做幂等，出过一次重复处理，事后加了唯一键加状态机校验才解决；第二个卡点是性能，批量处理一开始串行，跑一次两小时，改成按连接池大小反推并行度做分片并行，压到 25 分钟。上线后稳定运行三个月，人工介入比例降了七成。现在看，监控和告警做得不够细，重做我会把可观测性提前设计进去。 

 真题四：介绍一下你的专利情况（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 个人经历类 ，用 讲故事法 。陷阱是讲成"我有一项专利"就没了。要讲三层：解决什么问题、你在其中的实际贡献（第几发明人、你做的哪部分）、和岗位有什么关系。不是第一发明人就如实说，重点讲你做的那一块。 

 答题话术参考： 我有 X 项专利，都是 XX 方向的，我想讲其中一项：XX。它解决的是 XX 场景下 XX 效率不高的问题，原有做法需要 XX，我们提出的方案是 XX，核心思路是把 XX 拆开处理，从而把复杂度降下来。我是第 X 发明人，我具体负责方案中的 XX 设计和实验验证，实验数据是我跑的，目前状态是 XX。说实话学生阶段的专利离落地还有距离，但对我是个完整训练：从发现问题、查文献、设计实验到写成材料，这个过程让我学会怎么把模糊的想法变成可验证的东西，这种能力到工作岗位上一样用得上。 

 真题六：对信息科技运营中心的理解？（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 综合分析类 ，用 主体分析法 的变式，按"认知 → 拆解 → 收口"三步。这是科运的核心题，且必然与"为什么选这个岗"连用（见第 7 题）。理解部分要说出四条线——生产运行管理、集团网络安全防控、集团云建设、生产运营领域数字化建设，并明确纠正"运维等于修电脑"，这一句是拉开差距的地方。 

 答题话术参考： 我的理解是，运营中心是中行总行直属机构，负责全行信息系统的生产运营管理，另外还有三块：集团网络安全防控、集团云建设、生产运营领域的数字化建设。所以它不是一般意义上"谁的电脑坏了去修"的运维，而是保障全行系统持续稳定运行的体系。落到日常工作，核心是三件事：一是稳定性，靠监控、变更管理和演练让系统不出事；二是应急，出事之后最短时间止血和恢复，靠预案和熟练度；三是效率，把重复劳动做成自动化。另外我也知道会有值班和倒班，这一点我投之前就想清楚了。 

 真题七：为什么选择此岗位？（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 求职意愿类 ，用 立人设法 ，按"个人角度 → 公司角度 → 生活实际 → 积极表态"展开。这题和第 6 题连问，结构上要承接：上一题讲"我理解这个岗"，这一题讲"所以是我"。重点是把"稳定"讲成主动选择而不是逃避，并落到运维的具体吸引力上。 

 答题话术参考： 主要有三点。一是能力匹配，我本硕都是计算机，做过系统开发也做过数据处理，另外我维护过实验室平台，做过监控告警和故障止损，对这个方向不是凭想象的喜欢，是做过之后确认自己能干也愿意干。二是我对这件事本身的判断，系统稳定运行的反馈很直接，出问题你几分钟内就要做出判断，这种压力和成就感做业务功能很难体会到；而且银行都在推数字化转型和集团云，运营中心正好在这条主线上。三是平台，它是总行直属机构，规模和复杂度在别的地方碰不到。所以这不是随手投的岗，如果有机会加入我准备长期做下去。 

 真题九：本硕成绩如何？（2021届 运维岗 暑期实习单面） 

 答题方向： 归到 个人经历类 的简历核实题，用 词+事 。和绩点题同构，考察点不是分数本身，而是学习态度和你面对这个问题的姿态。分数好就报排名和核心课；一般就如实报，把重心转到核心课和项目产出上，不要长篇解释。 

 答题话术参考： 本科绩点 XX，专业排名大概前 XX%，研究生成绩是 XX。本科基础课我打得比较扎实，数据结构、操作系统、计算机网络、数据库这几门都是 XX 分以上，后面做项目和排查问题时我发现真正用得最多的就是这几门。研究生阶段我把更多时间放在项目和实习上，成绩比本科略低一些，这个我不回避。要说收获的话，研究生阶段最大的成长不在课业而在工程实践，那两个项目和那段维护经历让我知道了真实系统是怎么出问题的。成绩单我可以提供，没有什么需要藏的。 

 真题十：如果你被分配到了运维这个岗位你能接受吗（2021届 运维岗 北京秋招单面） 

 答题方向： 归到 求职意愿类 ，用 立人设法 ，按"明确接受 → 说明我理解的运维是什么 → 表态"三步。注意这和后面那句是 连在一起发生的 ：面试官问完"能不能接受"，紧接着主动展开讲运维的工作内容和工作时长（7×24 三班倒），说明这是科运的 标准化告知动作 。所以第一句必须干脆，"原则上可以""应该没问题"在运维岗等于没答。回扣开篇：JD 一字不提排班，这就是那句被藏起来的话。 

 答题话术参考： 能接受，而且我投的时候就是冲着这个岗位来的，不是被调剂之后才考虑。我理解运营中心做的是全行信息系统的生产运行保障，包括生产运行的日常管理、网络安全防控、集团云这些，落到我个人身上就是监控、变更、应急处置、值班。我在实验室维护平台做过两年，处理过磁盘打满导致服务不可用的故障，也做过上线保障，对这个节奏有体感，不是凭想象说自己能接受。我也知道它有作息不规律的一面，已经跟家人说过，也做好了调整作息的准备。如果分配到这里，我的态度很明确：接受，并愿意长期做。 

 真题十一：面试官展开讲"运维的工作内容以及工作时长（7×24 三班倒）"，你怎么接（2021届 运维岗 北京秋招单面） 

 答题方向： 本篇最稀缺的一段素材。原帖记录得很清楚：面试官主动展

来源：牛客网 ｜ 类型：面经 ｜ 发布：2020-11-16 ｜ [原文链接](https://www.nowcoder.com/discuss/353157336648851456)

今天下午1点于国际金融研修院参加了中行信科的面试，面试形式是一面群面+二面单面，大概四五位面试官（没有仔细数）. 进入面试地点先签到+填写资料，然后抽签群面. 

 进入群面，有五分钟思考时间然后第一轮发言，我第一位发言（可能是性格比较着急吧！）后面十分钟讨论时间.总的来说大家口才都很不错，观点也比较统一，带了手表的小姐姐担任了计时和总结的工作（可能由于紧张的缘故，总结的比较一般，如果没这么紧张她应该能说的更好哈哈）. 

 然后是单面，由于我的序号是6等待前面五位同学先面，我们又回到了签到的地方，于是我就开始吃吃喝喝（哈哈，面试的额外收获吧，吃了不少零食）大概一个小时左右轮到了我.先是自我介绍，学历简历啥的我都没啥问题并且获得了面试官的认可，其中中间的面试官首先问：如果你被分配到了运维这个岗位你能接受吗，然后就展开讲了运维的工作内容以及工作时长（7*24 三班倒）我一开始没听到三班倒，就说了句不睡觉的吗，这....然后面试官们就都开始笑；接着一个女面试官问我有没有互联网的offer以及为什么不选择，我直白的回：因为没有户口，然后大家又笑了（好吧）；然后中间的面试官继续问他选择了我，我留下的概率是多大，我没给出明确回复，但是提出了晋升方面的问题；最后女面试官让我介绍了一个社团的活动；在结束的关头旁边那个一直不说话的面试官提出了一个问题，你简历填写把你妈妈的名字写成了自己的（好吧，气氛变得异常尴尬，确实我很粗心！！！） 

 最后我面试结束啦，外面下着小雨，这几天北京的空气确实不太好😂！总的来说面试体验还不错，第一次经历群面（群面真有意思，but大家说方案的时候确实不考虑方案落地）并且见到了几个漂亮小姐姐，还吃了不少零食. 

 ps：弱弱问一句打车费能报销吗？哈哈哈哈！
