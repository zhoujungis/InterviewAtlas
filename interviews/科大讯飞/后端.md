## 科大讯飞C++二面 面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-13 ｜ [原文链接](https://www.nowcoder.com/discuss/928573373704077312)

一、什么是右值引用和移动语义，std::move的本质是什么

 左值和右值 ：左值有名字、可取地址（变量、对象）；右值是临时值、即将消亡（函数返回的临时对象、字面量）。C++11 用 && 表示右值引用，只能绑定右值。

 移动语义解决的问题 ：传统拷贝对指针成员要“申请新内存+复制内容”，而一个即将销毁的临时对象，它的资源（堆内存、文件句柄）完全可以直接“过户”给新对象—— 移动构造 把对方的指针拿过来、把对方置空，只有几次指针赋值的开销，没有深拷贝：

 Buf(Buf &&other) noexcept // 移动构造
{
 data = other.data; // 直接接管资源
 other.data = nullptr; // 对方置空，析构时不会释放
}

 
 std::move 的本质 ： 它不移动任何东西 ，只是 static_cast ，把左值强制转换成右值引用类型，从而让编译器选择移动构造/移动赋值。真正的“移动”发生在移动构造函数里。被 move 后的对象处于“有效但未定义”状态，只能重新赋值或销毁。

 加分点 ：移动构造要标 noexcept ，否则 vector 扩容时会退化用拷贝（move_if_noexcept 机制）；完美转发 std::forward 配合模板引用折叠，保持参数原本的左/右值属性传递。

 二、手写线程安全的单例模式

 class Singleton {
public:
 static Singleton& instance()
 {
 static Singleton inst; // C++11：局部静态变量线程安全（魔法静态）
 return inst;
 }

 Singleton(const Singleton&) = delete; // 禁止拷贝
 Singleton& operator=(const Singleton&) = delete;

private:
 Singleton() = default; // 构造私有
 ~Singleton() = default;
};

 
 要点 ：

 
 三要素：构造私有、禁拷贝、静态访问点；

 C++11 起局部静态变量的初始化由编译器保证线程安全 （初始化代码带锁），这是最优雅的现代写法，面试首选；

 经典追问“饿汉和懒汉”： 饿汉：main 之前（全局静态对象初始化时）就创建，天生线程安全，但可能拖慢启动、顺序不可控；懒汉：第一次调用时创建，有线程安全问题；传统解法是双重检查锁（DCLP）——但要点出DCLP 在无内存屏障时有隐患（指令重排导致别的线程拿到“半初始化”对象），C++11 后应该用 std::call_once + std::once_flag，或直接用局部静态变量；

 多线程下析构是单例的真正难点，可以提 std::shared_ptr 的 weak_ptr 方案。

 
 三、设计一个线程池，讲清楚核心组件

 整体架构：任务队列 + 工作线程数组 + 同步原语 + 管理接口 。

 class ThreadPool {
public:
 explicit ThreadPool(size_t n) : stop(false)
 {
 for (size_t i = 0; i task;
 {
 std::unique_lock lk(mtx);
 cv.wait(lk, [this] { return stop || !tasks.empty(); });
 if (stop && tasks.empty()) // 停止且任务清空才退出
 return;
 task = std::move(tasks.front());
 tasks.pop();
 } // 取任务后立刻放锁
 task(); // 执行期间不持锁
 }
 });
 }

 template 
 void submit(F&& f)
 {
 {
 std::lock_guard lk(mtx);
 tasks.emplace(std::forward (f)); // 完美转发
 }
 cv.notify_one();
 }

 ~ThreadPool()
 {
 {
 std::lock_guard lk(mtx);
 stop = true;
 }
 cv.notify_all(); // 唤醒所有线程退出
 for (auto &t : workers)
 t.join();
 }

private:
 std::vector workers;
 std::queue > tasks;
 std::mutex mtx;
 std::condition_variable cv;
 bool stop;
};

 
 面试讲解要点 （比代码更重要）：

 
 工作线程循环 = “拿锁 → 等任务 → 取任务 → 放锁 → 执行”， 执行任务时不持锁 是关键，否则并发度为 1；

 cv.wait 带谓词防虚假唤醒； stop 标志 + notify_all 实现优雅退出；

 追问点：任务队列满了怎么办（有界队列 + 阻塞提交或拒绝策略）；线程数怎么定（CPU 密集型取核数，IO 密集型可加倍，动态伸缩是进阶）； std::function 有类型擦除开销，追求性能用模板 + 具体类型任务。

 能类比 QT： QThreadPool + QRunnable 就是这套思想的官方实现。

 
 四、C++类有哪些默认成员函数，什么情况下编译器不会生成

 经典六大（C++98） ：默认构造、析构、拷贝构造、拷贝赋值；C++11 新增： 移动构造、 ，合称默认成员函数。

## 科大讯飞C++一面 面经带答案

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-12 ｜ [原文链接](https://www.nowcoder.com/discuss/928234313760407552)

一、C++代码从源文件到可执行文件经历了哪些步骤

 四个阶段： 预处理 → 编译 → 汇编 → 链接 。

 1. 预处理 ：处理 # 开头的指令——头文件展开（#include）、宏替换（#define）、条件编译（#if/#ifdef），删除注释，生成 .i 文件；

 2. 编译 ：把预处理后的代码进行词法分析、语法分析、语义分析、优化，翻译成汇编代码，生成 .s 文件；

 3. 汇编 ：把汇编代码翻译成机器指令，生成可重定位的目标文件 .o （Windows 下 .obj ）；

 4. 链接 ：把多个目标文件和库链接起来，完成 地址重定位 和 符号解析 ，生成可执行文件。链接分静态链接（代码拷贝进可执行文件，体积大但独立运行）和动态链接（运行时加载 .dll/.so，体积小且多个程序共享一份库）。

 加分点：g++ 中对应 -E / -S / -c 选项分别只执行前三步；链接错误 “undefined reference” 就发生在第四步的符号解析。

 二、C++程序的内存分区

 1. 代码区（text） ：存放可执行的机器指令，只读，共享；

 2. 全局/静态区 ：存放全局变量和 static 变量，初始化的在 .data 段，未初始化的在 .bss 段（程序启动时自动清零）；

 3. 常量区 ：存放字符串常量、const 常量；

 4. 堆（heap） ：由程序员手动分配释放（new/malloc），向高地址增长，分配效率低于栈，容易产生碎片；

 5. 栈（stack） ：由编译器自动管理，存放函数的局部变量、参数、返回地址，向低地址增长，分配速度快，但空间有限（通常几 MB），函数结束自动回收。

 加分点 ：栈和堆的生长方向相反；栈溢出就是递归太深或局部变量太大；堆内存忘记释放造成泄漏，可用智能指针/RAII规避。

 三、虚函数和纯虚函数的区别

 虚函数 ：基类中用 virtual 修饰、有默认实现的函数，派生类可重写（override），通过基类指针/引用调用时走动态绑定，执行实际派生类的版本。目的是实现运行时多态。

 纯虚函数 ：声明形式 virtual void func() = 0; ，没有实现（或只在类外给出实现）， 强制 派生类必须重写。含纯虚函数的类是 抽象类 ，不能实例化对象，只能作为接口被继承，用于定义统一接口规范。

 要点 ：

 
 虚函数是“可以重写”，纯虚函数是“必须重写”；

 抽象类不能创建对象，但可以定义指针/引用指向派生类对象；

 派生类如果没有实现所有纯虚函数，它自己也是抽象类；

 多态场景下基类析构函数要声明为 virtual，否则通过基类指针 delete 派生类对象资源泄漏。

 
 四、重载、重写（覆盖）、重定义（隐藏）的区别

 1. 重载（overload） ：同一个作用域内（同一个类），函数名相同、 参数列表不同 （个数/类型/顺序），与返回值无关。编译期根据参数静态绑定。

 2. 重写/覆盖（override） ：发生在 基类和派生类 之间，基类函数是 virtual，派生类函数 函数名、参数、返回值完全相同 ，构成运行时多态，通过基类指针动态绑定。

 3. 重定义/隐藏（hide） ：基类和派生类中函数名相同，但参数不同（或基类函数不是 virtual），派生类函数 隐藏 基类所有同名函数——即使参数匹配也无法通过派生类对象直接调用基类版本，需要加作用域 d.Base::func() 。

 一句话区分：重载看参数在同类，重写看 virtual 在继承，隐藏是同名但没构成重写的坑。

 五、vector的底层原理和扩容机制

 底层 ：vector 是一块 连续 的动态数组，内部维护三个指针：指向起始位置的 start、指向最后一个有效元素 的 finish、指向已分配空间末尾的 end_of_storage。因此支持 O(1) 随机访问。

 扩容机制 ：当 size == capacity 再 push_back 时：

 
 申请一块更大的内存（一般是当前容量的 2 倍 （GCC）或 1.5 倍（MSVC））；

 把旧元素 拷贝/移动 到新内存；

 释放旧内存，更新三个指针。

 
 扩容的代价和注意点 ：

 
 扩容涉及整体搬移，均摊下来 push_back 仍是 O(1)，但单次操作是 O(n)；

 扩容后所有迭代器、指针、引用全部失效 ——这是最常考的坑；

 预知数据量时用 reserve(n) 预分配，避免多次扩容；

 加分点：C++11 后扩容搬移优先用移动构造（noexcept 时）而非拷贝，效率更高； emplace_back 就地构造少一次临时对象。

 
 六、lambda表达式的用法和底层实现

 语法 ： [捕获列表](参数列表) -> 返回类型 { 函数体 } ，如 auto add = [](int a, int b) { return a + b; }; 

 捕获方式 ：

 
 [=] 按值捕获所有外部变量（只读，副本）；

 [&] 按引用捕获（注意生命周期）；

 [x, &y] 指定混合捕获；

 [=]() mutable 加 mutable 后可修改按值捕获的副本。

 
 底层实现 ：编译器把 lambda 生成一个 匿名的仿射类（functor 类） ，捕获的变量成为该类的成员变量，lambda 函数体是它的 operator() 。所以 lambda 的本质是匿名函数对象，捕获即成员初始化。

 加分点 ：无捕获的 lambda 可以隐式转换为普通函数指针； std::function 可以存储任意可调用对象但有类型擦除开销；性能敏感场景直接传 lambda 模板参数可被内联。

 七、QT的信号槽机制原理，和回调函数相比有什么优势

 原理 ：信号槽基于 QT 的元对象系统：

 
 类声明中加 Q_OBJECT 宏，moc（元对象编译器）会扫描头文件，生成带 Qt 元信息的 moc_xxx.cpp ；

 signals 只是声明，由 moc 自动生成实现，emit 一个信号实际是调用 QMetaObject::activate ，遍历该信号连接的所有槽函数并逐个调用；
