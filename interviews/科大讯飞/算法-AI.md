## 10.26 科大讯飞 推理工程部 AI Infra 一面

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-26 ｜ [原文链接](https://www.nowcoder.com/discuss/944283905056665600)

10.26 科大讯飞 推理工程部 AI Infra 一面

 面试形式 ：线上视频面试

 

 面试岗位 ：AI研究算法工程师 - 大模型推理 Infra 方向

 

 所属部门 ：资源星火公司 - 推理工程部

 考察重点 ：异构算力适配、vLLM/SGLang 框架理解、推理瓶颈分析、资源调度与 GPU 池化、AI Coding 工程意识、底层岗位稳定性

 一、自我介绍与项目背景

 简单做一下自我介绍，重点讲一下和 Infra 最相关的项目或实习经历。

 简历里写了在华为做过 AI Infra，这段主要做了什么？和推理模型有没有关联？

 回答思路 ：坦诚没有深度改过底层源码，但重点讲工程侧的真实体感——环境适配、OOM 排查、压测调优、Profiling 数据收集。落脚到“理解开源框架跨到国产算力时，算子不兼容、动态 shape 处理、显存调度差异是主要痛点”。

 二、异构算力与国产化适配

 聊聊你对“原生算力”和“异构算力实践”的理解。

 回答思路 ：原生意指 CUDA 生态成熟、开源框架默认优先支持；异构是为了自主可控，也是部门实际在打的方向。核心矛盾不是“能不能跑”，而是“跑得好不好”——算子覆盖度、图模式编译、通信与内存一致性。插件式适配（如 vllm-ascend 作为后端接入）是保留开源生态迭代速度的工程解法。

 三、vLLM 与 SGLang 框架理解

 用 vLLM 或 SGLang 实际跑过模型吗？框架里各个模块分别起什么作用？

 vLLM 的 PagedAttention 和 Continuous Batching 分别解决什么瓶颈？

 SGLang 的 RadixAttention 和 vLLM 的 prefix caching 是什么关系？

 回答思路 ：

 vLLM：PagedAttention 用 block table 做逻辑到物理映射，消除 KV Cache 碎片；Continuous Batching 把调度粒度下沉到每个 decode step，完成即替换，GPU 槽位不空转。

 SGLang：RadixAttention 用基数树管理前缀 KV 复用，在多轮对话、Agent、RAG 等高前缀重复率场景下额外榨取吞吐；HiCache 进一步把缓存从 HBM 扩展到主机内存和分布式存储。

 定位差异：vLLM 强在“把每一份显存用得最紧凑、让 GPU 不闲着”；SGLang 强在“让重复的前缀不重复算”。

 四、推理瓶颈分析与优化实验

 推理时的瓶颈主要在哪？内存瓶颈和计算瓶颈分别怎么定位？

 如果让你做优化实验，你会怎么设计？

 回答思路 ：

 瓶颈：Prefill 是 compute-bound，Decode 是 memory-bound；长上下文下 KV Cache 显存爆炸是推理侧显存的主战场。

 实验设计：先跑基线，记录 TTFT、TPOT、吞吐、显存峰值；用 Profiling 工具（Nsight / msProf）确认是 memory-bound 还是 compute-bound，再做针对性调整——显存碎片调 block size / gpu-memory-utilization，前缀重复率高对比开启/关闭前缀缓存，算力打不满考虑量化或投机采样。核心是用数据判断，不盲目调参。

 五、资源调度与 GPU 池化

 从产品/资源管理角度，弹性扩缩容和 GPU 池化通常有哪些策略？

 回答思路 ：

 池化：MIG 硬件隔离最强但静态；时间切片 / MPS 灵活但隔离性弱；隔离性与利用率此消彼长。

 扩缩容：推理场景冷启动极慢，扩容易缩容难；指标上不能只看 QPS，队列深度 + 等待延迟才是推理的黄金信号；预测式扩容 + 缩容保护期是防震荡的常用手段。

 落到岗位：底层引擎决定“每份卡用得有多满”，中间服务决定“几份卡在什么时候存在”，两者配合才能把成本打下来。

 六、AI Coding 与工程提效

 团队很看重 AI Coding，你怎么看它在 Infra 场景里的价值？

 回答思路 ：AI Coding 不是“一键生成系统”，而是底层工程效率的放大器。在 Infra 语境下三个实际落点： 算子迁移辅助 （CUDA → CANN 的理解与初稿生成）、 压测脚本生成 （海量 benchmark 场景的样板代码）、 海量底层日志排障 （把又长又杂的报错喂给 AI 辅助定位方向）。经历少不是问题， 会用 AI 工具快速啃开源代码、快速排错，本身就是这个岗位的生产力 。

 七、岗位意愿与稳定性

 你个人兴趣是不是更偏向 AI 产品？如果 Infra 不匹配，也可以推荐你去产品部门。

 我们底层引擎负责把模型更快、更低成本地跑起来，上层再做规模化 API 服务。你觉得哪个和你更契合？

 回答思路 （这一环节是面试官反复试探稳定性，回答必须坚决闭环）：

 承认对产品有热情，但逻辑反杀：AI 产品的体验瓶颈往往就在底层推理速度和成本上。TTFT 下不来、并发一高就 OOM，上层封装再好用户体验也是零。

 正是因为懂产品痛点，才更要在底层引擎把算力榨干。上层 API 是壳，底层引擎才是定价权。

 明确表态：愿意从适配、测试、压测这些基础工作干起，目标是沉在底层把真本事练出来，而不是去上层做 API 调用的“传话筒”。

 不得不说科大讯飞hr和面试官还是太温柔了点 这次没啥准备换其他地方估计都挨骂了

 💬 面试问题复盘与考察点拆解

 经历深挖：华为 AI Infra 的实践
面试官： 看你简历有在华为做过 AI Infra，主要做了什么？我看你之前的经历可能跟我们现在的推理模型相关。

 考察点： 验证你对国产算力生态（昇腾）的熟悉度，以及真实的工程排障能力。

 应对思路： 坦诚自己没做过底层源码开发，但重点强调在华为云或昇腾环境下的工程落地、环境适配、OOM排查、压测调优。一定要点出“深刻体会到了开源框架跨平台迁移时算子不兼容、动态 Shape 处理难”的痛点。

 核心架构：原生与异构算力的实践
面试官： 聊聊你对原生和异构算力实践的理解。

 考察点： 是否理解为什么要做适配，痛点在哪。

 应对思路： 原生意指 CUDA 生态成熟，异构则是为了国产自主可控。难点在于底层算子不兼容、显存调度逻辑差异。解法是通过中间层（如 vllm-ascend）抹平差异，并在调度层做资源分配。

 资源调度：弹性扩缩容与 GPU 池化
面试官： 从产品角度，你们有哪些弹性扩缩容策略？怎么管理 GPU 资源？

 考察点： 宏观的集群资源调度思维。

 应对思路：

 池化： 提到 MIG（硬件隔离）、时间切片、MPS（多进程服务），分析隔离性与利用率此消彼长的矛盾。

 扩缩容： 从定时的“预测驱动”讲到“指标驱动”（推理看重队列深度而非单纯QPS），强调“冷启动”是最大敌人。

 结合点： 提到了火山引擎 + HAMi-core 的细粒度配额控制。

 框架理解：vLLM 与 SGLang 的对比
面试官： 有没有用过开源框架跑模型？了解里面的模块作用吗？知道推理的瓶颈吗？

 考察点： 是否真正看过架构，理解显存与计算的瓶颈。

 应对思路：

 vLLM： 核心是 PagedAttention（解决显存碎片）和 Continuous Batching（消除 GPU 空转）。

 SGLang： 核心是 RadixAttention（基数树管理，解决前缀重复计算）。

 瓶颈： Prefill 是 Compute-bound（算力瓶颈），Decode 是 Memory-bound（访存瓶颈）；长上下文带来的 KV Cache 显存爆炸。

 实验： 遇到瓶颈不要瞎调，用 Profiling（Nsight/msProf）看时间线。如果是访存打满，去做量化；如果是显存碎片，去调 Block Size。

 业务定位：底层引擎、中间服务与上层产品
面试官： 我们提供底层引擎（抠算力、降成本），中间做云原生弹性服务，上层出 API 和 AI 产品，你觉得哪个和你契合？

 考察点： 稳定性测试！面试官极度害怕候选人嫌底层苦，干两月跑去业务线。

 应对思路： 强烈表态留在底层引擎。告诉面试官，正因为懂产品对延迟和成本的敏感度，才更要在底层把算力榨干。上层 API 是壳，底层引擎才是定价权。

 前沿视野：对 AI Coding 的看法
面试官： 我们很看重算力和 AI Coding，你怎么看？

 考察点： 是否拥抱新工具，能否利用 AI 提升底层开发的脏活累活效率。

 应对思路： AI Coding 在 Infra 领域能极大提效。比如：辅助 CUDA 到 CANN 的算子翻译、生成海量 Benchmark 压测脚本、辅助分析又臭又长的底层报错日志。

 CNN优点：局部权值共享，平移不变性可以更好提取特征以及处理高维数据；缺点：网络过深时其梯度回传变化相对于输入往往很小，出现梯度消失或爆炸的情况；解释性一般 RNN优点：相比于CNN，RNN结合序列上的时序上下文来提取特征，但是在处理序列数据时没有进行信息的过滤，在稍长序列中就会出现梯度消失、爆炸的情况 LSTM优点：LSTM经过使用全连接层设计遗忘门、输出门、输入门来过滤信息，使得在长序列数据中表现较好。但是在时间跨度非常大的序列数据中，会出现计算复杂和耗时偏多的问题 Transformer优点：相比于RNN，可以直接并行计算序列数据，计算的Attention也更有解释性，可以为不同的头分配不同的任务。虽然全局信息可以捕捉，但是不如CNN捕捉局部信息来的好，而且其位置编码的语义问题也很困扰，最后在Transformer内部堆叠残差层和BN层过多时，顶部会出现梯度消失的问题 

 4.损失函数和激活函数的计算公式（问了下交叉熵做二分类和多分类的区别） 

 5.Dropout训练和测试的区别，Dropout的原理 

 Dropout原理： dropout训练减少了神经网络结点之间的共适应性，当隐藏层节点被随机删除后，是的网络具有了一定的稀疏性，从而有效的减轻了不同特征间的协同效应。也就是说，某些特征可能会依赖于固定关系的隐藏节点的共同作用，而通过dropout，迫使一个网络节点和随机挑选出来的其他节点共同工作，达到更好的网络泛化能力。 

 Dropout训练和测试的区别：训练时以一定的概率p（通常是50%）关闭隐藏层神经元的输出，也就是输出为0。这种策略可以从不同角度理解：首先这使得每次训练的模型并不是相同的结构，可以认为是原网络的子集，最终的输出是这些不同模型不同结构共同作用的结果（类似于集成学习中Bagging的策略）；另外Dropout方法可以让神经元之间减小依赖性，因为随机的关闭可以使得神经元之间不会总是同时作用。
 测试时，全部神经元都使用，但是他们的输出乘上了系数（1-p）。
