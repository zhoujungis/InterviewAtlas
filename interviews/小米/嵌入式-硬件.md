 🔑本篇： 小米汽车嵌入式一面面经 

 🔑遇到的问题：

 自我介绍（2 分钟） 

 项目里硬件选择的原因？ 
答：选型优先从需求、功耗、成本、外设资源三方面评估。主控芯片需要满足 ADC、SPI、I2C 外设接口，算力支撑姿态解算与 PID 控制；考虑项目功耗要求，选用低功耗 MCU，休眠电流满足指标；同时兼顾供货与成本，芯片生态成熟，官方驱动、参考例程完善，能缩短开发周期。避开资源过剩带来成本浪费，也防止外设不够需要额外扩展芯片，增加硬件复杂度。

 adc 的频率是什么？ 
答：ADC 频率一般分两个概念，ADC 外设时钟频率、采样率。ADC 外设时钟是供给 ADC 模块的工作时钟，决定 ADC 内部逐次逼近电路工作速度；采样率是每秒完成多少次 AD 转换，单位 Hz。采样率不是越高越好，受奈奎斯特采样定理约束，采样频率至少大于信号最高频率 2 倍；同时高采样率会带来功耗上升、数据量增大，需要考虑 MCU 读取和处理能力。

 adc 转换你是怎么实现的？ 
答：两种实现方式，项目中采用 DMA+ADC 中断方案。配置 ADC 通道、采样周期、分辨率，开启 DMA 搬运，ADC 完成一次转换后触发 DMA，自动把采样结果搬运到内存缓冲区，转换完成触发中断通知任务读取数据。对比查询方式，CPU 不用轮询等待转换结束，节省 CPU 资源；简单场景也可以用软件查询，但是 CPU 占用高，大数据采集不推荐。

 你这个项目是闭环结构还是开环结构？ 
答：本项目属于闭环结构。系统采集传感器实际输出状态，和目标期望值做差值，送入控制器运算，输出控制量调整执行机构，持续修正偏差。开环没有反馈，无法自动抵消扰动；闭环依靠反馈可以抑制外界干扰，控制精度更高，但需要考虑稳定性问题。

 pid 算法了解吗？ 
答：PID 包含比例 P、积分 I、微分 D 三个环节。P：快速减小偏差，P 越大响应越快，但是超调变大；I：消除稳态误差，积分作用太强容易震荡；D：预判偏差变化趋势，抑制超调，改善动态性能，噪声大的时候微分项会放大噪声。
项目中采用增量式 PID，相比位置式，输出增量，不会出现积分饱和，异常时输出冲击更小，适合本项目执行器控制。调参顺序一般先 P，再 I，最后 D。

 姿态解算方面，你测量的六个参数的姿态解算加定时器设置任务的普通程序和 freertos 有什么不同？freertos 的优点在哪里？ 
答：裸机普通程序一般是大 while (1) 循环 + 定时器中断，顺序轮询执行。姿态解算、ADC 采集、定时任务串行跑，任务优先级不好管控，一旦某个模块阻塞，其他任务会被拖慢，实时性差；复杂逻辑下代码耦合高，后期维护难。
FreeRTOS 是抢占式 RTOS，可以给姿态解算、传感器采集、控制任务分配不同优先级，高优先级任务可以抢占低优先级任务，保证姿态解算这类实时任务按时执行。任务解耦，每个功能独立成任务，代码结构清晰；自带队列、信号量等通信机制，方便任务间数据交互；支持阻塞延时，空闲时 CPU 进入低功耗，降低功耗。
FreeRTOS 优点：抢占式调度，实时性强；任务模块化，方便开发维护；丰富内核组件；支持低功耗模式；占用资源小，适合 MCU。

 DMA 的半传输中断是什么场景使用？ 
答：DMA 半传输中断，就是 DMA 传输到缓冲区一半时触发中断。典型场景是 ADC 连续采样的双缓冲。缓冲区分成前半段、后半段，DMA 填满前半段触发半传输中断，应用程序处理前半段采样数据，DMA 继续填充后半段；填满后半段触发传输完成中断。实现边采集边处理，不会丢失采样数据，适合连续高速数据流采集，比如陀螺仪、ADC 持续采样。

 MCU 低功耗模式下，中断唤醒的原理是什么？唤醒后程序从哪里开始执行？ 
答：MCU 进入低功耗后，内核时钟停止，外设时钟按需保留，等待唤醒源（外部 IO 中断、定时器中断、外设中断）。中断信号触发后，内核恢复时钟，退出休眠。唤醒后 不是从头跑 main ，而是从进入低功耗指令的下一行代码继续执行，先进入中断服务函数处理中断，中断返回后回到主程序。

 什么是内存对齐？嵌入式里为什么要关注内存对齐？ 
答：内存对齐就是结构体成员按照指定地址边界存放，不是紧密挨在一起，中间会填充 padding 占位。很多 MCU 硬件访问只能从对齐地址读取数据，非对齐访问会触发硬件异常或者两次读取，降低性能；另外 DMA 传输要求内存地址对齐，不对齐会造成 DMA 读写出错。编译器可以用__attribute__((packed)) 取消对齐，但嵌入式底层、DMA 场景慎用。

 嵌入式中栈溢出一般怎么排查？有哪些现象？ 
答：现象：程序随机死机、HardFault、变量莫名被篡改，抓栈回溯发现栈空间越界。排查方法：①加大栈空间测试；②开启栈水印（FreeRTOS uxTaskGetStackHighWaterMark）查看剩余栈最小余量；③看函数内局部大数组、递归、多级函数调用；④仿真器看栈指针 SP 是否超出栈范围。局部不要定义超大数组，优先堆或者全局缓冲区。

 什么是 HardFault？一般哪些操作会触发？ 
答：HardFault 是 MCU 的硬件故障异常，属于最高优先级异常。常见触发原因：空指针访问、数组越界、非对齐访问、除法除 0、栈溢出、非法指令、访问受保护内存。排查手段：保存栈帧，查看 LR、PC 寄存器，定位出错指令地址，反汇编找到对应代码。

 编译器优化等级 O0/O1/O2/O3 的区别，嵌入式开发一般选哪个？ 
答：O0 无优化，调试友好，变量都保存在栈，断点正常；O1 基础优化，去掉无用代码，兼顾体积和调试；O2 较多优化，提升速度，不增加代码体积，产品常用；O3 最高优化，极致速度，代码体积可能膨胀，部分代码逻辑会被编译器重构，调试困难。嵌入式产品 release 版本常用 O2，调试阶段 O0。

 malloc 在中断里可以调用吗？ 
答：一般不建议，很多 RTOS 的 malloc 内部自带互斥锁。中断上下文调用 malloc，若锁已经被占用，会造成死锁；同时内存分配耗时不确定，影响中断响应实时性。内存申请尽量放到任务中。

 为什么选择小米？你对 IoT 嵌入式方向怎么看？ 
答：小米 IoT 生态体量很大，软硬件结合场景丰富，嵌入式开发覆盖 MCU、Linux 设备、低功耗设备、传感器控制等方向。岗位可以接触底层驱动、RTOS、设备端稳定性、软硬联调，和我做的传感器、姿态控制项目匹配。我希望持续深耕嵌入式底层，参与消费级物联网产品开发，持续打磨系统稳定性和低功耗能力。

 有些项目问题我就不详细说了，每个人项目不一样，一定要熟悉项目同学们。 

 反问环节：团队嵌入式技术栈和产品方向？新人培养和项目参与方式？想了解咱们团队主要用 RTOS 还是 Linux，驱动、应用大概怎么分工；新人入职后是跟项目还是先培训，多久能独立负责模块；日常工作偏底层驱动、系统稳定性，还是 IoT 业务开发？

 7. 如果程序偶尔死机，但很难复现怎么办？

 回答思路： 

 可以按照 “保留现场 → 增加信息 → 提高复现率 → 定位原因” 的框架。

## 嵌入式面经 c语言 笔试题

来源：牛客网 ｜ 类型：面经 ｜ 发布：2023-08-15 ｜ [原文链接](https://www.nowcoder.com/discuss/521107501819985920)

1.预处理&关键字（22道） 

 
 1.1 宏定义是在编译的哪个阶段被处理的？ 

 答案： 宏定义是在编译预处理阶段被处理的。 

 解读： 编译预处理：头文件包含、宏替换、条件编译、去除注释、添加行号。 

 
 

 1.2 写一个 " 标准 " 宏 
 MIN ，这个宏输入两个参数并返回较小的一个。 

 答案： 

 
 #define MIN(
 A , B) (( A ) <= ( B )? (
 A ) : ( B )) 
 

 解读： 

 （1）注意这个题目要用三重条件操作符，在宏中要小心地把参数用括号括起来，并且整个宏也要用括号括起来，防止替换时出现错误。 

 （2）注意若写"least = MIN(*p++, b);"这句代码会产生副作用，将*p++代入宏体，指针p会做两次自增操作。 

 
 

 1.3 已知数组 table ，用宏求数组元素个数。 

 答案： 

 
 #
 define COUNT ( table ) (sizeof(
 table ) / sizeof( table [
 0 ])) 
 

 解读： sizeof(table)得到数组长度，sizeof(table[0])得到数组元素长度，两者相除即可得到数组元素个数。 

 
 

 1.4 带参宏和函数的区别？ 

 （1）带参宏只是在编译预处理阶段进行简单的字符替换；而函数则是在运行时进行调用和返回。 

 （2）宏替换不占运行时间，只占编译时间；而函数调用则占运行时间（分配单元、保留现 场、值传递、返回）。 

 （3）带参宏在处理时不分配内存；而函数调用会分配临时内存。 

 （4）宏不存在类型问题，宏名无类型，它的参数也是无类型的；而函数中的实参和形参都要定义类型，二者的类型要求一致。 

 （5）而使用宏定义次数多时，宏替换后源程序会变长；而函数调用不使源程序变长。 

 
 

 1.5 内联函数的优缺点和适用场景是什么？ 

 （1）优点：内联函数与宏定义一样会在原地展开，省去了函数调用开销，同时又能做类型检查。 

 （2）缺点：它会使程序的代码量增大，消耗更多内存空间。 

 （3）适用场景：函数体内没有循环（执行时间短）且代码简短（占用内存空间小）。 

 
 

 1.6 关键字 volatile 的作用是什么？给出三个不同的例子。 

 （1）作用：告诉编译器不要去假设（优化）这个变量的值，因为这个变量可能会被意想不到地改变。精确地说就是，优化器在用到这个变量时必须每次都小心地重新读取这个变量的值，而不是使用保存在寄存器里的备份。 

 （2）例子： 

 ①并行设备的硬件寄存器（如：状态寄存器）。 

 ②一个中断服务子程序中会访问到的非自动变量。 

 ③多线程应用中被几个线程共享的变量（防止死锁）。

## 嵌入式2021秋招记录

普通一本（本硕），嵌入式软件开发岗，收到小米、联发科、浙江大华、汇川技术、英威腾、上能电气、富士康、格力offer。最高28w，最低减半。

 以下开始讲述一些我找工作的经验，希望对大家有帮助（觉得有帮助的，记得点个赞关注走一波，谢谢大家）。

 公众号：嵌入式Linux系统开发

 一、简历篇

 （1）个人联系方式

 简历的话要把电话，email这些重要的信息放到显眼的位置，方便联系。

 （2）技能掌握

 常用“熟悉”,“精通”慎用（精通应届生就不要用了）

 “了解”的话适用于只是看过一点书，只是一种浅尝辄止的感觉，比如你只是通过刷了刷面经，了解了一些面试常见的问题，那么这种就应该用了解。

 （3）荣誉奖励

 奖学金，优秀干部，竞赛获奖，paper啥的都往上怼，多多益善。

 （4）项目

 项目篇很重要，基本面试的第一个环节都是扣你的项目。

 项目一定要准备1到2个亮点（难点），就是你曾经做项目遇到什么问题，如何解决的，解决思路和方法面试官很喜欢听。

 做过项目或者有实习经历的，面试很容易成功，因为你是确确实实做过东西，而不是瞎编的。

 问项目过程中，一般会先问你这个项目是干什么的，什么产品或者什么功能。整体代码框架分为几层，你主要做什么。是单独开发还是和同事一起开发，遇到过什么问题，如何解决的。

 二、简历投递篇

 （1）公司官方网站网申

 学历不好的，不建议这走这条路，容易被刷，985/211也有一定几率被刷。

 （2）内推

 关注“牛客网- 互联网求职神器和备考学习平台”的内推信息，都是真实可靠的，虽然不一定免笔试，但是可以保证你简历不被刷。

 微信公众号“ 互联派 ”也有很多内推的信息，值得关注。

 （3）内推完之后的添加个人信息

 强推“牛客网简历助手 助手介绍_牛客简历助手”——简历一次填写，N网闪填__牛客网

 爽的一批，谁用谁知道，你填写完牛客网的简历助手，进来其它求职网站的时候，可以把插件调出来，如果调不出来，多点几下，自己摸索哈。这样可以省时省力，不用每个公司都把自己的简历写一遍。

 （4）我基本上投了100份简历，有这个岗位的大公司我都投了个遍。混到了40个笔试机会，所以基本上所有嵌入式方面的题目我全部都见过了。你也可以海投，一般笔试时间不会冲突，我九月份每天都有笔试，十月份也有十几场笔试。

 三、笔试面试篇

 提前批：一般公司的提前批是免笔试的，这个机会一定要抓住，提前批不耽误正常网申流程，相当于多了一次机会。（其实你每次应聘都是会有记录的，现在的面试官可以看到你所有的过往的面试记录，但我觉得影响不大，但有的公司也会看，提前批不过，正式批直接刷）（提前批每年六七月就开始了，一定要注意，很早的）

 笔试：就算你内推成功了，也会有极大可能笔试。其实笔试题吧，你把《程序员面试宝典》《剑指offer》刷一刷，杭电OJ刷一刷，然后把字符串变换、队列和栈、双向链表的插入等基本数据结构会写，问题不大，然后感觉这些公司的笔试题也就那么回事。

 面试：面试这个就看平时积累了。电话面试视频面试其实还是有一定操作空间的，现场面全凭自己实力。所以你自己简历上面的项目和技能，不可以瞎编，一定是自己做过，了解技术框架和技术细节。

 HR面试：一顿跪舔就行，就是你们公司真好，你自己罗列个123哪里好；女朋友，有也说没有（也可以说有，女朋友就在xx公司的地方上班/上学，很紧）；父母不干涉决定；薪资，普遍薪资就行。总之就是求生欲强一些，面试之前去他们公司官网看一下他们公司的产品。
