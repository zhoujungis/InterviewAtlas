## 面经11：联想 | 嵌软 | 秋招

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-24 ｜ [原文链接](https://www.nowcoder.com/discuss/921519108749791232)

1. C++11 之后有哪些比较重要的新特性？你项目中用过哪些？

 答案：C++11 之后增加了很多重要特性，比较常见的有：

 
 auto 和 decltype：简化类型声明；

 Lambda：方便定义匿名函数；

 智能指针：unique_ptr、shared_ptr、weak_ptr；

 右值引用和移动语义：减少不必要的数据拷贝；

 nullptr：代替传统的 NULL；

 范围 for；

 constexpr：支持编译期计算；

 std::thread：提供线程支持；

 std::mutex、std::condition_variable：提供线程同步机制。

 
 后续 C++14、17、20 又加入了结构化绑定、if constexpr、std::optional、std::variant、Concepts、协程等特性。嵌入式或者 Linux 开发，我认为比较重要的是智能指针、移动语义、Lambda、RAII、并发库以及 STL。

 2. 什么是静态多态和动态多态？两者有什么区别？

 答案：静态多态主要是在编译期确定调用哪个函数，典型实现方式是函数重载、模板和 CRTP。动态多态是在运行期确定调用哪个函数，C++ 中主要通过虚函数实现。

 例如静态多态：

 template 
void print(const T& obj)
{
 obj.print();
}

 
 编译器在编译阶段就可以确定具体调用哪个 print ()。

 动态多态：

 class Base
{
public:
 virtual void print()
 {
 cout print();

 
 这里通过基类指针调用 print ()，实际执行的是 Derived::print ()。

 核心区别：

 静态多态
编译期确定
 ↓
函数重载 / 模板 / CRTP

动态多态
运行期确定
 ↓
虚函数 / 虚函数表

 
 静态多态没有虚函数调用的运行时开销，但灵活性相对低；动态多态更加灵活，但需要虚函数表和间接调用。

 3. 什么是多态？C++ 的动态多态是怎么实现的？

 答案：多态简单来说就是：同一个接口，在不同对象上表现出不同的行为。C++ 动态多态主要通过：继承 + 虚函数 + 基类指针或引用 实现。

 例如：

 class Animal
{
public:
 virtual void speak()
 {
 cout speak();

 
 虽然 p 的类型是 Animal*，但是最终调用的是 Dog::speak ()。本质上，编译器通过虚函数表和虚表指针，在运行时找到真正应该调用的函数。

 4. 什么是虚函数表？虚表指针存在哪里？

 答案：对于包含虚函数的多态类对象，编译器通常会为该类生成一张虚函数表，也就是 vtable。对象内部通常会存在一个指向虚函数表的指针，也就是 vptr。

 可以简单理解为：

 对象内存：

┌──────────────────┐
│ vptr │ ──────────────┐
├──────────────────┤ ↓
│ 成员变量 │ ┌─────────────────┐
│ 成员变量 │ │ vtable │
└──────────────────┘ ├─────────────────┤
 │ Base::func │
 │ Base::func2 │
 │ Base::~Base │
 └─────────────────┘

 
 需要注意：C++ 标准并没有规定必须使用 vptr + vtable 的实现方式，这是主流编译器实现动态多态的一种方式。至于 “虚表指针到底在哪里”，通常情况下：vptr 是对象的一部分，位于对象的内存布局中，常见实现中位于对象起始位置。但具体位置由编译器、ABI 和继承结构决定，不能把 “vptr 一定在对象第一个字节” 当成 C++ 标准。

 5. 什么是 access () 函数？Linux 中有什么作用？

 答案：access () 是 Linux/Unix 中用于检查调用进程对某个路径是否具有指定访问权限的函数。

 常见使用方式：

 #include 

if (access("test.txt", F_OK) == 0)
{
 printf("文件存在\n");
}

 
 常见参数包括：

 
 F_OK → 判断文件是否存在

 R_OK → 判断是否具有读权限

 W_OK → 判断是否具有写权限

 X_OK → 判断是否具有执行权限

 
 例如：

 if (access("/tmp/test.txt", R_OK) == 0)
{
 // 可以读取
}

 
 但是需要注意一个经典问题：access () 判断权限和真正操作文件之间存在 TOCTOU（Time Of Check To Time Of Use）竞争窗口。

 access()
 ↓
判断文件可以访问
 ↓
文件状态发生变化
 ↓
open()
 ↓
实际操作失败

 
 因此在安全敏感场景下，不能简单依赖 access () 做权限检查后再执行操作。

 6. '\0' 和 '0' 有什么区别？

 答案：两者完全不同。

 
 '\0' 是空字符，ASCII 值为 0。

 '0' 是字符 '0'，ASCII 值通常为 48。

 
 而 int a = 0; 这里的 0 是整数 0，不是字符。

 可以理解为：

 
 '\0' → 空字符 → ASCII 0

 '0' → 字符 0 → ASCII 48

 0 → 整数 0

 
 例如字符串 char str[] = "abc"; ，实际内存是： 'a' 'b' 'c' '\0' ，最后的 '\0' 是 C 字符串结束标志。

 7. 计算机网络各层有哪些代表协议？TCP/IP 和 OSI 怎么对应？

 答案：实际面试中建议按照 TCP/IP 五层模型来回答：

│ 应用层 │ HTTP / FTP

## 联想校招遇到问题，最好的咨询方式是什么

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-06 ｜ [原文链接](https://www.nowcoder.com/discuss/914916250759757824)

问对渠道、讲清问题、提供必要信息，往往比重复催问更容易得到准确答复。 

 校招季里，最让人焦虑的往往不是某一道题，而是不确定。简历投递后一直没有消息，测评做到一半遇到系统异常，面试预约页面显示错误，已经完成测评却仍显示“待完成”……遇到这些情况，很多同学的第一反应是到处找人：问学长学姐、私信招聘人员、在社交平台留言，或者请内部员工代为查询。 

 

 但校招问题并不是“问的人越多，处理就越快”。招聘流程涉及个人信息、具体岗位和系统记录，真正有效的做法，是先判断问题属于哪一类，再通过正确渠道提交完整信息。这样既能保护个人隐私，也能减少来回补充材料的时间。小编采访了联想校招的HR，梳理了一些内容供大家参考。 

 第一步：常见流程问题，先问校招官网机器人 

 如果你想了解的是通用问题，比如如何投递、毕业时间要求、测评基本规则、面试流程或比较常见的问题，可以先使用联想校招小助理“想想”。 

 “想想”用于解答招聘流程中的相关问题。校招没有客服电话，因此，遇到常见流程问题时，不必四处寻找所谓“招聘热线”。先把问题用一句完整的话描述清楚，通常比只输入“在吗”“急”或者“帮我查一下”更有效。 

 比如，与其问“为什么没动静”，不如问“我已经完成综合能力测评，但校招官网仍显示待完成，应该怎么处理”；与其问“我能不能换”，不如说清楚“我已经投递了一个岗位，想了解是否支持更换投递岗位”。明确的场景能帮助系统更准确地识别问题。 

 可别小看换个答疑机器人，据悉官方定期迭代，现在已经能覆盖绝大部分校招常见问题。 

 

 第二步：涉及个人流程或系统异常，发邮件到校招官方邮箱 

 如果问题涉及个人复杂问题，例如系统报错、Offer之后的个性化事项，或者“想想”暂时无法准确回答，正确渠道是联想校园招聘官方邮箱：chinacampus@lenovo.com。 

 这个邮箱由校招团队运营，用于处理从简历投递到入职阶段的校招咨询。根据联萌服务站答疑规则，邮箱在工作日的回复时效一般为24小时。涉及技术支持或需要其他团队核实的问题，可能需要多次反馈，但校招团队都会继续跟踪。 

 尤其是Offer之后的咨询，往往包含个人录用信息和个性化安排，不适合在公开渠道中查询，也不由外网聊天机器人公开回答。此类问题应通过官方邮箱点对点沟通。 

 

 一封有效的咨询邮件，至少要写清楚这些信息 

 最好的邮件不是写得最长，而是让处理人员一次就能定位到你的记录。建议在邮件标题中写明“咨询类型＋姓名＋问题”，例如“测评状态咨询＋张某某＋已完成仍显示待完成”。据悉，每一年的校招季，HR总是能收到不少“不知是谁”的咨询邮件。 

 正文可以先说明本人姓名，再提供与问题直接相关的信息。涉及申请流程时，尽量写明投递项目、岗位名称和UID；涉及系统异常时，写明发生时间、操作步骤、页面提示，并附完整截图；涉及测评问题时，提供姓名、原始测评链接和系统提示截图。 

 例如，因系统原因没有完成测评时，官方答疑材料要求候选人发送姓名、原始测评链接及系统提示截图，由后台核实是否属于客观或特殊原因。已经完成测评但状态没有更新，如果一天后问题仍然存在，也可以发邮件反馈。 

 截图不要只截一个红色提示框，最好保留浏览器页面、时间和上下文，但也不要附上与问题无关的敏感资料。描述时按“我做了什么—系统显示什么—希望协助什么”来写，比单纯说“系统坏了”更容易处理。 

 

 哪些情况不适合反复催问 

 不同岗位、部门和招聘阶段的处理节奏可能不同。没有收到下一步通知，并不一定意味着系统异常。比如，只有收到正式通知，才能确认流程已经进入新的环节；面试轮次也会因岗位和部门而不同，应以实际通知为准。联想的校招项目，只要没有明确收到官方的感谢信，就表示流程还在正常推进中。 

 对于正常等待中的流程，如果官方信息已经说明仍在推进，频繁向多个渠道重复询问并不会改变筛选结果，还可能让同一个问题被不同人员重复处理。更好的做法是保持手机和邮箱畅通，同时留意垃圾邮件，并在出现明确异常时再提交咨询。 

 当然，如果页面故障冲突、链接无法使用、个人信息错误、预约功能异常，或者已按要求完成操作但状态长时间没有更新，就应该及时通过官方邮箱反馈，而不是一直猜测。 

 

 不同问题，应该找不同的答案入口 

 岗位是否开放、如何投递以及当届招聘要求，应优先查看联想校园招聘官网及官方发布信息。通用流程问题，可以先询问校招小助理“想想”。涉及系统异常、测评链接、面试预约或Offer后的个性化问题，应联系chinacampus@lenovo.com。 

 对于测评中的技术故障，要保留原始链接和系统截图；对于面试预约页面的姓名或手机号错误，应发送邮件说明；对于三方协议、网签、纸签、就业网、落户等需要核验个人材料的事项，也应通过官方邮箱沟通，不要仅依据社交平台经验自行判断。 

 如果问题来自某封官方通知，最简单的做法是先完整阅读邮件正文和附件。很多时间节点、操作要求和下一步安排已经写在通知中。咨询时可以直接说明“我已查看某封邮件，但对其中哪一项仍不理解”，这样比重新从头询问更准确。 

 

 校招咨询邮件可以这样写 

 邮件标题：测评状态咨询＋姓名＋已完成但官网仍显示待完成。 

 邮件正文可以简洁写明：“您好，我是参加联想校园招聘的候选人。姓名：×××，UID：×××，投递项目及岗位：×××。我于×月×日完成测评，但目前校招官网仍显示待完成。附件为原始测评链接及系统页面截图，辛苦协助核实。谢谢。” 

 这不是唯一模板，但它包含了身份、项目、问题、时间、证据和具体诉求。对处理人员来说，这些信息比大量情绪描述更有帮助。再补充一个题外话，根据小编向HR了解到，有些同学的邮箱设置了个性化签名档，这个签名当中有的时候会设置一张头像（或者叫图片），这张图当发送至企业邮箱时，可能因为格式限制消失，会变得非常巨大，直接影响邮件的格式和易读性，同学们可以酌情去掉这种个性化的设置，毕竟求职场景下，效率和专业度排在更前面。

 我2023年8月30日才开始大量投递，9月28日停止投递，共投出63家，只有9家进了一面，最终拿下6个offer，联想上研院、东风研发总院、吉利路特斯、 上海发那科、 潍柴动力，还有一家我最后决定去了的国企。我的进一面概率特别低，只有14%，比我的本科同学差了非常多，可能是因为我硕士学校qs排名不够强；我硕士是研究型的，当时选实验室和研究内容去的。大家应该不会有我的挂简历率高吧，所以真没什么可焦虑的。另一方面就是我的投递较晚，8月30日时，本科时的同学跟我说他们都投了100家了，我当时才投2家，吓了一跳，说好的秋招呢？真急了，每天投递1到9家，到月底投了63家。有相当多的企业，时隔很久才捞我面试，给我offer，我在秋招大部分时间，是无offer的状态。我offer的获得时间是：最早一个10月21日，11月拿了2个，12月拿了2个，最晚一个日企是3月5日。所以我想我的经历，是不是能宽慰一下大家焦急的心呢？我本科时的同学，进面率很高，特别是一些只看学历打包招人的，比如很多国企。再比如我同学去笛子线下很快就进了，我9月2日投了，11月30日才有个技术规划部门的电话。人就怕比，朋友拿了很多了，自己啥也没有；朋友非常好进的，我自己简历挂了，当然就很急。所以，找工的一个核心是有自己的节奏：

 不焦虑，把握自己的节奏

 首先，最重要的是，明确自己找工作的核心诉求是什么，这外显为投递什么企业的什么岗位。我在日本有找工作经验，这一点叫做「就活の軸」（就活是就业活动），也就是找工作活动的中心。对我自己来说，那就是 1. 离家近，要在长三角。 2. 要和机器人相关，不做纯软不做纯硬。 3.WLB工作生活均衡，不接受高强度长期加班。这个核心诉求来源于「自己分析」，涉及到自己的生活和工作态度，对未来的生活方式的预期等。拿我自己的例子来说，我恋家，喜欢和看好做机器人这一事业；躺平宅宅，消费少，预期不买房不生娃，所以卷不可以是长期的损害身体的，就算卷也只能是为了兴趣；基于以上，总结出了这三点核心诉求。所以，我没有投递互联网，没投狼性文化企业，投了一些外企和国企，私企方面投了联想这种wlb点的企业。

 第二，通过海投先拿到第一个offer。在第一点中决定好的业界中，海投自己的目标企业和岗位，先保住下限。一般拿到第一个offer的时候，心理就没有压力了，剩下的每一家都是锦上添花。

 第三，精选已拿到的offer，精投后续投递企业。通过网络啊校友啊，收集一下要去的企业、部门和岗位的内部信息，整体考虑如果在这里工作，是不是自己想要的生活。这个阶段就可以放弃一些海投的但不是特别想去的企业的面试，也可以放弃一些不够满意的offer，集中精力去准备自己的目标企业的新投递或者选拔进程。

 做到这三步的话，就建立起了围绕自己目标的、有自己计划的找工作节奏，就不再是盲目和他人比较，也能维持自己的内心安定。这时候的评估指标就变成了我的求职是否已经完成了我的目标？在我的规则里，是否是一个较优解？我是否满足了？盲目追求最优解既不可能也无必要，人的认知是有限制的，谁也不知道未来的事。

 关于面试和选择offer

 我的面试拿offer率67%，三家进了面但没offer的商飞、电装中国、智元机器人，主要还是岗位投错了。 其他方法论上，我在考虑要不要写一些具体面经和避雷帖，还有怎么选择offer。这里先简单说两句。

 准备面试，一方面总结好自己的竞赛、研究、论文和实习，做好ppt。一份ppt能复用很多家面试。深挖自己的研究，避免被人问倒。一般来说，面试官也不会是你的具体研究的特别熟悉前沿的专家，所以做好自己的逻辑闭环和细节，面试官大多会从方法论、通用的基础知识提问，或者结合他的业务做一些发散性提问，问你的研究或者其中的一个工具，能不能用在业务上？另一方面，做好企业研究，要有比较充分的选择公司的理由，这个在日本就活叫「志望動機」。既能向上管理，给hr画画饼，又能提前思考自己的技能、经验怎么在工作中活用，从而提前准备好面试官的问题，在交谈时还可以主动谈一些技术见解和业务发展见解，最低也能在反向提问「逆質問」里有东西问。

 选择offer，最好是多把握一些信息。包括读财报，分析研发投入占比，力求发现公司该业务是否景气，未来如何；包括了解部门内部员工意见，加班怎么样，领导怎么样，氛围怎么样；信息充分，才能放进自己的评价标准里仔细考虑。最好是想办法获得一些内部信息，比如某公司的机器人业务是谁的乙方，离公司业务有点远那么它盈利逻辑是什么，公司发展它的决心如何，是否会分离出去？牛客网里评论或者私信往往能碰到拿到同样offer的小伙伴，一交流一共享信息，都能多出很多判断。再就是在入职之前，最好手上再留一个好offer，这是对自己的保护。我就是脸皮薄，决定了offer之后立刻把其他拒绝了。结果入职前，要去的国企的领导找我面谈，说了一些大变动，但是我已经没有退路了。现在也是项目忙，不得不加班。也就只能劝自己较优解就很不错了，最优解是要运气的。

 

 以上就是一些分享，也算是记录一下自己的秋招历程了。希望大家都有自己的节奏，找工作都能达成自己的目标。

 如果有需要我再写点别的，看反响吧。

## 实习经验贴

实习经验贴

今天腾讯hr打电话来，我就知道，我没想到腾讯也oc了。腾讯绝对是我自三月份开始投简历以来最为苦战的对手。
回到三月份开头，我迟迟没有被腾讯约面，后来才知道是简历挂了。那时候脑回路还不大正常，居然觉得简历写得越简约越好，看到别人的简历文字一堆一堆的大为嫌弃，所以在自己简历上勇敢留白，在朋友的再三提醒之下都没有改。
直到后来被快手挂简历之后才幡然醒悟，开始狠狠改简历，把每个句子都延长到两倍。当然后来腾讯还是约面了，第一次面试很紧张，手撕了四道题，有两道是因为我准备到了，在问基础知识的时候，问JS中有那些基本的类型，我少说了两个。
等等，又是快一个星期，才约二面，写了一道题，然后问了一个很宏大的问题，问我认为前端目前有哪些部分，让我讲讲浏览器渲染流程，那时候对我来说这些问题有点超前了，如果让我现在来回答，我就很愿意跟他聊一聊。
聊到后半段，面试官问我人生有什么烦恼，我说其实并没有什么烦恼，转头一想，我说以前谈恋爱的时候经常烦恼，然后开始大谈特谈……后半段跟面试官聊得很开心。
那时候觉得为了这场面试已经竭尽全力了，一想到假如过了二面，前面还有三面，就感到道阻且长，那时候我还不能想到，在这两个月里我整整面了八次腾讯。
过了几天腾讯面试官打电话说，约面吧，原来前一个部门已经把我挂了，还是挺难接受这件事的。
这说明跟面试官聊得很开心是没有用的，该展现实力的时候要支棱起来。
重新约面的时候我就变得有点弃之不顾了，一想到要重新从一面开始，再一步一步爬上去，就像西西弗神话的描述，重新把石头推上去，我怎么打得起精神。
所以这一次面试我没有打起精神，后来也被挂掉了。
不过准备腾讯的面试让我已经完完全全足够应付一些小公司了，所以在准备面腾讯的同时，面的小公司没有一次失手，只不过小公司一般要求尽快到岗，所以面到二面以后我就主动提出，我们分手吧。
整个三月份都在应付腾讯，快到四月份的时候，投了一堆简历，流程是先筛简历，然后做测评，然后笔试，然后面试。在面试之前有这么多环节，其中第一个测评就是很麻烦并且还挺难的，在这时候才感觉到腾讯的好处。
能够被腾讯约面，已经很幸福了。
做了美团的笔试题，选到了3月30号那一场，比较简单，终于得到美团的约面。一面顺利通过，约得二面。
而腾讯又捞我了，可惜那一个晚上七点我状态不好，能打起精神已经很不容易了，那时候觉得非常对不起面试官，他那么认真地发问，我却答成这个样子。

美团的二面发生在也发生在四月份的某天晚上，那时候我明白这是我颤颤巍巍如履薄冰最接近对岸的路，是我零星炭木最接近燃烧的一次，只要这一次，燃起火来，以后就有火了。
好在答得不错，每个问题都答到了，我放心地关掉会议。

这其中还约了很多面试，其中最印象深刻的是蚂蚁，当时打电话来邀请我笔试，我本来想拖一拖的，但是第二天下午有课上小测，晚上有钉钉的笔试。
所以我在第二天的上午打开笔试链接，惠风和畅，第一道题是手撸一个布局，难在CSS属性全要默写，这种题我没有提前准备过，但是写布局和调色是我最喜欢的部分，所以我不但还原了布局，甚至连颜色也大致还原了。
交卷之后，在十分钟以内，我非常惊讶，蚂蚁就约面了，约在下午。
这么着急，我心里觉得很有机会，所以下午课上做完小测匆匆回寝室等来了三十分钟的面试，面试环节里没有手撕，一切顺利。
结果后来就没有了消息，直到多天后的一个晚上，被告知他们已经找到合适的人选了。而那一天我同时还得到了美团被挂的消息，以及百度的面试被取消的消息。
一天之内给我灯全吹熄了，但是那天我心情挺好，波澜不惊，觉得该放松一下，做点别的，那天想写小说，所以就写了一篇。

那天晚上脑子里想的全是小说里的措辞，直到第二天早上，我差点没赶上美团的面试，没错美团挂完就捞，很有江湖义气。
那天十点我人还有点不清醒，因为昨天刚被挂，所以也有点弃之不顾，但是我已经养成营业习惯了，还是全神贯注地去回答每一个问题。同一天晚上七点半完成了腾讯二面。
自此之后腾讯和美团就完全同步了，美团二面和腾讯三面约在同一天，再之后美团hr打电话发生在腾讯hr面的前十分钟。
那时候我心里感到一丁点的焦虑，还好美团hr在六分钟之内挂掉了电话，不然我怎么去和腾讯hr解释这一切。
在我心里腾讯的优先级还是高一些的，腾讯约面的是wxg部门，是众所周知最难的部门，在牛客上看过wxg的四轮，五轮，每轮高强度轰炸面经，知道腾讯wxg这个title多么有用，假如秋招简历上有意无意地透露一下wxg的来自，那快手字节还敢那么容易地筛掉我的简历吗。
而且，我觉得腾讯的蓝色比美团黄色好看。
再回到腾讯wxg捞我的那一天，我心里直言真看得起我，怎么捞上我的，那时候我的判断有两个，觉得要么是kpi面，要么是狂风暴雨般的拷打，后来发现都不是。
面试官问得没有想象中难，但是很认真地问问题，很认真地记录，我也是人，我也有感情，人家真情实意来面我我还能看不出吗。但是面完我就放下了，没去想二面的可能。
第二天就约二面了，这时候我也没敢当真，也没有特意去准备，
只没想到接下来又约了三面。
我才感到有一丁点的真情实意，wxg不是要来真的吧。
后来腾讯的三面在23号的下午三点，面试官抱歉地说电脑没电了所以用手机给我面试，我心中只觉得大概率没有手撕环节了，果然也没有，大家聊聊天就结束了，面完一小会儿看状态，三面也过了。
这时候我心里高兴，习也不复了，晚上的美团也快弃之不顾了。
不过到了晚上的美团二面，我仍然是好好营业，问题都答上来了。
接下来的第二天美团hr电话比腾讯hr面试来得早十分钟，腾讯面完之后进入录用评估的阶段了，没错，经过漫长的三轮技术面一轮hr面，还要进行惨烈的录用评估，也就是排序，在几个候选人中对比，有对比就有伤害。
我不敢想披荆斩棘到这个环节被挂掉是多大的打击。
所以在美团发来offer之后，我等了腾讯一天，没有消息，我就接了美团。
到今天晚上，腾讯打电话问我意愿，我才正式面临这个抉择。

我选择了美团。

原因有二
前面接受了美团offer，现在毁约可能会被拉黑。
其次wxg部门没有转正的名额，而美团转正几率更大。

那两天等腾讯录用评估的时候，我总是想，假如没有美团offer，等腾讯录用评估的时候该是多么胆战心惊。我避免了胆战心惊，但是也没法去腾讯了，即使是出于自己的选择。

写了这么多，本来打算写一点努力可以换来更大的选择权以及绝对的力量可以无视风险来盖棺定论的。但我懒得为这些东西措辞了。

毕竟我走了这么远的一条路，所想要的不过是一个安静的下午，能够安静地读一本自己喜欢的书罢了。

再记录几个有意思的细节。
在面腾讯之前我在发过一个朋友圈吐槽微信每次更新都在修bug，新功能好像再也没有了。
后来接受腾讯高强度拷打之后悄悄把这一条删掉了，因为我已经慢慢意识到能进微信部门的都是什么级别的高手，要复现一些功能不是不行而是……微信自有考量吧。

## 面试官：小伙子知道synchronized的优化过程吗？我：嘚吧嘚吧嘚，面试官：出去！

来源：掘金 ｜ 类型：面经 ｜ 发布：2024-03-24 ｜ [原文链接](https://juejin.cn/post/7349437605857656843)

写在开头

 面试官：小伙子，多线程中锁用过吗？
我：那是自然！
面试官：那你知道synchronized的优化吗？
我：synchronized作为重锁，开销大，在早期不被推荐使用，后期进行了优化，至于怎么优化的话，您让我想想哈...
面试官：好的，那你出去好好想吧！

 对于synchronized的优化，虽然被问到的场景不多，但在很多网友发的面经中发现很多人都会挂在这个点上。

 在我们初学锁时，很多人可能都觉得它是一个重量级锁，代码中不建议使用，但其实现如今经过了层层优化后，synchronized被广泛的应用在了JVM源码以及众多开源框架中，我们今天就来一起学习一下synchronized的优化过程！

 对象锁的四种状态

 首先，我们这里要记住一个Java迭代版本 JDK1.6 ，这个版本对于synchronized来说是划时代的，在此之前，synchronized确实是一种重量级悲观锁，这个时候的它使用起来极耗资源，为所有高效开发者所弊病，但在1.6版本之后，引入了“偏向锁”和“轻量级锁” 的概念，这极大减少了获取synchronized锁和释放锁所需资源，synchronized重获新生！

 在此之后，对象的锁便拥有了4种状态，根据锁的级别从低到高可分为：

 
 无锁 -> 偏向锁 -> 轻量级锁 -> 重量级锁 

 
 无锁

 无锁其实很好理解，就是没有对共享资源进行任何锁定，所有线程都可以去访问并修改同一资源，但同时只能有一个线程修改成功，其他线程不断尝试直至成功，并会将原内容覆盖。

 偏向锁

 偏向锁，指的就是偏向第一个加锁线程，对象的代码一直被同一线程执行，不存在多个线程竞争，该线程在后续的执行中自动获取锁，降低获取锁带来的性能开销。

 轻量级锁

 轻量级锁是指当锁是偏向锁的时候，被第二个线程 B 所访问，此时偏向锁就会升级为轻量级锁，线程 B 会通过自旋的形式尝试获取锁，线程不会阻塞，从而提高性能。

 重量级锁

 指当有一个线程获取锁之后，其余所有等待获取该锁的线程都会处于阻塞状态。

 重量级锁通过对象内部的监视器（monitor）实现，而其中 monitor 的本质是依赖于底层操作系统的 Mutex Lock 实现，操作系统实现线程之间的切换需要从用户态切换到内核态，切换成本非常高。所以在没有被优化之前，synchronized这种重量级锁，才不受重视！

 

 对象锁的存储

 学习完对象锁的四种状态后，我们继续思考下一个问题，既然对象锁有四种状态，那它们是存储在哪里的呢？

 会联想的同学，我想已经猜出了大概，首先在Java中的锁都是基于对象的，既然基于对象，那它存在的地方大概率要在对象中，而我们知道在JVM中，对象分为三个部分对象头、实例数据、字节对齐，其中对象头又由Mark Word和Klass Point构成，而Mark Word（标记字段）用于存储对象自身的运行时数据，例如存储对象的HashCode，分代年龄、锁标志位等信息，是synchronized实现轻量级锁和偏向锁的关键。我们64位虚拟机为例看下图：

 
当对象状态是偏向锁时，MarkWord中存储了偏向线程的ID，并且将是否偏向标志置为1；当对象状态是轻量级锁时，Mark Word存储的是指向线程栈中Lock Record的指针；当状态为重量级锁时，Mark Word为指向monitor（监视器）对象的指针。

 synchronized 锁升级的过程

 有了上面的知识储备，我们趁着打铁，来聊一聊synchronized 锁升级的过程，由低到高，逐渐升级。

 1️⃣首先，在锁对象的对象头里面有一个 threadid 字段，未访问时 threadid 为空，这时是 无锁 状态，任何线程都可竞争获取共享资源；

 2️⃣ 先得到共享资源的线程，其线程ID会被记录到Mark Word中，此时锁状态为偏向锁；

 3️⃣ 当后续还有线程去获取共享资源时，会先判断 threadid 是否与其线程id一致。如果一致则可以直接使用此对象；如果不一致，则升级偏向锁为轻量级锁，通过自旋循环一定次数来获取锁；

 4️⃣自旋的线程在自旋过程中，成功获得资源(即之前获的资源的线程执行完成并释放了共享资源)，则整个状态依然处于 轻量级锁的状态，如果自旋失败；

 5️⃣进入重量级锁的状态，这个时候，自旋的线程进行阻塞，等待之前线程执行完成并唤醒自己。

 2、面试官说问点基础的吧，问我hashmap和hashtable的区别。 

 我答介绍了hashmap的数据结构，回答上了两个，a、hashmap是线程不安全的,hashtable是在此基础上加了synchronized实现的。b、hashmap允许一个key为null，允许value为null而hashtable不允许。 

 
 3、了解gc吗？介绍以下gc。 

 我说了下堆的结构，说了新生代使用的都是复制算法，老年代使用两种算法，标记清除和标记整理。又说了新生代和老年代各有三种垃圾回收器，还有一种g1垃圾回收器，说了gc是如何判断该对象是否该被回收，即可达性分析算法。介绍了可达性分析算法：有一些对象被称为GCroot对象，其他对象根据是否被GCroot对象直接或者间接引用，如果被引用就不回收，如果没有被引用就被回收。 

 
 

 又介绍了GCroot对象包括哪些， 

 a、虚拟机栈中引用的对象。 

 b、本地方法栈中引用的对象。 

 c、方法区中静态变量引用的对象。 

 （刚刚翻了翻笔记确实也没错，但是根据我现在的了解，类的静态变量应该在1.8被移到了堆中，所以下次再回答这类问题直接说静态变量引用的对象）。 

 d、我说我忘了。。。翻了翻笔记是常量引用的对象。 

 
 4、问我了解反射机制吗?

## 联想秋招面经（已收offer），去年的经验不知道有没有用

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-07-23 ｜ [原文链接](https://www.nowcoder.com/discuss/380476416142454784)

回忆一下去年秋招面试的事情~ 

 
 

 下午还在睡觉的时候，接到hr小姐姐的电话和我沟通offer的事情，高兴到从床上弹起来。 

 我面试的是供应链相关的岗位，全程都是视频面试。现在和小伙伴们复盘下我整个面试的全过程吧~ 

 9.8一面 

 首轮是无领导小组讨论，总时间90分钟。刚开始每个人先一分钟自我介绍，中文英文都可以，然后讨论。我们这一组是五个人讨论一个case，讨论时间30分钟，然后针对设定的两个问题，出一个人总结回答。讨论的案例是和联想自己有关的，我们这一组是为联想智慧教育、智慧医疗、智慧制造等场景的建设提解决方案的。 

 关于群面的经验大家可以自行百度了，我也是第一次参与，感觉我这一组的氛围整体很和谐，中途也有几次尬场的现象，但是话痨的我出面主动缓解了。 

 总结： 我个人感觉整个群面过程自己没有特别出彩的地方，没有当Leader没有当time keeper，一直处于一个协调推动的角色。中途因为电脑显示屏原因耽误了团队一点时间，结束后觉得自己要凉了。不过后来觉得，群面考察的点应该是团队协作能力，你只要在讨论中能找到适合自己的角色让hr发现你的存在对这个团队是有价值的就可。 9.13二面 

 怀揣着激动地心情参加了二面，就那种死而复生的感觉，群面结束后真觉得自己没戏了。 

 二面是业务面，4个你未来部门的面试官+1个hr。时间30分钟。 

 问题： 自我介绍 谈谈你参与的其中一个比赛经历（STAR法则去阐述） 为什么选择这个岗位（专业背景+公司背景+个人） 分享一件你最近觉得买的最值的东西，谈谈整个购买的过程。（这个应该就是考你应变能力了，确实没想到会问这种问题，我讲的是我买华硕电脑的事，面联想说自己买华硕？我脑子好像有什么大病） 籍贯、意向工作的城市 反问环节 总结： 整体氛围很轻松，大家就聊天。面试官思路很清晰，能对你的回答进行快速的总结提炼给你反馈，整体面试体验是很舒服的，有来有往。 9.23三面 

 三面是部门总监+HR提问。面试时间40分钟。 

 总监part 不愧是总监，上来先给我整了十多分钟的压力面，一直追问你。 

 1.自我介绍 

 2.为什么选择这个岗位？ 

 3.说出你认为能担任这个岗的最重要的三个点？ 

 4.职业规划（这里问了我很久，总监希望我能给一个很详细的不要太宽泛，我猜测他一是要评估我是否目标清晰二是他的团队是否能实现我的价值） 

 5.对你每一阶段的规划你想怎么实现？ 

 6.每一阶段评判自己合格和优秀的标准是什么？ 

 7.假如我给你50块钱让你去买咖啡，你发现钱是假币，以这个为背景和他进行情景模拟。（这个题应该是考察我的沟通能力和灵活性，个人觉得这个我没有回答好，主要是确实听到这个问题挺懵的，现场做戏？本戏精怕自己演起来停不住，但是想着毕竟可能是未来老大要搂着点。） 

 8.反问环节（问了他对我的期待和他的管理风格以及刚刚有一个他问我好久的问题当年他是如何回答的等等） 

 HR part 终于熬到了HR这一part。 

 1.分享一段你的实习经历 

 2.在实习中有没有遇到让你很困难的任务？ 

 3.期望薪资 

 4.意向城市、是否接受去非意向城市。 

 然后三面就结束了，HR和我说一到两周内出结果，三面结束后我又有了一种要凉的节奏，总觉得总监那里没有发挥好。 

 终于9.28号，我收到了HR小姐姐的电话和我沟通offer相关事宜，偶然得知我是我们那批群面唯一入选的。感觉自己还挺幸运的叭，一个月来心情跟过山车一样，不过还好，最后结果是好的。 

 联想的面试体验整体很好，节奏把握让人很舒服，HR会提前电话沟通面试时间，结果也会在一周左右出来，面试到后面几轮还会安慰你说辛苦了，战线拉的这么久。总之是一次不错的体验，想来的小伙伴可冲。

投递简历后，过了两天收到线上面试通知，电话面试，会问什么时候可以入职，对工作经历问的很细，具体到工作时间，工作内容，工作内容主要会问和招聘职位有关的能力，会问有没有学到什么，有没有遇到困难这些,通过之后线下面试,无领导小组讨论包括自我介绍、针对案例讨论、还有随机抽取一张明信片，由图片内容联想自己的一个特质，用英语进行介绍。最后通过了,过了几天就拿到了offer 

 其实供应链管理相关的岗位，更多的是考察个人的快速学习能力和反应能力，以及对供应链的整体理解。 

 第一点是快速学习能力。对于 学习能力 这个话题，相信从小到大，无论是老师还是朋友，都或多或少有提及。总之，供应链涉及到的范围非常广，涉及到的行业也是众多，需要有极强的学习能力，才能够把所学到的知识和技能运用到实际的工作中。尤其对于没有工作经验的朋友来说，快速学习能力就显得至关重要了。这个能力决定着你是否能够快速的掌握 供应链管理 相关岗位所需要的知识与技能，也间接地确保了你在工作中会表现得当，符合岗位的要求。

 首先，1min自我介绍。我做的攻略都是要求1分钟，超过会打断，不同的base还会要求用英语。但是我们这组氛围很好，面试官也很友善，没有强调时间、语种，所以大家都是用中文，平均在一分半左右。 

 第二部分，阅读材料，小组讨论。一篇材料设置两个问题，问题一：20min，讨论不超过15min，汇报5min；问题二：30min，讨论不超过25min，汇报5min。我们这组的小姐姐都很友善，没有强势、咄咄逼人，刚开始讨论以及最后总结时都很谦让的，但也能感受到大家都在摩拳擦掌。我觉得大家都很好，也都很有想法，我自知做不了leader和总结者，想当个time controller，于是我在大家阅读完材料都沉默不开始讨论的时候，打破僵局，说时间差不多啦，我们开始吧巴拉巴拉。但是我这个人偏偏是个猪脑袋，算来算去，时间也没算太明白，想法呢更是一点没有，感觉我都看不懂题目，第一题我就是在划水。第二场讨论开始，我还是积极参与的，虽然没啥创新性想法。但我这人性子就是比较软，窝里横，还有点怂，看面经的时候大家说，不要吵架，要团结协作，所以当我说的观点或提出的问题被大家质疑的时候我也没多坚持。还有时间掌控这方面，还没等我开口，另一个小姐姐就提醒啦，就更没我什么事情啦。 

 第三部分，个人阐述观点。材料+问题一+问题二。这个没有指定顺序，大家就想好了自由发言就好啦。 

 最后，面试官也对材料和我们的表现进行了总结：在讨论时贴合我们自己就行；观点题说大家观点都很好；也和我们说了解决客户问题的思路；评价其他小姐姐沉稳，善于思考，话题引导，时间提醒啦，对我的评价是参与度不错，也有自己的观点，希望我更power一些，要用事实和例子更加坚持自己的观点。 

 总体来说，十分愉悦，所有人都很好，虽然知道自己凉了，但还是很开心，学习到了很多。嗯，我更喜欢、更想去联想了，只恨自己不争气！虽然只有一个半小时，我自己很喜欢的一个小伙伴是北师心理学那个小姐姐，从她的发言内容来说，总是一针见血、四两拨千斤地概括所有内容，并且熟练套用心理学理论，而且在联想客户岗实习的她分析解决问题的时候，思路完全正确，很有个人魅力，嘿嘿嘿。最后想提醒的是，我在看面经时，发现大概三年前群面会要求英文自我介绍+英语topic，最近两年群面没有要求英文（不同岗位、城市可能会有不同），但是二面是一定会有，有的还是英语日常话题，有的是分析案例。而且在我这次面试中，面试官说话时是很自然的夹带英文单词的，可见联想是对英语水平有要求的，这一点还是要重视，可以提前练习。 

 以上就是我对这次面试的总结，写面经，攒人品，积好运🍀

1. es6中的set有顺序吗

 无重复值的有序列表， Set 的遍历顺序就是插入顺序。这个特性有时非常有用，比如使用 Set 保存一个回调函数列表，调用时就能保证按照添加顺序调用。
 
 2. React事件绑定

 并不是将合成事件直接绑定在dom上面，而是采用 `事件冒泡` 的形式冒泡到 `document` 上面，
 https : //juejin.cn/post/6988450132928757768/ 
但在 React v17 中， React 不会再将事件处理添加到 document 上，而是将事件处理添加到渲染 React 树的根 DOM 容器中
 
 3. diff算法

 diff算法的核心是对树进行分层比较，并且只对两棵树的同层进行比较。React会对新旧两棵树进行一个深度优先的遍历，每遍历到一个节点就把该节点和新的树进行对比。当发现节点已经不存在，则该节点及其子节点会被完全删除掉，不会用于进一步的比较。这样只需要对树进行一次遍历，便能完成整个DOM树的比较。
 
 4. 函数防抖节流的应用场景

 防抖：在事件触发n秒后执行函数，如果在n秒内再次出发，重新计时 
节流：当多次执行某一动作，每个一段时间，只执行一次函数。

 节流

 
 理解：在函数多次频繁触发时，函数执行一次后，只有大于设定的执行周期后才会执行第二次

 场景：页面滚动（scroll）、DOM 元素的拖拽（mousemove）、抢购点击（click）、播放事件算进度信息

 功能：节流函数在设置的delay毫秒内最多执行一次（简单点说就是，我上个锁，不管你点了多少下，时间到了我才解锁）

 
 function throttle ( fn, delay ) {
 let flag = true 
 return ( ...args ) => {
 if (!flag) return 
 flag = false 
 setTimeout ( () => {
 fn. apply ( this , args)
 flag = true 
 }, delay)
 }
}
 
 防抖

 
 理解：在函数频繁触发是，在规定之间以内，只让最后一次生效

 场景：搜索框实时联想（keyup/input）、按钮点击太快，多次请求（登录、发短信）、窗口调整（resize）

 功能：防抖函数在被调用后，延迟delay毫秒后调用，没到delay时间，你又点了，清空计时器重新计时，直到真的等了delay这么多秒。

 return ( ...args ) => {
 clearTimeout (timer)

 fn. apply ( this , args)
 }, delay)
 }
}

 答做好基础会计方面知识的准备，还有EXCEL常用技巧的准备，比如数据透视表，VLOOK函数等这些最好掌握。 

 
 

 珠海市格力集团 

 面试过程或经历: 

 唯一一次自我感觉很不错的校招经历：校招是群体面试，大概10个人一组，挨个做自我介绍，HR在此环节会特别注重你的表情、语气以及态度。其实没必要太紧张，不要搞得好像晚会主持人，但也不要太木讷，轻声轻气的，让人听不清说话。只要态度端正、表情自然，声音以清晰响亮为主。 

 第一轮时HR会提问一些问题，比如说：如果公司团队出差，赶飞机，有人生病了，该不该为了他改签机票。我回答的是可以把此人留下单独就医，然后再回公司。也有说不该改签的，忍耐一下，以单位为重。总之把自己的想法说出来就好。 

 第二轮时是小组面试，具体的题目我记不清了，但在面试中HR会默默观察，并且为每个人的表现打分。此环节注意，不要一个人带节奏，多和同伴交流，互相探讨，不要给HR留下你过于强势霸道的印象。这个环节其实挺看运气的，如果你的组员都挺容易沟通，那么整个环节都很畅快。如果你的组员都是闷葫芦，那就需要你主动一点，打开话题。基本上我就过了这么二轮，就拿到OFFER了。
