## 面试鹅厂前，你还能做哪些准备

来源：牛客网 ｜ 类型：面经 ｜ 发布：2025-06-04 ｜ [原文链接](https://www.nowcoder.com/discuss/759815317534023680)

省流： 

 【了解岗位】全方位多渠道收集岗位工作信息（学校资源、招聘网站、社交和求职软件） 

 【拆解JD】将岗位jd拆解，形成简历内容框架和重点 

 【了解岗位】全方位多渠道收集岗位工作信息 

 腾讯内部分为六大事业群，无数业务线，技术岗更是会涉及具体的技术类型和专业领域的细分，在决定想要投递鹅厂之后，首先需要对相应的岗位进行了解。学长个人建议可以从以下几个方面去着手： 

 学校资源 

 ●大厂就业 的师兄师姐 

 这里主要问问他们有没有内部交流群。一般同师门会流传上一届的就业去向、面试岗位、经验和薪酬。 

 问岗位做什么的，本专业/实验室做这个岗位的优势是什么，可能有什么样的问题。 

 ● 自己的导师/就业办老师 

 一般高校老师不会缺去大厂的得意学生，就业办也会登记毕业生的就业去向。如果他们正好有学生就在鹅厂工作，帮忙搭桥引线介绍认识也是顺手的事 

 招聘资源 

 在确定自己适合的岗位后，可以进一步在招聘信息聚集的平台上展开下一步搜索。主要包括：牛客网、BOSS直聘、猎聘、脉脉等 

 这里除了关注岗位的工作职责描述，弄清楚会做些什么事情之外，还可以再关注这个岗位的社招信息，让你对岗位有更长远的视角，比如薪酬范围如何，是否符合自己工作2~3年后的预期，社招岗位和校招岗位的能力要求区别是什么，哪些能力会在社招岗位中更加看重 

 社交和求职软件 

 主要看看 B站、小红书、微博等平台的面经帖，适度看看脉脉。 

 对于成功经验的分享，可以看看主要把握了哪些关键点，对于失败经验的分享，主要看看别人存在的问题，从中总结经验，对于避雷帖， 如果是已经确认了要去的部门和岗位，可以多在社交平台上搜索关键词帮助自己避雷 

 【拆解JD】将岗位jd拆解，形成简历内容框架和重点 

 这是最容易忽视的地方，但其实大厂的岗位jd都是严格根据用人画像来写的，拆解jd实际上是在解读需求，根据需求来完善简历才能事半功倍！ 

 对于校招岗位而言，JD描述里一般会包含学校、学历、专业、技能、项目/实习经验等。 

 学校 

 ● 潜在目的：判断你的学习能力如何 

 用事实说话即可。举例子：比如绩点、奖项。奖项这里挑重点，如果你获得过国家奖学金、校级奖学金、还有各种乱七八糟的奖项，选择最能够突出你能力的放上即可。 

 专业方向 

 ● 潜在目的：判断是否对口、判断是否具备专业背后的隐藏能力 

 不过需要注意的是，除非有非常强的对口需求，否则一般不要因为列的专业不符合就拒之门外了。 

 技能水平 

 ● 潜在目的：判断能不能具备完成对应工作的能力 

 有证书的摆证书，但不要摆一些低级证书。当然技能也可以用项目和经历来体现，比如比赛，比如实习等。 

 项目实习 

 ● 潜在目的：判断能不能快速上手 

 没有也不要被吓到。项目/实习可能是大家最头疼的部分。有的同学可能因为导师原因、学校原因或者自己就业意识不太强，缺少相应的实习，这里就需要去挖掘你过往的经历中和岗位本身/背后的潜在要求相匹配的部分。做国家课题、解决一个技术难点、帮老师写书，甚至校外兼职这些都可以算。

 1. 引言

 年前面试 “百度网盘” 部门的 “后端高级开发工程师”，在三面的时候有道面试题印象挺深刻的。

 记得当时的面试官十分专业，问了很多项目相关且思考性很强的问题，还有几个是我平日在开发过程中积累过的优质 BUG，也都问到了。

 正在我沾沾自喜，以为考的都会，答的全对时，面试官开始发难了：“既然你项目上的思考还挺多，那我考你个项目设计的题目吧！首先说明，这些题目不是为了难倒谁，只是想看一下候选人掌握技术知识的深度和广度！”

 

 “啊，对对对！是这样的”，虽然心里百般忐忑，确实日常需求都是 CRUD（增删改查），架构类的设计很久没在项目里做过了，但还是表现出不慌不忙、胸有成竹之色。

 毕竟面试宝典有曰：面试中一半的时间都是在打心理战！只要做足功课，在考场上自信满满地防御，凭面试官一两个小时的进攻，我们也不会败下阵来。

 2. 需求分析

 面试官问：“微博作为国民常用的社交类 APP，平时用吗？可以说一下微博常用的几个功能吗？”

 微博还真没咋用，不过最近刚看了一篇关于微博的系统设计方案，于是不慌不忙地答到：“微博常见功能有刷微博，发帖子以及用户关注，此外，用户还可以点赞、评论、收藏和转发微博。”

 “好，那如果现在让你设计一个微博系统，结合刚才你说的几个核心功能，你会怎么设计？需要考虑系统高并发、高性能以及高可用性。”

 拿到 “产品需求” 之后，我首先在脑海中构建了一个核心功能的用例图，如下：

 

 每个需求说明如下：

 
 
 刷微博：用户打开手机 APP 端的微博主页，显示关注的好友最近发表的微博，按最近时间排序；

 
 发微博：用户可以发表不超过 140 字文本的内容，可以包含图片和视频；

 
 关注好友：用户可以关注其他用户，被关注者可以看到粉丝信息和粉丝数。

 
 3. 概要设计

 微博的业务功能不难理解，但是 并发量和数据量 都非常大：

 
 10 亿级别的用户量，平均每个用户上千个帖子数，每个用户可关注上千个好友；

 高并发量，每秒十万级的平均页面访问，每秒万级的帖子发布量；

 用户分布不均匀，部分明星用户的帖子数量或者粉丝数量，超出普通用户几个数量级；

 时间分布不均匀，某个用户可能突然在某个时间点成为热点用户，其粉丝也可能陡增几个数量级。

 
 其具有一个典型社交类系统的特征，可归结为三点： 海量数据，高访问量，非均匀性 ，接下来从其最常见的关注好友、刷微博、发帖子三个功能来做概要设计。

 3.1 关注好友

 

 如上图微博打开某个博主的主页面，页面包含最基础的关注功能：包括 Ta 的关注用户、Ta 的粉丝数，以及我们可以点击关注此博主。而从博主的主页面，我们还可以进入他的关注和粉丝两个子页面：

 
 关注（attention，后文同）页，展示该用户关注的所有用户信息

 粉丝（follower，后文同）页，展示该用户的所有粉丝用户信息

 
 在上述页面中，用户可以关注某个用户，也可以删除粉丝，即取消其他某个用户对自己的关注，功能的业务交互如下：

 

 用户关注好友时，需要先经过负载均衡服务器，然后把请求发送到微博的用户服务器集群，这里涉及到用户信息的展示，所以用户服务器可能会访问对象存储服务器获取图片和视频，以及从 Redis 或 MySQL 中取出文本数据。

 最后，如果修改了用户的关注状态，就会把信息写入到 Redis 及 MySQL 集群中。

 3.2 刷微博

 刷微博系统的核心是解决高并发问题。系统整体部署模型如下：

 

 首先，我们采用 CDN（Content delivery network，内容分发网络）来快速返回用户请求，它的原理是将服务器部署在用户广泛使用的地区节点，当用户访问系统的时候，通过 全局负载技术 将请求分发到最近的服务器上，由它们直接给用户提供服务：

 

 当没有采用 CDN 时，每次用户请求都会直接到达系统的应用服务器集群，这将对系统服务器产生极大的流量压力；而采用 CDN 后，用户请求会根据 CDN 负载均衡器返回的目标服务器，将访问发配到这些用户邻近的节点上。

 采用 CDN 的优势是能够极大地 避免网络拥堵，使得内容传输更快、更稳定 ，CDN 可以看作是系统缓存，对于微博这种很少更改数据的场景下尤为适用，正常情况下 CDN 可以过滤掉 90% 以上的请求，直接返回数据。

 因此，当用户通过 CDN 访问微博系统时，绝大部分都可以被 CDN 缓存命中。也就是说，图片以及视频等极耗带宽的请求压力，90% 以上可以通过 CDN 消化掉。没有被 CDN 命中的请求，会到达数据中心的反向代理服务器，反向代理服务器检查本地缓存是否有请求需要的内容。如果有就直接返回；若没有，才到分布对象存储集群中获取相关图片和视频，或者从应用服务器应用获取微博文字内容。

 从微博应用服务器集群获取内容时，会先从 Redis 缓存服务器中，检索当前用户关注的好友发布的最新微博，并构建一个结果页面返回。如果 Redis 中缓存的微博数量不够 20 条，则继续从 MySQL 数据库中查找数据。

 4.3 写微博

 

 写微博时不需要 CDN 和反向代理，而是直接通过负载均衡服务器到达应用服务器集群。应用服务器一方面会把发布的微博写入 Redis 缓存集群，另一方面写入 MySQL 分片数据库中。

 注意，我们在写入数据库时， 如果直接写库，当有高并发的写请求突然到来，可能会导致数据库过载，进而引发系统阻塞或崩溃 （参照 “缓存雪崩” 问题）。所以，数据库写操作可以先写入消息队列里（比如 Kafka集群），由消息队列的消费者程序从消息队列中按照一定的速度消费消息，并写入数据库中，以保证 DB 的负载压力不会激增引发异常。

 4. 详细设计

 4.1 表设计

 用户、粉丝、关注和帖子表：

 
 user 表：主键id，用户信息（名称，头像，注册时间，大v认证，手机号等）

 relation 表：主键id，followId，attentionId[粉丝和被关注者ID]

 post 表：主键id，userId，postTime[发布时间（精确到毫秒即可）]，content

 
 索引优化

 post 表可以用组合索引 userId+postTime 查询某个用户最近的帖子，这里组合索引作为二级索引，故需要回表。 为了减少回表次数，我们可以把 userId 和时间戳拼接位 postId 作为主键 ：比如，前 20 位作为时间戳精确到毫秒+用户Id， 转成 62 进制（0-9a-zA-Z）的字符串作为 postId，也能保证主键是递增。

 但这样会导致索引树占用更多空间，且查询时没有纯数字主键那么快，所以最后可以根据实际情况比对两者的优劣选择最合适的主键类型。

 4.2 分库分表

 当 follow、attention、user 表数据量突破千万级、亿万级之后，微博读写数据库的压力非常大，对于单机数据库肯定是无法承受的。所以微博 DB 需要采用分片部署的分布式数据库。

 垂直拆表

 上述 relation 表 [id, followId, attentionId] 存储粉丝和关注信息，当用户增多时就会出现一个问题，那就是分库分表的拆分 key 不好选择：

 
 如果选择 followId 做 hashKey，查询当前用户的关注列表时都在同一个分片，但查询用户所有粉丝时就需要在多个分片上；

 如果选择 attentionId 做 hashKey，查询某个用户的所有粉丝列表时都在同一个分片，但查询当前用户的关注列表时又需要分片。

 
 所以我们将 relation 表拆分为：

 
 follow 表：主键id，userId，followId

 attention 表：主键id，userId，attentionId

 
 水平拆表

 水平拆分即采用 hash 分片的方式部署分布式数据库，分片规则可采用用户 ID 或者帖子 ID。

 如果按用户 ID 分片，同一个用户发表的全部帖子都会保存到同一台数据库服务器上，好处是 当系统需要查找某个用户发表的微博时，只需要访问一台服务器即可完成 。缺点是，对于明星用户，其数据访问会非常多，热点数据的访问导致该服务器负载压力过大。同样地，如果一个用户频繁发布微博，也会导致单个服务器数据增长过快。

 如果按帖子 ID 分片，虽然可以避免上述用户 ID 分片带来的热点聚集问题，但是 当查找某个用户的所有微博时，需要访问的分片数据库服务器是随机的 ，对整个数据库服务器集群的压力太大。

 综合考虑，用户 ID 分片带来的热点问题，可以通过优化缓存来改善。某个用户频繁发表微博的问题，可以通过设置每日发表帖子上限来解决（比如每天每个用户最多发表 50 条微博）。最终，微博采用按用户 ID 分片的策略。

 分片逻辑可以用 hash 取模，也可以用一致性 hash 映射等方式。

 4.3 热点用户问题

 拆完表之后，虽然一定程度解决了快速查表的问题，但是对一些热点明星用户的查询还需要优化。比如以下几种场景：

 
 明星热点用户有很多粉丝，在查询粉丝数量时通过 follow 表查询 count 时扫描的行数非常多，而且这种低效的操作会由于粉丝数的增多而扩大。

 刷微博时，明星用户有很多帖子都是重复被查看的，如果每次粉丝去查询时都到 DB 中获取，无疑会出现严重的性能压力。

 
 解决以上两种场景下的 DB 查询问题，可以引入缓存。但是缓存空间有限，我们必然不能把所有数据都缓存起来，设置一个好的缓存淘汰策略是我们讨论的重点。

 时间淘汰策略

 对于热点话题来说，无论是热点帖子、热点用户，都需要加入缓存，缓存的淘汰策略可以设置为时间淘汰算法。

 将最近 n 天内发布的微博全部缓存起来，用户刷新微博时，只需要在缓存中查找。某用户获取的微博列表如果有 10 条，就直接返回给用户；如果缓存中的微博数量不足，再去数据库中查找。

 所以，我们可以缓存 7 天内发布的全部微博文本，其中缓存 key 为用户 ID，value 为最近 7 天发表的帖子 ID 列表。同时，帖子 ID 和帖子内容也分别作为 key 和 value 缓存起来。

 本地缓存模式

 此外，对于特别热门的微博，比如明星结婚/离婚/出 GUI 等情况，由于高并发访问全都集中在一个 key 上，会给单台 redis 服务器带来极大的负载压力。所以微博系统可以启用 本地缓存模式 ，即应用服务器将特别热门的微博内容缓存在服务器内存中，当用户在刷微博时，会优先检查帖子 ID 对应的微博内容是否在本地缓存中。

 我们可以针对 500w 以上粉丝数的大 V 用户，缓存其 48 小时内发表的全部微博，进一步减轻热点数据带来的查库压力。

 5. 微博发布/订阅问题

 微博用户关注好友后，如何快速得到所有好友的最新发布内容，即发布/订阅问题，是微博的核心业务问题。

 5.1 推模式

 当用户发布一条帖子以后，立即将消息推送给粉丝。但是此时粉丝不一定在线，那么就需要将数据存储起来。这样，用户每新增一条帖子，都需要将帖子推到它的粉丝所在 DB 的分片上，粉丝每次浏览新消息时，直接查询自己分片所存储的数据即可。

 推模式一个明显的问题： 如果一个用户有上千万的粉丝，那用户每发布一条微博，就需要在订阅表中插入上千万条记录，即 “写扩散” 。粉丝之中不乏有很多的僵尸粉（上线频率极低的用户），带来的后果就是数据库压力非常大，导致阻塞或崩溃。

 5.2 拉模式

 当用户发布一条帖子以后，只保存在自己的业务表。当粉丝上线以后再去关注的人业务表里读取帖子，然后按照时间顺序排序后返回。

 拉模式的问题是：如果一个用户关注了 500 个明星用户，每次查询时都需要到各分片中查询不同明星发表的帖子， 一个明星有千万级甚至亿万级的粉丝数，意味着可能会同时有千万级甚至亿万级的读数据操作，即 “读扩散” ，带来的问题就是数据库分片的读数据减压效果体现不出来。

 所以，微博系统首先需要限制用户的关注数，微博普通用户的关注上限是 2000 人，VIP 用户上限为 5000 人。其次，尽量减少刷新微博页面时查询数据库的次数，多用缓存读取帖子。

 5.3 推拉结合

 我们发现，即便对微博用户限制好友数，但单一的 “推模式” 或者 “拉模式” 都难以解决微博系统的订阅/发布问题，所以我们最终采用 “推拉结合” 的模式，具体有如下两种实现方式。

 1）区分大 v 明星

 对于大 v 明星用户（粉丝数大于 500w）来说，为了防止写扩散，我们只需要将数据同步到 100 个数据库分片上即可（假设有 100 个数据分片），它至少需要三个字段：userId，postId，postTime。无论多少粉丝，就只复制 100 份，这样就避免了很多几乎永远不会上线的僵尸粉因为数据写浪费网络性能和存储资源。

 对于普通用户来说，还是继续采用推的模式，这样大多数用户在读取最新帖子的时候只需要在自己用户对应的分片上就可以获取到数据了。

 这样设计的方式较为简单，但是用户在刷微博的时候， 查询过程可能需要查询两次，分别是自己订阅表下的帖子信息，和关注用户发布表下的帖子信息 。

 2）区分在线状态

 第二种方式是根据用户状态来判断推拉：如果用户当前在线，就使用推模式，系统会在 Redis 缓存中为其创建一个好友最新发表的微博列表。关注的好友如果有新微博发布，就立即将帖子信息插入列表的头部，当该用户刷新微博时，只需要将这个列表返回即可。

 如果用户不在线，系统就将列表删除，当用户再次登录刷新时，用拉模式为其重新构建列表 。

 如何确定用户在线呢？一方面可以通过用户操作时间间隔来判断，即心跳机制；另一方面也可以通过机器学习，预测用户的上线时间，利用系统空闲时间，提前为其构建最新的微博列表。

## 面试官问我：有没有并发系统设计的经验，我该怎么说？

 3.18 钉钉群面 

 【自我介绍】+【无领导小组 营销案例讨论】 

 一、基本感受 

 自我介绍说的磕磕绊绊，分析案例的时候感觉自己被专业对口和思路清晰的大佬围着吊打，感觉要凉了。 

 如果想要进入营销一类的岗位，在准备群面时，最好还是提前了解和熟悉一下无领导小组案例分析的思路，明确项目每一个阶段思考的角度，不至于像我一样无话可说。 

 当然，在这种时候，学市场营销类专业或者有过相关实习的同学优势非常明显，讨论的时候都是专业名词和营销方式张口就来QAQ 

 二、讨论的时候可以做的 

 -领导者：有明确思路时，主动carry全场 

 -纠察者：关注题目每一点要求，指出讨论中缺漏的地方 

 -记录者：记录梳理大家的发言，如果最后做presentation你可以立刻用电脑共享一个脑图，那效果可太好了 

 -控场者：留心讨论时间，主动提醒大家推进到下一阶段的问题 

 -亮点输出者：结合题目中的信息，在脑中做好充足的思路准备，适时发表自己独特的看法 

 -倾听者：没有理清思路的时候不要随意发言，否则是在浪费时间 

 三、细节记录 

 -我们这场有一个学marketing的硕士，对于市场营销流程非常熟悉，开口就是专业名词叙述，大部分流程都是他主动推进的 

 -有一位社会学的小姐姐，对项目的想法很立体，也很熟悉流行的营销手段，她提出的想法操作性很强，营销的目的性和创意性也很强 

 -有一位一看就是对屈臣氏做过很多功课的，案例中虚构的公司一看就是指代屈臣氏，因此他很关注潜在的品牌优势，比如30分钟送货到家 

 -还有一位两次que到时间，提醒大家该推进进度了 

 -最后是我，因为思路混乱以及完全不熟悉市场营销的专业术语，两次输出想法效果不佳后，主要就是保持沉默以免打扰讨论进度QAQ 

 -最后5min汇报的时候，是marketing的硕士小哥哥做的。我发现他没有把社会学小姐姐的idea明确表达出来，就que了一下。也不知道会不会让面试官觉得我打扰汇报的完整性QAQ。我本意是觉得这是我们做这个项目的亮点之一，在汇报的时候可以着重体现。但小姐姐补充自己的idea之后说，这是具体的措施，是可以融入项目的不同阶段不同方面，不需要重点说出来。呜呜好吧。

 A、B其实没什么好说的，是自己准备不充分。面试官问了很多专业的问题，比如笔试中的，哪些数据异常（重玩率高但通关率高、该关流失率低，），异常原因。我答的误触，实际上应该是这一关比较好玩，所以出现了玩家重复游玩的情况；另一家也差不多，问我策略游戏（冰汽时代）前中后期资源规划（从游策的角度而不是玩家角度），回合制站位；这一家对我和面试官都是浪费时间。 

 怎么说呢，问的问题太专业细致了，看得出是想找能够直接入职做游戏的应聘者，不出意料这两家都凉了。也没办法，因为确实自己这方面积累不够，12月底才开始正式积累游策方面的知识。 

 C就非常不甘心了，因为我笔试HR都过了，专业面可能答的不够好吧（我会给自己60及格分，但是可能面试官要求比较高）。加上还是有点紧张，有很多准备的东西没有答上来。 

 详细说一下产品面试： 

 自我介绍 

 对产品经理职责的了解 

 平时有接触过产品相关新闻/对新出的产品有多少了解 

 分析一下提到的产品（我说的小黑盒） 

 好的产品是什么样的 

 对微博转发功能这么看 

 微信长按拍照发文字怎么看 

 里面大部分问题都提前准备了，所以还算好；转发和好的产品那个没准备到，答的太简单了 

 
 

 这几天简直度日如年。专业面之后了两天本来显示审核中，然后第二天再看就回退成了等待专业面试结果；好不容易昨天晚上看变成了审核中，早上睁开眼睛就变成了未录用。 

 大概就是这些了。武汉还有两家比较合适的产品经理岗，不知道能不能把握住机会。

## 虽迟但到的群面经验贴~

秋招一直忙忙碌碌，起起伏伏的，本来想尘埃落定了再来敲几篇成功或失败的经验贴，但前两天微博上写小日记吹了个牛皮说我群面零失败哈哈哈哈，然后还有认识的不认识的小姐妹来问我，既然有人问那我肯定要写 😉 

 就按我面试的企业来分别写一下吧，也算是相关企业的面经贴了（最近疯狂被各企业养鱼，攒攒人品，希望早日被捞起） 

 以下按面试时间排序，各企业排名不分先后 🤣 

 
 

 1.字节跳动-抖音电商-物流解决方案 

 啰嗦话： 

 这是我秋招的第一场群面，面试前还是有点怯的，所以我面试前参加了一场一个群里自发组织的线上模拟群面找找感觉【还是很有用的，至少提升了自己的信心~】。

 啰嗦话2： 

 想来离字节一面都过去这么久了，现在我还在池子里，桑心

 啰嗦话： 

 这是我当时最重视的一场面试了，毕竟作为一个物流人嘛，京东集团的管培还是很香的【这里插一句学校背景，本211硕985，物流人】
 

 正文： 

 9.5群面，12人，无自我介绍，无面试官提问，读题3min（面试官计时），讨论总共30min（剩5min面试官会提醒），总结3min。题目是讨论疫情下跨境电商的趋势、机遇和挑战。感觉题目挺泛，不好定框架。第一个发言跳了timer，简单定了一个框架，但明显不合适，大家讨论的越来越散，10min左右终于有同学跳出来总结并理清了思路。期间一直有人抢着报时，跳timer，之前的表现不太好，我一直在问大家对某一点的看法，自己没有输出观点，好在后期输出了一两个观点，最后被推选为总结，总结的还可以。但这场的leader应该不是我。感觉一开始跳timer如果不得不顺势带框架的话，最好说了之后问大家其他的框架建议，不要草率用自己的框架。而且最好第一个发言还是要用两三句话带领大家梳理一下题目，不然容易跑偏。
 啰嗦话2： 

 听说京东管培的群面淘汰率挺高的，能过还是很荣幸的，不过最终还是专业面被刷啦，无缘京东了~ 

 
 

 3.联想-物流管培生

 啰嗦话： 

 联想一共只有两面，每一面都有三四个面试官在线上，感觉整体面试体验还是不错的，效率高，已oc 

 
 

 4.震坤行-商品运营

 9.16，一面线下群面，30min讨论，5min总结，题目和物流相关，整体氛围不是很好，团队协作不好，出现明显分歧（主要因为其中一人意见相左且强势），惯例当了timer和总结，观点贡献少，略微推动进展，预总结的时候有一点让我特别不爽，我有个地方没记录清楚说错了，另一个同学马上说赶紧换一个人记录和总结，也太没有团队合作精神了吧。但总的来说，拿到总结这个角色还是比较稳。
 啰嗦话2：

 啰嗦话： 

 南孚的面试体验还是挺好的，宣讲会后直接群面，然后等十几分钟通知结果直接二面哈哈哈，当晚通知offer，不过没录我第一意向录了第二意向，综合考虑我就没接offer啦 

 
 

 6.美的-供应链管理

 想先说点题外话，其实秋招线上线下参与，整整两个多月，投递了40余份简历，参与了将近20家企业的面试，期间会很心累和迷茫，要说我是不是找到了一个完全符合我心意的offer，并没有，我现在的可选offer里，没有一个是我很想去的，甚至我最后选择的还是我实习的公司，是实习完以为自己大概率不会回去的公司 😂，没有找到让自己很满意的offer，多少还是有一点点遗憾，但确实不后悔，这两个月我不能不经历，没有这两个月里对各种公司和岗位的尝试，我就不知道自己到底偏向于什么，也不知道自己的能力怎么样到底能够到什么高度，一些我想去的公司，可能因为投递时间，可能因为个人表现还不够突出，最后都没有去成，但是我日后大概率不会为现在的选择而后悔了，因为已经好好地努力过~

 （1）秋招（8-11月）和春招（2-5月），秋招有提前的趋势，需尽早准备。日常实习全年不定期放出。 

 （2）非技术岗人才需求量/headcount（hc）主要集中在秋招，春招基本hc很少且竞争更为激烈（考研考公失败+秋招0offer+秋招看看新机会）。 

 （3）应届毕业生从大三升大四的暑假（4年制）开始找全职工作，基本上需要有至少一段（3个月起）的公司实习经历，所以建议从大二升大三的暑假开始准备找公司实习的事情，如果非top学历的同学想比较稳地去头部公司（BAT）产品类建议至少拥有3段岗位对口、具有含金量的实习经历。 

 （4）大公司一般采取站点集中一周面试的形式，一般由北向南开展（所以有为了去一家公司，去很多站点霸面的情况）。我base南方非一线从9月末开始有面试，初期不知道这点但看到有大量小伙伴已有面试十分焦虑，这点大家可以借鉴。还有我有次看某厂站点面试没捞我还很沮丧，后来被调到远程面试。求职路上有很多很魔幻的情况，所以建议大家不要过分沮丧或放弃，要常怀希望。 

 
 

 2. 主要流程 

 （1）一般情况分为：投简历- 笔试 - 业务面/小组长面 - 总监面 - （交叉面）- HR面 （面试顺序会调换，可根据面官和面试内容推定是哪种）。一般情况下面试为3-4轮，4轮以上的同学可能是因为面官觉得不匹配但是觉得能力不错推荐给别的部门/其他岗位。 

 （2）霸面：你特别想去的企业没给你发面试通知，你通过朋友/同学/论坛问到面试时间、地点，于是“精神小伙，不请自来.jpg ”/毛遂自荐直接去招聘现场霸面（一般设有霸面区，没有就和HR套近乎申请），霸面腾讯的概率还是比较高的。（求职的时候多认识些小伙伴、多加些求职群多重要呀～ 

 （3）内推：网申环节分为普通申请和内推两种形式。需要强调的是 不要迷信现在所谓的内推 ，因为它的操作定义发生了变化 。 以前，内推指的是利用人脉等资源将自己的简历在网申后给到公司内部了解你的人，让他们把简历直推面试官，或者你认识的人就是面试官，会给你面试机会。但是现在，由于企业实行内推成功的奖励，内部员工会将内推资源分享给很多不了解的人。企业也会降低内推的权重，仅限于优先筛选简历。综上，可以看出： 重点不是有没有内推，而是你有没有通过内推人把自己推荐给面试官，或者从内推人那里了解到你求职的岗位等信息。 

 
 

 3. 途径 

 （1）互联网公司采取网申的形式，部分公司 宣讲会现场收简历仅用于筛选优秀简历或提供与面官/HR交流的机会 （见过有人搭讪加到面官微信的操作hhhhh）。 

 （2）全职：网申一般在公司招聘官网/微信公众号找投递入口。实习：可在实习僧、牛客、求职/实习类微信公众号和微博（白熊求职等），注意防骗（求职不需交任何费用）。 

 （3）求职主要分为实习转正和校招，一般为标注可转正的日常实习（秋招结果不如意的同学可考虑继续实习春招再战）和部门有hc的暑期实习可转正。某些头部公司暑期实习转正会占用较大比例hc，部分公司会强制要求接校招offer后实习（部分实习可抵试用期）。 

 
 

 【注意】 

 （1）部分公司有简历冰冻期，时长为3个月-1年不等，请提前调查好再投递。 

 （2）投简历后最快当天几个小时后立刻会发起面试，也有可能半个月-1个多月再发起，要做好充足准备，赶前不赶后。 

 
 

 4. 关于求职的常见误区（又名：我曾经的天真想法hhh） 

 （1）性格测试显示我适合做xxx（岗位），我一定没问题。（❌） 

 答：关于择业不是一篇文章能解决的，是需要每个人反思自己的能力和精力、综合外界要求等多方面因素做出的决定。一个人能否获得一份工作，性格也许会有影响，但是最重要的还是你的能力、经历和资源。 

 
 

 （2）现在招聘都强调985优先，我学历符合又有几段学生干部经历就能得到不错的工作。（❌） 

 答：第一，“优先”不是决定条件，只是加分项。第二，起点不能决定结果。考上985只是对你高中学习的基本认可，你大学的经历和 让面官感受到的个人能力 才是你能否offer的决定因素。这需要你能够有技巧地充分展示出你的能力，提炼你的经验，说服面试官。第三，不同环境有不同的考评规则。求职教育行业可能会在意的学历和学习成果，但是 处于商业社会的企业更在意你是否能给企业带来实际营收，并且你为企业带来的营收是否能超过企业支付给你的薪酬待遇总值。更具体来说，企业在意的是你是否拥有和岗位直接相关的能力，最好有直接相关的实操经验 ，尤其是在互联网这个十分强调实操能力的行业。 

 
 

 （3）我只要满足企业的招聘要求（Job Description, JD）我就一定能拿到offer。（❌） 

 答：第一，求职不是考试，不是60分及格，而是 你是所有竞聘人中最适合这个岗位的人 ；第二，求职不是求职者条件的硬性PK，而是 你要让面试官感受到你的能力，让面官“喜欢”你 ；第三，能力不是企业唯一考量的因素，性价比、稳定性等都是雇主考虑的范畴。 

 
 

 （4）我没有得到offer/我没有通过面试，一定是因为我很差。（❌） 

 答：这是求职过程中非常常见的沮丧心理，杀伤力极强，但其实就是nonsense。第一， 秋招不仅是能力战，更是体力战和心理战。 “丧”除了消耗时间不能带来任何实际产出，如果一直沉浸在这种消极情绪中只会让求职结果越来越糟。更重要的是，行动起来，总结经验，快速迭代自己；第二，没通过是因为在这场面试中面试官认为你显得不适合这个岗位（你看，这么多限定条件），不能全盘否定你的能力，也说明不打无准备之仗；第三，招聘结果受很多因素影响，不全是你的错，可能就是忽然没了hc呢！ 

 
 

 5. 关于“求职”的看法 

 经过对秋招的反思，lz惊讶地发现：求职的过程不就是我们既在做产品策划/经理，又在做产品运营吗！你品品～ 

 
 

 产品策划/经理阶段： 

 人人都是“我”这款产品的PM，需要在有限的时间段小步快跑、快速迭代“我”这款产品推向市场。第一，根据OKR法则（Objective & Key Results）设立目标；第二，认知用户，开始分析用户（公司/面官）、场景（工作场景/业务）、用户心智，同时进行用户分层分析，列出核心用户（dream company）及其需求；第三，创造用户价值，不仅是逻辑上能帮用户解决问题，而且需要用户主观上认为“我”能为公司解决问题；第四，迭代，在实践中产出MVP（Minimum Variable Product，最小可行产品）低成本试错，验证P/MF，根据用户反馈和数据快速（面试结果）迭代，实现从0到1。 

 
 

 产品运营阶段： 

 运用各种手段把“我”这款产品与用户连接起来，推向市场，实现用户从1到100的增长（斩获1-100offer，在想🍑）。比如：第一，根据AARRR漏斗模型，扩大入口流量，基于明确目标和精力向尽可能多的公司投递简历；第二，提高用户活跃度，在面试开始要快速抓住面试官的注意力，积极主动展现自己的能力和case，带动面试官的情绪。 

 
 

 所以，我们可以充分讲产品策划和产品运营的知识运用到求职的过程中。我将在面经分享给大家。 

 
 

 二、求职准备 

 注意：在开始这一环节之前，你需要拥有一定的公司实习/项目/学生干部经历，这是一个不能短期提升的东西。 

 1. 认识你自己 

 问自己以下问题： 

 （1）商、政、学三条路，我为什么要选择____? 

 （2）我找工作希望得到什么？优先级是？ 

 （3）我的目标行业/公司/岗位是什么？ 

 例如：在企业校招中，应届毕业生较多涌向投行、证券、咨询、互联网、地产、四大八大、银行等行业。你为什么想从事互联网行业？这个行业的人才需求量大吗？竞争激烈吗？ 

 （4）我性格和能力上的优缺点是什么？和我们的目标有哪些匹配和不匹配的地方？ 

 （5）你为了实现目标做过哪些努力？ 

 
 

 2. 市场调研：这个蛋糕有多大？ 

 目标的确定需要建立在市场需求上，一个行业的人才需求量和这个行业的发展息息相关。从2012年从pc转向移动互联网到2018年底共享经济出现危机开始互联网寒冬，互联网行业的人才需求量已不胜往昔，开始出现缩招。 

 
 

 （1）宏观上，行业发展报告 （咨询公司/行业头部公司/数据服务商等） ，例：艾瑞咨询、比达咨询、QuestMobile等。 

 我要不要进入互联网行业？这个行业有前景吗？发展趋势？未来机会？ 当决定进入互联网行业后，我应该从事哪个垂直领域呢？这个垂直领域的发展趋势？市场规模？用户规模？上下游产业链？主要产品？ 
 

 （2）微观上， 

 结合公司和岗位看往年数据，例：各公司招聘公众号校招数据报告、第三方招聘平台看相关岗位的需求量、往年面经搜索岗位名称预判竞争程度。 深入访谈已经工作n年的学长学姐/问答平台大V（请吃饭/付费咨询，考验社交能力的时候到了！），了解该行业从业人员的工作与生活状态、学历/经历/能力背景要求、职业发展路径和福利待遇。特别强调的是， 你不仅要知道这个行业光鲜和美好的一面，更要关注这个行业不那么光鲜（或者说 bottom line ）是不是你能接受的！破除因为不了解而对这份工作产生的幻想！ 

 
 

 综上，基本可以预判你目标公司岗位的竞争程度，提前做好心理和能力上的准备。 

 
 

 3. 行业/垂直领域资讯：把自己变成一个准内行人 

 （1）这不仅是一道直接会问的笔试（鹅厂第三次笔试大题5G）/面试题（HW群面5G；某OTA小组长业务面），还需要你灵活融入你的面试/笔试问答中。 

 （2）需要关注：行业热点、发展趋势、头部企业动向和大型会议、行业重要会议（例：微信公开课、罗振宇时间的朋友跨年演讲、三节课有可能互联网大烩）等。 

 （3）推荐网站 

 综合：36氪，虎嗅，钛媒体，腾讯/网易/新浪/搜狐科技 O2O：品途商业评论，亿欧 电商：亿邦，派代 新媒体榜单：新榜，清博指数 产品经理：人人都是产品经理，PMCAFF 运营：鸟哥笔记，姑婆那些事儿 广告：腾讯广告、百度营销、梅花网、SocialBeta 
 

 4. 了解公司和岗位 

 （1）途径：公司官网、公司招聘官网、百度新闻、拉勾（公司主页）、天眼查 

 
 

 （2）公司层面： 

 该公司的愿景、价值观、人才观； 公司业务流程、发展阶段、重大事件（发布会、高层演讲）； 主要产品（体验并有自己的见解，优缺点和解决方案）； 竞争对手、业务相近公司的动态。 
 

 （3）岗位层面： 

 认真阅读JD并应用到你的简历中； 在约面试的时候主动询问/确认即将面试的岗位、所属事业部（BU）、具体职责。 
 

 在这里需要强调的是： 

 择业中涉及的行业/公司/岗位的三个层面每一个都有很多细分方向， 岗位叫什么不重要，最重要的是根据JD或其他你得到的信息（内推人、问面官等）这个岗位具体的工作内容是什么。 比如：产品策划/经理可以分为前端、中台和后端，数据、策略、用户等方向；运营等的方向更是繁多，甚至称呼不统一，主要分为内容运营、活动运营、用户运营，还有细分的平台运营、行业运营、电商运营、渠道运营、社区运营、社群运营等等，不过感觉越来越多统一称为产品运营。然后，你需要根据这些信息 有针对性的去修改简历和准备笔面试 。 

 
 

 推荐阅读：求职面试18问（知乎专栏）

 Q：运营为什么要读产品的书？ 

 Lz当时也不知道这点，后来在笔/面试的过程中发现运营也会经常考到对产品的认识，需要有逻辑成系统的回答。从工作角度考量，产品和运营都是在做产品，方法不同，会密切合作，所以运营有必要了解产品的需求。

 7. 材料准备（建议至少预留2周时间） 

 （1）荣誉/资质证书 

 因在毕业季会频繁用到，所以建议即时扫描纸质版证书，将电子版上传到邮箱，以便随时取用。 如有毕业可按照种类（奖学金、语言能力、实习/志愿证明等）区分汇集成册。 
 

 （2）可以证明自己能力的作品（准备作品的过程也是对专业知识应用和巩固的过程） 

 个人原创作品 例如：做运营的小伙伴可以展示原创推文、活动页、个人经历简述（每个字都需斟酌，都有可能会被问到）等。 

 
 

 产品体验报告/竞品分析报告/产品需求文档（运营可做前2个） A. 可以先去“人人都是产品经理”看看别人的结构，或者参加白熊求职训练营押金班，结合自己的情况总结。 

 B. 像做一个research/小论文一样做，立足具体、现实、贴合业务的研究问题，利用贴合问题的分析维度，得出明确的结论。 

 C. 研究问题的来源：新版本新功能、某个爆款综艺/产品/大促的复盘等。 

 D. 数据来源：AppAnnie，TalkingData，易观千帆，QuestMobile等。 

 
 

 【常见误区】很多人在分析后仅得出关于产品交互层面的建议。 

 产品的迭代主要是以盈利为导向的，有用的建议是解决和业务增长直接相关的问题，好的解决方法是以最小的代价解决尽可能多用户遇到的问题。 

 
 

 分析维度举例如下，请立足研究问题选择适当维度： 

 - 市场层面 

 产品定位、目标人群、解决需求、市场背景、上下游产业链、公司背景 

 
 

 - 产品层面 

 用户与场景（用户画像）；用户分层（用户组成、核心用户）；用户价值（产品核心流程、用户行为路径）；用户体验（用户体验框架、交互体验）；商业化（商业模式toB/C）；迭代（用户评价、版本更新频率及功能、迭代方向）。 

 
 

 -运营层面 

 从产品数据分析出业务目标和问题，例如： 

 Q1：如何提高某活动流量？（新老用户、推广渠道、各环节及转化率） 

 Q2：如何提高某活动营收？（GMV=用户数*付费转化率*用户单次消费金额*用户平均购买频次） 

 Q3：如何提高某环节转化率？（入口流量与此前环节转化率/流失率，代表性步骤分析） 

 
 

 产品流量分析模型：AARRR模型（获取、活跃、留存、付费转化、传播） 客户创利能力模型：RFM模型（Recency，Frequency，Monetary） 
 

 内容运营：内容（类型：PGC/UGC/PUGC等）的生产（频率，长短期规划，标准，风控）、组织（聚合，索引，拳头内容呈现）、流通（站内外，技术/运营）。 活动运营：目的（拉新/促活/成交/传播），目标，噱头与利益点，活动节奏，玩法（创意），合作方，项目管理，复盘。 渠道/广告运营：SEO/SEM，ASO/ASM（厂商、第三方、预装），信息流（抖音、快手）等。 
 

 
 

 8. 笔试准备（建议预留至少1个月刷题） 

 笔试一般分为选择题和问答题，选择题基本上是公务员的行测题和部分专业技能题，问答题一般是专业知识或应用题。 

 
 

 选择题： 

 行测题考试范围主要涉及：数量关系、资料分析、判断推理与语言理解题，可以淘宝买书或者下载粉笔app刷题，每天定量练习，按照专题逐个击破。 专业知识题可以用牛客的题库练习。
