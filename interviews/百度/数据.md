 2.3 面试环节

 一共四轮（1群面，2单面，3hr面 4.大领导面通过）

 2.3.1 第一轮 （群面）

 面试方式：腾讯视频会议，大概一共3-6位面试官参与到面试会议

 这种群面在互联网企业一般比较少，常见于在事业单位；银行；运营商或者一些500强的企业之中。

 面试大致内容：

 先自我介绍然后以下几个主要问题：

 1. 介绍下你最近做的几个项目

 这块的话，只要你面试过几次，项目烂熟于心后，这时候介绍的节奏完全可以自己把握，比如哪个地方停顿，留给面试官思考，哪些地方抑扬顿挫，哪些地方留下悬念与包袱，但注意技术吹比的程度请依据面试官的反馈进行动态调整，别给自己挖坑，也别浮夸过度。
以上的技巧只是让你将这块面试题分数提升，核心还是在于你的项目是否有技术难题，是否企业带来真正的价值（通过技术赋能企业，带来市值的提升）等等。。。

 2. 请介绍下数据治理在车企如何进行实施？

 数据治理每家具体的实施其实都不一样，没有统一的标准，但总体的打法以及设计都是一样的。

 首先你需要了解车企数据业务主要是啥？我认为是这几块（想错也没啥，可以通过你与面试官的沟通进行获知）

 
 用户运营

 车辆运营

 公司业务流程运营

 
 其中治理的阶段重点关注点，可以结合你面试企业的数据团队以及平台建设进度，可以进行推测出，比如对方团队只刚开始建设一年，很多平台都还没建设起来，用的都是些开源的平台或者第三方提供的平台，这时候你完全可以断言目前近两年核心要治理的点就是如下：

 
 打通各部门数据（全部汇聚到数据治理这边）

 各部门数据来了，现在需要建设一个统一的标准(车企行业数据资产标准)

 数据资产的产生源头结合2进行集成的平台

 
 具体要实施就是：
对应的就是 1. 建设数据集成平台；元数据管理平台 2.建设指标词根；行业元数据标准；3. 资产管理平台

 每一个都可以拿出来巴拉巴拉讲几个小时，这个环节一定要注意多多与面试官互动，拿到对方的底层需求以及当前业务痛点，结合对方的兴趣点进行对应展开扳扯。。。

 3. 元数据管理如何做的？

 网上现在大部分直接丢一个apache altas方案去说，但我建议大家先了解好对方企业的背景，一定要考虑对方的业务背景，业务需求，技术架构以及组件清理，人力情况，当前企业的总体目标是啥等等去制定方案。
当然，你可以先分享下你之前是如何建设的。然后再结合对方的情况进行方案的输出。

 4. 指标系统如何建设起来的？以及XXX问题如何解决的？

 这一步的话，面试官已经直接拿出当前他们面临的问题直接开问了，所有这一块的问题，其实我之前就做个思考与总结所以能够直接拿捏死。
当前大部分数据开发数据治理到业务使用层面的很多问题，都是由于1. 逆向治理导致 2. 数据不全导致（由于安全性；以及跨部门等等原因导致） 3. 开发阶段不规范不统一 等等原因造成。

 这块的回答，我的习惯就是从问题本身造成的业务层体验，讲到底层原因(不仅是技术原因，更多是人，企业本身的原因), 再给出一个合理对方认同的方案。整个过程你需要适当与面试官互动去了解对方企业业务背景，组织架构，技术架构等等。。。。

 5. 技术小问题了

 前几个问题讲完，其实就已经过了1个小时了。。。
后面就是问些平台的运维的问题了
比如CDH的管理以及问题的处理
平台的选型等等问题了。。。

 2.3.2 第二轮

 第二轮就是一个技术小哥来问了，小哥应该是做数据开发的还有数据治理的。

 第一部分就是一些SQL，flink,kafka的技术题目
第二部分还是和他又扯了一遍数据治理的项目，我之前经历的两家公司都搞个这块，而且业务背景以及做的方案都不一样，这块拿出来切磋交流下。
第三部分数据运营，就是数据这层搞好了，如何利用数据进行数智化运营？，数据运营产品其实无非就这几块1.报表大屏 2. 画像 3.搜索推荐。结合对方的兴趣点以及你自己擅长的选一个讲讲就行了。

 上面讲完又是一个半小时了

 2.3.3 第三轮

 第三轮HR面，就是了解下你的个人情况，个人经历，你的未来意向以及规划。

 2.3.4 第四轮

 我以为3轮就完事了，结果竟然还有第4轮。。。
第4轮大领导面
这一轮主要是像领导说明你的技术以及业务强项，然后会考察下团队协作管理能力，以及与其他部门以及第三方协作能力。后面主要还是领导给我讲了很多新能源车企业务领域的背景，还有上汽几个品牌的介绍，以及为什么当前做技术的转型。

 记得其中最深刻的一句大致是：
传统车企之前是想通过业务驱动技术，而新能源的打法是技术驱动业务

 个人路线 

 lz认为应该有很多双非或者名校的朋友在困惑学历差底子差怎们去卷互联网的开发岗，毕竟在现如今面试靠刷题、过简历靠背景的今天早点找准方向很重要。lz在大二就开始思考这个问题，因为作为一个转专业的人来说计算机是一个全新的领域，来就是图发展、薪资高。在一开始的时候我选择从书籍入的门，甚至到了学框架的时候还在捧着大部头走了很多弯路（知乎上的路线还是少看吧，书是前期铺垫后期强化的，不适合中期学习），直到发现黑马程序员、尚硅谷的课程才找到头绪，但是这个时间点已经来到了大三，求职数挖/大数据以lz本科学历和现在的技术栈完全不够的，所以走了考研这条路给自己提升学历增加时间，奈何一志愿失败读博规划搁浅，遂调剂二年制学校拿学历火速毕业。 

 
 

 求职期望也从算法转向大数据 （实习的时候看lz所面的核心组的简历一水92硕 大厂实习 论文选手 双非完全不够打也证明选择是对的）。考完研火速参加春招吃着之前的老本找个分工作，工作几个月给简历多了三行，带薪摸鱼开始系统性学习大数据，按照尚硅谷大数据路线学习、结合talkdata的路线进行侧重点选择（特别感谢talkdata），等研究生开学基本框架已经全部学完，开学后开始做项目---深挖这个项目让我实习、秋招面试有东西可说、系统性刷题，电子出版社、动物图书一本本看做脑图。 

 ---------------------入门阶段------------------------------------ 

 java入门 《 Java程序设计语言》-机械工业出版社 看书敲书上案例入门，结合尚硅谷的视频 基本语法ok、集合的底层实现、oop有一定的了解、并发有一定认识； java并发 《java并发 》--国外的丛书 java开发人员编写，重点学习v olatile、synchronized、JMM、各种锁、CAS java 虚拟机 《 深入理解JVM》，重点学习 内存结构、回收机制、类加载机制 
 数据库： 《数据库基础概论》--本科教材 事务、锁、并发一致性、隔离级别 mysql必须要会的，重点看尚硅谷视频实操，书可以参看《MYSQL技术内幕：InnoDB存储引擎》、《高性能MySQL》，重点索引、存储引擎、性能优化、锁、分层架构 redis：有精力可看，视频没必要看了，按照尚硅谷的文档安装操作一遍即可，书参看《redis设计与实现(第二版)》，重点基本数据结构、跳表的实现、哨兵、持久化机制 大数据组件：hadoop是基础必看，侧重点三大组件的角色、hdfs的读写流程（源码级别）、shuffle过程、yarn调度机制；spark/flink选一精学，重点shuffle流程、基本组件；书籍推荐《Hadoop权威指南》 大数据相关组件：zookeeper 选举原理，书可看《从PAXOS到ZOOKEEPER分布式一致性原理与实践》，了解分布式事务、分布式锁原理；kafka快速的看遍尚硅谷视频，重点看课件的零拷贝、组件角色 
 计算机基础 

 计算机网络：主要看了谢希仁的《计算机网络第七版》，重点就是TCP和HTTP了 

 操作系统：重点就是进程、线程、死锁、调度 算法 ，FIFO、LRU 。 

 数据结构： 直接刷题吧，真不会建议看看严奶奶的数据结构 

 计算机组成原理：没啥用 

 有精力建议系统性看看，看透后会发现这些框架技术是相通的。 
 ---------------------深入阶段------------------------------------ 

 java 有时间可看《java编程思想》或者《On-Java8-中文版-LaTeX精排》 《大型网站技术架构：核心原理与案例分析》提高综合场景知识面、把各组件串联起来对大型项目架构有一个总体的理解 《深入理解Spark 核心思想与源码分析》底层性能优化、内存调优、shuffle过程的深入理解（比如表的连接中触发shuffle的类型），大数据普遍基于jvm去运行的，所以重点要建立 spark内存、 jvm、系统内存间的联系

 记得第一次去面试java后端是在大三的时候，刚刚把spring mvc学完做了几个demo，是一家做公益服务的小公司。面试官是一个和睦的中年大叔，第一问 jsp怎们前后端通信的，我直接愣住，记忆犹新啊真的是个特别简单的问题，灰溜溜回学校继续学技术，意识到自己到找份工作还差很远，还天天水牛客看大佬。
 

 
 

 考研失利，参加春招吃以前的老本天天看尚硅谷视频、cyc2018的资料背八股文，只敢投递传统企业公司，碰上选择题没太大问题，代码题大部分直接gg。每天起来第一件事各个网站逛一遍寻找可以投递的新企业，下午准备复试，网上背八股文，每一天都沉浸在考研失利、找不到工作的焦灼中，春招拿了三个offer，格力、万达、国泰新点，心情好了些调剂院校也比较满意，趁着夏日来上海梦想中的城市打工啦。这是一家传统软件公司，主营业务政府相关的项目副营自研互联网产品，驻场在公安局提供的场所，没有一点点的归属感心里有种做贼的感觉，甲方爸爸们操着一口上海话围绕着我，好像置身于另一个世界，到六点立马拎包走回家买菜做饭跑步。周六是不是要来值班，任务从来没有做好排期，说要就要，打这以后我发誓再也不来这种类型的公司了，一定要去做自己产品的公司，什么传统软件做政府业务的、定制的靠边站都是一路货色。这种类型的公司常常被认为是外包，作为乙方和别家公司通力合作完成大的政府项目是个很正常的事情，真外包待遇、所签署公司是不一样的。 

 
 

 不去这样的公司去哪尼，大厂。 

 
 

 好像冲浪多的同学都拼了命的想去大厂，我也不例外，无数浪花中的一朵。有那么一种念想，程序员不去大厂很失败、大厂是有光环的闪闪发光，去了，你腾达飞鸿。卷王一个个诞生。 

 
 

 去大厂这个念头真的是自己想要的吗，不是社会氛围感染强加给的吗？ 

 
 

 在大厂，早上9.30-10.30上班，来个倒茶开会wc吃饭散步午睡，干活吃饭散步干活。像不像电子厂或者监狱，早上大巴车拉来郊区打工，工作是劳动改造获取些许报酬，吃完放风，一天12个小时都在公司，健身房、超市、理发店、按摩房还缺张床就可以住公司。说是活干完就能走，周三填个工时排个名卷中带麻。回家后时间只能玩会手机洗洗睡。一直认为互联网作息时间就是反人类，弹性上下班，你来的早因为同事没来无法开展工作只能也晚来，领导不看几点来只看几点走，走晚了休息不好第二天起得晚==要来晚，一早上的时间浪费掉，恶心循环。

 4.针对项目中的某一个功能问？ 

 【反思】回答这个问题时，我从功能背景、功能介绍、功能特点上说的，但是没有突出自己在这个功能中的作用，后来面试官说跳过这个问题吧·····

 6.你做数据分析，是按着什么样的思路进行的？对整个项目有什么作用？按照你的分析结果，是否有项目功能优化的落地？ 

 7.你最近比较关注的一个作品是什么？（书籍、电视剧、综艺等） 

 8.如果让你用百度搜索这个作品，你希望看到的搜索结果页有哪些内容？（可以不考虑百度现有的内容和排序） 

 9.你觉得产品经理最重要的三个能力是什么？
