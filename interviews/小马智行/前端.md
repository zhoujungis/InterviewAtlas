## 2023 年度总结，2024 依然前端

来源：掘金 ｜ 类型：面经 ｜ 发布：2024-01-02 ｜ [原文链接](https://juejin.cn/post/7318446300591964169)

开篇

 2023 年对我来说是极为特殊一年，大概是因为去雍和宫许愿赚大钱的缘故，我佛慈悲，于是...小钱儿是赚了一些，但实现方式嘛...加班~

因此 2024 年只需要一件事，再去趟雍和宫，把赚大钱这个目标再加一些条件。

好了，总结完毕，全剧终~

 正片

 2021

 2021 年 08 月份，离开了奋斗 5 年多的在线教育行业，第一次作为一个纯前端开发进入职场，收留我的，是那个在疫情肆虐、互联网已经不复当年的年头儿，不退反进，逆流而上的小破湖。

我本来不愿意去一个集中爆发的独角兽幼崽公司，太累了~

但是面试的过程改变了我的想法，梦想伟大、方兴未艾，之后真的很憧憬，很想和小破湖一起奋斗，打造互联网的下一个巨头（翻译：给的实在太多了！）

 2022

 事实证明，在大的浪潮下，即便是独角兽公司，也很快走了下坡路，迎着外面此起彼伏的裁员声音，匆匆时光，终说再见，干了短短的 16 个月后，2022 年 12 月，小破湖的生涯也迎来了结束，拿到了人生中第一个毕业大礼包，虽说礼包相较于当年其他互联网还算优秀，但也没有100%，没那么理想，这就是 2022 年的一年。

 

 2023

 离开小破湖，短暂的休息，除夕之后，入职了现在的公司，小马家~

第二次作为纯前端岗出发，待遇的话，年包下降，月薪上涨，职级提升，在那个时间点，也算很不错了，尤其考虑到小破湖在那个方面对标的可是...从一个正常的职业生涯上升来看，小马这边更像是个现实版，OK。

回想 2023 年，好像也没什么大事发生：

 
 躲过了二阳、三阳、甲流

 深感赚钱不易，放弃强追学区房，转而先还完了房贷，再说

 养鱼、养草不再养的飞起，如今更真的像一个爱好了

 王者荣耀有了多个荣耀典藏却不再出现在手机桌面

 摇号儿，蓝牌、绿牌均未中签，积分又增加 12

 岁月累加，偶尔会想起，那时候头也不疼，颈椎也不疼，也不会在失眠的夜里头辗转反侧，也不会在睡醒的早晨头昏脑胀，那时候爸妈身体还很健康，他们年轻，平安喜乐，爷爷奶奶也陪在身边

 不知不觉又是一年

 
 2024

 暂时应该不会离开前端，因此 2024 年应该还是前端的一年

 AI 或者说前端智能

 这是目前说来最想做的事情，也会花最主要的业余精力，希望有机会在小马公司内部推进前端智能化，如果更进一步，想落地一个智能前端方向，一个前端智能化研究小组。

学生时代，学的最好、最感兴趣的是前端方向；研究生的研究方向是物联网、机器视觉。对当时的我来说，毕业后最有可能选择的方向就只有前端和机器学习。

毕业后尝试了进入人工智能的公司实习，在那个方兴未艾的时间，加之自己学艺不精，短暂的实习之后，觉得自己不是那块料儿，前端更火，因此又选择了前端方向实习。

毕业后并未在实习公司小破狐的小破游留下，转而进入一家在线教育行业公司，之后，阴差阳错的在那个 nodejs 流行的时间，成为了一名 nodejs 后端开发，全栈开发，这一干就是 5+ 年，如今回归前端，又遇上大模型盛行，不得不说，有一种命运在交叉的感觉，无论是不是一种指引，这个想法，将会是 2024 最重要的一个，没有之一。

 一面 

 

 1、跨域以及解决办法 

 （ 1 ）跨域是指一个域下的文档或脚本试图去请求另一个域下的资源，这里跨域是广义的。 

 （ 2 ）我们通常所说的跨域是狭义的，是由浏览器同源策略限制的一类请求场景。 

 （ 3 ）同源策略是一种约定，它是浏览器最核心也最基本的安全功能，如果缺少了同源策略，浏览器很容易受到 XSS 、 CSFR 等攻击。所谓同源是指 " 协议 + 域名 + 端口 " 三者相同，即便两个不同的域名指向同一个 ip 地址，也非同源。 

 （ 4 ）跨域解决方案： 

 ①通过 jsonp 跨域 

 ② document.domain + iframe 跨域 

 ③ location.hash + iframe 

 ④ window.name + iframe 跨域 

 ⑤ postMessage 跨域 

 ⑥跨域资源共享（ CORS ） 

 ⑦ nginx 代理跨域 

 ⑧ nodejs 中间件代理跨域 

 ⑨ WebSocket 协议跨域

 2、 Vue 和 React 的区别 

 （ 1 ）监听数据变化的实现原理不同： Vue 通过 getter/setter 以及一些函数的劫持，能精确知道数据变化； React 默认是通过比较引用的方式（ diff ）进行的，如果不优化可能导致大量不必要的 VDOM 的重新渲染。 React 不精确监听数据变化。 

 （ 2 ）数据流的不同： Vue1.0 中可以实现两种双向绑定； React 一直不支持双向绑定，提倡的是单向数据流。 

 （ 3 ）组件通信的区别： React 本身并不支持自定义事件，而 Vue 中子组件向父组件传递消息有两种方式：事件和回调函数，但 Vue 更倾向于使用事件。在 React 中我们都是使用回调函数的。 

 （ 4 ）模板渲染方式的不同：在表层上，模板的语法不同， React 是通过 JSX 渲染模板。而 Vue 是通过一种拓展的 HTML 语法进行渲染，但其实这只是表面现象，毕竟 React 并不必须依赖 JSX ；在深层上，模板的原理不同。 React 是在组件 JS 代码中，通过原生 JS 实现模板中的常见语法，比如插值，条件，循环等，都是通过 JS 语法实现的，更加纯粹更加原生。而 Vue 是在和组件 JS 代码分离的单独的模板中，通过指令来实现的，比如条件语句就需要 v-if 来实现对这一点，这样的做法显得有些独特，会把 HTML 弄得很乱。
