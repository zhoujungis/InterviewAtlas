## 扒了35家AI公司面经，考最多的居然不是Transformer

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-06 ｜ [原文链接](https://www.nowcoder.com/feed/main/detail/7167eed8010c436f8b31ee8d171d4801)

GitHub上有人整理了35家AI公司的面经，约600道题。
我做Agent方向一年了，对着榜单过了一遍，发现一个反共识的事：

大家以为AI岗面试会考Transformer原理、注意力公式、预训练流程。
实际上考最多的是——KV缓存。

直接上高频Top4，准备AI岗的朋友自测：

1. KV缓存是什么？显存占用怎么算？（8家问过）
OpenAI、xAI、Mistral、Apple、NVIDIA都问过。
别觉得这是细节题。大模型推理最贵的就是显存，KV缓存占了一大半。你连这个算不清楚，面试官默认你没真上过生产环境。
我去年面试被问70B模型跑128k context，KV缓存占多少显存，当时答不上来，直接凉。

2. MoE混合专家的路由和负载均衡（6家问过）
DeepSeek、月之暗面、Qwen都问。
大部分人只会说MoE就是多个专家选着用。
面试官想听的是：路由怎么选专家？专家负载不均怎么办？Kimi K2那种1T参数的MoE训练成本怎么算？
这些全是工程问题，不是论文问题。

3. Prompt、RAG、微调怎么选？（6家问过）
这题最考水平。
初级选手：能跑就行。
中级选手：数据够就微调，不够就RAG。
高级选手：先看更新频率——知识频繁更新用RAG，风格固定用微调，简单任务用Prompt。
能把这个决策逻辑讲清楚的，基本是真做过项目的。

4. 给几亿用户的聊天助手设计架构（5家问过）
经典系统设计。但跟传统后端不一样：并发请求怎么排队？模型推理怎么做batch？多轮对话上下文存哪？成本怎么压？
这题能答明白的，基本就是真做过推理服务的人。

看完这份榜单我的感受：
AI岗面试已经过了背Transformer原理图就能过的阶段。
现在真在招人的公司，考的全是怎么把大模型便宜、稳定、快地跑起来。
论文看再多，不如真把一个开源模型部署起来跑一遍。

想冲AI岗的朋友，别光刷理论，先把这四道题自己讲一遍。
讲不出来的，就是你要补的课。 #从事AI岗需要掌握哪些技术栈？#

## DeepSeek（深度求索）——AI Agent 开发岗 社招一面

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-08 ｜ [原文链接](https://www.nowcoder.com/discuss/926970960375214080)

更像技术合伙人之间的设计讨论。"不考知识点，聊设计、聊趋势、聊想法"。全程 90 分钟，从项目架构到评测体系到 Loop Engineering。

 
 开场与项目讨论

 
 
 你最近在关注 Agent 领域的什么新技术？——你说你关注了 DeepSeek-Harness，你怎么理解它和 LangChain 的本质区别？Harness 解决了什么 LangChain 解决不了的问题？

 

 
 选一个你做得最满意的 Agent 项目，完整讲一遍。——从业务背景到技术方案到落地效果。不要报菜名（说用了 RAG、用了 Multi-Agent），我要听设计决策背后的思考。

 

 
 
 架构设计深度追问

 
 
 你的 Agent 整体架构是分几层的？——每一层的职责是什么？层与层之间的接口是怎么设计的？为什么这么设计？如果换一种分层方式会有什么不同？

 

 
 你的 Agent 是用的 ReAct 还是 Plan-and-Execute？——为什么选这个？如果任务更复杂（比如 50 步的长链路），你的方案还 work 吗？怎么改进？

 

 
 多 Agent 协作是怎么实现的？——通信模式是什么？如果子 Agent 返回的结果是自然语言（而不是结构化数据），主 Agent 怎么解析？怎么保证解析不出错？
