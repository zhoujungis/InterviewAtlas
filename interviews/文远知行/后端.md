 Redis中的分布式锁怎么弄？ SET NX命令和Redission 

 如何理解幂等？ 哪怕这个请求执行了很多次，最终产生的有效状态和执行一次相同。 

 工程中如何实现幂等？ 第一类是创建类操作，比如创建订单、发优惠券，优先用业务唯一号配合数据库唯一索引来保证，这是比较可靠的最终兜底。 第二类是状态变更，比如订单支付，我通常会用状态机或者条件更新，比如 update order set status='PAID' where id=? and status='UNPAID'，只有第一次更新成功，后续重复请求不会再次生效。 第三类是接口重复提交，可以使用请求唯一 Token 或 Idempotency-Key，配合 Redis SETNX 做快速去重。 第四类是 MQ 重复消费，可以用 messageId 或业务流水号建立消费记录表，并通过数据库唯一索引保证一条消息只产生一次业务效果。 如果并发比较高，也可能配合 Redisson 分布式锁，但我认为分布式锁主要解决并发互斥，本身并不能完全解决幂等，所以核心业务最终还是要依靠数据库唯一约束、业务状态或者业务流水号兜底。
