## 阳光电源嵌入式软件开发一面 面经汇总

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-17 ｜ [原文链接](https://www.nowcoder.com/discuss/930024452375474176)

1. 请做一下自我介绍？

 我是某某，本硕嵌入式/电子相关，主攻 MCU + RTOS 业务软件，做过通信采集、控制状态机、外设驱动和联调排障。

 技术栈以 C 为主，熟悉 FreeRTOS 任务划分与同步、SPI/I2C/UART、ADC 采样链路，以及 MQTT/TCP 侧的数据上报。

 项目里我通常负责：需求拆任务、关键路径时序、内存与栈预算、异常与看门狗策略，以及和硬件/上位机对接口。

 近期想往光伏/储能电力电子控制或通信平台方向深挖，更看重长期做产品固件而不是纯 demo。

 2. 介绍一个代表性项目：难点是什么，你怎么突破的，收获是什么？

 选一个能量流/数据采集/设备通信闭环项目讲：目标指标（采样率、延迟、丢包率、重启恢复时间）先说清楚。

 难点一：高频采集与慢速上报抢 CPU——用 DMA + 环形缓冲把硬实时和业务解耦，业务任务只消费完整帧。

 难点二：多任务共享外设或全局状态——明确“谁写谁读”，用队列传所有权，锁只护短临界区。

 难点三：现场偶发挂死/内存碎——固定静态分配优先， malloc 路径加水位与断言，栈用水印统计再定大小。

 收获：会用证据排障（示波器、逻辑分析、RTOS 运行时统计），而不是靠猜；能把“能跑”收敛到“可量产边界清晰”。

 3. 你对阳光电源了解多少？为什么选阳光（合肥/南京）？

 阳光是光伏逆变器、储能变流、电站监控等领域的龙头，嵌入式软件直接贴合电力电子控制、通信与运维平台。

 业务上既有强实时控制闭环，也有协议栈、云端/本地监控，技术纵深比纯消费电子更贴我的方向。

 选合肥/南京：产业聚集、项目节奏快，便于长期做产品迭代而不是短期外包交付。

 个人匹配点：我能扛底层驱动与 RTOS，也愿意把状态机、采样精度、通信可靠性做到工程指标级。

 4. 堆和栈有什么区别？ static 关键字有哪些作用？

 栈：函数局部、自动分配释放，速度靠 SP 移动；空间有限，深递归/大数组易溢出；通常不跨函数生命周期返回其地址。

 堆： malloc/free 或系统堆管理，生命周期程序员管；可能碎片化、不确定耗时，实时路径要谨慎。

 嵌入式里还会有 .data/.bss 、CCM、DTCM 等区，别把“堆栈”简化成 PC 那套虚拟内存模型。

 static 局部变量：生命周期拉到整个程序，仍文件/函数作用域，适合状态保持且不想污染全局命名空间。

 static 全局/函数：限制链接可见性为翻译单元内，减少符号冲突，便于模块封装。

 再补一点：文件内 static const 表常放 Flash；注意初始化顺序与多文件依赖，别隐式依赖启动顺序。

 5. 声明变量要注意什么？全局变量什么时候用、有哪些坑？

 先定作用域与生命周期：能局部就局部；跨模块才考虑文件内 static 或受控全局。

 定宽类型优先（ uint32_t ），注意对齐、位宽、有无符号、易变外设要用 volatile 。

 中断/多任务共享必须谈同步：关中断、原子、消息队列或锁；光靠“我记得会改”不够。

 全局适合：硬件句柄表、真正的单例配置、跨层只读常量；不适合当“临时缓存垃圾桶”。

 坑：隐式耦合导致难测、初始化顺序不确定、ISR 与线程同时写无保护、命名冲突、链接期符号膨胀。

 工程做法：全局只读开放、可写走接口；模块状态用 static + API；跨核/跨任务传数据优先拷贝所有权。

 6. 什么是野指针？如何避免？ malloc/free 场景怎么防？

 野指针：指针值不是合法对象地址——未初始化、指向已释放、指向已失效栈对象、越界后仍当合法用。

 规避：定义即初始化（ NULL 或有效地址）；禁止返回局部地址；数组/缓冲带长度一起传；生命周期结束立刻置空。

 malloc 后必须判空；写入不超过申请长度；配对 free ，谁分配谁释放或契约写死。

 free 后立刻 p = NULL ；禁止 double-free；禁止 free 后继续读旧指针做“缓存优化”。

 嵌入式增强：能静态池就别堆；堆分配集中在初始化；运行期分配加计数/水位；调试开 overflow canary 或 heap tracing。

 释放顺序注意嵌套结构：先释放内部指针再释放外壳，避免只丢外壳造成泄漏或半悬空。

 7. 你用过哪些 MCU？STM32F4 的 RAM 大概多少？外设资源怎么答才像用过？

 常用可答：STM32F1/F4/H7、GD32，或你们项目真实料号；按内核、主频、总线矩阵讲差异。

 F4 不是一个数：F405/F407 常见 192KB（含 CCM），F429/F469 常见 256KB 量级，以具体 datasheet 为准。

 要拆清：SRAM1/SRAM2、CCM 能否被 DMA、DTCM/ITCM（若对比 H7）——这才是面试官想听的“资源意识”。

 外设层面能点到：多路 USART、SPI/I2C、定时器能力、ADC 通道与 DMA 请求线、是否有 ETH/USB/CAN。

 结合项目说瓶颈：是 CPU、RAM、DMA 冲突还是 ADC 采样抖动，而不是背参数表。

 8. SPI 几根线？怎么工作？I2C 呢？MQTT 是什么，多组数据上网怎么设计？

 SPI 常见四线：SCLK、MOSI、MISO、CS；三线半双工也有；还可多从机多 CS。模式看 CPOL/CPHA，全速由主机时钟推。

 特点：全双工、速率高、无内建寻址应答；适合 Flash、屏、高速 ADC；注意线长、环回采样、DMA 与 CS 时序。

 I2C：SCL/SDA 开漏 + 上拉，7/10bit 地址，起停条件、ACK/NACK、时钟拉伸；速率标准/快速/快速+；适合传感器、EEPROM。

 I2C 坑：上拉阻值、总线挂死恢复（九时钟）、多主机仲裁、与模拟前端共地噪声。

 MQTT：发布/订阅，Broker 中转；QoS0/1/2，遗嘱、保持心跳、主题树；嵌入式端重点是会话恢复与流量控制。

 多组数据上网：按主题拆分（遥测/告警/配置）；本地环形队列聚合，定时或阈值阈值批量 publish；关键告警高 QoS，周期量 QoS0；断网本地落盘/覆写策略；统一时间戳与序列号防乱序。

 9. 进程和线程有什么区别？你用过哪些锁，各自怎么理解？

 进程：独立地址空间与资源集合，隔离强、切换与 IPC 成本高。

 线程：共享进程地址空间，切换轻，但共享内存必须同步；MCU 上 FreeRTOS 任务更接近“线程模型”。

 裸机/RTOS 语境要会映射：任务=线程近似，无 MMU 时“进程隔离”基本不存在，靠软件规范。

 互斥锁 mutex：保护共享资源，可配备优先级继承；持锁要短，禁止在持锁时做长阻塞 I/O。

 信号量 semaphore：计数资源或同步事件；二值信号量常作 ISR→任务通知，但不该当互斥乱用（缺拥有者语义）。

 临界区/关调度或关中断：最短路径保护，延迟确定；时间一长直接砸实时性。

 还有读写锁、自旋锁（SMP）、无锁环形缓冲：按场景选，别只会一句“加锁就行”。

 10. 生产者-消费者模型怎么做？常见问题有哪些？

 典型实现：环形队列 + 空/满信号量，或 FreeRTOS Queue；ISR 生产、任务消费最常见。

 正确性要点：单生产者单消费者可无锁环缓；多生产者必须互斥或分区队列。

 常见问题一：假唤醒/竞态——满时仍写、空时仍读，索引更新要原子或进临界区。

 常见问题二：优先级反转与抖动——高优先级消费者等低优先级生产者持锁，需继承或避免锁。

 常见问题三：覆盖与丢失策略——实时遥测可覆盖旧数据；计费/告警不可丢，要反压或扩容。

 常见问题四：内存与缓存一致性——DMA 写缓冲后要 cache invalidate；CPU 写给 DMA 要 clean。

 验收看：峰值吞吐、最坏延迟、丢包率、队列水位告警，而不是“联调偶尔能通”。

 11. FreeRTOS 创建栈怎么定？什么是优先级反转，怎么解决？

 先按调用链静态估：局部大数组、printf/浮点、协议栈峰值、中断嵌套余量，再留 20%–50% 安全余量。

 运行期用栈水位（ uxTaskGetStackHighWaterMark ）压测最坏路径：上电自检、异常重连、日志暴增。

 禁止在任务栈上放巨大缓冲；大块改静态/堆池；递归要有深度上限。

 优先级反转：高优先级任务等低优先级持有的锁，中间又被中优先级任务抢跑，导致高优先级间接久等。

 解法：优先级继承（mutex）、优先级天花板、减少锁粒度、用无锁队列把共享变成消息传递。

 设计层：别让低优先级任务干“必须马上完成才能放锁”的长活；持锁只改共享状态，耗时放锁外。

 12. 状态机关键要素与实现方式？如何保证实时性？

 要素：状态集合、事件、转移条件、进入/退出动作、可选守卫与层次/并发状态。

 实现：表驱动（状态×事件→处理函数）、 switch-case 、函数指针状态对象；复杂控制更推荐表驱动 + 纯动作函数。

 事件来源要统一入队：GPIO/定时器/通信 ISR 只投递事件，状态迁移在任务上下文执行，避免 ISR 里跑长逻辑。

 实时性：状态处理最坏执行时间要有预算；长动作拆分或扔低优先级工作队列；周期状态用时间事件，别空转轮询。

 可维护：禁止“隐蔽全局改状态”；每个转移可日志/埋点；上电有明确初始态与故障态，故障恢复路径要可测。

 和 RTOS 结合：一任务一状态机，跨任务只发事件；别多任务同时改同一状态变量。

 13. ADC 采样精度不够或数据不准，怎么排查和优化？

 先分清是“噪声大、偏移、增益错、偶发尖峰、还是通道串扰”，用已知基准源/短路输入定量。

 硬件：参考电压是否干净稳定、模拟地回流、输入阻抗与采样保持时间是否匹配、抗混叠滤波、布线远离开关电源。

 配置：分辨率、采样时间、时钟源抖动、多通道扫描顺序、DMA 是否覆盖缓冲、是否过早读转换结果。

 软件：去极值均值/中值、过采样抽稀、校准偏移增益、工程单位换算别用错 Vref；注意 cache/DMA 一致性。

 系统：CPU/射频/PWM 开关噪声与采样时刻对齐——可同步到安静窗口采样，或提高采样后数字滤波。

 验证：同一点位示波器对比、温度漂移复测、满量程与零点、长期跑飘；指标用 LSB、mV、相对误差说话。

 优化顺序：基准与地 → 采样时间/输入网络 → DMA 时序 → 校准与滤波；别一上来只加软件滤波掩盖硬件问题。

## 面试官竟然问我的缺点是什么，居心何在？

来源：牛客网 ｜ 类型：面经 ｜ 发布：2023-02-24 ｜ [原文链接](https://www.nowcoder.com/discuss/458566635910119424)

“你的缺点是什么？” 

 我相信在面试过程中很多同学都遇到过这个问题。

 有人会回答“我的缺点是没有缺点（得意的笑）”！

 HR和面试官听完摇摇头不说话了！内心OS是“这么不坦诚，我们还聊个3.1415926吗？”

 

 实话回答说“我的缺点是不确定是否胜任岗位”，HR和面试官听着可能就摇摇头了！

 自信是硬通货，不行我们也没法要呀！

 

 

 说实话，这个问题对初出茅庐的应届生而言，这可能是比较头疼的问题，一不小心就可能掉进坑里。

 介绍一下我自己：3年校招经验，500余次面试，主要负责研发工程师、销售经理、运营岗位、支持服务类等岗位的招聘。

 对于这个坑的问题，我的建议是： 

 首先是了解面试官的目的是什么？ 

 然后要了解如何回答才能在面试中得到高分? 

 下面是我对这个问题的分析，希望对正在找工作的你有所帮助！

 

 一、面试官的目的是什么？ 

 当面试官问到这个问题时，我们要从面试官的角度思考一下，他问这个问题的目的是什么。一般有三点目的： 

 1.找出与岗位不匹配的缺点 

 对面试官来讲，他肯定是想要找到符合岗位的人才。如果求职者的缺点对岗位不利，肯定是无法通过面试的，不然对面试官而言就是引火烧身。

 例如：质检岗位说自己比较粗心；

 研发岗位说自己缺乏创新能力；

 销售岗位说自己不善沟通。

 这些缺点对岗位而言都是致命的硬伤，一旦说出基本不会有面试官选择你。

 2.看看你是否有清楚的自我认知 

 面试时大家都希望展现出一个完美的自己，这都可以理解。

 但是你要清楚人无完人。适当的一些小缺点 （根据岗位职责和岗位要求避重就轻的回答） ，面试官也是可以接受的。

 面试官询问这个问题一方面是想要了解你是否有自我认知；

 另一方面是想要判断之前对你的认知是否有过大的偏差。

 3.挖掘求职者面对缺点时的态度 

 我在面试时，发现部分求职者仅仅回答缺点。

 然后就手足无措地看着面试官，等待着面试官的“审判与凝视”。这种做法其实是不可取的。

 面试官问这个问题还想要考察你面对缺点的态度，以及你如何应对这些缺点。

 所以，在回答问题时也可以适当回答一下自己往后如何克服这一缺点。

 例如；在非销售岗时“我的缺点就是说话比较直，可能在与同学、朋友沟通过程中不能很好的考虑到周围人的感受，但是我目前已经认识到了这一点，也在利用空闲时间根据相关书籍学习并提升自己的沟通技巧。”

 

 二、面试时应该如何回答这个问题？ 

 1.缺点避重就轻，无伤大雅 

 

 例如上图就是我们阳光氢能事业部目前在招聘的硬件工程师。

 在面试期间一位同学的回答：

 “由于我是应届生没有太多的实践经验，但是在校期间我也了解并学习了Altium Designer等辅助设计软件，同时对于制氢电源、光伏等领域的设计标准和规范都有一定的了解，最近我也在不断学习和丰富自己的相关知识。”

 像上面这种回答就很好，避开了岗位的核心要素，缺点不会对岗位造成很大影响，都在面试官的接受范围之内。

 但是切忌与工作毫无关系。 

 例如，在面试海外运营专员时回答“我的缺点是不喜欢运动，缺乏一定的运动细胞。”要知道我们是来工作的，面试官不会关心你是否有运动细胞。

 面试官问这个问题只是想看你是否对自己有清楚的自我认知以及你的临场发挥和沟通能力。

 所以在回答问题时也不要扯太远，这种感受就像老师看到跑题的论文一样，难以理解。

 2.缺点可改正且容易改正 

 当面试官问你缺点时，不代表他不愿意接受一个有缺点的员工。

 所以这个缺点对岗位来说一定是可以改正并且容易改正的。这样的缺点才是无伤大雅的。

 反之，缺点就会成为缺陷，会降低你在面试官心中的评分。

 例如在面试工艺工程师的时候有的同学回答“虽然我的专业知识比较扎实，但是缺乏一定的实践，入职之后还需要师傅带我。”

 这样的回答不仅表达出你的缺点容易改正，而且还侧面突出了了自己专业能力扎实，一举两得。

 3.提出解决方案 

 面试官不仅想要了解你的缺点还想要考察你的应对能力。

 如果你只是用一两个词形容了自己的缺点，很有可能让面试官给你贴上标签。如果这个缺点面试官比较介意就是降低你的面试印象。

 其次当你给出解决方案时，面试官不仅会认为你认真准备了面试，了解了这个岗位同时也让面试官知道你的缺点并不会对工作造成影响。

 总结 

 1. 回答避重就轻，不对岗位核心要求产生太大影响；

 2. 缺点可以改正且容易改正；

 3. 问题最后提出应对缺点的方案。

 8、最后反问我问了阳光的加班强度，以及岗位需要的技能，这俩问题对面都回答的比较笼统。 

 远程面试总共30多分钟，体验较好没什么特别难的。 

 

 小结： 阳光电源从报名到面试到最后谈薪都过去好久了，趁空闲整理下面试记录。阳光电源作为国内新能源行业的龙头，发展还是非常不错的（阳光给我加广告费），如果有想在新能源行业发展的同学是可以考虑阳光电源的，除了合肥，阳光电源在南京、上海和深圳都有了研发中心。此外我要说的就是慎重选择光储集团，就近几年光储集团的加班好像非常严重。研发相关的岗位还是推荐去中央研究院。 [激动]
