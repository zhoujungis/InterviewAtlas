## 面经67：比亚迪 | 三面

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-11 ｜ [原文链接](https://www.nowcoder.com/discuss/938860748321587200)

比亚迪三面面经

 
 1. 自我介绍

 回答思路

 个人背景 → 科研方向 → 核心成果 → 项目经历 → 岗位匹配 

 建议大家控制时间在 1～2 分钟，是突出和应聘岗位最相关的经历。

 可以按照以下顺序组织：

 - **个人背景**：学校、专业、学历、研究方向。
- **项目经历**：参与过哪些相关项目，主要研究什么问题。
- **核心成果**：论文、专利、竞赛、项目指标或其他实际成果。
- **个人工作**：自己具体负责哪些模块，解决了哪些问题。
- **岗位匹配**：为什么希望进入嵌入式软件相关岗位。

 
 2. 讲一讲实习和XX项目，在其中具体担任的工作？

 回答思路

 项目背景 → 研究目标 → 个人职责 → 技术路线 → 项目成果 

 回答时需要区分“团队完成了什么”和“自己实际做了什么”。

 建议重点说明：

 1. 项目要解决什么实际问题。
2. 自己承担的具体任务是什么。
3. 使用了哪些工具、技术或实验方法。
4. 项目过程中遇到了哪些问题，自己如何解决。
5. 最终取得了什么结果。

 
 3. 项目中遇到过哪些问题？如何怎么解决的？

 回答思路

 问题现象 → 原因分析 → 验证方法 → 解决方案 → 结果对比 

 项目问题

 重点突出工程调试能力，例如：

 - 通信异常、数据丢失。
- 传感器采集不稳定。
- 任务调度或资源竞争。
- 控制效果不符合预期。
- 系统运行过程中出现偶发故障。

 
 推荐大家回答时一定要讲清楚自己如何验证的原因，而不是光说“我查阅资料后修改了参数，最后解决了问题”。 建立假设、设计验证并形成闭环，

 4. 你觉得整个项目做下来，遇到的最大困难

## 嵌入式大厂面试核心要素总结｜从 C 语言到项目复盘，一篇讲透

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-20 ｜ [原文链接](https://www.nowcoder.com/discuss/931177170972442624)

秋招最大的感受是： 嵌入式面试看起来杂，其实考的就那么几块，只是每家的权重不一样。 把核心要素拆开看，复习方向会清晰很多。下面按"考什么、怎么答、坑在哪"的顺序梳理一遍，给还在准备的兄弟们参考。

 一、先看总览：五个维度，权重不同

 C 语言与数据结构

 30%

 必考，答不出来直接挂

 操作系统 / RTOS

 25%

 区分度最高的一块

 体系结构与底层（ARM、启动、驱动）

 20%

 决定你是"应用"还是"底层"

 硬件与通信协议

 15%

 岗位强相关，硬件岗权重翻倍

 项目与软素质

 10%

 决定评级和能不能过主管面

 一句话结论： C 语言是入场券，操作系统是分水岭，项目深度决定薪资档位。 

 嵌入式大厂面经总结基础八股文专栏：（支持简历辅导，答疑）300K+同学学习，2300+人订阅，包括常考八股文以及大厂面经

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 二、C 语言：永远的地基

 这块没有捷径，但考点高度集中，属于"背了就有分"。

 指针类 

 数组指针 int (*p)[5] 和指针数组 int *p[5] 的区别，一定要能画出来

 函数指针的声明、用途（回调、驱动里的 file_operations ）

 野指针、悬空指针的成因与规避（置 NULL、free 后置 NULL）

 二级指针什么时候必须用（修改指针本身）

 关键字类 

 const 三种位置： const int *p 、 int * const p 、 const int * const p 

 volatile 三大场景：硬件寄存器、中断里被修改的变量、多线程共享变量。追问基本是"编译器优化会怎么坑你"

 static ：修饰局部变量（生命周期）、全局变量/函数（可见性）

 sizeof 与 strlen 、 #define 与 const 与 enum 的取舍

 内存与底层 

 五大内存分区，以及 .bss 为什么要清零、 .data 为什么要从 Flash 搬到 RAM

 malloc/free 与 new/delete 的差异，内存碎片怎么处理

 结构体对齐规则（三条，能算偏移量）、 #pragma pack 

 union 判大小端、位域的内存布局

 memcpy 与 memmove 的区别，以及 为什么 DMA 场景要注意重叠 

 位操作（嵌入式特色） 

 置位/清零/取反/取某几位，写成宏

 统计二进制中 1 的个数、判断是不是 2 的幂、交换两个变量

 环形缓冲区、状态机、位带操作（Cortex-M）

 这块的复习方式很简单： 白纸上手写，不看答案能写对才算会。 

 三、操作系统与 RTOS：分水岭

 大厂问 OS 不会只问概念，一定会往下追一层。

 必答清单 

 进程 vs 线程 vs 协程，切换开销从哪来

 进程通信五种方式，各自适用场景（共享内存最快但要自己做同步）

 线程同步：互斥锁、自旋锁、读写锁、条件变量、信号量、原子操作—— 自旋锁为什么不能睡眠 

 死锁四个必要条件，以及实际项目里怎么破

 用户态/内核态切换、系统调用开销

 虚拟内存、缺页中断、页面置换算法（LRU 手写思路）

 中断是重灾区 

 中断处理流程、现场保护、中断嵌套

 上半部/下半部、软中断、tasklet、工作队列的差异

 中断上下文里不能做什么 （不能睡眠、不能拿可能睡眠的锁、不能 copy_to_user）

 中断与轮询的取舍

 RTOS（FreeRTOS 为主） 

 任务调度机制、优先级反转与优先级继承（互斥量的意义就在这）

 信号量、队列、事件组的区别

 临界区保护、Tick 中断、任务栈大小怎么估

 heap_1 ~ heap_5 的差异，为什么很多项目用 heap_4

 实时性的定义：硬实时、软实时，最坏响应时间怎么算

 四、体系结构与底层：拉开差距的地方

 ARM 基础 

 工作模式、寄存器组（R13/R14/R15、CPSR）

 异常向量表、中断响应全过程（保存现场→跳转→恢复）

 流水线、Cache（I-Cache/D-Cache）、写回 vs 写通、Cache 一致性与内存屏障

 启动流程（问得非常多） 上电 → ROM Code → Bootloader（BL1/BL2/U-Boot）→ 内核解压 → 挂载根文件系统 → init。追问点：链接脚本干了什么、重定位、分散加载、 _start 到 main 之间发生了什么。

 Linux 驱动（底层岗必备） 

 字符设备驱动框架： cdev 、设备号、 file_operations 、 mknod 

 设备树与 platform 总线， probe 的调用时机、 compatible 匹配

 内核并发控制：自旋锁、互斥体、原子操作、RCU

 阻塞/非阻塞 IO， poll/select/epoll 与等待队列

 内核态与用户态数据拷贝、 ioctl 、sysfs

 内存： kmalloc vs vmalloc 、slab 分配器

 能讲清楚"驱动加载到设备可用"这条完整链路的人，基本都能过技术面。 

 五、硬件与通信协议

 硬件岗权重翻倍，软件岗也会问基础。

 I2C ：起始/停止条件、7 位地址、ACK/NACK、时钟拉伸、总线仲裁、上拉电阻为什么必须有、100k/400k/3.4M

 SPI ：四线、CPOL/CPHA 四种模式、全双工、多从机片选

 UART ：波特率、帧格式、TTL/RS232/RS485 区别

 CAN ：报文 ID 与仲裁、位填充、错误帧、显性/隐性电平、CAN-FD（车载必问）

 开漏与推挽、三态门、上下拉

 建立/保持时间、时序图怎么读

 工具：示波器、逻辑分析仪、万用表、JTAG/SWD 的实际使用经验

 加分项： 能讲一次真实的硬件调试经历 （比如 I2C 拉不起来最后发现是上拉电阻选错），比背十条协议管用。

 六、手撕代码：嵌入式爱考什么

 不是 LeetCode 中等偏上就够，嵌入式有自己的题库：

 链表：反转、合并有序链表、找中点、判环、删除倒数第 N 个

 字符串：逆序、回文、 atoi 、手写 strlen / strcpy / memcpy 

 位运算：统计 1、判断 2 的幂、交换奇偶位

 排序与查找：快排手写、二分边界处理

 环形缓冲区实现 （读写指针 + 满/空判断）

 按键状态机 （消抖 + 长短按）

 注意：嵌入式手撕更看重 边界处理和代码规范 ，变量命名、 assert 、入参校验都会被看。写完主动说一句"这里我考虑了大端和小端的情况"，印象分很高。

 七、项目：决定薪资档位

 简历上每个项目都要能回答这五个问题：

 这个项目解决什么问题，你在里面的具体职责

 技术方案为什么这么选，备选方案是什么，为什么放弃

 遇到最难的一个 bug 是什么， 怎么定位的 （这一问最见功力）

 有没有做过优化，量化指标是什么

 如果重做一遍，你会改什么

 用 STAR 结构讲，但 结果一定要量化 ：响应时间从 50ms 降到 8ms、内存占用降 30%、功耗降 25%、良率提升到 99%。没有数字的项目描述，面试官记不住。

 忌讳两点：一是项目讲得像产品说明书，二是被追问细节就卡壳—— 写在简历上的每一行，都要经得起三层追问。 

 八、不同大厂的偏好差异

 华为 ：C + 操作系统 + 网络，机试门槛高，技术面深，主管面看抗压和稳定性

 大疆 ：C++、算法、项目深度，手撕代码比例大

 海康 / 大华 ：C、驱动、协议，风格务实，问得细

 汇川 / 比亚迪 / 宁德 ：RTOS、控制算法、电机，偏工程应用

 车企与车 BU ：AUTOSAR、CAN/CAN-FD、车载以太网、ISO 26262 功能安全

 芯片原厂（地平线、瑞芯微、全志、紫光展锐等） ：启动流程、SoC、驱动、体系结构

 手机厂（小米、OPPO、vivo、荣耀） ：BSP、功耗、稳定性、Linux 内核

 外企（NXP、ST、高通、Intel 等） ：英文、体系结构、Linux 内核深度

 投递前先看 JD 关键词，能省一半复习时间。

 九、非技术面与反问

 为什么选嵌入式 ：不要答"因为喜欢硬件"，要答"因为软硬结合能直接看到结果，我在 XX 项目里体会到了"

 职业规划 ：3 年做深某个方向（BSP / 驱动 / 车载 / 芯片验证），不要泛泛而谈

 反问 ：团队方向、技术栈、新人培养机制、考核与转正节奏。 别问加班和薪资，那是对 HR 说的 

 十、复习节奏参考

 打基础

 第 1-3 月

 C 语言 + 数据结构，每天一道手撕

 补体系

 第 4-5 月

 操作系统 + ARM + 启动流程

 补岗位

 第 6 月

 驱动 / 协议 / 岗位专项

 冲刺

 面试期

 面经复盘 + 错题本，每天记录被问倒的问题

 最重要的一条：每次面试后当天写复盘。 被问倒的问题第二天补上，两周之后你会发现重复率极高——嵌入式面试的题库，其实相当收敛。

## 嵌入式手撕必考20题汇总（建议收藏）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-13 ｜ [原文链接](https://www.nowcoder.com/discuss/928680586456100864)

先聊聊：手撕代码到底有多重要？

 很多同学以为嵌入式面试就是背八股：背背volatile、背背中断流程、背背通信协议就完事了。 大错特错。 

 现在的嵌入式大厂面试（华为、字节、大疆、宁德、比亚迪、小米、海康、TP-Link等等），几乎无一例外都会安排 手撕代码环节 。有的公司甚至手撕挂了，八股答得再漂亮也不要。原因很简单：

 八股可以背，代码骗不了人 。手撕环节考的是你真实的编码功底、思路清晰度和工程习惯，这是装不出来的。

 嵌入式岗位对代码严谨性要求极高 。一个位操作写错、一个空指针没判，在真实产品里可能就是设备死机、批量返工。面试官通过手撕，一眼就能看出你有没有“产品级”的编码意识。

 手撕是分层最明显的环节 。八股大家分数都差不多，真正拉开差距、决定你是SP还是普通offer的，往往就是手撕这一关。

 而且嵌入式手撕有自己的鲜明特点： 不太考复杂算法 ，重点考察C语言基本功、位运算、内存操作、字符串处理和链表能力，题目经典、重复率极高。也就是说， 这是最容易通过提前准备拿满分的环节 。

 下面这20道题，是我结合各大厂嵌入式面经整理的高频必考题。建议每道题都 亲手写一遍、能白板/腾讯会议共享屏幕下一遍写对 ，不要只看。

 嵌入式大厂面经总结基础八股文专栏：（支持简历辅导，答疑）300K+同学学习，2300+人订阅，包括常考八股文以及大厂面经

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 必考20题清单

 【位运算类】——嵌入式特色，出场率最高 

 判断一个整数是2的整数次幂

 统计一个整数的二进制表示中1的个数

 置位、清零、翻转、判断某一位（寄存器位操作四件套）

 求两个整数的平均值（要求不溢出）

 不用临时变量交换两个整数

 求一个数的绝对值（不允许分支判断）

 【字符串/内存类】——基本功照妖镜 

 手写strlen（考虑const、返回size_t、边界处理）

 手写strcpy / memcpy（重点：内存重叠问题，memmove的实现）

 手写strcmp / strstr

 字符串转整数atoi（处理正负号、非法输入、溢出）

 手写内存置零memset

 判断字符串是否为回文

 【C语言关键字/语法类】——结合八股一起考 

 用宏定义求结构体成员的偏移量（offsetof）和容器首地址（container_of）

 定义一个宏，求两个数的最大值/最小值，并说明宏的坑（副作用、括号）

 用宏实现位域操作：将指定位置1/清0的带参宏

 函数指针的声明与应用：用函数指针实现一个简单的回调机制

 【数据结构类】——链表是重灾区 

 单链表的反转（手撕率第一名级别）

 判断链表是否有环（快慢指针）

 找到两个单链表的相交节点

 链表的中间节点 / 删除链表倒数第N个节点

## 面了 30+ 家嵌入式岗，我总结出 7 条比刷题更重要的经验

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-31 ｜ [原文链接](https://www.nowcoder.com/discuss/923926351768195072)

去年秋招到今年春招，我前前后后投了 30 多家 ，方向覆盖 MCU 产品岗、Linux 驱动、BSP、工控、车载、消费电子 ，有的挂在简历，有的挂在笔试，有的挂在二面深挖，也有几家拿到了 offer。

 说实话，最开始我也以为嵌入式面试就是：

 C 语言 + STM32 八股 + FreeRTOS 概念 + 项目背稿

 结果真上场以后才发现， 真正决定过不过的，往往不是你会不会背，而是面试官能不能从你嘴里听到“工程感”。 

 这篇不灌鸡汤，只讲我面了几十家之后，觉得最值得早点知道的经验。

 我也是靠这套面试八股文专栏和这些大厂面经上岸的，非常推荐：

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 先说结论：嵌入式面试，拼的不是题量，是这 3 件事

 如果只能记三句，记这个：

 简历上的每一个词，都要能扛 3 层追问 

 项目不是功能清单，而是一条能讲清的链路 

 二面以后，考的不是知识，是判断力和排障能力 

 很多人不是不会，是 准备方向错了 ：

 刷了 200 道八股，项目还是讲不清

 简历写满 RTOS/Linux/驱动，一问 probe 失败怎么查就卡住

 五个项目都很浅，没有一个能扛 30 分钟

 所以别再用“题量”骗自己了。嵌入式面试，最后拼的是你能不能像一个真正能进组干活的人。 

 一、第一家就教会我：简历不是越满越好

 我最早一版简历，技能栏写了：

 精通 C、精通 STM32、熟悉 FreeRTOS、熟悉 Linux 驱动、熟悉 UART/SPI/I2C/CAN、熟悉 Bootloader、熟悉 OTA……

 看起来很能打对吧？

 第一家大厂技术面，10 分钟就被问穿了。 

 面试官没为难我，就问了一句：

 “你说熟悉 FreeRTOS，那互斥量和二值信号量怎么选？你们项目里为什么用队列不用全局变量？”

 我答的是定义，不是场景。

 他又追问：

 “你说做过 OTA，那升级失败怎么回滚？pending 写在哪？断电怎么办？”

 我又开始背流程，背不全。

 那次之后我才明白：

 简历不是写给 HR 看的，是写给面试官“找漏洞”用的。 

 我的简历改法

 后来我只保留 1 个主项目深挖 ，技能栏全部降级表述：

 精通 C

 熟练

 熟悉 Linux 驱动

 了解驱动框架，做过字符设备实验

 熟悉 FreeRTOS

 项目中使用 FreeRTOS 做多任务划分

 五个项目并列

 1 个主项目 + 1 个辅助项目

 改完后，投递通过率没明显变，但面试深度对话明显变顺了。 

 因为面试官终于知道该往哪里问了，而我也终于接得住。

 二、笔试没那么玄，但很多人死在“基础不牢”

 我面过的公司里，笔试大概分 3 类：

 1. C 语言 + 数据结构

 最常见。

 链表、字符串、指针、位操作、简单排序，真的会出现。

 2. 选择题大杂烩

 C、OS、计网、MCU、协议、RTOS 混在一起。

 看着散，其实都在考“基础广不广”。

 3. 岗位专业题

 驱动岗会考设备树、内核基础；

 MCU 岗会考中断、DMA、通信协议；

 车载岗会考 CAN、诊断、实时性。

 我踩过的坑

 只刷难题，结果笔试考的是字符串和链表

 只会概念，手写代码一塌糊涂

 把笔试当秋招附属，结果提前批直接挂

 真正有用的准备

 C 语言手写代码必须练 ：字符串、指针、数组、链表

 把 JD 当复习清单 ：写驱动就补 Linux，写 MCU 就补外设和 RTOS

 笔试不要拖到秋招前一周 ，提前批就会考

 三、一面和二面，根本不是同一种考试

 这个是我面了十几家以后才反应过来的。

 一面考什么？

 C 语言基础

 外设/RTOS/Linux 基础概念

 项目是不是你做的

 表达清不清楚

 一面更像：

 “你是不是合格的候选人。”

 二面考什么？

 架构为什么这样设计

 为什么不用另一种方案

 遇到过什么 bug，怎么定位

 如果量产/长期运行，哪里会先出问题

 如果让你重做，你会改什么

 二面更像：

 “你进组以后，能不能独立扛事。”

 我印象最深的一次二面

 面试官听完我项目介绍，只问了 4 个问题：

 为什么 OTA 元数据放 EEPROM，不放 Flash footer？

 为什么 Modbus 线圈保存要异步，不直接在通信回调里写？

 I2C 读失败你们怎么恢复？

 如果现场升级一半断电，系统怎么保证还能启动？

 没有一个问题是八股定义。 

 那一刻我才懂：

 二面不是考你知道多少，是考你有没有真正做过决策。 

 四、项目经历，真的是嵌入式面试的“胜负手”

 我看过很多同学的简历，功能写得很多：

 智能小车

 温湿度采集

 OLED 显示

 蓝牙控制

 超声波避障

 但一问：

 “你负责哪一部分？软件怎么分层？为什么这里用中断不用轮询？掉电怎么办？”

 就卡住了。

 什么样的项目能打？

 我后来总结，能打的项目至少有 4 个特征：

 1. 有分层

 能讲清 APP / 协议 / BSP / 驱动 / 公共模块。

 2. 有闭环

 不只是采集，还至少有通信、存储、升级、异常恢复中的两三项。

 3. 有排障

 你讲过真实 bug，以及怎么定位、怎么修。

 4. 有工程意识

 看门狗、日志、版本管理、掉电保护、总线恢复，至少占一两项。

 我自己的主项目后来只留这个方向

 STM32H7 双核工业控制

 Bootloader + 双分区 OTA + EEPROM 元数据

 Modbus RTU + 线圈掉电保存

 FreeRTOS 多任务 + 以太网升级 + LVGL 显示

 不是因为它多高级，而是因为它能扛追问。 

 五、不同岗位，准备重点完全不一样

 这是我面几十家后最大的体会：

 嵌入式不是一个大类，至少分 3 条主线。 

 1. MCU / RTOS 产品岗

 重点准备：

 C 语言

 中断、DMA、时钟、启动流程

 FreeRTOS 任务与同步

 UART/SPI/I2C/Modbus/CAN

 项目架构和稳定性

 适合：海康、汇川、安克、拓竹、很多工控和消费电子岗。

 2. Linux 驱动 / BSP 岗

 重点准备：

 C 功底

 进程线程、内存、文件系统

 设备树、platform driver、字符设备

 probe 失败排查

 用户态和内核态通信

 适合：华为 BSP、小米底层、龙旗、部分手机/显示公司。

 3. 车载 / 工控 / 通信岗

 重点准备：

 CAN/CAN FD

 通信可靠性

 实时性

 诊断、异常恢复

 有时还会考 C++

 适合：比亚迪、车企供应链、中兴通信底层、部分机器人公司。

 千万别一份简历海投所有嵌入式岗。 

 我早期就这么干，浪费了很多面试机会。

 六、面试官最爱问的，其实不是定义，是“整条链路”

 后来我把高频问题归了类，发现核心就 5 类：

 1. 数据怎么走

 一帧 Modbus 从串口到任务怎么处理？

 SPI 读传感器到界面显示经过哪些层？

 OTA 包从网口到 Flash 怎么落盘？

 2. 为什么这样设计

 为什么用 RTOS，不裸机？

 为什么这里用 DMA？

 为什么参数放 EEPROM，不放 Flash？

 3. 出错怎么办

 通信超时怎么办？

 I2C 挂死怎么办？

 升级失败怎么办？

 任务卡死怎么查？

 4. 并发怎么协调

 两个任务抢 I2C 怎么办？

 中断里能做什么，不能做什么？

 擦 Flash 时别的任务怎么不被拖死？

 5. 量产怎么想

 看门狗怎么配？

 日志怎么做？

 版本怎么管理？

 现场出问题你怎么查？

 能把这五类问题讲顺，面试质感会完全不一样。 

 七、我总结的 7 条“比刷题更重要”的经验

 经验 1：只深挖 1 个项目，胜过堆 5 个浅项目

 每个项目准备 10 个追问 ，比背 100 道题更有用。

 经验 2：简历每个词都要能降级

 扛不住三层追问，就别写“精通”“熟悉”。

 经验 3：八股要背，但必须落到场景

 volatile 不是背定义，是要能说出你们项目里哪里用了、为什么。

 经验 4：准备 3 个排障故事

 通信问题 1 个、死机/复位 1 个、性能/稳定性 1 个。

 二面特别好用。

 经验 5：提前批别等

 7–8 月就开始投，别等 9 月正式批。

 嵌入式很多岗位提前批抢人很明显。

 经验 6：内推 + 官网双通道

 嵌入式内推往往比纯海投更有效，尤其是部门明确招 MCU/驱动/BSP 时。

 经验 7：面完一定要复盘

 不是记题目，是记：

 我在哪一层被问穿？

 是概念、项目、还是岗位不匹配？

## 嵌入式车企常考面试题汇总

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-03-11 ｜ [原文链接](https://www.nowcoder.com/discuss/861163073678155776)

最近总结了车企嵌入式岗位的常见面试题，涵盖了比亚迪、小鹏、理想、蔚来等新能源车企以及传统Tier1供应商的面试内容。随着智能汽车的快速发展，车企对嵌入式工程师的要求越来越高，不仅要懂传统的CAN、LIN通信，还要掌握车载以太网、AUTOSAR架构、UDS诊断等知识。

 这次整理的25道题目都是实际面试中的高频考点，从车载通信协议到整车网络架构，从诊断协议到功能安全，基本覆盖了汽车电子领域的核心知识点。无论你是准备校招还是社招，这些题目都值得好好研究。

 常见面试题

 CAN 总线的基本工作原理是什么？仲裁机制是如何实现的？

 CAN2.0 与 CAN FD 的主要区别是什么？为什么需要 CAN FD？

 CAN 报文的标准帧和扩展帧有什么区别？各自的使用场景是什么？

 CAN 总线出现错误时有哪些错误类型？节点是如何进行错误处理的？

 CAN 网络中为什么需要终端电阻？终端电阻的典型值是多少？

 如何计算 CAN 总线的总线负载率（Bus Load）？影响因素有哪些？

 LIN 总线与 CAN 总线相比有哪些特点？适合应用在哪些汽车场景？

 LIN 网络中的 Master 和 Slave 是如何通信的？调度表（Schedule Table）的作用是什么？

 FlexRay 总线的静态段和动态段分别有什么作用？

 为什么在部分汽车系统中会选择 FlexRay 而不是 CAN？

 什么是车载以太网（Automotive Ethernet）？与传统以太网有什么区别？

 100BASE-T1 与 1000BASE-T1 的主要特点和应用场景是什么？

 SOME/IP 协议在车载以太网中的作用是什么？

 什么是 DoIP（Diagnostics over IP）？它解决了什么问题？

 UDS 诊断协议的基本结构是什么？常见的诊断服务有哪些？

 在 UDS 中，Session、Security Access 和 Routine Control 的作用分别是什么？

 ECU Bootloader 的主要功能是什么？整车 ECU 升级的基本流程是怎样的？

 什么是 OTA（Over-the-Air）升级？在汽车系统中需要解决哪些关键问题？

 什么是网关 ECU？在整车网络架构中承担哪些功能？

 传统分布式 ECU 架构与域控制架构有什么区别？

 什么是 AUTOSAR？Classic AUTOSAR 和 Adaptive AUTOSAR 有什么区别？

 AUTOSAR 中 RTE（Runtime Environment）的作用是什么？

 汽车电子中常见的网络管理（Network Management）机制有哪些？

 在车载网络中如何进行时间同步？为什么时间同步很重要？

 在整车通信网络设计中，如何保证通信的可靠性与实时性？

 汽车行业对嵌入式工程师的要求不仅包括扎实的软件基础，更强调对汽车通信协议、整车网络架构以及车规软件体系的理解。熟悉这些典型面试问题，有助于系统梳理汽车电子相关知识体系，也能更好地应对车企或 Tier1 的技术面试。在实际准备过程中，建议结合项目经验与协议规范进行深入理解，以提升整体竞争力。

 嵌入式车企面试八股文准备方法

 在准备汽车电子相关嵌入式岗位面试时，很多公司（尤其是车企和 Tier1）都会通过“八股文式”的技术问题来快速判断候选人的知识体系是否完整。因此，系统化整理知识点、形成结构化记忆，是提高面试通过率的重要方法。下面总结几种比较有效的准备方式。

 1. 按汽车通信协议体系系统复习

 汽车嵌入式面试中最常见的一类问题就是 车载通信协议 。建议按照通信层级进行整理，例如：

 低速通信 ：LIN

 中高速通信 ：CAN / CAN FD

 高带宽通信 ：FlexRay / 车载以太网

 诊断协议 ：UDS、DoIP

 服务协议 ：SOME/IP

 复习时不要只记概念，建议按照以下结构去准备每个协议：

 协议产生背景

 数据帧结构

 仲裁或调度机制

 优缺点

 典型应用场景

 与其他协议的对比

 例如很多面试题其实就是围绕这几个点变化。

 2. 整理“高频对比题”

 车企面试特别喜欢问 协议对比类问题 ，例如：

 CAN vs LIN

 CAN vs CAN FD

 FlexRay vs CAN

 车载以太网 vs 传统 CAN 网络

 Classic AUTOSAR vs Adaptive AUTOSAR

 建议自己整理一份 对比表格 ，从以下维度总结：

 速率

 拓扑结构

 实时性

 成本

 应用场景

 这样在面试时可以非常清晰地回答。

 3. 熟悉整车电子架构

 近几年车企越来越关注 整车架构理解能力 ，面试中常见的问题包括：

 分布式 ECU 架构

 域控制器架构

 中央计算架构

 网关 ECU 的作用

 OTA 升级流程

 准备时建议理解三个层面：

 车内通信网络 

 控制器架构变化 

 软件架构变化 

 很多问题其实都是围绕这三个点展开。

 4. 熟悉汽车诊断和升级流程

 车企岗位经常会问 诊断与升级相关问题 ，例如：

 UDS 诊断流程

 ECU Bootloader 工作原理

 OTA 升级流程

 DoIP 的应用场景

 准备时可以重点理解：

 诊断服务结构

 会话控制流程

 安全访问机制

 升级完整流程（下载、校验、刷写、重启）

 这些问题在车企面试中出现频率非常高。

 5. 建立“场景式记忆”

 很多人背八股文的问题在于 只记定义，不理解场景 。

 例如：

 为什么车窗控制常用 LIN？

 为什么自动驾驶域使用车载以太网？

 为什么 CAN 需要终端电阻？

 如果能结合 实际车载应用场景 去记忆，不仅更容易记住，也更容易在面试中展开回答。

 6. 整理个人项目与八股文的结合

 车企面试通常会把八股问题与项目结合，例如：

 项目中用的是什么通信协议？

 如何设计 CAN ID？

 如何排查总线异常？

 总线负载率如何评估？

 因此建议在复习八股文时，把每个知识点都尝试 往自己做过的项目上关联 。

 总结

 准备车企嵌入式岗位的八股文，核心不是死记硬背，而是建立一个完整的知识框架。通常可以围绕四个重点进行系统复习：

 车载通信协议（CAN / LIN / Ethernet） 

 整车电子架构 

 诊断与升级（UDS / DoIP / OTA） 

 AUTOSAR 软件架构 

 当这些内容形成体系后，大部分车企嵌入式面试问题都可以比较从容地应对。

 嵌入式开发必备知识总结

 1. 嵌入式系统基础 

 嵌入式系统组成 ：通常包括硬件（MCU/CPU、存储器、外设）、固件/驱动、操作系统和应用层软件。

 嵌入式操作系统 ：熟悉实时操作系统（RTOS）和任务调度机制，了解任务优先级、中断处理、信号量、互斥量等同步手段。

 资源限制意识 ：嵌入式系统常受限于内存、计算能力和功耗，开发时需考虑代码优化、内存管理和效率。

 2. 编程与编码规范 

 C/C++语言能力 ：掌握指针、内存操作、数据类型、结构体、宏定义等，理解硬件寄存器操作和位操作。

 MISRA C ：熟悉嵌入式开发规范，保证代码安全性、可维护性和可移植性。

 单元测试 ：掌握模块级测试方法，验证输入输出及边界条件，确保功能可靠。

 3. 外设与通信接口 

 常用接口 ：GPIO、UART、SPI、I2C、CAN等。

 CAN通信 ：理解报文格式（标准帧11位ID，扩展帧29位ID）、优先级、CRC校验机制、重发机制，保证总线可靠性。

 调试工具 ：熟练使用JTAG、逻辑分析仪、示波器等进行硬件调试。

 4. 控制与算法基础 

 电机控制 ：BLDC、步进电机原理，霍尔传感器和PWM控制，闭环控制思想。

 电池管理系统（BMS） ：SOC/SOH估算、电压/电流/温度监控、充放电控制、均衡管理、保护机制。

 滤波与控制算法 ：卡尔曼滤波、PID控制、电池估算算法等。

 5. 软件架构与标准 

 AUTOSAR ：理解模块化设计、软件组件和RTE接口，适用于大型汽车嵌入式系统。

 功能安全 ：ISO 26262标准，理解ASIL等级及其对软件开发和验证的要求。

 OTA升级 ：理解远程软件升级原理、完整性校验和安全性保证。

 6. 开发流程与项目管理 

 版本控制 ：Git等工具用于管理代码版本和协作开发。

 调试与仿真 ：通过模拟器和硬件在环（HIL）测试验证软件功能。

 性能优化 ：在内存和CPU受限条件下优化代码，提高系统响应速度和可靠性。

 总结 嵌入式开发要求工程师具备硬件理解、软件能力和系统思维。除了掌握C/C++编程、操作系统、通信协议和控制算法，还需熟悉行业标准（如MISRA C、ISO 26262、AUTOSAR）和调试工具。通过系统化学习、项目实践和不断复盘，才能在嵌入式开发中快速成长，解决实际问题。

 当然了，正如我在面经里面说的那样：“从这次经历而言，我觉得个人实力和机会都很重要。没有22年这场风波我也没机会进面试。没有自己的一些项目和奖项，也没机会拿offer。”虽然选择TP确实有一定的风险，但我最后还是选择了TP。首先，我就这一个offer，青岛联通发的时候TP都在走签约流程了。第二，我有考研，这俩可以互相备份，这次考的也还行，估计初试能过。第三，TP相比其他岗位给的实在是多，且公积金和社保全额缴纳，相比之下非常良心了，为啥不选呢？

 如果从经验来说，我觉得 肖四 说的就挺对。

 第一，要树立崇高的职业理想 ：你要敢选，愿意为了找工作而忙活，而不是三天打鱼两天晒网，无论啥考研、保研、就业都是一个要求，这点一定要能做到。我秋招进场算晚的，这一样拖了三个月才基本结束。

 第二，要服从社会发展的需要。 找工作本质上就是你和企业双向选择的过程，但这里面占据主导地位的还是企业，能不能满足企业的需要直接关系到你能不能拿到offer，我如果只需要一个保安，你塞给我一个清北博士那肯定不合适。我需要一个歼击机，结果你是轰炸机，那也不行。你得根据你的专业去匹配相对而言比较好的方向，相对宽泛的专业方向多，但也意味着单个方向不够精通。相对专精的专业可能方向少，但如果对口的市场足够大也能过得很滋润。

 第三，要做好充分的择业准备。 你要根据你的所学，掌握扎实的基础知识技能，满足企业的要求。以我选择的硬件方向为例，起码数模电知识你得会吧？射频嵌入式也得了解点吧？就算没项目也得有点比赛经验吧？都这个样。我最后看了看，那个问题汇总，我大概整理了45000字，基本涵盖了所有会问的问题，这也是我能通过TP一二三面拿到offer的一个重要条件。与此同时，网上的求职经验你也得看，了解对口公司的笔试、面试，要是有时间最好刷刷题，这样稳妥地多。

 第四，要培养创业的勇气和能力。 如果你确实有本事，又恰巧财力雄厚，自己当资本家剥削别人剩余价值这不是更好吗哈哈哈哈。

 也罢，等完成TP三方签署，我的秋招就算彻底结束了。今年还算是比较理想，秋招收到了不错的工作offer，考研预估成绩也比较理想，到了12.26我也一直没有阳性，我已经很满足了，回头开春看看能不能去实习，有空的话可以再投点春招看看，反正也在官网填了一堆信息，不弄浪费了。

## 秋招比亚迪等车企硬件工程师经验

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-02-06 ｜ [原文链接](https://www.nowcoder.com/discuss/353157517985390592)

本人本科双非一本硬件工程方向，目前 211 水硕一名，早就听说硬件工程行业是日渐饱和，前段时间秋招试水了几家大车企，分享一下自己的微不足道的经验吧。 

 比亚迪 

 （硬件测试工程师） 

 三轮面试，第一轮HR会问一些基本情况，也可能会让你用英文介绍一下自己，第二轮技术面问你做过的项目之类，第三轮就是HR可以谈薪资之类的； 

 面试问到的具体问题： 

 （1）请问你过去做过哪些项目？
 （2）那个最让你影响深刻？详细描述一下项目的过程。
 （3）能否英文交流？六级英语是否考过？
 （4）你又哪些技能以及擅长的？ 

 （5）对公司有哪方面认识，对工作地点调动有什么看法？
 （6）最后薪水看你学历，我给的9000底薪加绩效大概就是一万二左右一月，包吃包住。 

 面试过程没有问道太多的技术问题，都是围绕你做过或者参与过的项目进行提问，对于英语口语方面有一定的要求，整个过程更像是聊天，最后我也拿到了offer！ 

 东风日产 

 （硬件工程师） 

 HR先进行电话面试，通过HR这关后，用人部门也与你进行电话面试！用人部门在电话里主要了解你的项目经理和一些技术上的问题！通过后委托HR约定面试时间，发面试邀请邮件。到公司有两轮面试，还是HR和用人部门，问题和电话里差不多，但更加详细，技术面完后，谈到薪资的要求，HR让回去等，就这套路。 

 面试过程问到的具体问题： 

 （1） 你的项目经历，描述越详细越好。 

 （2） 具体用过哪些平台的DSP，对于大三电的了解？ 

 （3） 件可靠性设计以及EMC，信号处理等等专业问题； 

 （4） 问到对于行业发展的开发以及个人的·职业生涯规划。 

 （给我的感觉是自己描述多于提问） 

 吉利汽车 

 （硬件工程师） 

 一天完成，上午很早就去了，下午很久才面试结束，人挺多的。刚开始说是现场面试，结果技术面试官没有来现场，就接到了电话，开始了电话面试。电面结束后开始HR面，这个是一对一的面试。 

 面试中问到的具体问题： 

 问了一些简历上的东西，例如你做了什么项目，在学校有哪些经历，对未来发展怎么看。还问了毕业设计做什么。面试中没有问什么技术问题，就了解了下家庭，工作意愿，和薪资。 

 整个面试过程是我多个车企面试经历里面相对而言最简单的，最后拿到了offer，不过薪资方面实在不符合我的期望，最后被我pass掉了。 

 今天的分享暂时就到这吧，目前也一直在备战春招，继续加油吧！！

 中颖电子 

 1. 简单的自我介绍； 

 2. 了解一些在校经历，学习成绩等； 

 3. 主要问了做过的项目，问到项目里的一些细节； 

 比亚迪 微电子有限公司 

 笔试+面试； 

 笔试：主要是一些性格题目，以及基本的英语题目； 

 
 

 1. 简单的自我介绍； 

 2. 问问在大学的生活情况以及将来希望的就业方向； 

 3. 说一说你现在的研究方向； 

 4. 在校期间参加过什么比赛，比赛得奖情况等； 

 5. 然后问到之前做过的项目，问得比较深入； 

 6. 然后要求写一个三分频电路； 

 7. 然后要求讲一讲异步FIFO； 

 8. 问对状态机了解怎么样？设计一个十字路口信号灯； 

 9. 问建立时间保持时间； 

 10. 问引入亚稳态会对电路带来什么样的后果？ 

 二轮面试：

 3. 然后谈谈对公司的了解； 

 4. 谈谈职业规划等； 

 
 

 科胜讯 

 笔试+面试； 

 笔试：分两个部分： 

 (1)英文测试：40分钟都必须用英文写，共三大题，最后一题是中翻英。 

 (2)技术测试：80分钟，共6页；

 3. 然后了解一下你的大学经历；然后由于经理面试；
