## 面经67：比亚迪 | 三面

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-11 ｜ [原文链接](https://www.nowcoder.com/discuss/938860748321587200)

比亚迪三面面经

 
 1. 自我介绍

 回答思路

 个人背景 → 科研方向 → 核心成果 → 项目经历 → 岗位匹配 

 建议大家控制时间在 1～2 分钟，是突出和应聘岗位最相关的经历。

 可以按照以下顺序组织：

 - **个人背景**：学校、专业、学历、研究方向。
- **项目经历**：参与过哪些相关项目，主要研究什么问题。
- **核心成果**：论文、专利、竞赛、项目指标或其他实际成果。
- **个人工作**：自己具体负责哪些模块，解决了哪些问题。
- **岗位匹配**：为什么希望进入嵌入式软件相关岗位。

 
 2. 讲一讲实习和XX项目，在其中具体担任的工作？

 回答思路

 项目背景 → 研究目标 → 个人职责 → 技术路线 → 项目成果 

 回答时需要区分“团队完成了什么”和“自己实际做了什么”。

 建议重点说明：

 1. 项目要解决什么实际问题。
2. 自己承担的具体任务是什么。
3. 使用了哪些工具、技术或实验方法。
4. 项目过程中遇到了哪些问题，自己如何解决。
5. 最终取得了什么结果。

 
 3. 项目中遇到过哪些问题？如何怎么解决的？

 回答思路

 问题现象 → 原因分析 → 验证方法 → 解决方案 → 结果对比 

 项目问题

 重点突出工程调试能力，例如：

 - 通信异常、数据丢失。
- 传感器采集不稳定。
- 任务调度或资源竞争。
- 控制效果不符合预期。
- 系统运行过程中出现偶发故障。

 
 推荐大家回答时一定要讲清楚自己如何验证的原因，而不是光说“我查阅资料后修改了参数，最后解决了问题”。 建立假设、设计验证并形成闭环，

 4. 你觉得整个项目做下来，遇到的最大困难

## 面了 30+ 家嵌入式岗，我总结出 7 条比刷题更重要的经验

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-31 ｜ [原文链接](https://www.nowcoder.com/discuss/923926351768195072)

去年秋招到今年春招，我前前后后投了 30 多家 ，方向覆盖 MCU 产品岗、Linux 驱动、BSP、工控、车载、消费电子 ，有的挂在简历，有的挂在笔试，有的挂在二面深挖，也有几家拿到了 offer。

 说实话，最开始我也以为嵌入式面试就是：

 C 语言 + STM32 八股 + FreeRTOS 概念 + 项目背稿

 结果真上场以后才发现， 真正决定过不过的，往往不是你会不会背，而是面试官能不能从你嘴里听到“工程感”。 

 这篇不灌鸡汤，只讲我面了几十家之后，觉得最值得早点知道的经验。

 我也是靠这套面试八股文专栏和这些大厂面经上岸的，非常推荐：

 https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 先说结论：嵌入式面试，拼的不是题量，是这 3 件事

 如果只能记三句，记这个：

 简历上的每一个词，都要能扛 3 层追问 

 项目不是功能清单，而是一条能讲清的链路 

 二面以后，考的不是知识，是判断力和排障能力 

 很多人不是不会，是 准备方向错了 ：

 刷了 200 道八股，项目还是讲不清

 简历写满 RTOS/Linux/驱动，一问 probe 失败怎么查就卡住

 五个项目都很浅，没有一个能扛 30 分钟

 所以别再用“题量”骗自己了。嵌入式面试，最后拼的是你能不能像一个真正能进组干活的人。 

 一、第一家就教会我：简历不是越满越好

 我最早一版简历，技能栏写了：

 精通 C、精通 STM32、熟悉 FreeRTOS、熟悉 Linux 驱动、熟悉 UART/SPI/I2C/CAN、熟悉 Bootloader、熟悉 OTA……

 看起来很能打对吧？

 第一家大厂技术面，10 分钟就被问穿了。 

 面试官没为难我，就问了一句：

 “你说熟悉 FreeRTOS，那互斥量和二值信号量怎么选？你们项目里为什么用队列不用全局变量？”

 我答的是定义，不是场景。

 他又追问：

 “你说做过 OTA，那升级失败怎么回滚？pending 写在哪？断电怎么办？”

 我又开始背流程，背不全。

 那次之后我才明白：

 简历不是写给 HR 看的，是写给面试官“找漏洞”用的。 

 我的简历改法

 后来我只保留 1 个主项目深挖 ，技能栏全部降级表述：

 精通 C

 熟练

 熟悉 Linux 驱动

 了解驱动框架，做过字符设备实验

 熟悉 FreeRTOS

 项目中使用 FreeRTOS 做多任务划分

 五个项目并列

 1 个主项目 + 1 个辅助项目

 改完后，投递通过率没明显变，但面试深度对话明显变顺了。 

 因为面试官终于知道该往哪里问了，而我也终于接得住。

 二、笔试没那么玄，但很多人死在“基础不牢”

 我面过的公司里，笔试大概分 3 类：

 1. C 语言 + 数据结构

 最常见。

 链表、字符串、指针、位操作、简单排序，真的会出现。

 2. 选择题大杂烩

 C、OS、计网、MCU、协议、RTOS 混在一起。

 看着散，其实都在考“基础广不广”。

 3. 岗位专业题

 驱动岗会考设备树、内核基础；

 MCU 岗会考中断、DMA、通信协议；

 车载岗会考 CAN、诊断、实时性。

 我踩过的坑

 只刷难题，结果笔试考的是字符串和链表

 只会概念，手写代码一塌糊涂

 把笔试当秋招附属，结果提前批直接挂

 真正有用的准备

 C 语言手写代码必须练 ：字符串、指针、数组、链表

 把 JD 当复习清单 ：写驱动就补 Linux，写 MCU 就补外设和 RTOS

 笔试不要拖到秋招前一周 ，提前批就会考

 三、一面和二面，根本不是同一种考试

 这个是我面了十几家以后才反应过来的。

 一面考什么？

 C 语言基础

 外设/RTOS/Linux 基础概念

 项目是不是你做的

 表达清不清楚

 一面更像：

 “你是不是合格的候选人。”

 二面考什么？

 架构为什么这样设计

 为什么不用另一种方案

 遇到过什么 bug，怎么定位

 如果量产/长期运行，哪里会先出问题

 如果让你重做，你会改什么

 二面更像：

 “你进组以后，能不能独立扛事。”

 我印象最深的一次二面

 面试官听完我项目介绍，只问了 4 个问题：

 为什么 OTA 元数据放 EEPROM，不放 Flash footer？

 为什么 Modbus 线圈保存要异步，不直接在通信回调里写？

 I2C 读失败你们怎么恢复？

 如果现场升级一半断电，系统怎么保证还能启动？

 没有一个问题是八股定义。 

 那一刻我才懂：

 二面不是考你知道多少，是考你有没有真正做过决策。 

 四、项目经历，真的是嵌入式面试的“胜负手”

 我看过很多同学的简历，功能写得很多：

 智能小车

 温湿度采集

 OLED 显示

 蓝牙控制

 超声波避障

 但一问：

 “你负责哪一部分？软件怎么分层？为什么这里用中断不用轮询？掉电怎么办？”

 就卡住了。

 什么样的项目能打？

 我后来总结，能打的项目至少有 4 个特征：

 1. 有分层

 能讲清 APP / 协议 / BSP / 驱动 / 公共模块。

 2. 有闭环

 不只是采集，还至少有通信、存储、升级、异常恢复中的两三项。

 3. 有排障

 你讲过真实 bug，以及怎么定位、怎么修。

 4. 有工程意识

 看门狗、日志、版本管理、掉电保护、总线恢复，至少占一两项。

 我自己的主项目后来只留这个方向

 STM32H7 双核工业控制

 Bootloader + 双分区 OTA + EEPROM 元数据

 Modbus RTU + 线圈掉电保存

 FreeRTOS 多任务 + 以太网升级 + LVGL 显示

 不是因为它多高级，而是因为它能扛追问。 

 五、不同岗位，准备重点完全不一样

 这是我面几十家后最大的体会：

 嵌入式不是一个大类，至少分 3 条主线。 

 1. MCU / RTOS 产品岗

 重点准备：

 C 语言

 中断、DMA、时钟、启动流程

 FreeRTOS 任务与同步

 UART/SPI/I2C/Modbus/CAN

 项目架构和稳定性

 适合：海康、汇川、安克、拓竹、很多工控和消费电子岗。

 2. Linux 驱动 / BSP 岗

 重点准备：

 C 功底

 进程线程、内存、文件系统

 设备树、platform driver、字符设备

 probe 失败排查

 用户态和内核态通信

 适合：华为 BSP、小米底层、龙旗、部分手机/显示公司。

 3. 车载 / 工控 / 通信岗

 重点准备：

 CAN/CAN FD

 通信可靠性

 实时性

 诊断、异常恢复

 有时还会考 C++

 适合：比亚迪、车企供应链、中兴通信底层、部分机器人公司。

 千万别一份简历海投所有嵌入式岗。 

 我早期就这么干，浪费了很多面试机会。

 六、面试官最爱问的，其实不是定义，是“整条链路”

 后来我把高频问题归了类，发现核心就 5 类：

 1. 数据怎么走

 一帧 Modbus 从串口到任务怎么处理？

 SPI 读传感器到界面显示经过哪些层？

 OTA 包从网口到 Flash 怎么落盘？

 2. 为什么这样设计

 为什么用 RTOS，不裸机？

 为什么这里用 DMA？

 为什么参数放 EEPROM，不放 Flash？

 3. 出错怎么办

 通信超时怎么办？

 I2C 挂死怎么办？

 升级失败怎么办？

 任务卡死怎么查？

 4. 并发怎么协调

 两个任务抢 I2C 怎么办？

 中断里能做什么，不能做什么？

 擦 Flash 时别的任务怎么不被拖死？

 5. 量产怎么想

 看门狗怎么配？

 日志怎么做？

 版本怎么管理？

 现场出问题你怎么查？

 能把这五类问题讲顺，面试质感会完全不一样。 

 七、我总结的 7 条“比刷题更重要”的经验

 经验 1：只深挖 1 个项目，胜过堆 5 个浅项目

 每个项目准备 10 个追问 ，比背 100 道题更有用。

 经验 2：简历每个词都要能降级

 扛不住三层追问，就别写“精通”“熟悉”。

 经验 3：八股要背，但必须落到场景

 volatile 不是背定义，是要能说出你们项目里哪里用了、为什么。

 经验 4：准备 3 个排障故事

 通信问题 1 个、死机/复位 1 个、性能/稳定性 1 个。

 二面特别好用。

 经验 5：提前批别等

 7–8 月就开始投，别等 9 月正式批。

 嵌入式很多岗位提前批抢人很明显。

 经验 6：内推 + 官网双通道

 嵌入式内推往往比纯海投更有效，尤其是部门明确招 MCU/驱动/BSP 时。

 经验 7：面完一定要复盘

 不是记题目，是记：

 我在哪一层被问穿？

 是概念、项目、还是岗位不匹配？

 下一次只补一个短板

 八、高频题清单（我面过最多的方向）

 C / 基础

 指针和数组区别

 const / volatile / static 

 栈和堆区别

 大小端

 内存对齐

 任务优先级怎么设计

 优先级反转是什么

 为什么 ISR 里不能调普通 API

 栈溢出怎么发现

 项目 / 工程

 你的项目怎么分层

 为什么选这个通信方式

 OTA 失败怎么回滚

 你遇到过最难的 bug 是什么

 如果重做项目你会改什么

 最后说几句实话

 面了 30 多家之后，我最大的感受不是“题有多难”，而是：

 很多人不是不会嵌入式，是从来没按“面试官视角”准备过。 

 面试官不是来听你背定义的，

 

 他是来判断：

 你是不是真做过

 你有没有工程思维

 你进组以后要不要人一直带

 所以，别再把准备理解成“多刷题、多背八股、多堆项目”。

 真正有用的，是： 

 定方向

 挖透一个项目

 把链路讲清

## 比亚迪嵌入式二面面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-01-31 ｜ [原文链接](https://www.nowcoder.com/discuss/847133979877617664)

前言： 这次比亚迪二面主要围绕嵌入式开发、电动汽车系统和汽车电子相关技术。我在准备过程中，重点复习了BMS、电机控制、SOC估算、CAN通信、OTA升级、功能安全和编码规范等内容。为了顺利应对面试，我把每个核心知识点进行分类整理，并结合项目经验和实际应用进行理解。

 面试题目整理： 

 请详细介绍一下你在项目中遇到的最难的问题，是如何解决的？

 你对AUTOSAR有了解吗？

 CAN总线的报文格式是怎样的？标准帧和扩展帧有什么区别？

 如何保证CAN通信的可靠性？

 什么是OTA？如何实现软件的在线升级？

 请解释一下功能安全ISO 26262，ASIL等级是什么？

 什么是BMS？BMS需要实现哪些功能？

 如何估算电池的SOC？

 BLDC电机的控制原理是什么？

 如何进行嵌入式软件的单元测试？

 你对MISRA C编码规范有了解吗？

 如果让你设计一个电动汽车的充电管理系统，你会如何设计？

 你为什么想加入比亚迪？

 总结： 复盘这次面试，我发现准备的关键是将知识体系化，将嵌入式开发理论、汽车电子原理、BMS功能、SOC估算方法、CAN通信机制、OTA升级流程、功能安全标准和编码规范等整合起来。在准备过程中，我采用了 分类整理、查资料、结合项目实践 的方法，同时把复杂概念简化成易于表述的逻辑链条，以便在面试中能够快速清晰地回答问题。这次复盘让我明确了自己在知识掌握上的薄弱环节，也为后续深入学习嵌入式系统和电动车技术提供了方向。

 准备嵌入式面试八股文就靠这套专栏了（涵盖多个大厂面试题）： https://www.nowcoder.com/creation/manager/columnDetail/mPZ4kk 

 嵌入式开发必备知识总结

 1. 嵌入式系统基础 

 嵌入式系统组成 ：通常包括硬件（MCU/CPU、存储器、外设）、固件/驱动、操作系统和应用层软件。

 嵌入式操作系统 ：熟悉实时操作系统（RTOS）和任务调度机制，了解任务优先级、中断处理、信号量、互斥量等同步手段。

 资源限制意识 ：嵌入式系统常受限于内存、计算能力和功耗，开发时需考虑代码优化、内存管理和效率。

 2. 编程与编码规范 

 C/C++语言能力 ：掌握指针、内存操作、数据类型、结构体、宏定义等，理解硬件寄存器操作和位操作。

 MISRA C ：熟悉嵌入式开发规范，保证代码安全性、可维护性和可移植性。

 单元测试 ：掌握模块级测试方法，验证输入输出及边界条件，确保功能可靠。

 3. 外设与通信接口 

 常用接口 ：GPIO、UART、SPI、I2C、CAN等。

 CAN通信 ：理解报文格式（标准帧11位ID，扩展帧29位ID）、优先级、CRC校验机制、重发机制，保证总线可靠性。

 调试工具 ：熟练使用JTAG、逻辑分析仪、示波器等进行硬件调试。

 4. 控制与算法基础 

 电机控制 ：BLDC、步进电机原理，霍尔传感器和PWM控制，闭环控制思想。

 电池管理系统（BMS） ：SOC/SOH估算、电压/电流/温度监控、充放电控制、均衡管理、保护机制。

 滤波与控制算法 ：卡尔曼滤波、PID控制、电池估算算法等。

 5. 软件架构与标准 

 AUTOSAR ：理解模块化设计、软件组件和RTE接口，适用于大型汽车嵌入式系统。

 功能安全 ：ISO 26262标准，理解ASIL等级及其对软件开发和验证的要求。

 OTA升级 ：理解远程软件升级原理、完整性校验和安全性保证。

 6. 开发流程与项目管理 

 版本控制 ：Git等工具用于管理代码版本和协作开发。

 调试与仿真 ：通过模拟器和硬件在环（HIL）测试验证软件功能。

 性能优化 ：在内存和CPU受限条件下优化代码，提高系统响应速度和可靠性。

 总结 嵌入式开发要求工程师具备硬件理解、软件能力和系统思维。除了掌握C/C++编程、操作系统、通信协议和控制算法，还需熟悉行业标准（如MISRA C、ISO 26262、AUTOSAR）和调试工具。通过系统化学习、项目实践和不断复盘，才能在嵌入式开发中快速成长，解决实际问题。

 一、知识体系构建（6-8周）

 第1-2周：C语言与数据结构

 第5-6周：操作系统与RTOS

 学习FreeRTOS或RT-Thread的基本使用

 理解任务调度、信号量、互斥锁、消息队列

 做一个多任务综合项目（串口+ADC+定时器+RTOS）

 第7-8周：项目复盘与面经刷题 

 深挖简历上的每个项目，准备技术讲解

 遇到过什么技术难点？怎么解决的？

 做过哪些性能优化？效果如何？

 如果重新做这个项目，你会怎么改进？

 ✨ 项目加分项
