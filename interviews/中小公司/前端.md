## 天津上x智x 应用系统开发工程师面经(偏前端开发)

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-11-13 ｜ [原文链接](https://www.nowcoder.com/feed/main/detail/7d3b568017fd49d5b1b01ae4c7553424)

线下面试11/13,中小厂,由笔试,无领导小组讨论和反问组成
笔试部分:
HTML CSS JS 三大件基本功和React/Vue 选择题+简答题

简答: CSS Flex布局 如何实现FlexBox内左侧固定长度,右侧伸缩长度?
虚拟DOM的定义是什么?有什么好处?

编程题:
JavaScript实现数组元素去重
使用React/Vue实现一个简单的双向绑定

无领导小组讨论:
给了40分钟时间讨论出方案,题目如下,个人解读在后面:

请大家互相讨论，协同完成方案设计。
任务目标：面向物料BOM业务，共同输出一套可行的设计方案；
不需要写完整可运行代码，不需要本地部署；
产出物可以是文档文字、表格、流程图、接口清单、页面模块草图；

一、业务背景
制造行业产品BOM（物料清单）：一个成品由多级子件组成，子件还可以继续拆分为下级零件，是无限层级树形结构。
举例：发动机总成 → 缸体组件 → 螺栓、垫片。

业务需求：
1. 输入一个成品物料编码，向下查询该成品完整BOM树，支持逐层展开查看子件；
2. 支持汇总统计底层原材料数量（只统计叶子节点，中间组件不统计）；
3. 支持导出BOM汇总清单；
4. 边界约束：BOM层级很深（可能十几层）；存在循环BOM风险（A包含B，B又包含A）；
5. 支持分页/懒加载，一次性加载全部层级会卡顿、慢。

二、小组分工输出内容（前后端对齐）
后端牵头：
- BOM树形数据数据库存储方案
- 查询方案（递归查询 / 预计算 / 路径字段等）
- 循环BOM怎么识别、拦截
- 底层物料汇总逻辑
- 接口清单、入参、返回结构
- 大数据量、深层级的性能优化思路

前端牵头：
- BOM树形页面模块、交互：展开/折叠、懒加载、勾选、汇总面板
- 树形组件数据结构设计
- 导出功能交互、加载状态、报错提示
- 异常场景展示：循环BOM告警、查询超时、物料不存在

双方必须对齐：树形返回JSON结构、错误码、异常提示文案。

三、必须产出清单
1. BOM数据库表结构设计（表名、核心字段）
2. BOM查询、底层物料汇总的业务流程
3. 循环BOM识别方案、拦截策略
4. 深层级BOM性能风险与优化方案
5. 后端接口清单（请求方式、入参、返回示例）
6. 前端页面模块、交互逻辑
7. 识别当前方案风险点，以及未知问题如何解决

四、时间安排
总讨论设计时间：40分钟
时间到之后，小组安排汇报（5~8分钟）；汇报结束面试官随机抽组内任意成员进行提问。

五、评分说明
评分不看方案是否完美，重点考察：

是否准确理解需求，不多做无关功能，不漏核心需求；
前后端之间能否对齐数据结构、达成一致；
方案是否简单合理，不做过度复杂设计；
小组每个人是否参与讨论，共同贡献想法；
能不能识别风险，清晰表达思路。

个人思路:
后端MySQL建表,使用parent_id,layer,结合id,code索引,构建树状数据字段,并在入库阶段就计算好叶子结点,层数等相关信息,MongoDB保存物料的唯一的JSON作为信息来源,查询使用异步查询.
前端需要注意树形结构渲染,使用ElementPlus结合业务需要改造,懒加载并约束每次显示的DOM数量,对较大数量的BOM的预览场景则采用Canvas,递归查询设置报警,前端使用Push API实现浏览器原生的异步查询/导出任 #牛客AI配图神器# 务的提醒.

后记: 前端的好处也不是没有,来面试的同学就我一个前端...

 2. map与普通对象的区别

 因为提到了Map这种数据类型，于是就问了一下Map和普通对象的区别。

 这里我只回答到了Map的键可以是任意类型而Object的键只能是字符串，并且Map可以迭代Object不行。

 所以请看一下Map和Object的详细差别吧：

 1. 键的类型

 
 Map : 键可以是任意类型，包括对象、函数、基本类型等。

 Object : 键只能是字符串或 Symbol，其他类型会被自动转换为字符串。

 
 2. 大小获取

 
 Map : 可以通过 size 属性直接获取键值对的数量。

 Object : 需要手动计算属性数量，例如使用 Object.keys(obj).length 。

 
 3. 性能

 
 Map : 在频繁增删键值对的场景下性能更好，因为它是专门为这种操作优化的。

 Object : 在频繁增删键值对的场景下性能较差，因为它不是为这种操作优化的。

 
 4. 默认键

 
 Map : 没有默认键，只包含显式插入的键值对。

 Object : 有原型链，可能包含一些默认的属性和方法（如 toString 、 hasOwnProperty 等），可能会与自定义键冲突。

 
 5. 序列化

 
 Map : 不能直接使用 JSON.stringify 序列化，需要手动转换为数组或其他格式。

 Object : 可以直接使用 JSON.stringify 序列化。

 
 6. 迭代

 
 Map : 可以直接使用 for...of 循环迭代，或者使用 forEach 方法。

 Object : 需要使用 for...in 循环（注意会遍历原型链上的属性），或者使用 Object.keys 、 Object.values 、 Object.entries 等方法。

 
 7. 原型链

 
 Map : 没有原型链，不会继承额外的属性或方法。

 Object : 有原型链，可能会继承一些不期望的属性或方法。

 
 3. vue中能实现数据响应的api

 vue中能实现数据响应的api，有watch和computed，ref和reactive。

 4. ref 与 reactive 的区别

 ref与reactive的区别，首先第一点，ref可以包装基本类型和引用类型，reactive只能包装引用类型。第二点，ref取值要用.value，而reactive可以直接访问。

 第三点，ref解构后仍然保持响应性，因为解构的是 ref 对象。

 const count = ref ( 0 );
 const { value } = count; // 仍然具有响应性 
 
 而reactive解构后会丢失响应性，因为解构的是普通对象。如果需要解构并保持响应性，可以使用 toRefs 。

 const state = reactive ({ count : 0 });
 const { count } = state; // 失去响应性 
 const { count } = toRefs (state); // 保持响应性 
 
 5. object.defineProperty 和 proxy 的区别

 1. 功能范围 

 
 
 Object.defineProperty :

 
 只能拦截对象属性的读取（ get ）和设置（ set ）。

 只能对 已知属性 进行拦截，无法拦截新增属性或删除属性。

 适用于对单个属性的精细化控制。

 

 
 Proxy :

 
 可以拦截对象的多种操作，包括属性读取（ get ）、设置（ set ）、删除（ deleteProperty ）、枚举（ enumerate ）、函数调用（ apply ）等。

 可以拦截 未知属性 的操作，支持动态属性的拦截。

 功能更强大，适用于对整个对象的全面控制。

 

 
 2. 使用方式 

 
 
 Object.defineProperty :

 
 需要针对每个属性单独设置拦截器。

 修改对象的现有行为，而不是创建一个新对象。

 

 
 const obj = {};
 Object . defineProperty (obj, 'name' , {
 get ( ) {
 console . log ( '读取 name 属性' );
 return this . _name ;
 },
 set ( value ) {
 console . log ( '设置 name 属性' );
 this . _name = value;
 },
});
obj. name = 'Alice' ; // 设置 name 属性 
 console . log (obj. name ); // 读取 name 属性 
 
 Proxy :

 
 创建一个代理对象，拦截对目标对象的所有操作。

 不修改原对象，而是返回一个新的代理对象。

 
 const target = {};
 const proxy = new Proxy (target, {
 get ( obj, prop ) {
 console . log ( `读取 ${prop} 属性` );
 return obj[prop];
 },
 set ( obj, prop, value ) {
 console . log ( `设置 ${prop} 属性` );
 obj[prop] = value;
 return true ;
 },
});
proxy. name = 'Alice' ; // 设置 name 属性 
 console . log (proxy. name ); // 读取 name 属性 
 
 3. 拦截操作 

 
 
 Object.defineProperty :

 
 
 仅支持 get 和 set 拦截。

 
 无法拦截以下操作：

 
 属性的删除（ delete ）。

 属性的枚举（ for...in 或 Object.keys ）。

 新增属性。

 

 

 
 Proxy :

 
 
 支持多种操作的拦截，包括：

 
 get ：读取属性。

 set ：设置属性。

 deleteProperty ：删除属性。

 has ： in 操作符。

 ownKeys ： Object.keys 、 for...in 等。

 apply ：函数调用（当代理目标是函数时）。

 等等。

 

 

 
 4. 性能 

 
 
 Object.defineProperty :

 
 性能较好，适合对少量属性进行拦截。

 但如果需要对大量属性进行拦截，代码会变得冗长且难以维护。

 

 
 Proxy :

 
 性能略低于 Object.defineProperty ，因为需要处理更多的拦截操作。

 但在需要拦截多种操作或动态属性的场景下， Proxy 的性能优势更明显。

 

 
 7. ref 与 reactive 的实现原理

 
 reactive 是借助proxy的代理作用，代理该引用类型的属性，当该属性被读取值时，返回该属性的值并且为该属性添加副作用函数；当该属性被修改值时，触发掉该属性的副作用函数

 ref既可以代理原始类型也可以代理引用类型，当代理的是引用类型时，返回的是一个RefImpl的实例，通过类身上的get和set属性去读取值和修改值；当代理的是引用类型时，其实走的还是reactive的调用机制。

 
 8. 聊一聊webpack 和 vite

 1. 工作原理 

 
 
 Webpack :

 
 采用 打包 机制，将所有模块打包成一个或多个 bundle 文件。

 开发模式下使用 webpack-dev-server 提供服务，通过热更新（HMR）实现快速开发。

 Vite :

 
 采用 基于浏览器 ES 模块 的开发模式，直接利用浏览器加载模块。

 开发模式下使用原生 ES 模块，按需加载文件，无需打包。

 生产模式下使用 Rollup 进行打包，生成优化的静态文件。

 

 
 2. 开发体验 

 
 
 Webpack :

 
 开发模式下，随着项目规模增大，启动时间和热更新速度可能变慢。

 配置复杂，尤其是需要处理多种资源类型时。

 

 
 Vite :

 
 开发模式下启动速度极快，因为不需要打包，直接按需加载文件。

 热更新速度更快，因为只更新修改的模块。

 配置简单，开箱即用。

 输出结果是什么？

 13. 代码题

 async function fn ( ) {
 return 1 
}

 fn (). then ( console . log )
 
 结果会输出1，这是因为：

 
 
 async function fn() :

 
 async 关键字用于定义一个异步函数。

 异步函数会自动返回一个 Promise 对象。

 在函数体内， return 的值会被包装成一个 resolved 状态的 Promise 。

 

 
 return 1 :

 
 这里的 return 1 相当于 return Promise.resolve(1) 。

 即使返回的是一个普通值（如 1 ）， async 函数也会将其包装成一个 Promise。

 

 
 fn().then(console.log) :

 
 fn() 调用异步函数，返回一个 Promise。

 使用 .then() 方法处理 Promise 的 resolved 值。

 当 Promise 成功解决（resolved）时， then 中的回调函数 console.log 会被调用，并接收 resolved 的值（这里是 1 ）。

 

 
 14. 代码题

 function fn ( ) {
 return new Promise ( ( resolve ) => {
 resolve ( 1 )
 }). then ( () => 2 )
}

 fn (). then ( console . log );
 
 输出结果是2.

 
 
 new Promise((resolve) => { resolve(1); }) :

 
 创建一个新的 Promise 对象。

 在 Promise 构造函数中，立即调用 resolve(1) ，将 Promise 的状态设置为 resolved ，并将值 1 作为 resolved 值。

 

 
 .then(() => 2) :

 
 then 方法用于处理 Promise 的 resolved 状态。

 这里的回调函数 () => 2 会接收上一个 Promise 的 resolved 值（即 1 ），但并没有使用它。

 回调函数返回 2 ，这会成为新的 resolved 值。

 

 
 fn().then(console.log) :

 
 调用 fn() ，返回一个 Promise。

 这个 Promise 的最终 resolved 值是 2 （由 .then(() => 2) 决定）。

 then(console.log) 会将 2 打印到控制台。

 算法肯定都会考，只不过看岗位吧，如果是后端可能基本都是考的算法题，而且难度较大；前端岗位的话，有些公司可能会出一些前端场景题（ 拼多多三道都是、腾讯音乐只有一道，SHEIN只有一道 ），然后剩下的算法题难度相对简单（ 相对后端来说 ）；但是也有些公司不分前后端，前后端都是一份试卷（ 携程 ）。

 
 所以，笔试还要好好做的，不然可能就会出现没有面试机会的情况，可能前一两次会紧张，后面做多了就习惯了，可能也不会发挥失常，编程题一般是按通过率来计算的，如果没有通过全部的测试用例，但是通过大部分的测试用例，也是有分的，所以不要在一道题上消耗太多时间，而且尽量通览一边题目，选有思路的题开始做，第一道题不一定是最简单的，这里作者就不得不提一个老六了（ tx音乐，把最难的放第一题，最简单的放最后一题 🤪），然后其实不用太紧张，有些考试可以使用本地IDE编写然后复制代码的，有些则不允许切出去，这个一定要看清楚，不然就会被判定为作弊，得不偿失。这里又要不得不提一下，每个厂的编程IDE可能不一样，尽量提前熟悉一下，别像作者一样，花了5分钟在考试的时候熟悉，而且有些厂的编程题是ACM模式（ 自己构造输入输出 ），有些是核心代码模式（ 类似LeetCode那样 ），而且错误用例不会显示，所以平时联系的时候也要养成这个习惯，可以用 牛客 进行练习。

 通过笔试后就是面试，面试每个人可能会有或多或少的紧张，这是很正常的，但是一定要摆正姿态，就当和面试官进行技术交流，这样可能就不会太紧张了，而且尽量面试前一小时不要看资料吧，这样会越看越紧张的，除非确实有重要的知识点没有记忆。还有注意点是，一定要找一个自己熟悉的环境面试，比如寝室里，或者实验室附近，因为熟悉的环境会让自己放松，从而更好得发挥出自己原本的水平，然后面试中肯定会要求手写代码，这个肯定和平时自己写代码不一样，因为会有面试官看你写，这肯定会紧张，所以平时一定要多多练习，如果平时都不能熟练得写出来，那么在面试的时候肯定更加难以完成，因为有时候会出现大脑空白的情况（ 作者自己就出现过 ），但是相比于后端， 可能前端岗位的手写题可能更倾向于实现某个需求（ 控制并发数 ）或者手写实现某个API（ reduce、Promise.all ）或者就是LeetCode的简单或者中等题了 。

 第一轮技术面大概率问基础知识，或者结合一点项目问；第二轮技术面大概率就以项目为主了；第三轮可能就看面试官心情了，因为第三轮一般都是大leader。平时的话可以看看基础知识点或者面试题，看多了几本被问到起码不会什么都说不上来，如果一时说不上来，也尽量和面试官说出你思考的过程，起码不会冷场，而且有的面试官也会提示你等等，这个面试也看运气的，哈哈 😀。过了技术面，就是HR面了（ 目前的就百度没有HR面 ），一般就问点基本信息，个人的优缺点，岗位的匹配度，个人的竞争力，校园经历，对面试的岗位的了解程度等等，这个看HR自己发挥吧。

## 2023前端求职经历回顾及面试题总结

来源：掘金 ｜ 类型：面经 ｜ 发布：2023-03-18 ｜ [原文链接](https://juejin.cn/post/7211775653166219323)

前言

 2022-2023 年是IT行业受到严重冲击的一年，行业情况是：多个公司裁员，很多员工失业……市面上各种人才，大厂出来的、机构出来的、公司倒闭的等等，找工作变得格外漫长。

 
随着2022 年年底疫情放开，各大公司经济正在恢复，但是坑位却很少，甚至没有。一些大厂甚至不招人，只裁人，“僧多粥少”的局面特别严重。这里引用当时任先生的一句话： “把活下来作为最主要纲领，边缘业务全线收缩和关闭，把寒气传递给每个人。” 

 慢慢地，熬过了冬天。2023 年的春节之前，几乎没有公司招人，直到 2023年2月10日 左右，春节后的两周，招聘软件上开始涌现出一些公司， 搜索结果列表明显增多：一些年前未曾看到的公司名字冒出来了。 是有真正在招人的，也有的只是为了打公司知名度，挂着招聘不理人的。（这种不要花时间在它上面）这是好的现象，但是，目前市面上竞争者仍然很多，换句话说，就是：一个岗位，简历很多。 我们要做的就是：充分准备，出类拔萃！ 

 一、求职经历

 本博主是2022年底被某个大厂裁员的，因此从年前看到了年后，期间回家过了个年。还在准备自己的某个考试。对于这场裁员，我其实是在等着的，先前的工作环境压力很大，工作气氛及其严肃，身体也有些变化。大礼包谁不想拿？只是这份礼包给的时机，作为员工，我们想不到。来了也挺好，因此，本博主完美避开了公司大面积感染阳性的危险，至今从未阳过！^_^

 行情不好，着急就业的话其实可以很快，但是给的都是平薪或微涨，从大公司到小公司都是这个样子，心气再高也得向行情低头。我有前同事找了半年的工作，据说2022年下半年基本没有面试机会。好在我这位同事最近也拿到了满意的offer！从猎头以及一些HR那边得到消息： “今年基本就是这个样子，大厂出来的也不好找工作，给的薪资基本都是平的，着急的即使是小公司也去了。” 所以，我这里，本来可以早就业，但是心里想达到期望的薪资范围，于是又拖了快一个月…… “相差不大的薪资水平下，选一个更好的发展平台” 成了我最终的决策，现在在阿里旗下的某公司工作。当然，有行业内的同学，“骑驴找马”，自己又有实力，跳槽涨薪是可以达到正常水平的！

 本博主是一位女生，但是还年轻，单身未婚，这一点可能也有优势。用其中一位HR的话说：“相比那些工作时间更久的，你认为自己怎么样？”，当时我是在面试，没想太多，只是简单说了几句。后面反思，这或许就是HR在拿我与其他人对比，是我表现自己优势的机会。当然，公司招人，需要的是技术能力！我面试的是高级前端开发工程师（期间不小心面了个前端专家，面试中才知道对方招的职级，阿里某部门）。还有面试官认为我很优秀的，但是薪资是个大问题……难啊！这时代，这行情，不易！

 确定工作后，我们组急招人，好不容易拿到HC（坑位），是 Java 后端岗位的，我们领导鼓励下属帮忙内推。于是我又开始从市面上捞人，发现简历真的很多……但是更多的是30岁以上的，这里对年龄没有偏见，只是客观描述一下现象，可能是有公司又裁员了吧。据一位应聘者说，他回家半年多，照顾家里，先前还有不错的机会，没有去，现在已经找不到工作了。期间我也有帮其他组内推，但是结果是：被刷掉的居多……当然，年轻又有能力的，特别棒！背景好能力强的不愁工作，相信自己！

 获取服务器所 支持的所有 HTTP 请求方法
