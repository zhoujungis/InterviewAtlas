## 【面经】【小厂zlrs】 AI Agent 工程师 一面

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-09-11 ｜ [原文链接](https://www.nowcoder.com/discuss/927944523437674496)

真题清单 & 参考回答

 1. 开场意向：你偏后端工程师，还是偏 Agent 工程师？ 

 参考回答：直接答"偏 Agent"**并补一句理由（"想做端到端 AI 产品、辞职也是为深耕这个方向"）

 2. 运维 agent 面向多少人？怎么部署的？ 

 参考回答： ToB 私有化叙事 ——不是内部工具，是卖给运营商的产品（移动/联通/电信）；客户采买后由我们同事 部署到客户内网，模型也部署在内网 （数据不出客户环境）。

 3. 两套 agent（AI 代码助手平台 vs 运维 agent）底层 runtime 是同一套吗？ 

 参考回答： 不是，两套架构 ——代码助手平台集成开源和内源的agent的SDK（OpenCode/OpenClaw）， 不单独维护 agent loop ，自己做的部分是前端会话交互 + MCP 服务器开发 + skill体系；运维 agent 是 自研 ReAct loop + 工具注册/调用（内部 API/脚本/命令）+ 记忆系统 + RAG 。

 4. 运维 agent 的 memory 模块怎么设计的？ 

 参考回答：记忆系统分为 长期/短期/外部 记忆

 长期 = 从对话提取的产品的事实global、用户偏好user、处理过的故障情景Episodic三类，做语义的向量化存储；记忆的存储是通过规则+llm提取，检索是通过关键词+相似度混合检索。

 短期 = 用户消息/AI 消息/工具调用过程。短期记忆设置有 token 预算 ，达到预算的 90% 触发 map-reduce 压缩 、保留最近 3 轮对话历史。

 外部=根据产品文档，操作指导书创建的知识库，已经筛选沉淀的运维经验库。

 5. 代码助手集成了 SDK，里面记忆有二次开发吗？ 

 参考回答：内核的记忆能力 用 SDK 自带 的，opencode sdk的自动上下文压缩和记忆持久化存储，二次开发内核的收益比较低，所以除了定制插件做遥测采集，没有二次开发。

 我们主要做的是会话记忆的平台化—— 三层会话存储 ：zustand 内存态（SSE 高频流式先刷内存保证 UI 连续渲染）→ 浏览器 IndexedDB（存多会话历史）+ sessionStorage（当前会话快照、防刷新秒开）→ SQLite 落盘（会话空闲/结束时，供重登/跨端拉历史）。

 6.（开放性）runtime 里如果有 500~800 个 skill，怎么管理、保证上下文健康、一次调用命中该命中的？ 

 参考回答：任何一轮决策时，skill的个数都不要超过10个，候选越多，选错的概率就越多。主要从一下两方面提高skill的使用质量：

 提高命中方面： 做分层路由，将每个skill的元数据存储起来，包含名字、描述、触发词、标签等，在拼接上下文时，1）首先做规则映射，按使用场景分类分级，通过关键词、触发词命中，做粗筛；2）可以通过混合检索双路召回再做RRF融合，得到最小集后，将name、desc进入上下文给LLM做选择

 治理与保证质量： 1）skill的描述是命中的基础，可以通过描述中预埋检索关键词来保证skill的路由正确，规范的命名与描述（做什么，使用场景，什么场景不用）来保证命中正确；2）相关skill可以做合并，命中后再在子集中展开；3）低频、废弃的skill不进路由池，新增skill要保证不影响原有命中率；4）通过数据飞轮持续迭代优化 description

 7. 底层 opencode 的 memory 模块是怎么设计的？ 

 参考回答 ：采用的是 opencode 原生的记忆能力 

 1）指令层，用的AGENTS.md，分为全局的和项目级，且兼容CC的CLAUDE.md做兜底。这部分是跨会话的记忆，每次都要拼到system prompt中。

 2）会话层，采用SQLite持久化存储，按照session隔离，包含session、message、part、event等

 3）压缩层，默认会话上下文达到阈值触发压缩，根据配置的保留token或者turn，进行head和tail的切分，对head进行增量压缩；支持配置裁剪，会扫描旧的工具输出，发给大模型时占位符标记，从而减少token占用

 8. Skill 的自我优化/自我演进，一般怎么设计？（全场最大空白） 

 参考回答 ：

 1）复核与淘汰：skill 注册中心加两个计数字段——每次 skill 被调用，从执行结果反推 helpful / harmful（处置成功且流程吻合 → helpful+1；miss 分析里被选错或误导 → harmful+1）。长期 harmful 占比高的 skill 自动降权、移出候选池，并进入人工复审队列。

 2）给 skill 调用埋点——命中哪个、任务是否完成、结果被采纳还是被纠错/回退；对话结束后，根据轨迹产出skill path：诊断报告 + 定位到具体 skill 的具体章节 + ADD/UPDATE/REMOVE 补丁。（重写的话llm倾向于删细节保简洁，往往效果更差）。补丁要过两道闸门才生效—— 评测集回归 ，使用skill命中评测集，保证补丁不能劣化任何已有命中+ HITL 审核 。通过后版本化上线，旧版标记后保留，审计记录使用的版本。

 3）批量归纳：参考 Trace2Skill 的做法，定时任务扫描案例记忆，把 多次相似失败 批量归因——“最近 20 次 XX 集群磁盘告警处置，15 次都在同一步走错”，一次改写，而不是逐条打补丁，多条轨迹都踩得坑写成通用规则，偶发情况丢弃。

 9.（前沿敏感度）Pi Agent / Hermes / DeepSeek Harness 这些有了解吗？ 

 参考回答 ：可以讲 Pi Agent 的极简设计、Hermes的自进化闭环、CC的基建（比如三级压缩机制）、DSH的插件模式。总之要有自己对某一块设计的理解。

 10. OpenClaw 和 OpenCode 的区别？ 

 参考回答 ：对"两个相近框架差异"的题，先 锁定比较维度 再作答

 定位： OpenClaw是AI执行网关，目标是在通信软件中发一句话，agent就在电脑上整理文件、跑脚本，开发场景是它的众多场景之一；opencode是纯粹的编码agent，对标cc，所有设计都是围绕读懂代码、改代码、跑测试这条链路。

 架构： openclaw是星型网关架构，一个gateway守护进程18789常驻后台，负责消息路由、会话隔离；opencode是C/S架构，agent内核跑在本地server里，tui是其中一个客户端，桌面应用、ide插件都能连同一个server，可以跑在服务器上。

 记忆系统： OpenClaw记忆以纯md存在本地，每次对话主动加载；检索用向量语义+BM25混合方式，上下文快满时会在压缩前出发memory flush；OpenCode的记忆是会话级的，使用sqlite进行存储，摘要压缩+可选修剪。

## 计算机视觉算法实习生面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2022-03-15 ｜ [原文链接](https://www.nowcoder.com/discuss/353159342998364160)

基本情况 

 本硕中等985，不是CS也不是自动化电子信息等强相关专业，去年3月开始转码，期间一段3个月小公司实习，一段6个月造车新势力实习（少卿带队 🤪，虽然不咋见到但是少卿yyds ），一段kaggle比赛经历（非top），一个个人小项目，无论文。

 投简历：字节，腾讯，阿里，京东，商汤，小米，百度。其中百度和小米沉了，商汤最开始由于我的海投行为，简历被一个部门锁了，但又不约面试，另一个部门没法进流程，涨教训了......后来锁简历的部门还是约了，但没想到是场KPI面试......

 面试结果：字节（一志愿一面挂，转部门offer）， 阿里云（发帖时刚约HR面，据内推的人说基本上稳了）， 腾讯（流程慢，发帖时还在录用评估，而且据说PCG要大裁员 🤣 ），京东（offer），商汤（一面KPI挂）。

 吐槽 

 1. 京东的发offer流程，一定需要导师同意，签字，才继续下一个流程（现在真的还有导师同意的实习么......凤毛麟角吧......）

 2. 还有腾讯的流程是真的慢，当然也有可能是没hc了......

 3. 怎么年初就开始KPI了.....

 经验总结 

 1. 关于简历 ：从面试经历来看，个人觉得，至少在我这个行业，面试官喜欢问的还是简历上的东西，不管哪家公司，所以尽量做到对自己简历上写的东西烂熟于心，还有就是，咱们程序员的简历排版整整齐齐就可以了，一定不要花哨......

 2. 关于八股文：其实在CV领域，八股文是真的不少。 三大领域分类检测分割的 经典的模型和方法，每年优秀的新模型和方法，再加上现在大火的transformer在视觉三大领域的花样百出，让人应接不暇，各种loss，各种优化器，各种激活函数，各式各样的池化层，卷积层，BN层，各种注意力机制，各种后处理方法，甚至各种机器学习方法...... 但其实，面试里面直接问你某某东西的原理其实并不多，特别是新的东西，偶尔直接问原理也是针对比较经典或者比较基本的东西来问的，比如BN原理和作用，梯度消失的原因和解决办法，分类resnet，mobilenet的发展，目标检测yolo系列的发展，分割deeplab系列的发展等等，都是属于很经典的，必须要学会的东西。而根据我的经验，大多数情况下，基本上是先问你简历上写的东西，你答的时候提了一嘴，然后面试官恰巧听到了，然后追问。比如我在介绍成果的时候说我用了某某方法缓解了类不平衡问题，涨了多少点，那么面试官很有可能就会问你，为啥要用这种方法，这种方法解决类不平衡的原理是什么，还有没有什么其它解决方法。

 3. 关于语言：这个行业在我看来，python和C++都是必备的，python需要比较熟悉，能够写写基本模型以及train，infer，eval代码和胜任各种数据处理工作，因为说白了这个行业是在和数据以及模型打交道，c++的话因为在模型部署的时候需要用到，可能会基本的stl和一些基本的数据类型和语法概念，比如类，成员函数和成员变量，重载和重写，构造函数和析构函数，虚函数，虚指针和虚表，static，const等等就差不多了，个人觉得智能指针CV这个行业不需要掌握，了解了解就可以了，面试也几乎不会问，而事实上据我了解智能指针一直被诟病，估计写C++后端的人用的也不多......

 4. 关于算法题：怎么说呢，对于大多数公司来说，实习的话基本上能写个大概或者能讲到面试官想要的思路，基本就不会在算法题卡你，当然字节除外（毕竟出了名的算法题一票否决权），对于秋招，听学长说是几乎所有公司，只要没a出来，基本等于凉凉。准备的话，我认为leetcode 剑指offer+top100够了，毕竟学的还是思路，可以背模板，但不要死记硬背题目，需要理清思路，毕竟不排除面试的时候面试官现场编题，有多余时间的话可以去codetop上针对性做做题。另外，我不知道为啥我面试的时候老是遇到那种pytorch或者深度学习的算法题，比如手撕BN，NMS，随机梯度下降，简单卷积操作，简单池化操作，IOU计算（单个和batch）等等这些......这个大家也需要注意，平常也需要练习......

 5. 关于智力题：这个我没咋遇到，这次除了字节给了个，我个人对这类题没啥经验，就不写了......

 6. 关于面试：保持心态，平和对待，不要高高在上，也不要卑躬屈膝，大家都是一样的打工人，都是从学校走出去的，都经历过校招阶段。

 
 

 
 

 最后，写写面经攒攒人品吧，全都是面试结束后凭借短暂的记忆写的，有可能不全哈，然后祝愿自己今年秋招顺利，KPI面试远离我，也祝大家炼丹顺利，今年秋招大捷。
