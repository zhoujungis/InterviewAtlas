1. 之前做过哪些驱动开发？

 （结合实际项目举例，突出技术栈和解决的问题）

 

 “主要做过几类驱动开发：

 
 字符设备驱动：如按键、LED、蜂鸣器，基于GPIO子系统实现，通过input子系统上报按键事件，支持中断触发；

 总线设备驱动：I2C接口的温湿度传感器（SHT30）、SPI接口的显示屏（OLED），适配设备树，实现设备探测、数据读写逻辑；

 外设驱动：UART串口驱动（调试用）、RTC实时时钟（DS3231），解决过时钟同步和中断冲突问题；

 虚拟设备驱动：模拟一个字符设备用于进程间通信，通过ioctl提供控制接口。开发中涉及设备树配置、中断处理、下半部机制（workqueue）、sysfs接口封装等。”

 3. 复位高低电平不一样，怎么处理？

 复位信号有“高电平有效”和“低电平有效”，处理方式：

 
 设备树中声明极性 ：通过属性指定复位电平，例如：

 驱动中适配 ：解析设备树属性获取极性，复位时输出对应电平：高电平有效：复位时gpiod_set_value(reset_gpio, 1)，结束后拉低；低电平有效：复位时gpiod_set_value(reset_gpio, 0)，结束后拉高。

 复用通用函数 ：使用内核 gpiod 接口（如 gpiod_set_active_low ）自动处理极性转换，无需关心硬件电平细节。

 5. 如何给应用层封装这些功能？

 通过 标准文件接口 或 sysfs/procfs 暴露功能，步骤：

 
 字符设备接口 ：注册字符设备（cdev_add），创建设备节点（如/dev/sensor）；实现open/read/write/ioctl回调：read返回传感器数据，ioctl控制设备（如启动/停止采集）。

 sysfs接口 ：通过device_create_file创建属性文件（如/sys/class/sensor/enable）；应用层通过cat/echo读写属性，驱动中实现show/store回调处理。

 接口规范 ：定义清晰的文档（如 ioctl 命令码、数据格式），处理错误码（如 -EINVAL ），确保应用层易用。

 
 6. 数据是直接写到外部flash？flash是内部还是外部？每次重启都要写？

 
 内部vs外部flash ：内部flash：芯片内置（如MCU的片上flash），容量小（KB~MB级），适合存bootloader、内核；外部flash：独立芯片（如SPI Nor、eMMC），容量大（MB~GB级），适合存应用数据、配置文件。

 是否直接写入 ：通常通过文件系统（如JFFS2、UBIFS）操作，而非直接写物理地址（避免管理坏块、磨损均衡）。

## 小鹏嵌入式软件开发二面 面经

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-07-16 ｜ [原文链接](https://www.nowcoder.com/discuss/907176079079526400)

1. 你们如何设计“一版应用适配多块板卡/多 SoC”，保证复用，同时不影响启动时间和实时性？

 
 先把软件拆成三层：板级移植层（引脚、时钟、外设基址、DMA）、芯片适配层（同系列 IP 差异）、业务层（状态机、诊断、通信策略）。

 业务层只依赖稳定接口，不直接碰寄存器；板级差异用配置表/设备树/代码生成处理，少写大片 #ifdef 。

 启动只初始化本板必需外设，非关键驱动延后或按需加载，避免多板兼容把启动拖慢。

 实时任务固定周期和优先级，换板只改驱动实现，不改控制环节奏。

 多板跑同一套门槛测试：启动时间、控制抖动、通信丢包，不达标就不合入。

 
 2. Linux 字符设备驱动里，数据怎么安全交到用户态？ read/write 、 mmap 、 ioctl 分别适合什么场景？

 
 read/write ：适合报文、日志、小配置；语义清楚，能阻塞/非阻塞，但高频大数据拷贝开销大。

 mmap ：适合连续大缓冲，比如采集环缓、帧数据；用户态直接访问映射内存，减少系统调用和拷贝。

 ioctl ：适合控制命令，比如起停、改模式、查询状态，不适合传大批量数据。

 常见做法是控制走 ioctl ，数据走 mmap 环缓，再用 poll/epoll 通知可读可写。

 要注意缓存一致性、多进程同步，以及进程退出后映射和缓冲的生命周期。

 
 3. DoIP 相比传统 CAN 诊断主要解决什么？如果做 DoIP 网关，连接管理怎么设计？

 
 DoIP 用车载以太网承载 UDS，带宽更高，更适合大数据量诊断和刷写。

 网关核心是三件事：逻辑地址路由到目标 ECU、TCP 会话管理、多诊断仪并发时的资源控制。

 连接流程一般是车辆识别、Routing Activation，再进入诊断会话。

 用 TCP keepalive 和应用层超时做保活；断线或异常退出时释放会话、回退状态。

 刷写期间按策略关闭非必要通信、抑制部分 DTC，降低总线干扰和误报。

 
 4. 多进程里为什么不用纯消息队列，而引入共享内存？怎么保证一致性和防止脏读？

 
 消息队列适合命令和事件；共享内存适合高频、大块数据，拷贝更少。

 常用环缓：单写多读时给每帧加序列号，读端校验序号变化，避免读到写到一半的数据。

 或者用双缓冲：写完再切换活跃页，读端始终读已完成的那一页。

 临界区尽量短；控制热路径优先无锁或轻量同步，必要时再加互斥。

 共享区放版本号字段，结构体变更时新旧进程可以识别不兼容。

 
 5. AUTOSAR 里 DEM 和 DCM 分别做什么？传感器超时从检测到能用 UDS 读出，链路怎么走？

 
 DEM 负责故障事件：检测使能、防抖、状态位、DTC 存储和冻结帧。

 DCM 负责诊断通信：解析 UDS、管理会话和安全访问，再调度到 DEM 等模块。

 应用或驱动发现超时后调用 Dem_SetEventStatus 。

 DEM 防抖通过后更新 Failed/Confirmed 等状态，必要时联动 FiM 做功能抑制。

 诊断仪发读 DTC 请求（如 ），DCM 查询 DEM

 2. 嵌入式里环形缓冲区和链表有什么区别？各自适合什么场景？ 

 答：

 
 环形缓冲区 固定大小数组 + 头尾指针，内存连续，无动态分配入队/出队 O(1)，内存占用可预期适合串口 DMA 接收、CAN 报文缓存、ADC 采样等定长、高频、实时场景

 链表 节点动态分配，长度灵活，但有碎片和指针开销适合长度不确定、频繁增删的场景MCU 上要谨慎使用 malloc

 选型原则 中断与任务之间传数据 → 优先环形缓冲区汽车电子更倾向静态分配，避免运行时内存不确定

 一句话 ：环形缓冲区是嵌入式最常用的生产者-消费者模型；链表更灵活，但不是 MCU 首选

 
 3. 如何判断环形缓冲区满或空？为什么有的实现会浪费一个槽位？ 

 答：

 
 空判断 ： head == tail ，表示无数据可读

 满判断（两种常见方式） 浪费一个槽位：(tail + 1) % size == head 时为满，实际可用容量为 size - 1计数器法：维护 count，满时 count == size，空时 count == 0

 浪费槽位的原因 ： head == tail 无法同时表示满和空，必须额外区分

 计数器法的代价 ：不浪费空间，但多一次读写和同步开销

 工程注意 多生产者/多消费者需加锁或关中断保护单生产者单消费者（如 UART DMA + 解析任务）可做无锁实现

 
 4. FreeRTOS 中优先级反转是什么？举一个三任务例子，并说明如何解决。 

 答：

 
 定义 ：低优先级任务持有共享资源，高优先级任务等待该资源，中等优先级任务抢占低优先级，导致高优先级被间接阻塞

 三任务例子 任务 H（高优先级）：要访问 SPI 总线，试图获取互斥锁任务 L（低优先级）：已持有 SPI 互斥锁，正在传输任务 M（中优先级）：不访问 SPI，但抢占了 L 的 CPU 时间结果：H 等 L 释放锁，L 被 M 抢占无法执行，H 实际被 M 间接阻塞

 解决方案 优先级继承：L 持锁期间临时提升到 H 的优先级，M 无法抢占 LFreeRTOS Mutex（xSemaphoreCreateMutex）默认支持优先级继承

 常见错误 ：用二值信号量代替互斥锁，无优先级继承，高优先级可能长期等待

 
 5. 任务上下文切换时，系统具体保存和恢复了哪些内容？ 

 答：

 
 触发条件 更高优先级任务就绪当前任务阻塞（等信号量、延时等）或主动让出时间片耗尽（若开启时间片轮转）

 硬件自动保存（Cortex-M） R0～R3、R12、LR、PC、xPSR

 软件保存 R4～R11（被调用者保存寄存器）使用 FPU 时：浮点寄存器 S16～S31 等当前任务栈指针 PSP、TCB 状态信息

 恢复过程 从就绪列表选出最高优先级任务从其 TCB 取栈指针，弹栈恢复寄存器跳回上次被切走的位置继续执行

 PendSV 的作用 ：上下文切换放在最低优先级异常 PendSV 中执行，保证切换原子性

 面试加分点 ：能说清「不是每次中断都切换，而是在 PendSV 里切换」

 
 6. 信号量和互斥锁都能做同步，选型上有什么区别？ 

 答：

 
 信号量（Semaphore） 用途：资源计数、任务同步特点：无「所有者」概念，不支持优先级继承场景：中断通知任务、限流

 互斥锁（Mutex） 用途：保护共享资源互斥访问特点：谁加锁谁解锁，支持优先级继承，可配置递归场景：保护全局变量、外设、总线

 错误用法 ：用二值信号量代替互斥锁保护共享变量

 正确用法 中断 → 任务：xSemaphoreGiveFromISR + 二值/计数信号量任务间互斥访问 SPI/CAN 缓冲区：使用 Mutex

 
 7. 汽车电子里 CAN 总线和 UART 相比，核心优势是什么？CAN 帧里有哪些关键字段？ 

 答：

 
 CAN 相对 UART 的优势 多主机：任意节点可发帧，无需主从架构硬件仲裁：多节点同时发送按 ID 优先级裁决，无冲突损坏可靠性：硬件 CRC、ACK、错误帧、自动重发抗干扰：差分信号，适合车内电磁环境实时性：短帧、确定性强，适合车身控制、动力、底盘

 3. 说说你对Linux内核的理解，内核空间和用户空间有什么区别？系统调用的过程是怎样的？

 参考答案： 

 Linux内核是操作系统的核心，负责管理硬件资源和提供系统服务。虽然我主要做的是基于RTOS的嵌入式开发，但也了解Linux的基本原理。

 内核空间和用户空间是虚拟地址空间的两个部分，通过虚拟地址划分。x86-64架构下，用户空间是0到0x00007FFFFFFFFFFF，内核空间是0xFFFF800000000000到0xFFFFFFFFFFFFFFFF。

 内核空间和用户空间的区别主要体现在权限和功能上。内核空间运行在特权模式（Ring 0），可以执行特权指令，访问所有硬件资源，执行内核代码。用户空间运行在用户模式（Ring 3），权限受限，不能直接访问硬件，不能执行特权指令，只能执行用户程序。

 用户程序需要访问硬件或使用系统服务时，必须通过系统调用陷入内核。系统调用的过程是：用户程序调用库函数，比如read；库函数将系统调用号和参数放入寄存器，执行syscall或int 0x80指令；CPU从用户模式切换到内核模式，保存用户态的上下文，跳转到内核的系统调用处理函数；内核根据系统调用号找到对应的处理函数，执行系统调用；系统调用完成后，将结果放入寄存器，恢复用户态的上下文，从内核模式切换回用户模式；用户程序继续执行，获取系统调用的结果。

 系统调用的开销比较大，因为涉及模式切换、上下文保存恢复、参数拷贝等。所以要尽量减少系统调用次数，比如用缓冲减少read/write次数，用批量操作减少系统调用。

 内核空间和用户空间的隔离保证了系统的稳定性和安全性，用户程序崩溃不会影响内核，恶意程序不能直接访问硬件。

 4. 说说你对虚拟内存的理解，缺页异常是什么？如何处理？

 参考答案： 

 虚拟内存是操作系统提供的抽象，让每个进程都认为自己拥有独立的、连续的地址空间。虚拟地址通过页表映射到物理内存，物理内存可能是不连续的。虚拟内存的好处是进程间内存隔离、支持比物理内存更大的地址空间、方便内存管理和共享。

 缺页异常是指访问的虚拟地址对应的页不在物理内存中，需要从磁盘加载到内存。缺页异常分为几种类型：

 硬缺页异常（Major Page Fault）是指页不在物理内存中，需要从磁盘读取。比如第一次访问mmap映射的文件，或者访问被swap到磁盘的页。硬缺页异常的处理时间长，因为涉及磁盘IO。

 软缺页异常（Minor Page Fault）是指页在物理内存中，但页表项还没有建立映射。比如fork后的写时拷贝，子进程第一次写共享页时，需要拷贝页并建立新的映射。软缺页异常的处理时间短，只需要更新页表。

 缺页异常的处理过程是：CPU访问虚拟地址，MMU查找页表，发现页表项的Present位为0，触发缺页异常；CPU陷入内核，执行缺页异常处理函数；内核判断缺页类型，如果是硬缺页，从磁盘读取页到物理内存，如果是软缺页，分配物理页或拷贝页；更新页表，建立虚拟地址到物理地址的映射；返回用户态，重新执行触发缺页的指令，这次就能正常访问了。

 如果物理内存不足，内核会选择一个页换出到磁盘，腾出空间。页面置换算法有LRU、LFU、Clock等，Linux使用改进的LRU算法。

 缺页异常对性能有影响，特别是硬缺页异常。优化方法包括：增大物理内存，减少swap；使用大页（HugePage），减少页表项数量，提高TLB命中率；预读，提前加载可能访问的页；优化内存访问模式，保持局部性。

 在嵌入式系统中，很多RTOS不使用虚拟内存，直接使用物理地址，避免了缺页异常的不确定性，保证实时性。

 3. 在项目开发过程中，你遇到的最棘手的技术问题是什么？如何解决的？

 参考答案： 

 最棘手的问题是系统运行一段时间后会出现任务卡死，整个系统失去响应。这个问题很难复现，有时运行几小时才出现，有时几天才出现。

 我的排查过程是这样的。首先我怀疑是硬件问题，检查了电源、晶振、复位电路，都没有问题。然后我怀疑是看门狗没有正确喂狗，但检查代码发现喂狗逻辑是正确的。

 我在关键位置添加了调试日志，通过串口输出任务运行状态。发现卡死时，某个任务一直在等待信号量，而发送信号量的任务也在等待另一个信号量，形成了死锁。深入分析后发现，问题出在中断和任务的交互上。

 具体情况是这样的：CAN接收中断中会发送信号量通知处理任务，处理任务会访问共享的数据缓冲区。为了保护缓冲区，我用了互斥锁。但在某些情况下，任务持有互斥锁时，中断到来尝试发送信号量，而信号量队列满了，中断就会一直等待，导致系统卡死。

 解决方案是重新设计中断和任务的交互机制。我改用了无锁的环形缓冲区，中断只负责把数据写入缓冲区，不涉及信号量和锁。任务定期轮询缓冲区处理数据。这样中断处理函数非常短，不会阻塞。同时我还优化了任务优先级，确保关键任务能及时响应。

 修改后进行了长时间的稳定性测试，连续运行一个月没有出现卡死问题。这个问题让我深刻理解了中断和任务的交互、死锁的预防、实时系统的设计原则。

 通信任务负责通过4G模块上传数据到服务器，处理下行指令。优先级设置为低，因为网络通信可以容忍一定延迟。

 存储任务负责将数据写入Flash，实现掉电保护。优先级设置为低，后台运行。

 监控任务负责检测系统状态，喂看门狗，处理异常情况。优先级设置为最高，确保系统可靠运行。

 开发过程中遇到的主要问题是任务间通信和资源竞争。多个任务需要访问共享的数据缓冲区，我用互斥锁保护。但一开始没有注意临界区的大小，导致高优先级任务被低优先级任务阻塞，出现了优先级反转问题。我通过使用FreeRTOS的优先级继承互斥锁解决了这个问题。

 还遇到过栈溢出问题。一开始我给每个任务分配的栈空间比较小，运行时出现了栈溢出导致系统崩溃。我用FreeRTOS的栈溢出检测功能找到了问题任务，增加了栈空间。同时优化了代码，减少了栈上的局部变量，避免深度递归。

 另一个问题是任务调度的CPU占用。一开始我设置的任务优先级不合理，导致某些任务占用CPU时间过多，其他任务得不到执行。我通过调整优先级和使用任务延时，让各个任务能够合理分配CPU时间。

 还有内存管理的问题。FreeRTOS提供了多种内存分配方案，我选择了heap_4，支持内存释放和合并。但要注意避免内存碎片，尽量在初始化时分配好内存，运行时不频繁分配释放。

 通过解决这些问题，我对RTOS的任务调度、同步机制、内存管理有了更深入的理解。

## 【回馈牛客】双非二本嵌入式秋招之路经验分享

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-11-25 ｜ [原文链接](https://www.nowcoder.com/discuss/353158977510907904)

前言 

 先做一个简单的自我介绍，广东某双非二本，大学期间一直在学校实验室，有过相关竞赛的国家级奖项，熟练使用STM32、C语言。项目完全是裸机开发，简单了解过FreeRTOS，在开始面试的时候才系统学了一点FreeRTOS的理论知识，当时也没去移植到项目中实践过。Linux这部分就知道几个指令，其他基本不会，而且还是在秋招开始后才去花几天学的一点点基础知识。

 我秋招求职的主要目标是嵌入式软件工程师(单片机)，因为对Linux的了解很少所以也没敢投Linux的岗位，城市的话主要是集中在广东地区，以深圳、广州为主。

 写这个面经的目的也很简单，就是回馈牛客网。在我秋招的这两个多月时间里，牛客网上面各位大佬的笔经面经给我提供了很大的帮助，所以写这个帖子来总结一下我自己的秋招经历，希望能帮助到更多人！同时也给大家鼓鼓劲，我这样的双非二本虽然没能像其他大佬那样拿到华为、大疆等顶级offer，但也能拿到几家还可以的大公司offer，那么你们努力也可以！

 从2021年7月开始准备简历参与网申，期间投递了26家公司，其中：12家直接被刷简历，5家笔试淘汰，3家面试淘汰，1家拒了面试，1家体验实习淘汰，4家offer。

 从这个简历淘汰率来说，其实还是建议同样是双非二本的同学有能力、有把握考研的就去考研，当然每个同学的情况不同，既然选择了直接就业那就好好准备，别让自己后悔！

 在这里简单提几句关于考研和直接就业的一点我自己的看法，拿我自己举例子，我大学期间在学校实验室待了比较久，也有相关竞赛的国家级奖项，项目经验相对丰富的情况下，如果我考研没有成功上岸，那么我只能参加春招，这样的话我大概率不能找到比现在直接秋招更好的公司，春招肯定是比秋招更难的了，因为机会会更少，而竞争也会更大。而我对自己考研上岸并没有很大的把握，加上我自己本身有一些技术经验的情况下，我综合分析了整体的风险之后最后选择了直接参加秋招，最后也拿到了比较满意的一个offer。大家可以用类似的思路去理性分析，自己是选择考研呢还是直接就业呢？

 秋招准备 

 秋招不仅是对技术能力、综合能力的考量，还是对信息获取能力的考验，越早获得招聘信息，对自己越有利。所以要多关注各高校就业指导中心公众号、想加入的公司的招聘公众号、牛客网、加入一些招聘的交流群之类的。各高校就业指导中心公众号的话最好是关注你期望的工作城市的高校的就业指导中心，因为有些比方说西安的一些公司只会在西安高校的公众号有推送，在广东高校的公众号可能就没有了。公司自己的招聘公众号上的消息一般是第一手的，所以有想加入的公司的话也要提前关注好其招聘公众号。

 为什么说及时获取到信息很重要呢？

 早了解早投递。因为越早投递就越早进入笔试面试流程，这样是比较有优势的，因为越往后岗位的需求就越少，那么面试的要求就会相对高一点，通过率也会更低。 提前批。如果有提前批机会的话要把握好，提前批很重要，有些公司提前批直接不用笔试，而且有些公司提前批淘汰之后是不影响正式批的，相当于有两次机会。 技术准备 

 一提到嵌入式这个岗位，大家的第一反应一般是Linux，由此可见Linux的重要性。可如果你和我一样在大学期间只做过单片机的项目没有接触过Linux，如果时间还来得及的话，那我建议你花几个月的时间去做一个Linux的项目，这会对你的笔试面试很有帮助。而如果你看到这篇帖子的时候已经是7月份的话，那么我想你应该没有足够的时间去系统地学习Linux并完成一个项目了。我就是属于后者，当我意识到Linux对于找嵌入式岗位的重要性的时候，已经没办法及时补救了。但是大家也不要灰心，还是有不少招嵌入式单片机的岗位的，只是相对来说不会用Linux限制了找工作的选择。

 C语言 

 无论是嵌入式单片机还是嵌入式Linux，C语言都是必考的内容，可以说C语言是嵌入式软件工程师吃饭的家伙，相信C语言的重要性不用多说。C语言这块的话，随着不断复习，自己的一个熟练程度也会越来越高，所以最重要的就是多看多练。对于嵌入式工程师来说C语言基本上是要完全掌握并且熟练使用的，下面就先列出在笔试面试中C语言需要掌握的/比较重要的知识点：

 运算符优先级 输入输出操作 原码、反码、补码 预处理 关键字 堆栈 数组 指针 函数 字符串 结构体、联合体 内存分配 主要是这几个大的方向，输入输出是必须要熟练的，因为在笔试编程题里面是几乎必须要用到的，这个部分可以去刷算法题来熟悉一下。关键字所有的关键字都要了解，像是static、volatile、extern、sizeof都是比较常考的。堆栈和指针都是重中之重，一定要全面完整地学习。像是大题的话往往是考算法、数据结构以及对字符串的一系列操作。

 C++如果有时间的话最好去学一下，就封装、继承、多态之类的，这部分我不是很了解，因为时间的原因我没有太多去学这部分的知识。而我经常在笔试题中遇到C++的题目，一般是代码选择题，这个时候完全看不懂靠蒙的话其实还是比较吃亏的，所以推荐把其他部分内容复习完以后还有多时间的话可以学一学C++方面的一些知识。

 数据结构与算法 

 数据结构 

 对于嵌入式软件岗位来说，数据结构相对没有互联网行业的招聘那么重要，但还是属于必考的知识点。对于嵌入式岗位，数据结构可以选择性地学习，不用全部都学会，毕竟准备的时间是有限的，当然有充足的时间的话，当然建议都学会了，因为对于顶级大厂来说，数据结构是考核的相对重点。

 数据结构对于大多数不冲顶级大厂的同学来说，主要学数组、链表、队列、堆栈就可以了，至于二叉树之类的，在我整个秋招的过程中，几乎没有被问到。可能像是华为这种公司会考到。

 算法 

 算法这部分建议去leetcode或者牛客网刷一下题，起码刷个20道简单题，熟练一下做题的方法，输入输出这些，对字符串的操作这些，因为后面笔试基本上都会考两题大题，基本上刷个20题，稍微总结一下，然后加上平时的积累就问题不大了，如果想进华为这样的大厂，就要刷中等甚至困难的算法题了，这个看各位自己的取舍，也可以在牛客网上看看你想投的那家公司的笔试面试侧重点在哪里，比如说华为笔试就是考3道算法大题。

 这里记录了我在秋招期间总结的数据结构与算法方面的知识点，感兴趣的同学可以自行跳转 【经验贴】数据结构与算法知识点汇总 

 网络 

 网络这部分考得还是比较少的，有些公司会问，有些公司不问，如果是涂鸦智能这样做物联网的公司那肯定是会问的。这部分就需要知道一些基础，如果项目中有用到的话就需要将项目中用到的协议了解清楚，以及你在做这个项目的时候为什么要选择这个协议而不是另一个协议。我就在一个物联网项目中有使用到MQTT协议，那我就去单独学了这部分的知识，如果并没有项目涉及网络这一块的话就掌握一点基础知识就好了，即使不理解也死记硬背背下来，但是还是建议大家能在理解的基础上记忆，不然面试官稍微往深入问一点就答不出来了，最经典的两个问题：

 tcp和udp的区别 三次握手四次挥手 这部分内容比较少，就不单独展开来讲了，主要就是上面提到的两个问题，把那两个问题理解了去面试非网络领域的公司就没什么大问题了。

 操作系统 

 操作系统这部分的基础知识是肯定要会的，尽管你可能像我这样在大学阶段只用过单片机，并且没在上面跑过uCOS或者FreeRTOS之类的实时操作系统的话强烈建议要去学一下这方面的知识，因为尽管是投的嵌入式单片机的岗位，往往也是要求会实时操作系统的。所以建议可以去学一下FreeRTOS或者RT-Thread之类的实时操作系统，有时间的话最好能够在自己的项目中实践一下，时间不够的情况下就把基础知识系统地先学一下。

 其次就是Linux，尽管投的是嵌入式单片机岗位，但嵌入式在广泛的一个定义里，大家还是默认是以Linux为主，所以Linux的基础知识也要会，因为有些公司在笔试的时候就会涉及到，这方面的话主要是要理解一些理论知识，知道线程进程，知道一些基础的指令，最好可以在ubuntu上写一个代码出来gcc编译一下。会这些Linux相关内容基本上就可以让你在笔试阶段不那么吃亏，当然只会这些是不足以支撑你去找一个纯Linux岗位的工作的。

 找工作流程 

 对于大部分公司来说，招聘流程是这样的：投递简历→测评→技术笔试→技术一面（初试）→技术二面（复试）→HR面（终面）→offer谈薪。有部分公司是没有单独的HR面的，就是技术二面会换成综合面，前半段聊技术问题，后半段聊一些其他东西。一般来说技术一面的面试官是你将来入职后的同事，技术二面或者综合面试的面试官就是你将来入职后的主管。主要的流程就是这样，不同的公司会有不同的招聘流程，不过都是大差不差的。

 简历 

 简历这部分我就简单提几点比较重要的注意事项：

 最好要有头像 技术类岗位的简历模板越简单越好，不要花里胡哨 简历要适当“炫耀”自己的能力 关于怎么写简历的具体内容，我写了一个帖子里面比较详细的描述了简历的各种注意事项及技巧，感兴趣的同学可以跳转去看看。 【经验贴】嵌入式应届生如何制作一份加分的简历 

 测评 

 测评一般就是些行测的题目，和一些心理测试的题目，有时间的话可以去看看公务员考试的题型有什么做题技巧，推荐b站刘文超，我是之前有想过考公务员，所以去看了看，感觉还是有不少帮助的，不过学这个还是挺浪费时间的，不学也能做题，一般是不建议大家刻意去学。大家在做测评的时候一定要认真，不要觉得这些题没什么用，就随便选，因为有些公司是会在测评的时候筛人的，如果你太随意的话很可能连测评都过不了，笔试的机会都没有。

 技术笔试 

 笔试大多数都是线上笔试，一般是要开摄像头，录屏的，这部分就没有什么特别的技巧，复习好各部分的知识点就可以了。有一点要注意的是有些公司的选择题是说不定项选择的，他可能会把单选和多选混在一起，所以大家做题的时候可以测试一下是否为多选，一般来说单选和多选的选项框会不一样（cvte就是这样，单选的选项框是圆的，多选的选项框是方的），很容易注意不到。

 有些公司的编程题是不提供编译功能的，就相当于是一个文本框，这样的类型就很有可能是人工改题的，那么如果做不出来可以在里面多写点注释，即使做不出来也可以让改卷人清晰地看出你的思路（可能会比啥都不写强，但也可能没用，我猜测的）。另一种是机器改的，直接提交之后他会用测试用例去测试你的代码通过率，这种情况下如果实在做不出来的话，也可以尽可能想办法提高代码通过率，因为是机改，所以添加备注是没有用的，只有尽量提高通过率才能拿更高分。还有一种是可以使用自己电脑的编译器写代码的，如果可以的话会有提示显示可以使用自己的编译器的。那在这种情况下，最好就先准备好自己的编译器，做好基础配置，方便后面直接写代码，如果遇到这种允许使用自己的编译器的题目，最好还是用自己常用编译器，因为这样出问题之后比较容易debug。

 技术面 

 技术面一般分为一下几个环节：自我介绍、技术八股文、项目、反问

 自我介绍 

 技术面的自我介绍需要准备两份，一份在2~3分钟左右，另外准备一份比较精简的在1分钟左右的。因为有些面试官会要求你做一个1分钟的自我介绍，那么你没有准备，还是讲这么长的话，讲到一半就会被面试官打断了，也会给面试官留下时间意识差的印象。

 把两份自我介绍的稿子写出来不断地念，反复修改直到自己觉得满意为止，念的时候还要给自己计时，注意时间的把握。

 技术八股文 

 所谓的技术八股文就是一些能够死记硬背的知识点的意思，面试官往往会直接考察你对某个知识点的掌握情况，这个时候就需要对前面提到的，C语言、单片机等知识比较熟悉才能从容应对。

 项目 

 项目这部分，首先是会让你介绍一下你的一个项目，然后面试官会根据你项目里用到的技术去进行提问，如果遇到面试官比较熟悉或者感兴趣的内容，可能就会问得比较深入，一般来说还是以面试者的讲述为主。对于自己写在简历里的项目一定要非常熟悉，针对项目里的每个技术细节都要熟练掌握。

 反问 

 反问环节基本上是每个面试都会有的，当面试官问完了他的问题之后，一般会问你有什么问题问他的，这个时候你千万不能说没有问题，因为这样往往代表你没有好好准备这个公司的面试，在面试官那里肯定是扣分的。

 在面试前准备好几个问题，等到这个反问环节的时候挑几个提问就可以了。在反问的这个环节，最好能体现出你的态度以及你对公司的向往。而有一些问题是很踩雷的，就不要问了。具体的有哪些问题可以问，哪些问题是要避雷的，大家可以从下面的链接跳转过去看看。

 HR面 

 这里提到的HR面是纯HR面，如果面试的公司没有这个环节取而代之的是综合面的话，那就参考技术一面并结合一点HR面就好了。

 在这个环节HR考核的主要就是你的一个态度、是不是想要加入公司以及和公司的企业文化匹不匹配。找工作是一个双向选择的过程，HR主要是负责筛选出和公司匹配的人才。所以在HR面的环节主要是要表现出自己对公司的兴趣，以及一个匹配程度。如果公司的企业文化就是996，而你完全不接受996那么就干脆不要参加了，因为你肯定是过不了最后一轮面试的，当然这里只是举一个例子，嵌入式软件工程师大部分还是要加班的。

 HR面基本就没什么了，一般以聊天的方式进行，基本上如实回答并且不经意间透露出对公司的向往就可以了，面试前要先去牛客上搜索一下大家的面经，看看面试官一般会问什么问题，通常来说HR面试官都有一个题库，问每个人都是差不多的问题。

## 【电源岗专题】21届学长校招经验分享

来源：牛客网 ｜ 类型：面经 ｜ 发布：2021-06-08 ｜ [原文链接](https://www.nowcoder.com/discuss/353158003195060224)

牛客 校招 研究院出品，专题特约 作者：@Lesson11(290590662) 
 

 
 

 作者按： 

 本文仅结合自身2021年秋招经验进行介绍，旨在为2022届应届生提供电源岗秋招经验，仅供参考。 

 

 
 

 一、岗位与相关公司介绍 

 电源岗在不同的公司招聘岗位中命名不同，有一些归类到硬件工程师岗位，有一些单独细分为电源工程师岗位，还有部分公司为功率变换工程师、电力电子工程师等，均为本文介绍的电源岗范畴。同时，针对不同的公司和部门要求，电源岗又可分为强电和弱电两部分。
 1、强电类电源岗： 

 该岗位主要针对电气类学生，涉及的电压等级较高，功率较大，主要的应用场合为大中型设备。如华为的数字能源产品线、远景能源、阳关电源、南瑞继保、台达电子等电力设备制造公司、以电力侧需求为主。除此之外，新能源车企同样需要类似的人才，如广汽研究院、小鹏汽车等。以下列公司为例，主要介绍强电类电源岗的校招情况。 

 a. 华为数字能源产品线。2021年秋招阶段，数字能源产品线有一定的扩招，总体的难度较华为其他部门相对较小。主要环节有网申、性格测评、线上笔试、线上三轮面试。网申环节注意毕业年份。性格测评有挂的，一般有两次机会。线上笔试满分100分，60分过线，只有一次机会。三轮面试环节前两轮为专业面试，最后一轮为综合面试。大部分三轮面试安排在一天面试完，少部分人分为几天，通过前一轮面试才有资格进行下一轮面试。华为数字能源产品线在整个电源岗中薪资水平为第一梯队，后续发展前景较大，公司的职业培训与规划完整，但相应的工作压力较大，岗位大多在东莞松山湖，少部分在上海和西安。 b. 阳光电源、台达电子等。该类公司属于行业龙头公司，且公司的甲方一般为国家电网、电厂等大型用电设备，所涉及的技术要求较为传统，难度较小。该类公司也需要进行网上简历提交，但没有笔试，只有面试，一般只有一轮专业面试和一轮HR面试。分布城市为合肥、上海、深圳等南方城市，北部城市设置岗位较少，有工作地域需求的同学需要注意。 2、弱电类电源岗： 

 该岗位主要针对电气类和电子类学生，涉及的电压等级较低，负载较低，一般均为DC/DC变换器方向，主要的应用场合为电子设备的供电与充电等，如华为的消费者BG、大疆、OPPO/VIVO/小米、怪兽充电等。以下列公司为例，介绍弱电类电源岗的校招情况： 

 a． 大疆的电源岗隶属于硬件工程类，由于受到美国制裁及公司战略调整的影响，2021年大疆校招难度极大，今年招聘难度未知，请谨慎选择。大疆招聘主要包括性格测评、笔试、面试三个环节。性格测评与大部分公司一致，选择的时候注意前后一致即可，忘记是不是有二次机会了，如果不放心，可以找知乎上分享的性格测试宝典。大疆的笔试环节为线上笔试，主要考察专业知识和一些器件及工具的使用，会涉及少量PCB知识。面试一共三轮，均为线上面试。一面主要考察基础知识，二面主要针对简历中的项目介绍，三面为综合面试，基本不涉及专业知识。三轮面试间隔时间不一，视具体情况而定。 b． OPPO/VIVO/小米等。该类型公司为移动通信类制造商，涉及的电源岗一般为手机、PC等供电或者充电器设计。招聘环节与大疆类似，面试为两到三轮不一，且面试主要针对简历中的项目。 二、行业介绍 

 强电类电源岗所属公司一般为大型电力设备制造商， 该类公司多为大中型企业，公司建立时间长，如阳光电源、汇川科技、南瑞继保等，皆为行业内的头部企业。公司一般发展比较稳定，且产品的研发周期比较长，相对于互联网等循环周期较短的企业，工作压力较小，存在少许加班，并不严重。同样的该类公司薪资水平一般，缺少吸引力，属于传统工科制造业，创新性相对较低。
 弱电类电源岗公司一般为消费类电子公司， 如HOVM手机厂商。该类公司年轻化程度高，工作氛围较好，薪资水平较高，对于应届生有更强的吸引力。但因为消费电子类循环周期较短，产品更新换代较快，常常伴随着大量的加班。 

 目前 强电类市场基本已经分割完毕，头部公司相对稳定 ，主要有华为、阳光电源、特变电工、上能电气等，随着国家的产业化改革以及能源结构的转变，无论是传统领域还是新能源领域，作为二次能源电能对应的电源工程师，未来都具有较好的发展前景。 弱电类市场一般为电子消费类市场，与人们的生活息息相关 ，且变换较快，无论是产品还是市场更新迭代都比较迅速，选择弱电类的电源岗，机会多，挑战大，更具有突破性。随着新型材料与充电技术的发展，无论是电子供电稳定性还是充电快速性，都是一个具有前景的研究方向。 

 三、校招基本情况 

 因疫情原因，2021年校招主要以线上为主，部分地区及高校会穿插一定的线下招聘，且主要集中在各省的省会城市和大学相对集中的城市。考虑到今年疫情防控的原因，主要招聘形式应该和去年类似，线下的校园招聘场次会增多，但仍然可以选择线上模式。 

 
 

 电源岗隶属于硬件工程师的范畴，部分公司有提前批，后面会详细介绍。主要过程分为网申、笔试、面试等环节。 

 a. 网申即为网上提交简历和填写本人基本信息。 各网申途径可找对应公司的招聘公众号或者一些专门做招聘信息分享网站（如牛客网等）途径获得。网申过程中需要注意的是一定要填写正确对应的手机号和邮箱，便于接收后续笔试和面试的通知。也有部分公司进行线下招聘收取简历。网上简历提交未果的同学可以选择相应的线下简历提交。 b. 电源岗为研发岗位，各公司招聘都会有笔试环节。 应届生可选择线下笔试和线上笔试。线下笔试即到公司约定地点或者学校阶梯教室进行手写笔试。线上笔试需要准备一台能联网的电脑和一个摄像头，需要实时监测为本人线上答题，后经系统提交。线上笔试需要注意的问题是一定要保证网络的稳定性，一些公司的笔试系统在断网之后会默认提交，没有二次机会。 c. 面试环节根据各公司情况的不同，主要有一次到三次面试不等。 面试主要为技术面和HR面。技术面主要涉及到简历中提到的项目经历和其中担任的一些工作以及取得的一定的成果。HR面一般为公司了解个人情况，兴趣爱好，期望薪资等问题，方便公司对招聘生有一个清晰的认知。同样的，面试环节也分为线下面试和线上面试。线下面试为与面试官进行面对面的交流与提问。线上面试一般包括电话面试和视频面试。电话面试为面试官与招聘生通过电话进行沟通与提问，视频面试则通过网络稳定的电脑进行面试。在面试环节，有部分公司要求必须有一面为线下面试，需要注意。 

 四、校招规划 

 电源岗对应的电源工程师在我看来是一个非常有前景的职业，无论是强电类的还是弱电类的。电在我们的日常生活中随处可见，是我们最常接触的二次能源，而怎样更好的应用好电，则是电源工程师的职责所在。
 无论是在工业生产领域还是消费电子领域，涉及到供电稳定性的公司都会招聘电源工程师，我们的选择相较于其他传统工科来说较多。针对电源工程师，在整个秋招过程中：
 消费电子类的公司 ：往往招聘时间较早，且有提前批计划。提前批一般会在五月中旬开始，时间大概持续一到一个半月。其正式秋招时间一般集中在八月份开始，比互联网公司晚大概半个月到一个月左右，一般环节为网申、笔试/性格测评、面试、offer等。简历一般需要在八月份之前就准备好，同时在简历中注明意向岗位。专业课复习的话，同样需要在简历网申之前就准备好，一般网申结束后，会分批次安排笔试和面试时间，具体间隔时间依公司而定。 强电类的公司 ：时间相对较晚，一般在九月份才开始启动校招。且校招公司大多数为传统制造业的公司，大多没有笔试环节或者笔试环节较为简单，面试环节也多为一轮或者两轮，招聘环节与消费电子类相同。除了一般的制造业公司，也有部分国企校招强电类电源岗，国企比较注重平时成绩和奖项等信息，面试难度相对较小。国企的校招时间一般在十月份左右。 下面以自身经历介绍一下个人准备秋招的各时间节点，仅供大家参考： 

 4月初： 开始准备简历，简历主要介绍自己的学校、专业及和所投岗位相关的项目经历等。 4月中旬： 就开始复习专业课，复习的内容主要包括电力电子基础、数电和模电，并且回顾简历上的相关项目及在项目中负责的工作。因为在这个时间段，大部分的公司还在进行上一年的春招补录，校招系统暂时没有开启，可在牛客网、BOSS直聘等软件上联系相关招聘人员，拿到一手的招聘信息。 5月 ：有少数企业开始提前批招聘，我在这个时间投递了OPPO、华为等公司，但并没有收到提前批面试通知，简历顺延至正式批。 6月： 大部分企业开始提前批招聘，关注各公司公众号及招聘网站，进行简历投递。同时继续复习专业课知识和回顾项目经历。与其他岗位不同，电源工程师涉及的专业知识多且杂，各个方向的差别极大，关于该岗位的面经和笔试题目基本没有，所以该方向的一些基础知识和自己的项目经历、实习中所涉及的内容为主要准备对象。 

 

 【关于提前批】 

 就以往经验来看，提前批的简历筛选较为严格，但是往往会免笔试，直接面试，面试难度相较于正式秋招来说简单一些，所以提前批是往往是一些同学斩获offer的捷径。提前批的面试一般只针对简历上的项目来进行提问，所以需要对自己简历上的项目比较熟悉，务必不能弄虚作假，否则很可能浪费一次很好的机会。同时，有提前批招聘的公司，即使在提前批面试中挂掉，也不会影响后面的正式秋招，一般正式秋招时，无需再次投递简历，提前批简历会顺延至正式秋招，但具体情况需要根据公司规定而看。 

 7-11月 ：该段时间为秋招的黄金时间，无论是弱电类的正式批，还是强电类，均在这个时间段内进行招聘。这半年内，基本上都用于投简历、笔试、面试，通过参加各种面试，积累经验，同类型的公司，招聘流程基本相似，笔试、面试内容也基本相同。尽可能多的在固定的时间内参加更多的公司招聘，在时间冲突时，选择自己更想去的公司。 12月-次年3月 ：这个时间段为秋招补录和春招的时间，同样重要，且不乏有好的岗位。因为这段时间会有很多拿到多个offer的同学进行选择并放弃一部分，所以会有部分名额空出，在秋招阶段没有拿到理想offer的同学，可以在补录和春招中继续投递简历，我个人的最后offer就是在2021年1月份拿到的，所以永远不要放弃校招的每一秒时间。 

 【关于校招】 

 在整个校招中，比拼的除了个人能力之外，也是一场信息争夺战。比别人更快更早的获取招聘信息，往往能抢得先机，有更大的机会。所以在整个校招过程中，需要从多方面、多渠道获取信息，可通过各种求职公众号、不同公司的校招群、各种论坛、学校就业网站等获取一手招聘信息。 

 对于研二或者大三的同学，可以尝试跟着学长学姐们参加招聘会，提前感受招聘的氛围，把握自己理想公司每年大概的招聘时间，多关注笔试考察的内容，做到心中有数，并学习一些面试技巧，让自己在下一年的校招中脱颖而出。 

 五、电源岗校招技能树 

 电源岗/电源工程师，无论是强电类还是弱电类，所需要的知识和掌握的技能都是相同的，唯一不同的地方就是应用场合不用，所涉及的标准不一样。下面列出了电源工程师需要掌握的各种技能，仅供参考。 

 
 
 

 
 

 在需要掌握的电路拓扑方面 ，一般弱电消费电子类侧重于DC/DC变换器，主要为Buck、Boost及相关的电路变形。而强电类除了DC/DC变换器之外，AC/DC，DC/AC等整流、逆变器等也需要掌握。 在CPB绘制方面， 弱电消费电子类的要求更高，一般需要熟练掌握PCB的设计与绘制，因为该类一般体积较小，集成度较高，对AD软件掌握的熟练度要求也高。而强电类一般对PCB的设计与绘制不做要求。 控制器的应用方面， 除了DSP/FPGA等控制芯片的使用，还需要掌握其他外围电路的设计和其他芯片及相关电路的设计与使用，如稳压芯片及其外围电路、采样芯片及其外围电路等。 

 六、学习资源推荐 

 1、电路拓扑 的学习 

 电源工程师主要涉及的拓扑主要参考王兆安版《电力电子技术》一书，该书详细介绍了交交变换、交直/直交变换、直直变换等多种电路拓扑，并针对不同的拓扑介绍了工作状态和相应的控制方法，对于电源工程师的基础入门具有很大的帮助。除此之外，数字电路与模拟电路也是需要掌握的内容，该部分内容参考大学教材即可，无特定书籍推荐，仅用来学习基础知识，包括器件的一些特性，和相关的电路拓扑及各种功放电路。 

 2、仿真分析软件 

 暂无推荐的书籍，更多的是靠自己搭建的仿真模型去亲自实践调试，不需要掌握全部的软件，只需熟练使用1-2个即可。其他类似的软件在使用方面大同小异。在使用仿真软件的过程中，重要的是在不搭建实物平台的前提下，对所需电路进行仿真验证。但由于一般仿真软件中都是理想模型，所以可以人为的添加一些组件，尽可能真是的模拟实物器件，比如设置相应的死区，器件添加电阻模拟开关损耗等。 

 3、器件选型 

 也暂无书籍推荐，更多的是依照所用电路拓扑的结构和实现的功能选择相应的器件。在选择器件的过程中，要充分的考虑到器件的特性，同时在搭建是实物平台时，应注意器件之间的连线和可拓展性等要求，为进行后续的系列实验留出裕度。 

 4、PCB绘制建议参考 

 （1）《Altium Designer 18电路设计从入门到精通》毛琼, 张玺, 闫聪聪等 

 本书以Altium Designer 18版本为平台，介绍了电路设计的方法和技巧，主要包括Altium Designer 18入门、原理图绘制、原理图编辑、原理图高级编辑、高级原理图绘制、原理图库设计、印制电路板绘制、印制电路板编辑、电路仿真、电路信号分析、封装库设计和大功率开关电源电路设计综合实例。
 （2）《信号完整性分析》Eric Bogatin 

 本书详细论述了信号完整性的问题，从信号完整性的设计和物理概念上，结合电阻、电感、电容等的相关分析，给出了不同情况下的信号完整性的解决方案。
 （3）B站视频 

 同时也可观看B视频Altium Designer 20 AD19 AD18 全套零基础入门PCB Layout设计实战视频教程【志博教育】 https://www.bilibili.com/video/BV1R4411a7xg?share_source=copy_web 

 初步了解PCB设计入门。
 PCB绘制方面，书籍和视频只是一种学习的引导，更多的还是需要自己亲自去绘制、制版，在实践过程中发现存在的问题并解决，提高软件的熟练度，掌握PCB绘制中的规律，提高工作效率。
 5、控制器及相关电路的学习 

 一般是伴随着PCB的绘制同步进行的，首先要了解控制芯片能够实现的功能、芯片工作条件和各引脚功能，再去设计相关的周围电路及绘制PCB版。其次，不同的控制芯片有不同的控制语言编写软件及算法语言，就DSP而言，是在C语言的基础上演化而来，而FPGA则需要的Verilog HDL。 

 DSP推荐书籍 ：《TMS320x2833x DSP原理及其C程序开发》苏奎峰等 FPGA推荐书籍 ：《HELLO FPGA》 这两本书作为DSP和FPGA的入门书籍，完全可以满足电源工程师对于控制器芯片的简单应用，且书中配合大量案例及相关例程，方便学习。 附《HELLO FPGA》的文件下载链接： 
 

 
 

 七、写在最后 

 电源工程师是一个理论与实践结合非常强的岗位，不仅需要专业的知识，更多的是需要在日常的科研中有较强的动手能力。设计的知识面较广，不仅包括硬件知识，同时也需要一定的程序编写能力。在工作前期，通常会面临着知识面匮乏，经验不足，动手能力差等问题，但随着工作时间和工作经验的增加，相应的问题都会随着解决。该专业的更新迭代的时间较慢，宝贵的知识与经验就是以后的竞争资本。最后，祝各位同学在校招中拿offer 拿到手软。
