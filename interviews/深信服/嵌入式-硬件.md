## 深信服嵌入式软件开发一面 面经 依旧八股轰炸了

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-08-11 ｜ [原文链接](https://www.nowcoder.com/discuss/916595209083883520)

1. 简历里嵌入式项目里，你遇到的最棘手问题是什么，怎么定位和解决的？

 
 典型是偶现死机或通信超时：先复现路径，固定版本、日志级别和触发条件。

 用串口/SWO 抓崩溃点，看 PC、LR、MSP/PSP，判断是 HardFault、栈溢出还是任务饿死。

 查中断与任务共享数据是否缺临界区，以及 DMA 缓冲是否未做 cache 一致性处理。

 对协议类问题，对拍抓包与状态机：确认是丢包、粘包解析错误，还是超时重传策略过激。

 修复后用压力测试和边界用例固化，把根因写进评审，避免同类问题再犯。

 
 2. 什么情况下会发生栈溢出，嵌入式里怎么排查？

 
 局部大数组、深递归、中断嵌套过深、任务栈预估偏小都会挤爆栈。

 现象常见：HardFault、返回地址被踩、局部变量莫名被改。

 排查可看 MSP/PSP 是否落到栈底以下，或用水位填充法看最大使用量。

 RTOS 下分别检查各任务栈与主栈，别只盯着主栈。

 处理办法：加大栈、改堆分配大缓冲、砍递归、缩短 ISR 路径。

 
 3. const int *p 、 int *const p 、 const int *const p 有什么区别？

 
 const int *p ：指向常量的指针，不能通过 p 改 *p ，但 p 可以改指向。

 int *const p ：指针本身是常量， p 不能改指向，但可以改 *p 。

 const int *const p ：指针和所指对象都不可改。

 函数参数里常用前两种表达“只读输入”和“固定缓冲区地址”。

 写接口时把 const 放对位置，能在编译期拦住误写。

 
 4. 手写 strcpy 要注意什么？和 memcpy 的差别是什么？

 
 strcpy 依赖 '\0' 结尾，目标缓冲区必须能装下源串加结束符。

 不检查长度时，源更长会越界写，属于典型不安全接口。

 memcpy 按字节数拷贝，不认字符串结束符，适合任意二进制数据。

 若源目区间可能重叠， memcpy 行为未定义，应改用 memmove 。

 工程上优先带长度的安全接口，并明确返回值与截断策略。

 
 5. volatile 解决什么问题？能不能代替互斥锁？

 
 volatile 告诉编译器：该对象可能被外部改写，禁止过度优化缓存到寄存器。

 常见场景：寄存器映射、中断里改写的标志位、多核共享的粗粒度状态位。

 它只保证“每次按内存访问”，不保证原子性，也不保证多核可见性的完整内存序。

 多任务对共享结构的读改写，仍需要关中断、互斥量或无锁原子操作。

 所以 volatile 和锁解决的是不同问题，不能互相替代。

 
 6. 互斥锁和信号量怎么选？二值信号量能当互斥锁用吗？

 
 互斥锁强调所有权：谁加锁谁解锁，常带优先级继承，适合保护临界区。

 信号量强调计数资源：发布可不由同一任务完成，适合同步和资源池。

 二值信号量可以做简单
