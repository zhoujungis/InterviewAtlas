## 地平线 C++ 一面面经（27届秋招）

来源：牛客网 ｜ 类型：面经 ｜ 发布：2026-10-25 ｜ [原文链接](https://www.nowcoder.com/discuss/943827328382083072)

1. 空类为什么是 1 字节？多继承下 this 指针是怎么调整的？

 参考答案：

 
 空类大小：C++ 要求同类型不同对象地址唯一，所以空类至少占 1 字节；一旦有虚函数就变 8 字节（一个 vptr），继承空基类时编译器用 EBO 把它压到 0 偏移，但两个同类型空基类不能重叠。

 指针调整：多继承下派生类指针转第二基类指针，编译器插入常量偏移，比如 class D : A, B 中 B 在偏移 16，转换就是 this + 16；虚继承更麻烦，要走 vbtable 间接取偏移。

 调用约定：成员函数不占对象空间，非虚函数地址在编译期确定，this 通过 rdi（x86-64）或 x0（AArch64）传入，返回大对象时还要多传一个隐藏指针。

 
 2. 智能指针在车载代码里有哪些坑？shared_ptr 的引用计数是原子的吗？

 参考答案：

 
 计数开销：shared_ptr 的计数是原子操作，单次拷贝约 10~20 ns，热路径上每秒百万次拷贝就是 2% 的 CPU；能用 unique_ptr 或裸引用就别用 shared_ptr。

 循环引用：父子互相持有会永久泄漏，必须有一端用 weak_ptr；我们的图结构里节点持有边、边反向持有节点，就踩过一次，跑了 6 小时才 OOM。

 控制块竞态：两个线程同时对同一个 shared_ptr 赋值（不是不同对象）是数据竞争，C++20 才有 atomic ；正确做法是各自持有副本，或加锁保护那一个变量。

 
 3. STL 容器在实时系统里有什么问题？为什么我们基本不用 unordered_map？

 参考答案：

 
 不确定性：unordered_map 的 rehash 是一次性搬所有节点，10 万条目时单次耗时 20 ms，直接打爆 33 ms 的帧预算；map 每次插入都有树旋转和节点分配，延迟抖动同样不可控。

 内存碎片：每个节点单独 new，长期运行后堆碎片化，分配 1 KB 可能失败；我们改用固定容量 open addressing 哈希表，预分配一块连续内存，插入最坏 O(n) 但无分配。

 替代方案：实时路径上用侵入式容器（boost::intrusive）把节点嵌在对象里，零额外分配；查找用排序数组加二分，1 万条以内比哈希还快，因为 cache 友好。

 
 4. 模板你用到什么程度？模板为什么会导致代码膨胀，怎么控制？

 参考答案：

 
 常见用法：策略模式用模板参数代替虚函数，编译期绑定可以内联，实测比虚调用快 3~5 倍；类型萃取配合 if constexpr 做分支，避免为不同类型写重复实现。

 膨胀原因：每组模板实参生成一份独立代码，vector 和 vector 完全不共享，10 个类型实例化一个大模板，二进制能涨 20 MB。

 控制手段：把与类型无关的逻辑抽到非模板基类（类型擦除），模板层只做薄封装；显式实例化常用类型并 extern template 抑制重复生成，我们的固件因此省了 30% 体积。

 
 5. 手撕：实现一个简化版 vector，支持 push_back、size、capacity 和析构，你打算怎么写？

 参考答案：

 
 三指针布局：begin、end、cap_end 三个指针，size 是 end - begin，capacity 是 cap_end - begin；push_back 先判断 end == cap_end，满了就按 2 倍扩容。

 扩容细节：新内存用 operator new 分配原始字节，再用 move_if_noexcept 逐个搬移，只有移动构造是 noexcept 才敢 move，否则退化成拷贝保证强异常安全。

 必须补的：拷贝构造、移动构造、析构、operator=，五个特殊成员漏一个就是双重释放；析构要显式调每个元素的 ~T()，再 operator delete 整块内存。

 
 6. 追问：扩容为什么是倍增？1.5 倍和 2 倍有什么区别？

 参考答案：

 
 摊还分析：按 2 倍扩容，n 次 push_back 的总拷贝次数是 1+2+4+…+n 0 且 (x & (x - 1)) == 0，减一会把最低位的 1 变成 0、后面全变 1，与运算为 0 就说明只有一个 1，3 次指令搞定。

 低位提取：x & (-x) 拿到 lowbit，常用于树状数组；清除最低位 1 用 x & (x - 1)，可以循环几次就统计出有几个 1。

 位计数：用 x = x & (x - 1) 循环 1 的个数次，或直接用 __builtin_popcount 映射到单条 popcnt 指令；ARM 上对应 cnt + addv，编译器会自动识别。

 
 8. 大小端你怎么判断？跨平台传数据踩过什么坑？

 参考答案：

 
 判断方法：union { int i; char c[4]; } u = {1}，看 c[0] 是否为 1；或者用 memcpy 到 char 数组，不要用指针强转，那是严格别名违规，-O2 下会被优化掉。

 平台差异：x86 与大部分 ARM 是小端，部分网络设备与 DSP 是大端；AArch64 支持 BE 模式但极少用，RISC-V 也是小端为主。
